# 文档维护与行为核对

产品手册记录已确认的产品承诺；开发文档解释当前实现。两者发生差异时，必须写明预期、实际、影响客户端及证据，不能仅按源码现状改写产品承诺。测试只证明它的断言，Agent Note 不补全缺失的产品意图。

## 内容归属

| 内容 | 负责位置 |
| --- | --- |
| 共享产品概念与功能语义 | 产品手册的 concepts 与 features |
| TUI、Web 的操作、展示与限制 | 对应客户端指南和参考 |
| 模块职责、实现入口和测试 | workspace README 与本地 docs |
| 跨包协议、安全、恢复与发布约束 | active |
| 开发步骤、阻塞和待决事项 | plans |
| 有持久解释价值的取舍与提案 | [Agent Notes](../../.agents/notes/README.md)；当前完整结论仍须在 owner 文档 |
| 仍被验证或运维使用的证据 | release、tests 等实际消费者所属领域 |

同一事实只在负责位置完整维护。导航只链接，不复制实现细节；客户端的差异不能被共享章节抹平。根 README 是双语产品入口，不以 TUI 代表全部产品。

| 位置 | 完整维护的内容 |

| [docs AGENTS](../AGENTS.md) | 文档任务入口与局部格式约束 |

| [PR 模板](../../.github/pull_request_template.md) | 本次变化、同步、验证及剩余问题的交付证据 |

入口只保留定位所需提醒，不复制完整执行流程。影响映射提供候选；是否需要修改由产品定义、实际 diff 和实现证据共同判断，有文档 diff 不等于语义通过。

产品或边界变化时，在原有负责页面维护功能→实现→验证及模块→功能的链接；只在入口、归属或关键交接变化时调整开发导航。重要实现结论给出源码路径和关键符号，跨层关系核对调用与接收双方。设计理由引用明确需求、owner 说明或 Agent Note；Note 按下方使用边界核对，找不到原始理由时标注“原始理由未找到”，推断单独标明。验证区分有测试文件、读过断言、实际执行通过；执行记录包含命令、代码版本、环境及未覆盖范围。沿用现有完成检查，不另设全景报告、人工审批或同步台账。

首发证据由独立检查器验证。命令作用域和完成判定按 Skill 执行。

## Agent Notes 使用边界

Agent Note 记录一个影响代码库的提案或决策的动机、备选方案和代价，不单独构成当前实施要求。路径按生命周期 `proposed`、`implemented`、`rejected` 或 `archived` 及决策类别组织；具体命名、内容和迁移规则见 [Agent Notes 规范](../../.agents/notes/README.md)。`implemented` 表示所述决定已交付，但不证明整篇文字仍适用于本次任务；`proposed` 不代表功能已上线，`archived` 仅供历史追溯。

实施以已确认需求、当前负责文档与相关契约为依据，并用源码和运行证据核对实际；源码不自动覆盖产品承诺。引用 Note 支持实施时，必须说明其当前适用范围，并指出支持该范围的已确认需求、当前负责文档或相关契约。没有现行依据时，将其作为待核实历史信息，不得据此恢复退役机制、扩大任务范围或增加审批门禁。

新增持久取舍时按规范选择 `feature`、`bug-fix`、`simplification`、`architecture`、`process` 或 `testing` 类别。新 Note 先写独立于方案的问题，再记录真实考虑过的备选及未采用理由、收益与代价、适用范围和可核实的验证；不补造缺失历史。重要决定变化时同步当前负责文档，处理旧 Note 的生命周期、替代范围及引用。部分替代须明确范围并保留两份 Note 的可检查链接；不能把整篇旧决定推定为全部有效或全部失效。不因文档迁移放宽实际安全或发布约束。

## 生命周期

普通小修复不新建计划。多阶段工作在 plans 中保存目标、步骤、验收与待决事项；完成后将知识和必要证据归位，删除计划，过程由 Git 保留。不另写 completed 副本，不建立空 generated 或重复索引。

仍在设计或部分实施的 Note 保留在 `proposed`；交付后更新为 `implemented`，陈述实际交付的决定与后果。否决的提案仅在其理由能防止再次犯错时保留于 `rejected`。已实施的 Note 若仍有历史价值、但理由不再指导未来工作，可按规范移入只读 `archived`；仍适用的取舍保持可读。完全失效的记录只有在当前 owner 保存全部独特理由、备选、后果和验证边界，并修复所有入站链接后才能删除；部分替代不满足这一条件。当前行为始终由手册、active、owner 文档及运行证据核对，Note 不形成第二套实现权威。

真实模型、性能或可靠性实验只沉淀可核实的问题、环境、变量、对照、结果、限制和复现入口。结论进入实际拥有该行为的 workspace 文档或跨包契约；不能用单次结果承诺其他模型、平台或版本行为，也不能以文档存在代替运行证据。进行中研究随有效计划记录，必要原始证据归测试或发布领域，完成过程由 Git 保存，不另建研究摘要库或完成记录树。外部来源直接链接到相关结论；未经本地验证的推测明确标明。模型调用、凭据与实验数据遵守[隐私和运维边界](../active/observability-privacy-operations.md)。当前实验入口以根 package scripts 与 tests 文档为准，不从旧记录恢复已删除工具。

## 写作与验证边界

Markdown 正文以中文为标准；根 `README.md` 保留英文、`README.zh-CN.md` 保留中文，命令、事实和入口同步。命令、路径、类型名、配置键和正式产品名称保留原文，不为翻译改产品行为。指南说明操作及正常、边界、失败和恢复行为；参考用表格，内部专题提供代码与测试链接。无适用内容不建立空章节，不规定字数或固定标题数量。

结构检查递归覆盖 handbook、development、active、runbooks、workspace 文档、Agent Notes 和当前入口，检查本地链接、wiki-link、active 元数据和映射。已归档 Note 与保留的计划证据不要求旧代码路径仍存在，但当前文档指向它们的链接必须有效。影响映射只覆盖实际生产源码、manifest 与相关基础设施；普通测试不因路径位于 workspace 内触发架构规则，专业路径与通用 source owner 互斥。映射仅提示产品与技术文档的核对范围，不要求行为不变的改动制造文档 diff。

不引入文档网站、语义评分、永久豁免文件、独立知识注册表或通用截图流水线。文档检查不替代 Runtime 正确性、安全和发布门禁。

## 当前事实与设计状态

需要留作后续实施依据的已确认设计，在 plans 中完整维护产品行为、适用客户端、验收场景、模块交接、数据与接口，以及适用的状态、事务、失败、取消、恢复影响和待更新文档。不适用的机制不制造空小节。

相关产品页和技术页标注“已确认设计，尚未实现”，链接到同一方案；没有专属页面时放在最近导航。当前正文不改成目标态，不建空功能页。普通小修复直接更新交付事实，不强制形成设计文档或标记。

部分交付只归位已完成事实，保留剩余设计入口；全部交付移除标记、归位必要证据，再删除计划；取消方案同步移除入口。产品与技术都核对，有变化才更新，行为不变时说明核对依据。

| 变化 | 需要核对的负责文档 |
| --- | --- |
| 操作、结果、限制、客户端能力 | 产品指南、参考、能力矩阵 |
| 职责、依赖、调用与数据交接 | 架构、链路、子系统、模块 |
| 状态、并发、事务、恢复 | 底层专题、跨包契约、恢复说明 |
| API、命令、配置和格式 | 精确参考、生成规范、兼容边界 |
| 测试方法与覆盖 | 测试入口、专题中的验证说明 |
| 启动、发布、运维 | 根入口、开发指南、runbook、实际证据 |
| 重要取舍与工作状态 | 必要 Agent Note、计划、backlog 与设计入口 |

## 两条读取路径

学习项目沿架构→链路→子系统→模块→底层；开发任务从症状/功能直接进入 owner 与测试，仅在发现跨层影响时扩读。架构解释组成，链路解释交接，模块解释机制，active 定义跨包不变量，手册定义用户表现。同一规则不在每层全文复制。

## 根文档与客户端规则入口

根 README 负责产品介绍与导流，手册负责完整产品定义，plans/backlog 负责工作状态。不要再建立 PRODUCT 或 ROADMAP 形式的第二份当前定义。CLAUDE 等客户端指令文件只路由到根 AGENTS，不复制权威顺序、架构或命令清单。

新根 Markdown 自动进入本地链接检查，避免新入口遗漏在硬编码名单外。历史决策以迁移后的 Note 或明确 Git revision 追溯，不把已退役方案当作当前实现依据。
