产品行为以[执行与结果](../handbook/features/execution.md)、[工具与审批](../handbook/features/tools-and-approvals.md)及已确认的子 Agent 协作方案为准。[69 个主用例与 80 项合同](../../tests/e2e/live/model/collaboration-v1.1-cases.md)逐项保存真实资格、证据和缺口，是测试结果的负责位置；本计划只维护执行顺序、交接和验收，不复制完整矩阵。

优先查清真实失败发生在文件效果、观察与叙述、完整正文传递、Provider 容量还是恢复边界。协作链路完整保留 child 实际生成的结果、来源与权限效果；模型回答核事实和语义。明确要求无损复制的独立任务才逐字节比较回复与原文件，Unicode、CRLF 和重复行等精确转写失败按模型能力保留，不能据此推成通用传输故障。不能以换模型、隐藏重试、只核头尾标记或删除失败报告制造通过。新一轮有源码变化时绑定新冻结摘要，原版本的失败不改签。机械通过与完整语义审阅分别记录。

用户已确认保留现有 `deepseek-v4-flash` 与 `reasoningEffort:medium`，按实际能力记录 F04，先补其他缺口。后续普通事实报告仍使用默认 4096 输出上限；既有 8192 精确复制对照是独立历史实验，不修改默认配置，不继续增加模型或预算对照。

完整收束要求每项原合同有对应执行证据及准确范围；无法在当前平台或正式能力下验证的分支须明确实际限制。受控默认全量、真实模型、本机客户端和其他平台资格分别核对，不能相互替代。
