# Kite Agent 真实模型测试方案

**2026-11-22 · 源码基线 `337fd8f8e204ad7127603d7185069ea5683dcf92`**

本方案覆盖 Kite Agent 的真实模型业务、普通客户端、恢复和安装制品。用例沿用 A01 至 A22 的编号，共 **247 条独立用例**和 **11 条端到端任务**。每条记录用户操作、通过判据和当前执行入口。会话运行中新增 Skill、MCP 以及两者联用进入第一批。实际执行范围按[客户端能力对照](../handbook/capabilities.md)、对应手册和待验制品确定。

用例中的 **现有**表示有对应真实模型驱动。**扩展**表示现有驱动还需要补前置、故障时点或断言。**实机**要求在指定普通客户端观察全过程。**候选**要求先核明制品、平台或显式装配资格。固定模型测试用于核接口和时序，也可用作驱动起点。它的结果独立记录。

## 运行中新增 Skill 与 MCP

本组在打开设置前先证明原 Session 有活动 Run，优先用可观察的真实工具时点保持活动。用于 J11 的 Skill 含独立随机资源标记，MCP 工具返回另一随机标记，业务端点使用私有计数。普通 Native 设置和会话都沿实际入口操作。

| 时点 | 用户操作 | 实际核对 |
| --- | --- | --- |
| 1 原轮仍活动 | 在原会话发送任务。看到流式输出或原工具实际启动后打开设置。另做原轮有待批交互的变体 | 记录原 Session、Command、Run 和已选来源。原卡、正文、草稿及阅读位置保持，真实模型流或后台工作按原时序执行 |
| 2 安装和配置 | 经设置安装新 Skill。新增自有 MCP，记录仅保存、适用认证、连接和目录可见各阶段 | Skill 条目可读取。MCP 配置完成、连接成功、目录披露和模型业务调用分别计证据。无模型调用权限时，自有业务端点计数仍为零 |
| 3 回到进行中的原轮 | 关闭设置，返回同一会话并观察原轮结算 | 原 Run 的 Skill 和 MCP 来源保持封存。设置不会重启原任务。原稿和旧结果按原顺序保留，旧副作用只出现一次 |
| 4 同一会话发新任务 | 保持 Session，明确提交要求使用新 Skill 与新 MCP 的任务。在独立变体不连接、拒绝或取消授权 | 产生准确的新 Run。真实 ModelInput 显示 Skill ID、版本、资源和新 MCP 定义的正确来源。获准样本实际端点调用一次且结果进入后继请求。未获准样本零业务派发 |
| 5 冷开并核对 | 正常关闭后重开，先查看原历史，再明确发送追问 | 历史和原回执可查。只读阶段零业务请求与副作用重放。明确新输入才产生新的模型决策 |

A16-10、A17-12 分别判定，J11 要求两条链路在同一 Session 串起来。新来源和新技能按新任务装配，原运行保留原定义。模式、信任或范围的现行限制仍按派发路径核对。现有来源在同一 Run 内的目录刷新属于 A17-05。 [Native 手册](../handbook/clients/desktop/README.md#配置编辑交互) · [Service 装配](../../apps/service/README.md) · [MCP 来源回归](../../apps/service/test/isolated/mcp-source-configuration.test.ts)

## 本地基线与手册口径

- **Skill Workflow** 已退役。扩展清单采用普通 Skill、CLI `--skill`、TUI `/skills` 的当前合同。旧 Workflow 只作为拒绝与历史只读用例。[扩展手册](../../docs/handbook/features/extensions.md#当前模型入口与目录范围)
- **Auto 审核** 明确超时或断连时最多重试两次。预算耗尽或其他审核技术失败结束原调用，零工具派发、无新增人工卡。另测模型明确要求人工确认的合法分支。Worktree 的准确工具与封闭内部 Job 使用当前免审核边界。[权限手册](../../docs/handbook/features/tools-and-approvals.md#权限模式) · [Worktree 驱动](../../tests/e2e/live/model/git-worktree.live.ts)
- **TUI 活动输入** 的公开指南和普通宿主配置需要分别记录。宿主配置为 `input.follow_up`，而输入指南把部分活动时点描述为 `input.steer`。A09 和 A21 分别取证实际原 Command、目标、后继模型请求和用户看到的行为。旧跨端脚本使用过 Ctrl+L，当前复跑按现行自动查回入口核对。[输入指南](../../docs/handbook/clients/tui/guides/input-and-queue.md) · [TUI 宿主](../../apps/cli/host/tui.tsx) · [当前 TUI owner](../../packages/ui/src/tui/README.md)
- **Native 验收入口** 使用普通窗口和当前实际能力。计划由模型自然发起，显式「先审核计划」与额外诊断入口只在指定测试制品单独取证。接入成功不能替代 Windows、Linux 或正式安装制品资格。[Native 手册](../../docs/handbook/clients/desktop/README.md) · [能力对照](../../docs/handbook/capabilities.md)

## 执行记录与判定

- **实测标识** 每个变体记录用例 ID、源码 SHA、OS 和 CPU、客户端或制品身份、Profile 类型、模型路由、协议、推理档位及权限模式。用受控合成输入和独立标记记录初始文件摘要、副作用目标和期望输出。
- **请求与效果** 开始、自然结束、失败和取消都需观察。用原 Command、Run、Execution、Interaction 和源引用对齐真实模型请求、工具回执、磁盘差异或端点计数、后继输入与最终回答。对断线和竞争只控制回执交付或合成环境，保留真实模型回复。历史读取与用户明确继续分别计请求与效果。
- **客户端过程** 以普通入口检查发送前、临时占位、流式正文、审批或问答、持久回执接管、切换和重开。在相关时点保留画面、终端帧或网络和持久记录。核因果顺序、重复、闪现、焦点、阅读位置、卡住及异常恢复。
- **结果标签** 使用「通过」「失败」「未命中」「阻塞」「不适用」。只看到 HTTP 200、原请求受理、某个子项或最终画面时写已取得的事实。实际分支未触发记未命中，已触发且违反判据记失败。清理或未知效果未核实则保留原状态。
- **产物** 输出到当轮独立目录。原报告、原请求顺序、必要去敏证据、实际效果和清理结果随结果保存。正常读、不适用入口与失败重跑分别计。修夹具后用新报告记录，原报告保留。
