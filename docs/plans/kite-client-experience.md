# kite 客户端界面与协作体验

状态：in_progress。整体交互设计已确认，左侧列表与右侧会话第一阶段已实施，其余界面继续按目标稿推进。已在用户提供的 shadcn 组件文件中完成交互细节修订；21 个业务状态统一放在交互原型页；原客户端页保留入口索引，组件页维护共享源和样例，原库页面保留。能力是否已经交付继续以源码、运行证据和[desktop owner](../../apps/kite-desktop/README.md)为准。

## 已确认需求

- 桌面客户端的产品名为 **kite**；**kite-code** 是 TUI 名称。仓库、workspace 包名和已有存储路径不因产品展示名称自动改名。
- 客户端覆盖代码开发以及研究、资料整理、文档和其他日常工作；默认页面与产出展示不能固定为代码工具。
- 使用 shadcn/ui 作为组件基础，接近原生桌面交互；以近白、中性灰和近黑组织层级，减少框线与状态色，只让必须处理的错误文字保留低饱和红色。
- 子代理需要在主消息中清楚展示，并能进入独立详情；大量任务下的浏览、定位和继续工作需要专门设计。
- 使用 Figma 的可编辑文字、自动布局和复用组件提高设计迭代的稳定性。
- 读取文件的路径文字本身作为链接，点击交给默认编辑器；不附加“打开文件预览”按钮。
- 会话的开始、发送和停止由 Composer 右侧唯一主控承担；不设置独立“开始执行”或进度行“暂停”。
- 普通用户和助手消息不重复显示身份；子 Agent 消息保留明确来源和接收方。
- 工具过程和审批生命周期沿用 TUI 已确认的基础语义，桌面端适配为可展开的轻量记录；完成的过程不以常驻操作卡阻断正文阅读。
- 暂不提供行内批注、批注草稿与保存批注功能；需要调整时在会话中说明。
- 客户端中，用户主动添加项目空间即表示授权使用该项目，不再追加首次信任确认。
- 子 Agent 使用与主 Agent 相同的消息样式，回传消息明确标注发送方、主 Agent 接收方及发送／接收状态。
- 资料与产出通过顶部按钮打开右侧吸顶副层，默认收起，不设置独立的“输入与产出”标签页。
- Agent 会话内容是用户注意力核心；侧栏、选中态和辅助入口保持低强调。会话选中只保留浅色底纹，不使用左侧竖线或强调边框；更多历史入口使用“展开更多”，位于所属空间的会话列表末尾。

## 组件视觉标准与验收

间距用途、排版与对齐、图标按钮状态、颜色和验收方式统一由[客户端设计规范](../../packages/kite-client-ui/docs/design-system.md)维护。保留当前 Figma 布局，图像生成的风格探索不替代此稿；计划不再复制另一份视觉数值表。

本轮规范收紧将发送／停止改为同位置、同尺寸的图标主控，更多与导航动作使用标准矢量图标；普通业务文字采用明确的字号／行高档位。共享组件与业务实例都须复查，不能只确认组件源修改成功。消息内容较长时由消息区滚动，不能把 Composer 挤出底部；文字列与容器随可用空间和内容布局。

迁移阶段已经验证中性灰、输入边界、长正文、命令换行和紧凑标题省略，正常可用文字最低对比度约 5.05:1，禁用控件单独检查。空草稿发送按原生 Disabled 状态处理，不能继续提交。已移除批注、首次信任和特殊子代理结果卡；工具覆盖补齐继续使用原有字体、颜色、按钮与消息，不新增另一套视觉样式。

当前共有 21 个业务状态。主会话和子代理详情均复查了副层关闭／打开两种渲染，审阅与执行原型复查了批注移除及子代理回传消息。统一原型页的 571 个实例均有源组件，127 处已配置导航均指向同页的有效业务画板；业务文字不再出现批注草稿、首次信任确认或“输入与产出”标签。上述证据来自结构、颜色值和渲染，不能据此宣称真实点击、原生吸顶滚动、键盘或完整 WCAG 验收通过。

产品级验收还必须在实现阶段检查：鼠标悬停与按下反馈、禁用语义、键盘焦点可见性和移动顺序、屏幕阅读器名称、文字放大及窄窗口重排。焦点必须有独立于选中／运行状态的清晰指示；隐藏或禁用控件不得继续提交操作。以上是实施验收要求，当前静态稿及结构检查不构成完整 WCAG 合规声明。

## 空间、会话与消息归属

空间是工作边界，拥有其中的会话、成员、文件范围和长期上下文。会话是空间内的一条连续任务线程，保存用户输入、主 Agent 回复、草稿和阅读位置。用户必须先选择空间，再选择其中的会话；标题栏用“空间 / 会话”持续显示当前位置。

主 Agent 回复是会话内的父级工作单元，承载工具过程、审批、回复和任务分派。由该回复触发的子 Agent 消息、状态和可审查产出仍归属该回复；消息使用与主 Agent 相同的组件、排版与正文样式，不增加分支线或独立结果卡。跨 Agent 消息通过“发送方 → 接收方”及已发送／已收到状态明确去向。普通用户与助手消息不为对称而增加身份标签；同一组子代理不同时铺开分派标题、总览、重复状态和逐条工具日志。进入子 Agent 详情时保留父会话面包屑和左栏中的父空间、父会话，返回后恢复原阅读位置；左栏不列同一任务的子 Agent 清单，其他子 Agent 仍从各自所属的消息或协作入口进入。

切换空间时保存原会话的草稿和阅读位置；子 Agent 不成为侧栏中的平级会话，也不脱离触发它的主 Agent 回复单独出现。

## 会话切换

侧栏只保留一棵“空间 → 所属会话”的列表。空间展开后，其会话紧接在该空间下方缩进排列，下一空间排在整组之后；不再把空间列表与“工作空间 · 会话”分组并列。“工作空间”是示例空间的名称，不是第二种空间类型。空间行以展开符号表达展开／收起，选中态只标识当前打开的会话，不同时高亮空间和会话。会话行默认只有名称，数量、状态和时间进入首次悬停 500 ms 后显示的详情浮层，最右侧圆点只表示自上次查看后出现了新状态；选中并查看后圆点消失。默认展示用户固定和最近主动访问的少量会话，后台消息不改变会话顺序；子 Agent 保持归属于触发它的主 Agent 回复，不额外挤入会话列表。完整历史的工作台入口仍按后续实施范围核实。

当前空间还有未展示的会话时，在该空间的会话列表末尾显示“展开更多”，原位展示更多会话；它不位于空间列表之外，也不跳转到全局会话页。没有更多内容时不显示该入口。会话选中底纹只用于轻量定位，原生实现仍须提供可访问的选中语义与清晰的键盘焦点；焦点反馈不做成常驻选中边框。

账户区固定在侧栏底部，距底边 16 px；上方列表使用弹性剩余空间，不能用固定高度留白撑出位置。头像、两行账户信息与更多菜单垂直居中，菜单符号保持单行。长会话列表在账户区上方滚动，账户入口不随列表内容多少上下漂移；这是目标稿约束，原生滚动与缩放仍须在实施时验证。

工作台按“需要我处理、正在推进、最近完成”组织，支持工作主题与时间条件筛选。需要用户回答或决策的事项进入“需要我处理”；等待另一个代理的材料不属于用户待办。工作主题由用户可理解、可调整的归属决定，不强制依赖自动语义分类。

2026-09-08 用户纠正：不需要会话标题搜索，点击会话直接加载消息，不设预览或“继续任务”二次确认。Web 与桌面共享此行为；方向键移动焦点，Enter 打开会话。切换时保留各会话草稿与阅读位置。此结论取代原预览式切换方案，Figma 旧画面中的搜索和预览确认不再作为实施依据。

列表有新状态时先原位更新反馈，保持当前选择与视口；跨组移动或重新排序在用户明确刷新或重新进入总览时应用，避免点击目标突然跳走。任务没有新进展时不制造提醒。固定项由用户管理，默认显示数量需用实际任务量验证。

验收用少量任务、约 50 项与约 200 项任务分别验证：找回几天前的工作、处理等待中的事项、点击加载消息、切换后恢复草稿与阅读位置。记录找回耗时、打开错误任务次数和键盘操作是否可完成，不能仅据分组外观判断改进有效。

## 子代理在消息与详情中的展示

正在推进的子代理使用紧凑状态入口；已完成且发回结果的子代理在主消息流中展示实际回传消息，不再同时保留同义的完成摘要行。正文采用共享 Conversation Message 组件，消息来源行可进入子代理详情。发送／接收状态来自实际交接事实，不能只因子代理执行完成就推断主 Agent 已收到消息。状态不能只依靠颜色，也不编造百分比。

子 Agent 页面是主 Agent 会话的下钻，复用同一会话页面结构和消息渲染规则，不是仅展示最终结果的详情卡。顶部通过“父会话 / 子任务”与返回入口表达层级；左栏沿用主会话的空间和会话列表，继续选中父会话，不切成子代理专属导航，也不把子任务列为平级会话。进入下钻不创建任务或停止父任务；返回恢复父会话的阅读位置、草稿与展开状态，子会话自己的阅读和展开状态按真实身份分别保留。

子会话正文依序展示来自主 Agent 的任务、阶段说明、探索与独立工具、普通助手回复和最终结果。正文、Markdown、工具展开、全部工具类型及状态、输出与错误规则完整复用[会话消息与工具渲染](#会话消息与工具渲染)，不能因为位于子页面就降为摘要文字、JSON 日志或另一套卡片。在自己的页面中，子 Agent 的回复使用普通 Assistant 消息；仅跨 Agent 的任务输入或回传需要来源信息。已发送／已收到仍须来自交接事实，正文不重复增加身份题头。

标题、独立滚动的消息区、活动交互与底部 Composer 沿用主会话的布局。可发送、停止或处理交互时，操作必须指向当前子会话的真实身份并由现有 child owner 提供；没有对应能力时按共享页面规则不提供操作，不能误发给父会话。Web 继续只读。资料与产出默认收起，通过顶部按钮打开右侧副层，内部只保留材料和文件入口；关闭副层保留阅读现场。子代理名称应能说明职责，重复职责还需用任务目标区分。

2026-09-11 按用户确认的下钻关系同步了[子会话默认页面](https://www.figma.com/design/qr0diiu1SH2prMVmhqMrJ0?node-id=4038-37)和[资料副层展开页面](https://www.figma.com/design/qr0diiu1SH2prMVmhqMrJ0?node-id=4085-213)：保留父会话侧栏、顶部返回、共享 Assistant／Tool Message／Composer，工具过程可展开，正文独立滚动。输入区是目标设计示例，不代表当前已接入独立子会话发送或停止能力。实施验收须核对下钻与返回、父子草稿和滚动隔离、消息归属、全部工具共用渲染，以及操作不误投父会话。

等待用户、等待依赖、执行中、完成、失败和取消分别展示。失败时说明已有结果和对父任务的影响；取消不等于撤销已经产生的文件或外部副作用。画面中的停止子代理、运行中补充要求等控制需要沿现有服务和 child owner 核实能力，不能仅在 UI 维护另一套执行状态或自动重试。

当前业务画面保留详情返回、协作摘要、完成、执行和等待依赖；失败与等待等复用变体继续由组件承载。等待用户、失败、取消和多个同类子代理仍是实施验收要求，不能把组件变体或已移出的状态说明当作完整业务流程验证。具体控制是否可用、并发交互如何排队及执行记录能否完整提供，仍须按 Runtime 与 child owner 的生产契约核实。

## 会话消息与工具渲染

2026-09-11 按“仔细检查 Agent 会话消息、涵盖所有工具消息”补齐设计。以下是共享桌面／Web 的目标呈现；Figma 已有可编辑样例，客户端尚未完整实现，不能用样例中的状态、文件、回答或计数证明真实执行。视觉数值由[设计规范](../../packages/kite-client-ui/docs/design-system.md#会话消息结构)维护。

### 默认阅读只保留有用的信息

2026-09-11 按用户“整体检查，避免过度的信息”收敛消息密度。会话正文承担意图、发现、需要决定的问题和最终结果；工具记录承担操作、对象与状态；展开详情提供核对所需的命令、差异、结果与来源。完整工具覆盖不等于完整铺开每次协议回执。

| 位置 | 默认呈现 | 按需核对 |
| --- | --- | --- |
| 读取与搜索 | 按已提供的探索分组显示紧凑过程，成功后收起 | 文件、范围、匹配和实际内容；空结果与截断仍可辨认 |
| 文件编辑／写入 | 操作、目标文件和一次终态；成功后收起 | 直接阅读 diff 或写入内容，不另加“已替换 1 处文本”“说明已写入”等同义成功段落 |
| Shell | 框外紧凑执行摘要，成功后默认收起；运行时提供近期输出入口 | 使用单层 Shell 容器核对命令和输出，展开时结果集中于底部；不再上下重复成功、完成及退出码 |
| 计划 | 当前计划、步骤与需要审阅的事实 | 只保留相关版本、正文和步骤结果；内部 plan_id、schema 版本与布尔回执不并排铺在正文下方 |
| 问题与审批 | 待处理问题、权限原因和有效操作保持可见 | 已回答记录保留问题与真实回答；已处理审批保留命令处置，移除活动按钮，不重复整套选项和审批说明 |
| MCP 与 Skill | 能力、来源和实际结果；无可读详情时不显示空展开入口 | 资源 URI、返回内容与必要限制；不重复展示已被可读结果覆盖的计数、activation_id、terminalStatus 或 JSON |
| 子 Agent | 来源、必要状态和有内容的回传；从所属消息下钻 | 子会话完整复用相同消息规则；主 Agent 不追加一段仅复述子 Agent 完成状态的 UI 文案 |

同一对象的同一状态在当前阅读区集中表达一次，不把“正在工作”或完成计数同时铺在标题、过程和输入区；导航列表仍可独立标识其他会话和父会话状态。运行、排队和等待属于不同对象时仍须区分，不能为减少文字把子任务状态当成整轮状态。计数和耗时仅在有真实来源且有助于理解范围时显示，不从几条可见消息补造计划进度。

失败原因、拒绝与未执行、停止中的收尾、取消后的已有修改、结果未知、部分输出以及需要用户处理的内容不能为了简洁而隐藏。折叠摘要必须保留重要异常；用户主动展开或上滚后，实时更新不替用户再次折叠或改变阅读位置。

展示精简不删除调用、输出或恢复证据，也不通过正则匹配“已完成”等词过滤模型正文、工具原文或子代理回传。UI 只基于可信字段避免重复生成回执、选择默认展开状态并分层呈现；不生成新的摘要事实。已知结构有可读映射时，内部诊断字段不占用普通阅读区，核对沿现有日志／执行详情入口；无法可靠解析的结果仍保留可读原文，不因“信息太多”丢弃。Web 仍只使用接口已经允许的数据。

本轮 Figma 已精简 19 项工具样例、主／子会话默认与副层展开状态，以及运行、审批、停止、恢复原型。工具目录中的展开画面用于核对内容结构，不代表业务页面默认展开全部工具。共享 Tool Message 的可选结果说明避免空白占位；不为每个成功回执增加独立消息组件。上述调整是目标设计，客户端仍需分别验证真实投影与阅读交互。

### 先决定消息归属，再渲染工具内容

一轮会话保留用户输入、必要的阶段说明、工具过程、明确来源的子 Agent 回传、最终回复，以及真实终态。工具完成与整轮完成分别表达，工具不能把前后不同阶段的正文合成一段，也不能在终态后留下第二条 loading 记录。

工具调用以既有 `toolId` 稳定更新。桌面应保留 [Runtime Client](../../packages/runtime-contract/src/notifications.ts) 已提供的 `presentation` 和 `presentationGroupId`，分别处理 `exploration`、`standalone`、`hidden`；分类的生产来源是 [model effect](../../apps/kite-service/src/bootstrap/runtime/model-effect.ts) 和 [event projector](../../apps/kite-service/src/runtime-client/event-projector.ts)。同一明确分组中的连续探索可以聚合，保留调用顺序和每项结果；不同分组、正文、独立操作、交互或子代理归属是分隔边界。缺失分组时不按时间接近或相同名称补造父关系。

`hidden` 不生成普通工具卡，但不能连带丢掉对应的子代理摘要或必须处理的交互。只读 `task` 的外层调用可能被服务标为 hidden；主消息展示子代理的真实来源、状态和回传正文，不再重复铺一份原始 `task` JSON。写入型委派若是 standalone，可保留可折叠的父工具；结果正文仍只呈现一次。发送／接收回执只有在对应事实存在时显示，不能由 completed 推断“已收到”。

“覆盖全部工具”是对所有输入都定义归属与结果结构，不是把所有调用强行画成顶层卡。下面的单条展开样例同样可用于探索组内部。Web 只消费 Public History 已允许的字段；没有明确身份、分类、参数或父关系时保留独立的安全摘要，不根据 label 推导，也不从底层 Store 补取隐藏字段。

### 完整工具覆盖

以内置契约的 [KNOWN_TOOL_NAMES](../../packages/builtin-runtime/src/tool-contracts.ts) 逐项核对，共 19 项；动态 MCP 和无法识别的工具另外兜底。下表规定可核对的信息与边界，不要求全部字段同时出现在默认消息中；按上节规则区分普通阅读、展开详情与诊断。字段只在真实结果提供时使用，不从计数、工具名字或示例补数据。

| 工具 | 折叠时的操作摘要 | 按需核对的内容与边界 |
| --- | --- | --- |
| `read_file` | 读取目标文件 | 完整路径、已取得的行范围、带行号内容和截断／继续标记；二进制或读取失败不显示空白成功 |
| `search_files` | 查找文件 | 实际模式、范围、返回路径和截断信息；0 个匹配是成功空结果 |
| `search_content` | 搜索内容 | 模式、范围、文件／行号／匹配片段；不把命中次数称为不同文件数 |
| `web_fetch` | 读取页面 | 安全来源 URL、实际 HTTP／提取状态、正文、链接及截断信息；网页正文按段落阅读，不默认启动浏览器或重试访问 |
| `edit_file` | 修改目标文件 | 实际目标、替换结果与本次 unified diff；失败或拒绝不显示“文件已修改” |
| `write_file` | 写入目标文件 | 本次写入内容／差异与保存结果；没有创建／覆盖事实时只写“已写入”，不把已有文件称为新建 |
| `shell_execute` | 执行命令或已提供的说明 | 完整可展示命令、分开的 stdout／stderr、真实退出码及超时／取消等原因；运行时保留有界输出尾部，成功后仍可复查输出 |
| `read_plan` | 读取计划 | 计划身份、版本、标题、正文、步骤及已提供的完成证据；读取不改变计划或步骤状态 |
| `write_plan` | 保存／提交计划 | 保存结果、计划身份与版本、实际审阅处置；“保存成功”不等于“已批准”，元数据结果不凭空补正文 |
| `update_plan` | 更新计划进度 | 当前计划身份、实际更新步骤与状态、是否完成及阻塞原因；更新成功不等于整份计划或整轮任务完成 |
| `ask_user` | 等待回答／已回答／已取消回答 | 当前交互中的问题、允许的选项与自由回答；回执保留真实回答或取消事实，不把取消回答当作停止会话 |
| `tool_search` | 查找能力 | 已返回的候选、来源、可用性与数量；发现不等于调用，更不等于授权 |
| `list_mcp_tools` | 查看服务工具 | 服务来源、工具与 schema 元信息、可用性、截断；连接成功不等于所有工具可执行 |
| `list_mcp_resources` | 查看服务资源 | 服务来源、资源名称／URI／MIME、返回数量和截断；只在源结果提供时展示后续页信息 |
| `read_mcp_resource` | 读取资源 | 服务与精确 URI、已返回的正文或部分结果封装；保留截断，不把资源 URI 当成本地文件路径 |
| `activate_skill` | 启用 Skill | 已披露的 Skill 身份、激活结果与可展示输出；启用不表示工作完成或增加权限 |
| `read_skill_reference` | 读取 Skill 参考 | 当前激活身份、已声明参考路径、编码与内容；参考路径不是默认编辑器的任意工作区路径 |
| `complete_skill` | 完成 Skill | 当前激活的完成回执、受校验的输出及仍需验证的事实；不自动把会话改为完成 |
| `task` | 委派具体子任务 | 已提供的名称／角色、父工具归属、真实步骤与结果、终态、工具次数和耗时；只读 hidden 外层不重复显示，缺失数值不填 0 |
| 动态 MCP | 安全的服务／操作标签 | 仅使用 App 已允许的 displayLabel、脱敏参数与结果。文本、结构化结果、资源链接保持来源；不支持的媒体显示 MIME／可用说明，不自动请求远程内容或把它当作无输出 |
| 未识别工具 | 已提供的安全名称，缺失时为“工具执行” | 同样保留生命周期、参数与原始文本。格式无法识别时使用可读的通用详情，不丢消息，不从任意 JSON 推导成功或文件变更 |

同时核对 [RuntimeToolDisplayName](../../packages/runtime-contract/src/notifications.ts) 的全部 20 个展示类别：15 个与当前内置名称相同，另有 `mcp_tool`、`other` 与协议保留的 `glob`、`skill`、`request_plan_review`。后三者收到时使用安全的通用记录或已存在的交互事实，不据它们新增可调用工具。当前 `read_plan`、`activate_skill`、`read_skill_reference`、`complete_skill` 经 projector 会归入 `other`，仅有脱敏标签；若实施专用内容投影，应沿现有闭合词表和协议补齐身份，不能把自由标签当成 schema 判别器。

### 状态、输出和交互

| 事实 | 用户可见结果 |
| --- | --- |
| 排队 | 排队中；未开始执行，不显示运行耗时、输出或退出码 |
| 等待授权／回答／计划审阅 | 标明真实等待原因；当前可用决策位于 Composer 上方，草稿保留 |
| 运行 | 运行中，展示已取得的近期进度；没有输出不推断卡住或失败 |
| 已提交停止 | 正在停止／等待收尾；原输出保留，未收到终态前不标已取消 |
| 成功 | 已完成；无文本输出可明确说明“无输出”，搜索空结果使用“未找到匹配” |
| 执行失败 | 显示失败及已取得的原因、部分结果；仅 Shell 显示其真实退出码 |
| 执行前拒绝 | 已拒绝、未执行及可展示原因；不显示运行输出、退出码或文件成功标记 |
| 取消终态 | 已取消／已停止；是否开始执行与是否有已有修改分别依据事实表达 |
| 结果未知 | 结果尚未确认，并说明需要核对实际结果；不合并为普通失败，不提供无条件重跑 |
| 部分／截断结果 | 保留实际工具终态，同时附“部分内容／输出已截断”；截断本身不是失败 |

源结果已截断与用户把完整内容折叠是两回事。“展开”只改变阅读状态，不能暗中重新执行工具或获取不存在的全文。stdout／stderr、格式化结果和必要参数可分层展开，但不能用单个 JSON 框代替所有工具的结果语义。长行在输出区横向滚动，普通正文与路径换行；流式更新不改变主动上滚或折叠的意图。终态覆盖同一身份的活动态，迟到进度不重新打开记录。

审批、问题和计划是同一调用关联的活动交互，不是工具已完成的证明。等待、提交中、提交失败、已处理四种状态都保留原上下文；提交失败保留原问题／审批和用户输入，不能只关闭面板。问题按服务给出的当前问题及交互顺序呈现，不在 UI 拼出另一套多问题执行队列。计划正文缺失／截断时禁用批准，仍允许已提供的反馈或取消。批准后的执行结果由工具记录表达；只读 Web 不出现可提交控件。

## 人机交互与执行证据

工具审批显示本次命令、具体外部效果和为什么此刻需要授权，提供“仅批准这一次”与“拒绝本次”。用户已经要求执行某项工作，不应仅因它会写入外部系统就重复审批；只有实际命令权限或其他明确规则要求时才出现，并说明原因。提交中阻止重复点击；批准不等于执行成功，执行回执由服务确认。批准、拒绝、停止均在原上下文展示真实结果，不跳回旧消息或另一个任务。

审批操作区只在等待决策及提交期间显示，处理结束后退出。命令记录留在消息流的对应执行位置，使用弱化文字显示命令和结果；不把“已批准／已拒绝”大卡片常驻在输入框上方。批准后先表示执行中，取得服务回执后才显示成功、失败及适用的退出码；拒绝与开始前停止明确显示“未执行”。原型的批准路径直接展示收到成功回执后的示例终态，省略运行时等待，不代表批准立即完成命令。

连续读取、搜索等只读探索按阶段聚合，过程位于该阶段回复之前。进行中仅显示近期步骤，完成后默认收成一行摘要，用户展开后查看目标路径；输出文件与读取过的输入材料分开。独立命令显示操作、目标和真实状态，必要输出与失败信息可复查。依据是 [TUI 工具与子代理](../handbook/clients/tui/guides/tools-and-subagents.md)、[审批与问题](../handbook/clients/tui/guides/approvals-and-questions.md)及 [ToolSummaryBlock](../../apps/kite-cli/src/tui/components/ToolSummaryBlock.tsx) 的完成后摘要语义；桌面端沿用语义，采用适合鼠标与键盘的展开控件，不复制终端字符树和终端布局。

Composer 持续保留。空闲时，有可发送内容才启用发送；运行中右侧显示停止；等待审批时可以保留补充草稿，审批按钮处理局部命令，停止终止当前执行。点击停止不伪造成用户消息，不撤销既有文件或外部效果；进入“已停止”前必须取得服务终态。连接中断时保留草稿与历史，不能使用旧 ready 状态提交。

新会话入口借鉴用户提供的 Codex 截图：阅读区以一句“今天想在这个空间完成什么？”和四个轻量建议呈现开始方式，保留大面积留白，不展示任务统计或历史消息。建议覆盖研究资料、整理内容、创作交付与解决问题；选择建议只填入可编辑草稿，不自动发送。底部继续复用同一 Composer，上方依次放置可切换的工作区、环境信息和可切换的 Git 分支，三项收在贴合输入框上沿的统一浅底上下文栏，左右比输入框各缩进 16 px，以文件夹、电脑和分支图标区分；工作区与分支默认透明，不显示下拉箭头或独立选中灰块，按钮随名称自适应宽度。三项垂直居中，文字统一为 14 px／20 px 行高，项间距 12 px、图文间距 8 px，菜单始终与对应按钮左边缘对齐；悬停或菜单打开时的轻底纹反馈须在客户端实施时验证，避免重复顶栏标题。空草稿发送保持禁用；开始首轮后欢迎区让位于正常消息流。当前 Figma 已完成入口视觉与工作区／分支选择的变量绑定及菜单动作；菜单内容是设计示例，建议填入草稿及发送后的切换仍是实施验收要求。

新会话切换工作区或分支时保留草稿，不自动发送或启动任务。工作区变化后刷新该工作区的分支列表，并显示实际当前分支，不能沿用上一工作区的分支；非 Git 工作区不显示分支选择。分支切换以宿主成功回执为准，失败时保留原选择与草稿，并展示具体原因；已有改动阻止切换时不自动丢弃改动或强制 checkout。这些是客户端目标行为，当前原型只演示选择值更新；工作区示例切换回 main 不代表所有项目默认使用 main。

补充问题和计划审阅放在输入区上方；保留选择、自由回答、取消、计划正文缺失／截断等既有交互边界。它们的实际可提交状态需沿当前 Interaction 与 Runtime 契约实现，不用静态稿新增提交权威。代码审阅暂不提供行内批注、批注草稿或保存功能；需要 Agent 修改时，由用户在会话输入区发送要求。“暂存此文件”和“还原此文件…”明确作用范围，还原前说明受影响文件及不可撤销的内容。

执行详情把模型、工具、Shell、退出码、测试和验证放在同一条可核验时间线；只有 Shell 事件显示退出码，其他事件以破折号表示不适用。停止中、清理中和部分结果分别表达；运行进入已取消终态后，只在消息流显示一行轻量结果，必要时说明已有文件或外部副作用不会自动撤销，不再占用独立大卡片。本轮是已确认的目标交互；当前桌面端的控制呈现与本文有差异，仍以桌面手册和 owner 中的现状说明为准。统一执行详情与这些呈现调整属于后续实现，不能以画板中的本地列表取代服务终态。

## Workspace、设置与恢复

资料副层只承担材料与产出索引，默认关闭；主会话用“查看产出”，子代理详情用“资料与产出”按钮控制。副层贴近标题栏下方并固定在右侧，关闭后焦点回到原按钮；窄窗口改为可关闭的覆盖面板并保证输入可达。打开实际文件内容时再进入对应文件阅读工作区，不把资料索引做成永久占位的标签页。吸顶、独立滚动、焦点返回和窄窗口行为仍须在原生客户端验证。

右侧 Workspace 统一规划 File、Document、Browser、Terminal 与 Review，并以连续边框和会话内容区分隔；它只在用户检查产出或证据时承载辅助内容，不取代 Agent 会话的主导位置。其中 Browser 继续作为未接入能力展示。File 只展示桌面端已经记录的成功文件工具修改；工作区当前变化、Git diff 和任务归属仍待实现，必须避免把用户原有修改归给 Agent。读取文件消息中的各路径文字分别是默认编辑器入口；实际打开的是对应项目中的文件，不把多个文件共用一个预览按钮。产出行打开同名内容；默认编辑器的选择与启动沿现有 editor owner，Figma 中的文字链接样式不代表操作系统启动已验证。差异、验证、文件定位、路径复制和外部打开保留明确操作。二进制、大文件和无法预览只在实际发生时显示对应提示；来源不完整属于归属信息，不等于预览失败。

设置页区分本地偏好、服务配置与 Secret owner。Provider 与模型沿现有 App Control；MCP 状态、连接详情、开始／取消认证、重新连接及 Skills 目录已沿既有 App Control 接入。没有对应接口的 Skill 安装和专用模型诊断不提供入口；配置管理的进一步操作按 TUI 与真实接口核实后再接入。设置页不单列权限或 Workspace 范围。本地服务连接管理完全由内部负责，内容页不展示重连、断开或服务未就绪提示；异常接入沿单一退避循环自动恢复，保留内容与草稿。恢复后同步实际运行状态，连接恢复不等于任务完成或停止，也不能抹去未确认操作。长历史、加载失败、空历史、上下文连续性及应用生命周期仍按各自 owner 展示。重连不自动重发 mutation，旧 ready 状态不能提交命令。

客户端用户主动选择目录、拖入目录或添加项目空间，即表示授权使用该项目；选择完成后直接进入，不追加“首次信任／授权确认”页面，也不要求再次确认正常连接。实现时由现有项目与信任 owner 承接这一明确用户动作，不在展示层维护另一套授权状态。主动添加／选择项目即授权已接入现有 Service 信任 owner，不再重复确认工作区；关联外部目录仍单独确认。保守的项目切换确认尚保留，与取消正常连接确认的目标仍有差异。缺失配置仍提供相应设置入口；更换项目涉及正在执行的任务时，应说明对旧任务的实际影响，不把项目加入本身再次包装成授权请求。
