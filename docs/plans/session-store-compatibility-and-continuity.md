# 会话存储连续性：剩余资格与数据恢复边界

状态：已约定的默认入口、已验证格式转换、历史来源归并与原会话续聊已实施。Linux 产品迁移入口与 Windows 原生维护／发布资格仍待验证；真实用户数据恢复与未来版本兼容分别判断。

当前实现以 [App Server 契约](../active/app-server-local-runtime.md)、[SQLite owner](../../packages/runtime-storage-sqlite/README.md)和[启动入口 owner](../../packages/kite-local-runtime/README.md)为准。本页保留尚未完成的资格、不可放宽的验收条件与历史证据边界，不作为另一份当前实现说明。

## 产品要求与不变量

Desktop、TUI、CLI、daemon 与 Web 在同一 OS 用户、同一 canonical config root 下使用唯一正式会话库 `<canonical-config-root>/kite-session.sqlite`。source/installed 的程序位置不能隐式选择另一份数据。显式选择另一数据根必须明确呈现；测试可以使用隔离数据根。启动发现已知历史来源、未结算发布意图或不兼容格式时，不能生成空库来显示成功的空历史。备份和迁移候选是私有恢复资产，不参与正常读写。

对声明支持的版本变化，经过验证的无损路径应自动保留原 Session ID、已提交 State/Event、History 顺序、Workspace/Fork、Run/receipt、删除事实与 Artifact 引用。原会话可发现、可打开，符合当前授权与执行条件时可向同一 ID 追加新一轮。历史可读不等于未完成旧 Run 可以自动续跑；外部结果未知时不能重新派发或伪造回执。Workspace 路径和授权变化不得改变身份或自动扩大执行权。未发送草稿和未落盘流式内容不属于 Store 保留承诺。

schema、epoch、事件语义与客户端协议分别判断。只支持经源 fixture、精确结构检查和目标 reader 验证过的组合；未知格式、损坏、来源冲突和无法确认旧 writer 已退出时保留原件并给出可操作诊断。安全拒绝证明没有破坏数据，不能当作兼容成功。程序回滚不自动回滚数据库，也不能用旧备份覆盖其后新增记录。任意未参与维护协议的旧安装器或手动启动的旧二进制不获得追溯的混跑资格。

## 当前已验证范围

默认 App Server 当前物理格式为 Store14。Store9/10、准确旧 epoch 的 Store11、Store12 及 Store13 仅按各自已实现的精确子集在启动准备阶段转换；不能凭较小 schema 数字推定可迁移。普通历史读取与状态查询不触发转换。准备器在独占维护期重新核实来源和旧 writer，使用一致性备份、私有候选、完整保留校验与可恢复发布意图；生产 reader 复核成功后才开放正常连接。相同身份的来源事实只在可证明等价时合并，分叉和未知语义拒绝。发布中断按已持久化意图和文件指纹接续，不盲目重导或覆盖新内容。

已验证的 macOS source CLI/TUI、配对 Desktop 和 installed CLI/TUI 入口可处理已知来源；source daemon 的短暂 stdio 准备路径也有隔离验证。转换、维护锁、启动诊断和原 ID 续聊有对应 owner 与测试证据。Store9 的旧 authority 映射、Store11 的 Run 输入／准备失败计数约束等仅支持已证明的子集；非空旧 Effect 或其他未证明事实拒绝。执行权失效进入 `recovery_required`，不伪造成功、cleanup 或 waiver。

2026-09-17 的隔离四来源全链演练及当时本机收敛记录证明：185 个原 Session ID、33,593 个底层 Event、217 个 Run、563 个 receipt、175 个 named snapshot 保留；140 个 Session 仍要求恢复，未重派旧任务。正式 Service 列表与逐一打开确认当时的 185 个 ID，客户端投影共 15,912 个展示事件。这些数字是当时的快照证据，不代表后续用户库状态，也不证明任意未来格式。原始阶段记录可由 Git 历史追溯。

另一个隔离副本曾验证旧会话执行权修正：原 299 条历史事件哈希不变，旧 Run 保持完成，新回复写回原 sessionId；这不是对用户原 Store 的写入，也不证明外部 Provider 联网。真实客户端、Store 转换及发布中断的验证入口分别见 [Desktop 原生验收](../../apps/kite-desktop/docs/native-validation.md)、[SQLite owner](../../packages/runtime-storage-sqlite/README.md)与[本机启动 owner](../../packages/kite-local-runtime/README.md)。

验收对每个声明支持的组合核对：新用户只有一份正式库；旧源不会变成空首页；原 ID、内容、因果与关联守恒；同 ID 续聊；坏记录和分页失败可见；备份、空间不足、取消、并发、发布崩溃和提交结果未知时无静默丢失；不兼容降级后再升级仍保留降级期间之前的新增内容。真实旧制品或准确源 fixture 才能证明跨版本语义，只修改 `meta.schema_version` 的合成库只能测试拒绝分类。客户端须用相应真实入口验证，Store 单元测试不能推定整条发行路径。

## 历史用户数据恢复

2026-09-25 曾短暂提出以空库作未发布首发入口，随后用户明确要求旧会话保留原身份和历史回放；空库方向已撤回，不再是当前要求。

在该阶段，含 **226 个会话**的用户当前 Store10 曾被错误清理并初始化为空 Store11。已停止对该用户库的恢复性写入。现有内置旧备份只能核实 **185 个更早会话**；不得据此宣称 226 个会话已恢复，也不能以合成兼容测试代替真实数据恢复。任何近期备份的可用性、缺失的 41 个会话与恢复时点均须单独核验；未确认前不得覆盖当前最新数据。此问题与未来版本转换是否正确分开报告。

如果需要从时间点恢复，必须先保留当前最新副本，核对备份身份、完整性、关联资产和恢复后会失去的新增记录，再经用户选择执行；不能因旧数据文件存在就称已恢复。历史兼容仍要求正常 Service 启动后保留原 Session ID、State/Event 和 Runtime History 回放，顶层目录只列根 Session，内部子线程不挤占分页。
