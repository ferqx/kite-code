# TUI 中英文国际化实施方案

状态：active

优先级：P1

依赖：现有 TUI Overlay contract、CJK display-width 换行规则、workspace 信任门禁。

## 目标

为 Kite Code 的 TUI 提供中文（`zh-CN`）与英文（`en-US`）界面，并使用户可以持久选择语言。方案只改变本地交互界面的展示文案，不改变 Runtime、模型请求、工具协议、会话事实或安全决策。

中文界面应使用自然中文，并保留能帮助开发者识别、复制和检索的英文技术标识；英文界面应使用自然英文，不能把中文句子逐词替换为英文。

## 范围

### 必须国际化

- 首次配置、配置错误、Windows sandbox 设置和 workspace 信任界面；
- Overlay 的标题、按钮、快捷键说明、空态、加载态、错误恢复说明与副作用提示；
- 帮助面板、slash command 描述、`/resume` 会话恢复、模型、权限、主题、回退和问答界面；
- 运行状态栏、工具卡片和汇总卡片的本地状态词、压缩进度、本地成功/失败提示；
- MCP 页面中由 Kite Code 自己提供的标题、字段名、状态、操作和说明；
- 数字、时间与日期的显示格式；
- 用户级配置语言与 `/language` 命令描述。

### 不国际化

- 用户输入、模型回复、思考内容、远端 MCP 返回的名称/description/输出、shell 输出和文件内容；
- 工具名、MCP fully-qualified name、模型名、Provider 名、路径、URL、环境变量、配置键与原生错误正文；
- slash command 的机器可读名称和参数：`/model`、`/mcp`、`/compact`、`/language` 保持不变；
- Runtime event、持久化 session、Core error code 与协议枚举。

本地化的错误提示可翻译外层说明，但其安全可展示的原始诊断参数必须原样附带。例如中文显示“导出失败：`<错误>`”，英文显示“Export failed: `<error>`”。不能尝试翻译未知异常或外部服务返回的正文。

## 术语与文案原则

中文界面使用以下稳定术语；首次出现时可带英文，紧凑状态行和重复界面只使用短名。

| 概念 | 中文界面 | 说明 |
| --- | --- | --- |
| workspace | 工作区 | 路径保持原样。 |
| provider | 模型服务商（Provider） | 首次配置说明中写全，后续可简称“服务商”。 |
| model | 模型 | 模型实际名称不翻译。 |
| sandbox | 沙箱（Sandbox） | 安全说明首次写全。 |
| MCP server | MCP 服务器 | 保留 `MCP`。 |
| Plan mode | 计划模式（Plan mode） | 模式切换和帮助页写全。 |
| `accept_edits` | 接受编辑（Accept edits） | 必须保留配置/运行时对应的稳定英文名。 |
| `auto` | 自动审批（Auto） | 同上。 |
| `full` | 完全权限（Full access） | 同上。 |
| Shell / Git / HTTP / STDIO / API key / Base URL | 保留英文 | 可在完整说明中补充中文解释。 |

`Enter`、`Esc`、`Tab`、箭头和 `Ctrl+C` 等按键名保留英文，以匹配真实键帽和终端约定。状态词（如 `Working`、`Queued`、`Cancelled`、`Awaiting approval`）必须本地化。

## 架构设计

### Locale 配置和启动顺序

在用户级配置中新增：

```jsonc
{
  "language": "system" // "system" | "zh-CN" | "en-US"
}
```

- `language: "zh-CN"` 或 `"en-US"` 的用户配置优先级最高；`"system"` 或缺省时才根据设备 locale 选择语言。
- 默认值是 `system`。从 `Intl.DateTimeFormat().resolvedOptions().locale` 取得设备 locale，并通过 `Intl.Locale` 读取其语言：语言严格为 `zh` 时解析为 `zh-CN`；所有其他语言均解析为 `en-US`；locale 无法解析或运行时不支持 `Intl.Locale` 时同样回退 `en-US`。
- 因此 `zh-CN`、`zh-TW`、`zh-HK`、`zh-Hans` 等中文系统语言都显示中文；`en-CN`、`ja-JP`、`en-US` 等非中文系统语言显示英文。地区不参与语言选择。
- 新增的 `loadUserLanguage()` 与 `saveUserLanguage()` 只读写用户配置，绝不让 `.kite-code/kite-code.jsonc` 的项目配置覆盖个人界面语言。
- `TuiBootstrap` 在 workspace 信任门禁之前只读取用户级 locale 偏好和宿主 locale；它不得读取项目配置、扫描 Skill、连接 MCP 或初始化会话。
- 宿主环境语言只影响文案选择，绝不影响 workspace 信任、授权、sandbox 或其他安全判定；未信任工作区的 `.env` 即使影响进程环境，也不能绕过任何门禁。
- `/language` 不带参数时打开语言选择器；选择后立即重渲染当前 chrome 并写入用户配置。命令本身不增加中文 alias，保证文档、补全和脚本入口稳定。

### 目录和类型

新增 `src/app/tui/i18n/`，以 TypeScript catalog 而不是运行时 JSON loader 实现：

```text
src/app/tui/i18n/
  types.ts       Locale、消息参数、catalog 类型与稳定 message key
  en-US.ts       基准 catalog
  zh-CN.ts       完整中文 catalog，编译期满足基准 key
  resolve.ts     用户偏好和宿主 locale 到已解析 locale 的映射
  context.tsx    I18nProvider、useI18n、数字/日期/时长 formatter
```

`zh-CN.ts satisfies typeof enUS`（或等价的显式 catalog 类型）必须使缺失 key、多余 key 和参数不一致在 typecheck 中失败。不要先引入通用 ICU 运行时依赖；当前两种语言和有限插值需求使用类型化 template 函数即可。出现复数或第三种语言需求时，再以保持 key/调用点稳定的方式评估 ICU。

### 展示层边界

- React 组件通过 `useI18n()` 取文案；纯展示函数接收已解析的 `t`/formatter 或返回稳定 message key，不读取全局 locale。
- `src/core/` 不导入 `src/app/tui/i18n`，不存储翻译后的文字，也不从文字反推状态。Core 继续提供 code、状态、参数和安全边界；App 映射为可见文案。
- `run-status.ts`、`render-utils.ts`、工具与子 Agent 卡片中的自有状态改为返回 message key 和参数，而不是英文字符串。`StatusBar` 和 React 卡片在渲染时翻译。
- 为 App 自己生成的可见通知新增结构化 `LOCAL_MESSAGE` action 和对应的非持久化显示 block（`key + values + isError`）；保留 `LOCAL_TEXT` 给本来就不可翻译的外部/动态文本。这样切换语言后仍在屏幕上的本地通知可重新翻译，且不会把 UI 文案写入 Runtime event 或历史 session。
- 语言切换必须把已解析 locale 作为 `useStaticContent` 的 presentation identity：它触发与 resize/session 重挂载相同的同步输出重建，并让 `OutputArea` 的 `staticKey` 失效。不能让 Ink append-only `<Static>` 保留切换前的状态词、工具动作或 `LOCAL_MESSAGE`，也不能通过追加第二份历史输出实现切换。
- 不重写已有用户、模型和外部工具内容。会话恢复时，历史内容按原文显示；当前 chrome、Kite Code 自有的结构化状态与本地通知按当前语言重新渲染。

### 格式化与宽度

- 使用 `Intl.NumberFormat(locale)`、`Intl.DateTimeFormat(locale)` 和 locale-aware duration formatter，替换裸 `toLocaleString()` 与英文 `s/m` 拼接。
- `SessionInfo.updatedAt` 不能继续在 `src/core/persistence/sessions.ts` 预格式化为字符串：Core/App 边界改为传递原始时间戳，`SessionSelector` 和 `CheckpointSelector` 在 TUI 层按 locale 格式化。Core 可保留机器可读时间 helper 或迁移兼容适配，但不得持有中英文 UI 格式。
- 所有截断、换行和列宽继续基于 `string-width` 与既有 `soft-wrap`；不能按 JavaScript `length` 或翻译后字符数估算终端列宽。
- 翻译内容避免把按键、路径、命令与可变值嵌入不能安全截断的长句。Overlay 的标题、meta、secondary row 和 shortcut bar 继续遵守现有显示宽度 contract。

## 风险与处置

| 风险 | 处置 |
| --- | --- |
| 翻译遗漏导致混合语言 | catalog 类型完整性测试；新增用户可见 key 必须经 lint/测试清单审查。 |
| 翻译文字进入 Core 或持久化协议 | 只在 `src/app/tui/i18n` 和 App 展示层建依赖；对 Runtime event/session 进行回归测试。 |
| 语言切换破坏 Overlay 高度或窄终端布局 | 为中英文分别增加 Ink 宽度渲染测试，并运行既有 CJK wrap 与 PTY 场景。 |
| Ink `<Static>` 在切换后冻结旧语言，或重建时重复输出 | locale 纳入 `staticKey` 与同步重建边界；增加切换后单份输出、无旧状态词残留的回归。 |
| 误翻译技术标识，降低命令可发现性 | 采用本方案术语表；命令、工具、配置与外部内容全部保持原样。 |
| 早期 locale 读取改变未信任工作区的启动边界 | 只读用户偏好；测试断言项目 locale/.env 不会改变 trust 前的资源访问或授权结果。 |
| 同一视觉状态在多处自行翻译而漂移 | 状态推导输出 key，catalog 作为唯一词汇源；不要在各卡片复制状态字符串。 |

## 回滚

- `language` 是可选用户偏好；移除/忽略它时回退为 `system`（设备语言为中文时显示中文，其他或未知情况显示英文），不影响 Provider、模型、MCP、授权或 session 数据。
- 若某个本地化 surface 出现布局或回归，先回退该 surface 到基准 catalog 的 `en-US` 文案，不回滚 Runtime 协议或迁移历史会话。
- `LOCAL_MESSAGE` 与 `LOCAL_TEXT` 在过渡期并存；必要时可停止产生结构化消息而继续渲染旧的 `LOCAL_TEXT`，不会导致持久化数据无法读取。

## 实施任务

### TUI-I18N-01：建立可审计的文案与术语边界

1. 为 `src/app/tui/**` 建立用户可见文案 inventory，按“自有界面、结构化状态、外部/原文”分类；将本方案的术语表作为 review checklist。
2. 定义 `Locale`、`ResolvedLocale`、message key、参数与 catalog 类型；以 `en-US` 为完整 key 基准，中文 catalog 编译期对齐。
3. 新增 catalog 完整性与不翻译边界测试：工具名、命令、模型名、MCP 名称与外部输出不能经 catalog 改写。

### TUI-I18N-02：接入用户偏好和语言切换

1. 扩展 `src/core/config/index.ts` 的 schema 和用户级写入 helper，但不得使 Core 依赖任何 TUI 类型或翻译资源。
2. 实现只读用户配置的 locale resolver：显式 `zh-CN`/`en-US` 优先；否则 locale 语言为 `zh` 时使用中文，其他或未知情况使用英文。在 `TuiBootstrap` 信任门禁前创建 Provider，并验证项目配置不参与结果。
3. 增加 `SHOW_LANGUAGE_SELECTOR`/`HIDE_LANGUAGE_SELECTOR`、`/language` parser 与说明，复用 `PreferenceSelector` 和 Overlay contract；会话恢复命令仍为 `/resume`，不得重新引入 `/sessions`。
4. 切换后立即更新 Provider 与 chrome；把 locale 纳入 `useStaticContent` 的重建 identity，确保 Static/Dynamic 块原子重绘，并对写入失败显示本地化、可恢复提示。

### TUI-I18N-03：迁移安全、首启和通用 chrome

1. 迁移 `WorkspaceTrustGate`、`ErrorBoundary`、first-run flow 和 Windows sandbox setup；安全选项的默认焦点、操作与错误恢复语义不得变化。
2. 迁移 Overlay primitives、Help、Input、slash suggestion、模型/权限/主题/会话/回退界面。
3. 将静态 command descriptions 改为 description key，保持 parser 仍只匹配稳定英文 command name。

### TUI-I18N-04：迁移状态和结构化本地通知

1. 将 run status、tool action、subagent 生命周期、compaction phase 和已知本地提示改为 key + 参数；由 render 层翻译。
2. 让 `LOCAL_MESSAGE` 只承载 catalog 已定义的 App 自有消息；未知异常、模型/工具文本继续走 `LOCAL_TEXT`。结构化消息必须参与 locale 触发的 Static/Dynamic 重建。
3. 用统一 formatter 迁移 token 数、文件数、时长、session/checkpoint 时间与导出时间；把 session 列表的时间从 Core 预格式化字符串迁移为原始时间戳后在 TUI 渲染。

### TUI-I18N-05：完成 MCP 与剩余复杂视图

1. 迁移 MCP 自有字段和操作，确认不会本地化 server/tool/command/endpoint 或远端描述。
2. 迁移工具卡片、汇总卡片、子 Agent 和输入问答中的本地文本；`ask_user` 的推荐后缀必须由 catalog 提供，且兼容历史标签中已有的中文后缀；用户问题/选项、答案与工具 summary 保持原文。
3. 逐项清理 `src/app/tui` 用户可见硬编码文案；允许技术标识和测试 fixture 保留英文。

### TUI-I18N-06：双语言质量门禁和当前规则收敛

1. 为 `zh-CN` 与 `en-US` 分别覆盖：信任门禁、首启、语言选择、slash 建议、`/resume`、权限、MCP、状态栏、工具状态、`ask_user` 推荐标记和日期/数字格式。测试 fixture 必须显式设置 `language`，不得依赖 CI/开发机的地区。

## 验收标准

- 用户可在“跟随设备语言”、`zh-CN`、`en-US` 之间选择；跟随设备语言时系统语言为中文则使用中文，其他或未知情况使用英文；项目配置不能覆盖该个人选择。
