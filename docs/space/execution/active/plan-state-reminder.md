## Rule

`graph.state.plan` must be projected as a trailing synthetic user-side runtime
state reminder.

Required message order:

```text
SystemMessage(static agent contract)
SystemMessage(cacheable runtime context)
...compacted conversation messages
HumanMessage(synthetic graph.state.plan reminder)
```

The plan reminder must:

- be generated from current `graph.state.plan`;
- appear after compacted conversation messages;
- use a `HumanMessage`, not a `SystemMessage`;
- include a marker like `<runtime-state source="graph.state.plan">`;
- explicitly say it is generated by the harness, not by the user;
- stay out of static system prompt and cacheable runtime context.

## Do Not

- Do not move plan state back into the static system prompt.
- Do not put plan state into `buildCacheableRuntimeContext`.
- Do not rely on `update_plan` ToolMessage history as the current plan.
- Do not use tail `SystemMessage` for this dynamic state unless a provider adapter
  proves it preserves semantics and cache behavior.

## Test Expectations

`tests/context.test.ts` should assert that plan state is the final synthetic
`HumanMessage`.

`tests/runtime-context.test.ts` should assert that runtime context contains mode
and tool policy but excludes plan details and context summaries.
