# ADR-0039：流式 Markdown 结构块按稳定子组件更新

**Status**: accepted
**Date**: 2026-07-26
**Decision makers**: @chenchao

## Context

ADR-0037 和 ADR-0038 稳定了 Markdown 文档、块级组件和普通段落，但表格、代码块、列表与引用在新增尾行时仍会重新执行整个结构块的渲染。长表格或长代码块因此仍可能出现不必要的计算和终端重排。

## Decision

1. 表格保持单一父级 `Text`，避免 Yoga 在边框行间产生空隙；表头、边框和每个数据行作为 memoized 子组件。
2. 表格数据行使用行序号保持追加过程中的稳定身份。新增行且列宽未变时复用已有行；新单元格扩大列宽时允许所有行重新布局。
3. 围栏代码块的每个代码行使用稳定序号和 memoized `CodeRow`；追加代码行不重新渲染已有行。
4. 连续列表项组成一个 list 块，每个列表项是 memoized 子行；连续引用行组成一个 quote 块，每个引用行同样独立 memoize。
5. 结构块的外层身份仍使用 Markdown 源起始行，并遵守 ADR-0037 的断线分段规则。

## Consequences

- 表格、代码块、列表和引用新增尾行时只创建或更新变化的子行。
- 表格列宽改变属于整体布局约束变化，所有表格行重排是必要行为。
- 表格仍输出为一个连续文本布局，边框不会因组件拆分出现缝隙。

## Verification

布局测试覆盖表格、代码、列表与引用的尾行增长，以及新增宽单元格触发表格整体列宽重排。全量测试和流式 PTY 场景继续验证最终输出与消息顺序。
