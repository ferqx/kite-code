# ADR-0033: 模型流重连后新开文本段

**Status**: accepted
**Date**: 2026-07-26
**Decision makers**: @chenchao

## Context

ADR-0032 选择在模型流重连后继续更新或替换原有展示。对于已经输出较长内容的回答，原位替换会删除用户已经阅读的文本并造成明显布局跳动。服务端通常没有真正的 token 续传能力，重连本质上是重新生成，因此把两次生成伪装成同一条连续流也不够透明。

## Decision

1. `model.retry` 到达时冻结断线前的流式文本并结束当前文本段；已展示内容永久保留。
2. 重连后的文本总是进入新的流式文本段，不修改旧段。
3. 如果新请求重放断线前的完整前缀，模型边界抑制重放内容，只把追平后的新增后缀发送到新段。
4. 如果新请求与旧文本分歧，新生成内容完整显示在新段中。旧段仍保留，用户可以明确看到断线前后两份输出。
5. partial tool call 的规则不变：失败尝试不创建工具状态，只有成功流的完整终态工具调用进入 Runtime。

该决定取代 ADR-0032 中“恢复后继续更新同一展示”和“分歧时原位替换”的展示条款；ADR-0032 的完整流重试与工具终态提交条款继续有效。

## Consequences

- 长回复不会因重连而消失或大幅重排。
- 同前缀恢复不会重复展示整段旧回答，但续写会清晰地从新段开始。
- 分歧生成会同时保留旧段和新段，可能增加纵向空间；这是对生成事实透明性的有意取舍。
- retry 状态仍通过状态栏展示，恢复 delta 或最终响应后清除。

## Verification

- 模型边界测试验证同前缀重放只发出新增后缀，分歧重生成完整发出新段内容。
- reducer 测试验证 retry 冻结旧 block，恢复 delta 使用新的 block id；多行分歧时旧行和新行同时保留。
- PTY 场景验证断线前文本与恢复后文本同时可见，partial tool call 不出现。
