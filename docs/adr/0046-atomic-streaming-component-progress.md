# ADR-0046：结构组件闭合外壳后按内部段渐进渲染

状态：accepted
日期：2026-07-29
关联：ADR-0039、ADR-0040、ADR-0045、`docs/active/thought-pre-consolidation.md`

## 背景

ADR-0045 通过完整组件提交消除了 Markdown 半成品的类型提升和结构抖动，但大型围栏代码或表格可能长时间没有顶层提交边界。静默等待终态看起来像流已卡住；额外的文字进度提示又不能让用户阅读已经生成完成的内容。

项目的 Markdown 渲染器已经支持稳定子行与增量解析，因此可以把“组件是否已识别”和“组件内部是否全部完成”分成两个生命周期。

## 决策

1. 普通段落继续按完整段落提交，列表继续按完整 item 提交。
2. 围栏代码在完整起始围栏到达后立即建立带完整上下边框的代码组件；表格在完整表头和分隔行到达后立即建立表格组件。
3. 活动结构组件只接收已经换行完成的内部行，当前未完成行保留在隐藏 source 中。
4. 活动组件是 Dynamic 树中的唯一可变回答块；此前完成的组件仍立即进入 Static。
5. 围栏代码的关闭围栏到达时立即冻结整个组件。表格在下一个顶层边界或模型终态到达时冻结。
6. 终态文本仍是权威全文；隐藏 source 用于终态去重和断线恢复，不持久化为新的 Runtime 事件。
7. 不显示独立的 `Generating response…` 文字进度提示。

## 备选方案

- 整个大型组件静默等待终态：拒绝，用户无法阅读已完成内容，也无法确认流是否推进。
- 显示行数进度但隐藏正文：拒绝，信息价值低于直接展示稳定的完整内部行。
- 逐 token 更新当前行：拒绝，会重新引入行宽变化、换行重排和表格列宽持续抖动。
- 把每一行渲染成独立 Markdown 组件：拒绝，会破坏代码框、表格和复制语义。

## 后果

- 大型代码块和表格在结构识别后立即可见，并按完整内部行增长。
- 当前组件保留在 Dynamic，因此其完整高度始终可渲染；不存在底部裁剪视口。
- 组件冻结后整体进入 Static，后续组件的增长不会改写它。

## 回滚

删除 `streamingComponent` / `streamingSource` 路径，恢复 ADR-0045 的完整组件静默缓冲；Runtime 与持久化 schema 无需迁移。
