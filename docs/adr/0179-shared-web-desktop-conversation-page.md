# ADR-0179：Web 与桌面共用会话页面

**Status**: accepted

**Date**: 2026-09-08

**Decision makers**: @chenchao

## Context

桌面两栏界面已开始通过 HTML 预览迭代，Web 仍维护独立侧栏与消息渲染。用户确认两端必须共用同一份页面代码，只按各端权限提供不同操作。直接引用桌面 App 会把 Tauri 与 Native Client 带入 Browser，并违反当前只读 REST 边界。

## Decision

由 `packages/kite-client-ui` 唯一维护会话主页面、目录、消息阅读、输入组件、Markdown 与样式。Web 与桌面入口均消费该页面，只负责真实数据投影、协议／路由／宿主接入以及已授权操作。通过存在的回调表达可用操作，不再叠加权限布尔表或在页面内判断平台。

Browser 保持既有只读 principal，桌面保留当前任务与原生操作；服务端授权仍是最终边界。诊断与宿主辅助面板沿已有 owner 接入页面的具名位置，页面只负责布局。HTML 预览直接使用生产 React 组件，测试数据不进入生产路由。

## Alternatives

- 两端各自维护相似页面：不能满足同一份代码的要求，视觉和交互容易分叉。
- Web 直接导入桌面 App：泄漏 Native 依赖，耦合连接、信任与本地文件能力。
- 同时统一传输协议或开放 Browser mutation：超出本次页面复用范围，且需要独立权限与服务契约设计。
- 建立平台插件框架或第二套页面状态仓库：目前两个明确消费者用展示数据与回调即可表达。

## Consequences

共享界面变更需要同时验证两端，Web preflight 与原生浏览器默认样式的差异必须在共享 CSS 中处理。共享展示类型不会扩大 Public API 返回字段；原有数据语义差异仍由各自投影 owner 记录和修复。当前职责与验证入口见[共享包](../../packages/kite-client-ui/README.md)，产品能力见各端手册。

## Rollback

若共享页面引入回归，按受影响变更回退共同组件并复验两个入口；不通过复制一份端侧主页面形成长期分叉。协议、凭据与持久数据格式未因本决策改变。
