# ADR-0038：流式 Markdown 普通文本按段落组件渲染

**Status**: accepted
**Date**: 2026-07-26
**Decision makers**: @chenchao

## Context

ADR-0037 将一次连接的累计 Markdown 保持为单一文档，并为内部块建立稳定身份，但普通文本仍以每行一个组件分组。模型生成自然段时可能连续输出多行软换行；行级组件既不表达 Markdown 的段落语义，也会让同一自然段的更新分散到多个相邻组件。

## Decision

1. 连续的普通文本行组成一个 `paragraph` 组件，以首行源位置作为稳定身份。
2. 空行封闭当前段落；标题、水平线、列表项、引用、围栏代码和表格同样构成段落边界。
3. 正在生成的段落只更新自身内容签名。后续出现空行并开始新段时，已完成段落保持原组件身份和内容。
4. 列表、引用、标题等结构暂时保持各自现有组件粒度，不并入普通段落。
5. 表格头从普通管道文本提升为表格时继续复用同一源起始位置。

本决定取代 ADR-0037 中普通文本使用单行块级组件的粒度；ADR-0037 的单一 streaming 文档、稳定源位置身份和组件 memo 规则继续有效。

## Consequences

- 流式长回答按照自然段局部更新，前面已经封口的段落不再参与后续渲染。
- 段落内部的显式输入行仍保持原显示换行，避免改变既有 TUI 输出格式。
- 尚未出现段落边界时，当前整个自然段会随累计 delta 更新，这是预期的最小变化范围。

## Verification

布局测试覆盖连续普通行聚合、空行封口、列表和表格结构边界，以及流式内容尾部增长时前序内容持续可见。Reducer 继续保证每次连接只有一个累计 Markdown 文档。
