# 第一章 项目全景

## 1.1 定位

Kite Code 是一个开源、多模型、跨平台的终端代码 Agent。它以自有事件化 Runtime Kernel 为执行核心，通过 AI SDK 对接模型，并提供可审计、可恢复、受策略约束的编程协作体验。

## 1.2 核心能力

| 领域 | 当前能力 |
| --- | --- |
| 交互 | React Ink TUI、Headless CLI、结构化事件流、斜杠命令、文件搜索 |
| Agent | 原生 Runtime loop、Plan Artifact、上下文压缩、模型重试与错误分类 |
| 能力 | Builtin Tool、MCP、Skill Workflow、Subagent、渐进式能力披露 |
| 治理 | interaction mode、审批、auto review、sandbox、副作用分类 |
| 可信完成 | Execution Receipt、Artifact、分级 Verification、repair/replan |
| 持久化 | SQLite event store、snapshot、会话恢复、fork、session log |

## 1.3 技术栈

| 层面 | 技术选型 |
| --- | --- |
| 运行时与语言 | Bun、TypeScript ESM |
| 模型调用 | AI SDK、`@ai-sdk/openai-compatible` |
| TUI | React 19、Ink 7 |
| MCP | `@modelcontextprotocol/sdk` |
| 数据与校验 | `bun:sqlite`、Zod、AJV、YAML、JSONC |
| Web 内容 | Readability、JSDOM、Turndown |

## 1.4 架构原则

1. **Runtime 权威**：State 只通过 Runtime Event 改变。
2. **Provider 无关**：模型与 MCP provider 通过边界适配，不进入 Kernel 决策。
3. **发现不等于授权**：Capability catalog、binding、policy 是不同阶段。
4. **先记录再副作用**：外部写入先持久化 invocation intent。
5. **证据决定完成**：高风险任务由 Verification 而非模型声明验收。
6. **前后端分离**：protocol/core/app 保持单向依赖，core 不含 TUI 展示逻辑。
7. **跨平台**：Windows 与 Unix 行为均属于实现边界。

## 1.5 代码地图

```text
src/protocol/   跨层契约
src/core/       Runtime、能力、策略、执行与验证
src/app/        CLI/TUI 输入输出适配
tests/          Runtime、策略、能力、TUI 与 golden 验证
docs/active/    当前行为和架构不变量
```
