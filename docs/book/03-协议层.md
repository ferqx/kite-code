# 第三章 协议层：跨层契约

`@kite/runtime-contract` 与私有 `@kite/runtime-spi` 定义跨 package 使用的中立、JSON-safe 数据。
Contract 不依赖其他 Runtime package；SPI 只依赖 Contract。`apps/kite` 组合这些契约，Kernel、Host、Storage
与 Builtin 各自只实现自己的 authority，不再存在 `src/protocol`、`src/core` 或 `src/app` 兼容层。

## 3.1 协议模块

| Owner | 职责 |
| --- | --- |
| `runtime-contract` | Client command/query/subscription、notification、projection 与 capability 中立 DTO |
| `runtime-spi/capabilities.ts` | Descriptor、Snapshot、Binding、Invocation、Receipt 与私有 registry contract |
| `runtime-spi/authority-threat-model.ts` | RAV1 authority sequence、可信域、真实 serialization/process boundary、attacker 与 key-custody 分类；不签发 grant |
| `runtime-spi/model-surface.ts` | Model Surface、Invocation Envelope、Response Record、canonical message/tool/route 与 opaque 私有 artifact reference |
| `runtime-spi/tool-pipeline.ts` | neutral resolve/validate/classify/prepared/recorded/terminal Tool Pipeline DTO 与 callback ports |
| `runtime-spi/verification.ts` | Verification mode、spec、check、reviewer 与结果 |
| `runtime-spi/subagent*.ts` | Subagent 角色、delegation/resume grant、lifecycle handle 与 typed observation/failure |
| `runtime-spi/git.ts` | Brokered Git 只读操作、能力证据、调用回执与失败码 |
| `runtime-spi/workspace-filesystem-provider.ts` | filesystem operation、purpose-bound grant、target/preimage identity、observation/result 与 Provider interface |
| `runtime-spi/sandbox-execution-provider.ts` | Sandbox preparation、exact command/cleanup grant、backend evidence、data-first prepared plan 与 Provider interface |

Contract/SPI 不拥有 Provider implementation，也不把 Runtime state machine 变成 transport DTO：

- `RuntimeEvent` 是 `agent-kernel` 的可持久 State 25 事实；
- `RuntimeAction`/`RuntimeUserAction` 与 `RuntimeActionProvider` 是 App 对 Kernel/Host 的组合 seam；
- Provider implementation 分别位于 `builtin-runtime`、`runtime-host`、`runtime-storage-sqlite` 或 App platform port。

CLI 和 TUI 直接消费这套唯一 Runtime API。TUI 的 `TuiAction`、interrupt payload 和 reducer action
属于 App 私有展示协议，只在 App 边缘转换为 Runtime action。

## 3.2 Model Surface 证据契约

`ModelSurfaceV1` 是模型调用前冻结的 provider-neutral 语义请求，不是 AI SDK `ModelMessage` 的持久化
别名。它封闭保存合并后的 system、canonical messages/tools、generation/stop/transport/SDK retry、
resolved capability value/digest、provider options 以及不含 credential/endpoint 的 route identity。

`ModelInvocationEnvelopeV1` 单独保存 invocation/thread/turn、Runtime revision、admission、reservation 和
attempt/time budget，因此这些运行 identity 不进入 `surfaceDigest`。`PrivateArtifactRefV1` 只暴露 opaque
locator、keyed integrity identifier、kind 和 byte length，不暴露原始 content digest 或相对路径。

MS-01–MS-04 已把该契约接入 production：五类调用都先编译并冻结唯一 Surface，再经
`ModelInvocationGatewayV1` 写入 Surface Artifact、执行 Provider/resource admission、逐 attempt ack、调用
单 attempt Source，并在 Response Artifact 与 completion receipt ack 后才释放可消费 response。旧
`invokeBoundModel()` 已删除；静态边界检查只允许 Gateway-owned live Source 导入 transport，并禁止其他
transport、AI SDK 或 LanguageModel low-level bypass。

`ModelAttemptOutcomeV1` 的 `success | retryable_failure | fatal_failure | aborted` 只描述一次已经发生的
Provider attempt；重试、backoff、预算和下一 attempt ack 仍只属于 Gateway。production 只构造 live Source。
2026-08-22 已按直接裁决删除旧 evaluation、ModelReplay catalog、record/replay response source、suite actor/context
与相关 CI；产品 State 25 restore/Event replay 和 Model Artifact readback 继续保留，不能由 evaluator 术语替代。

`CapabilityArtifactRef` 在 State 25 与当前 epoch 只允许 private format v2 ref。Tool receipt 产生
`PrivateCapabilityArtifactRefV1`，包含 keyed opaque `artifactId`、kind、keyed integrity identifier 与 byte
length；legacy format v1/path reader 已删除。Tool Pipeline
用 `capability.invocation_recorded/execution_started/execution_result_recorded/execution_succeeded/
execution_failed/execution_unknown` 保存调用 certainty 与 opaque evidence，不把 result 正文或存储路径写进
Runtime 协议。

PS-01 的 `WorkspaceFilesystemProviderV1` 是 Protocol-first、JSON-safe seam。operation 封闭为五个
filesystem 工具及 `workspace_only | external_read | approved_external` path scope；`external_read` 是免审的
observe-only scope，`approved_external` 只表示已批准的 Workspace 外 mutation。grant 分为 observe、prepare mutation、
commit mutation 三种 purpose，并绑定 invocation/capability/effect/Workspace/protected-path/approval/TTL。
prepare observation 包含 no-follow/followed target identity 和完整 preimage，commit grant 再精确绑定其
identity/preimage digest；Provider 不能扩权。Runtime capability record 只保存 mutation-ready 的 opaque
preimage ref/digest identity，以及成功 terminal 的 digest-only observation stamp，不保存 path、正文或 grant。
这些 facts 已由 CUT-01 纳入 State 25/`kite-runtime-2026-08-18` 唯一生产格式。

PS-02 的 `SandboxExecutionProviderV1` 只拥有 confinement preparation 和受 grant 约束的 allocation disposal，
不拥有 Policy、approval、Runtime State/Event 或 process spawn。`SandboxPreparationV1` 绑定 Tool
invocation/attempt、capability revision、canonical Workspace、effective effects/admission、exact argv/command
digest、execution/protected-path boundary、network/filesystem mode、resource limits、timeout 与 cancellation；
`SandboxPreparationGrantV1` 和每一种 `SandboxCleanupGrantV1` 都是 purpose-bound、short-lived、single-use
sealed grant。allocating prepare 还必须精确绑定 durable preparation intent digest。

Provider 只返回 immutable `PreparedSandboxExecutionV1`：approved argv、实际 confinement argv、cwd/env/stdin、
backend/capability/enforcement evidence、resource semantics、expiry 和 exact cleanup handle。Pipeline 将完整 plan
写入 keyed private Artifact 并 durable ack ready；Runtime 随后 durable ack dispatch identity，才允许唯一 consumer
单次启动进程。POSIX consumer 用继承的 owner-only `flock` 把 spawn 前 dispatch 与 supervisor 生命周期连接，
再用 Linux boot/start-ticks 或 Darwin `proc_pidinfo` 微秒 start identity 绑定 PID/PGID/executable；Windows consumer
消费独立 preparation 模块生成的 protocol V6 request。restore 只有在 plan/ready evidence、process identity、
process-group/Job cleanup 与 inherited lock 全部收敛后才允许 disposal。Fake 没有 Local fallback，production
没有旧 direct executor 或裸 Shell fallback。这些字段已由 CUT-01 纳入 State 25 与当前 epoch。

PS-03 的 `SubagentProviderV1` 只拥有 child lifecycle、cancel 和 observation transport，不拥有
Model Gateway、Tool Pipeline、approval、Runtime event、receipt 或 verification。Pipeline 在父 Tool attempt 的
durable acknowledgement 之后签发 single-use delegation/resume grant，精确绑定父 invocation/attempt、
capability/effect/admission、Workspace、resource ceiling、cancel correlation、child identity 与 current model context；
`BuiltinChildRuntimeDriverV1` 只消费该 grant 下的 single-use registration callback；child 模型只经唯一
Gateway，child tool 只经完整 Tool Pipeline，Driver 自身不取得这两类 authority。

normal task、approval resume 与 Skill fork 已切到唯一生产 `LocalSubagentProviderV1`，Fake 只是无
Local fallback 的拒绝/崩溃测试 seam。Task request、最终 task、continuation 与 full Provider handle 都进入
各自 private immutable namespace，Protocol ref 只含 opaque keyed identity/integrity/byte length；Runtime v25
以 low-information lifecycle 事实执行 two-phase handle-ready、startup reconcile 与 pending fork gate。
App/Host/Kernel 以 `model.invocation_prepared/attempt_started/completed/interrupted/evidence_unavailable` 保存
opaque evidence ref 与 dispatch certainty，不保存正文。restore/fork 严格验证 completed evidence；缺失、
损坏或 key unavailable 会保留已确认 transcript，但不能把 Artifact 当成重新调用模型的 authority，pending
调用也不会自动重发。这些字段是 State 25 与当前 epoch 的必需 Model evidence；旧 evaluator 已不存在。

## 3.3 Runtime 事件边界

RuntimeEvent 不能被 UI 直接修改。可恢复事件先由 reducer 归纳为 RuntimeState，再由 App 投影为
block、状态栏和交互界面；瞬态 `model.*_delta` 与 `tool.progress` 只用于当前进程展示，不进入 event
store 或 snapshot。

工具终态使用 Runtime-owned canonical `ToolOutcomeV1`。App 只消费结构化 status、failure、dispatch/
effect certainty、recovery 和 timing，不从 stdout、stderr、路径或用户文案反推执行事实。当前事件缺少
合法 envelope 时 fail closed，不存在 historical decoder。

## 3.4 Capability 与 Verification

RAV1-01 的 Project identity 是 Host-issued 的 opaque binding：协议只携带 project identity/revision 与 canonical workspace digest，不携带可由 Client 任意选择的 projectId。Session、ExecutionEnvironment、Provider、Credential、Artifact 使用独立 identity schema，避免无关配置变化导致全局 composition 失效。

RAV1-02 的 Grant/Receipt envelope 与 child frame 分别使用持久化和进程外 domain；issuer、key id、nonce、expiry、sequence 与 payload digest 都必须在 verifier 中精确匹配，验证失败不得进入 Kernel fact。

RAV1-03 的 DataOrigin 记录 observation、owner 与 parent lineage；Context Compiler 只能选择 payload，Egress authority 仍由 Kernel 决定。Model 与 MCP 是不同 destination，CredentialHandle 是 purpose-bound opaque 引用。

Capability 的稳定身份是 `capabilityId + revision`，模型可见名称只存在于 turn-scoped binding。
`CapabilityDescriptor` 区分审计描述与模型描述，并记录描述来源；Catalog、Binding、invocation receipt
和 Artifact 都只保存 Provider-neutral 数据。

`ToolApprovalPayload` 只承载 Runtime 计算出的命令、风险、effects 与授权选项。模型不能通过参数声明
intent、grant 或 prefix rule。`VerificationSpecV1` 描述检查和结果，不在 Protocol 层执行命令、读文件
或调用 MCP。

## 3.5 Plan 与 Subagent 数据

当前 Runtime 只创建 PlanDocument V2。其持久 identity 是
`planId + version + structuralDigest`；Completion evidence 只保存 verification、terminal tool、skipped
step 和 unresolved reference，不保存 prompt、命令、路径或 stdout。

Subagent continuation 可以携带 Builtin/App 私有 recovery journal，但公开 `task` Tool Result 不暴露 identity
key、fingerprint、lineage、execution journal 或 continuation。挂起审批的原始路由必须持久化，恢复时
不得降低授权边界。

## 3.6 预发布格式策略

当前 Runtime snapshot 必须同时匹配源码声明的 schema version 与 format epoch。不匹配的数据不读取、
不迁移、不重放、不改写；既有数据库和 Artifact 文件也不主动删除。正式发布前若格式再次改变，更新
epoch 并直接删除被替代路径，不积累在线 migration 链。

RAV1 的真实性只部署在真实持久化、序列化或进程外边界。同进程 Kernel/Host/Builtin typed object 继续依靠严格
schema、identity equality、single-use、expiry/revoke，不重复包 HMAC；Runtime Store、私有 Artifact、sandbox/MCP
子进程、远端 Model/MCP 与 OS credential broker 的处置见
[`runtime-authority-boundary.md`](../active/runtime-authority-boundary.md)。
