# 第三章 协议层：跨层契约

`src/protocol/` 定义 App 与 Core 确实需要共享的中立、JSON-safe 数据，不依赖 `src/core/` 或
`src/app/`。物理依赖方向是 `app → core → protocol`；Runtime 的状态机和调用接口不因为有多个 App
消费者而整体进入 Protocol。

## 3.1 协议模块

| 文件 | 职责 |
| --- | --- |
| `events.ts` | Plan、审批、用户输入、交互模式等跨层 DTO |
| `capabilities.ts` | Descriptor、Snapshot、Binding、Invocation、Receipt、Artifact 与 CapabilityResult |
| `verification.ts` | Verification mode、spec、check、reviewer 与结果 |
| `subagent.ts` | Subagent 角色和公开生命周期载荷 |
| `git.ts` | Brokered Git 只读操作、能力证据、调用回执与失败码 |
| `model-surface.ts` | Model Surface、Invocation Envelope、Response Record、canonical message/tool/route 与 opaque 私有 artifact reference |

Protocol 不定义 Runtime event、action 或 provider implementation。当前 Runtime 协议位于 Core：

- `RuntimeEvent` 是 Kernel 的可持久事实；
- `RuntimeAction`/`RuntimeUserAction` 是当前 action 输入；
- `RuntimeActionProvider` 是 Core 与 CLI/TUI 的交互端口。

CLI 和 TUI 直接消费这套唯一 Runtime API。TUI 的 `TuiAction`、interrupt payload 和 reducer action
属于 App 私有展示协议，只在 App 边缘转换为 Runtime action。

## 3.2 Model Surface 证据契约

`ModelSurfaceV1` 是模型调用前冻结的 provider-neutral 语义请求，不是 AI SDK `ModelMessage` 的持久化
别名。它封闭保存合并后的 system、canonical messages/tools、generation/stop/transport/SDK retry、
resolved capability value/digest、provider options 以及不含 credential/endpoint 的 route identity。

`ModelInvocationEnvelopeV1` 单独保存 invocation/thread/turn、Runtime revision、admission、reservation 和
attempt/time budget，因此这些运行 identity 不进入 `surfaceDigest`。`PrivateArtifactRefV1` 只暴露 opaque
locator、keyed integrity identifier、kind 和 byte length，不暴露原始 content digest 或相对路径。

MS-01–MS-04 已把该契约接入 production：五类调用都先编译并冻结唯一 Surface，再经
`ModelInvocationGatewayV1` 写入 Surface Artifact、执行 Provider/resource admission、逐 attempt ack、调用
single-attempt transport，并在 Response Artifact 与 completion receipt ack 后才释放可消费 response。旧
`invokeBoundModel()` 已删除；静态边界检查禁止 transport、AI SDK 或 LanguageModel low-level bypass。

`CapabilityArtifactRef` 在当前 epoch 是 private format v2 ref 与 legacy format v1 ref 的封闭读取 union；新
Tool receipt 只产生 `PrivateCapabilityArtifactRefV1`，包含 keyed opaque `artifactId`、kind、keyed integrity
identifier 与 byte length。legacy ref 只供现有 Artifact 读取，不能成为新 dispatch receipt。Tool Pipeline
用 `capability.invocation_recorded/execution_started/execution_result_recorded/execution_succeeded/
execution_failed/execution_unknown` 保存调用 certainty 与 opaque evidence，不把 result 正文或存储路径写进
Runtime 协议。

Core Runtime 以 `model.invocation_prepared/attempt_started/completed/interrupted/evidence_unavailable` 保存
opaque evidence ref 与 dispatch certainty，不保存正文。restore/fork 严格验证 completed evidence；缺失、
损坏或 key unavailable 会保留已确认 transcript 但禁止 strict replay，pending 调用不会自动重发。这是
Runtime schema v24 同一 format epoch 内的加法字段；只有 CUT-01 可切换 epoch。当前尚无
`ModelAttemptOutcomeV1` catalog/record/replay source，Artifact 存在不代表历史请求可 replay。

## 3.3 Runtime 事件边界

RuntimeEvent 不能被 UI 直接修改。可恢复事件先由 reducer 归纳为 RuntimeState，再由 App 投影为
block、状态栏和交互界面；瞬态 `model.*_delta` 与 `tool.progress` 只用于当前进程展示，不进入 event
store 或 snapshot。

工具终态使用 Runtime-owned canonical `ToolOutcomeV1`。App 只消费结构化 status、failure、dispatch/
effect certainty、recovery 和 timing，不从 stdout、stderr、路径或用户文案反推执行事实。当前事件缺少
合法 envelope 时 fail closed，不存在 historical decoder。

## 3.4 Capability 与 Verification

Capability 的稳定身份是 `capabilityId + revision`，模型可见名称只存在于 turn-scoped binding。
`CapabilityDescriptor` 区分审计描述与模型描述，并记录描述来源；Catalog、Binding、invocation receipt
和 Artifact 都只保存 Provider-neutral 数据。

`ToolApprovalPayload` 只承载 Runtime 计算出的命令、风险、effects 与授权选项。模型不能通过参数声明
intent、grant 或 prefix rule。`VerificationSpecV1` 描述检查和结果，不在 Protocol 层执行命令、读文件
或调用 MCP。

## 3.5 Plan 与 Subagent 数据

当前 Runtime 只创建 PlanDocument V2。其持久 identity 是
`planId + version + structuralDigest`；Completion evidence 只保存 verification、terminal tool、skipped
step 和 unresolved reference，不保存 prompt、命令、路径或 stdout。

Subagent continuation 可以携带 Core 私有 recovery journal，但公开 `task` Tool Result 不暴露 identity
key、fingerprint、lineage、execution journal 或 continuation。挂起审批的原始路由必须持久化，恢复时
不得降低授权边界。

## 3.6 预发布格式策略

当前 Runtime snapshot 必须同时匹配源码声明的 schema version 与 format epoch。不匹配的数据不读取、
不迁移、不重放、不改写；既有数据库和 Artifact 文件也不主动删除。正式发布前若格式再次改变，更新
epoch 并直接删除被替代路径，不积累在线 migration 链。
