# 第三章 协议层：事件与动作

协议层是三层架构的枢纽——它零依赖，定义了 Core 与 App 之间的全部通信契约。

## 3.1 AgentEvent：Core → UI 的事件流

`AgentEvent` 是一个 23 种子类型的 discriminated union，按功能域分为 7 组：

### 3.1.1 步骤边界事件

```typescript
| { type: "step_begin"; data: { node: string } }
| { type: "step_end";   data: { node: string } }
```

每个 LangGraph 节点（agent / tools / approval / user_input）执行前后各 emit 一次。TUI 用它驱动 phase 指示器和 Footer 状态行。

### 3.1.2 模型产出事件

```typescript
| { type: "reason"; data: { text: string } }   // 模型推理过程（thinking）
| { type: "text";   data: { text: string } }   // 模型最终回复
```

`reason` 对应模型的 `reasoning_content` 字段，TUI 中渲染为可折叠的 Thinking 块。`text` 是面向用户的回复内容。

### 3.1.3 工具调用与执行事件

```typescript
| { type: "tool_call"; data: ToolCallPayload }   // 模型请求调用工具
| { type: "tool_done"; data: ToolResultPayload }  // 工具执行完成
```

`ToolCallPayload` 包含 `call_id`、`name`、`args`。`ToolResultPayload` 包含 `ok`（成功/失败）和 `summary`（人类可读摘要）。

### 3.1.4 人机交互中断事件

```typescript
| { type: "need_approval"; data: ToolApprovalPayload }  // 工具需要审批
| { type: "need_input";   data: UserInputPayload }      // Agent 需要用户输入
```

这是 interrupt 机制的核心。当 Agent 遇到需要人工决策的场景时，runner 暂停，等待用户通过 `UserInputProvider.requestAction()` 返回动作。

### 3.1.5 状态变更事件

```typescript
| { type: "state_change"; data: StateChangePayload }
| { type: "file_change";  data: { path: string; kind: "add"|"edit"|"delete"; linesAdded?; linesRemoved?; preview? } }
```

`state_change` 携带工作区访问模式（read-only/write）、阶段（planning/building）、计划状态、授权模式等。`file_change` 记录文件增删改操作。

### 3.1.6 上下文管理事件

```typescript
| { type: "compact_begin"; data: { reason: string } }
| { type: "compact_end";   data: { summary: string } }
| { type: "cache_metrics"; data: CacheMetricsPayload }
```

上下文压缩触发时 emit `compact_begin`/`compact_end`，TUI 显示 `⏳ Compacting...`。`cache_metrics` 携带 prompt cache 命中率指标。

### 3.1.7 异常与生命周期事件

```typescript
| { type: "error";       data: { message: string; recoverable: boolean } }
| { type: "model_retry"; data: { attempt: number; error: string; delayMs: number } }
| { type: "final";       data: string }
```

`recoverable: true` 表示网络超时/速率限制，可自动重试；`false` 表示配置/权限错误，需用户介入。

### 3.1.8 子 Agent 事件

```typescript
| { type: "subagent_start";        data: SubAgentStartPayload }
| { type: "subagent_step";         data: SubAgentStepPayload }
| { type: "subagent_tool_result";  data: SubAgentToolResultPayload }
| { type: "subagent_done";         data: SubAgentDonePayload }
| { type: "subagent_error";        data: SubAgentErrorPayload }
```

子 Agent 生命周期的完整事件链，TUI 用它渲染 SubAgentBlock 的运行/完成/错误三态。

### 3.1.9 透传事件

```typescript
| { type: "interrupt"; data: unknown }  // LangGraph 原始 interrupt
| { type: "update";    data: unknown }  // LangGraph 原始 state update
```

低级透传，供 checkpoint/state tracking 消费者使用。

## 3.2 UserAction：UI → Core 的动作

```typescript
type UserAction =
  | { type: "approve";     grant: ShellGrantUsed }     // 批准工具执行
  | { type: "reject" }                                  // 拒绝工具执行
  | { type: "input";       text: string }               // 用户自由文本输入
  | { type: "cancel" }                                  // 取消当前 interrupt
  | { type: "switch_auth"; mode: AuthorizationMode }    // 切换授权模式
```

## 3.3 InterruptPayload：中断的两种形态

```typescript
type InterruptPayload =
  | { kind: "approval"; approval: ToolApprovalPayload }  // 工具审批
  | { kind: "input";    question: UserInputPayload }     // 用户输入
```

## 3.4 UserInputProvider 接口

```typescript
interface UserInputProvider {
  onEvent(event: AgentEvent): void;                        // Core 推送事件
  requestAction(payload: InterruptPayload): Promise<UserAction>;  // 请求用户动作
  setup?(): Promise<void>;                                 // 可选生命周期
  teardown?(): Promise<void>;
}
```

TUI 和 CLI 各自实现此接口。Core 层只依赖接口，不感知前端类型。

## 3.5 事件序列示例

```
// 简单问答
step_begin → reason → text("2+2=4") → step_end

// 连续调工具
step_begin → reason → text("让我看看") → tool_call(read_file) → tool_done → step_end
step_begin → reason → tool_call(edit_file) → tool_done → file_change → step_end

// 需要审批
step_begin → reason → tool_call(shell_execute) → need_approval
  → [TUI 显示审批块，等待用户]
  → [用户批准]
  → tool_done → step_end

// 子 Agent 派发
step_begin → reason → tool_call(task) → subagent_start
  → subagent_step → subagent_tool_result → ... → subagent_done
→ tool_done → step_end
```
