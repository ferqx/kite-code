# 第十二章 测试与首发验证体系

测试以行为边界分层，不使用企业认证或长期观察替代本地可复现结果。

## 12.1 测试层次

| 层次 | 目录/命令 | 目标 |
| --- | --- | --- |
| 单元与策略 | `tests/` | schema、分类、工具、配置与纯函数 |
| Runtime | `tests/runtime/` | Kernel、Scheduler、Store、Capability、Verification、恢复 |
| Runtime 韧性 | `test:runtime:fault`、`test:runtime:soak` | SIGKILL/SQLite/failure contract 与固定 7-case bounded CI profile |
| Agent/Evaluation | `tests/evals/agent-tasks/`、`tests/evals/capabilities/` | oracle、核心 adversarial、安全/正确性和 false-completion |
| Compaction | `tests/evals/compaction/`、`test:model:live` | 结构、事实、语义、continuation、route/handoff 与真实模型兼容 |
| Operations | `tests/observability/`、`scripts/operations/` | metadata-only mapper、status、kill switch、runbook 和本地 rehearsal |
| TUI | `tests/tui-system/harness/`、`tests/tui-system/scenarios/` | 快速 harness 与真实 PTY 完整入口 |
| 开源候选 | `tests/release/oss-*`、`release:*` | standalone build、manifest/checksum、安装、启动、回滚、卸载 |
| 真实 Provider | `test:provider:smoke` | DeepSeek 与千问各一次低成本最小调用，不记录正文或 credential |

旧 Sigstore/attestation、retained evidence、promotion 和 production supply-chain contract 测试继续存在，
用于证明相关控制面在 authority 为空时 fail closed。它们只是历史安全资产，不属于 ADR-0068/ADR-0069
的发布路线图，也不能在 fixture 通过后产生外部认证结论。

## 12.2 G0：本地正确性与安全

整体收口时运行：

```bash
bun run test
bun run test:runtime:fault
bun run test:runtime:soak
bun run test:tui:system
bun run typecheck
bun run format:check
bun run lint
bun run check:core-boundary
bun run check:docs-impact
bun run check:docs
git diff --check
```

G0 还要求 Workspace 越界、secret、network、MCP write、destructive/unknown effect 与 Verification
false pass 全部 fail closed；P0/P1 为零；P2 修复或记录处置；安装、卸载和回滚基本流程可用。

`test:runtime:soak` 的 CI profile 每个固定 case 一次。报告为 `failed` 或 `inconclusive` 时不得包装成
通过。旧 qualification 的 8 轮资源证据只作为按需诊断资产，不是发布后 Task 或必须等待的长期窗口。

## 12.3 G1：普通发布验证

候选构建命令：

```bash
bun run release:build
bun run release:verify
bun run release:smoke
```

build 编译 `kite` 和 `kite-tui` standalone executable；verify 在执行 payload 前检查 exact archive、
manifest、逐文件 SHA-256 和 archive SHA-256；smoke 在临时 managed prefix 中完成 install、CLI help/
version、已安装 standalone TUI 的 version 与真实 PTY startup、第二候选 install、rollback 与 uninstall。

`.github/workflows/release-candidate.yml` 在 `macos-15`、`ubuntu-24.04`、`windows-2025` 原生 runner 上
固定 checkout PR head SHA，验证 manifest commit identity，运行同一流程和 TUI PTY startup，然后上传
14 天保留的 unsigned CI artifact。workflow 只有
`contents: read`，不创建 Release、不 publish、不申请 OIDC/attestation。

真实 Provider 命令：

```bash
bun run test:provider:smoke -- --provider deepseek
bun run test:provider:smoke -- --provider qwen
```

DeepSeek 固定 `deepseek-v4-flash` 与官方 endpoint，并显式关闭 thinking 以确保 16-token 预算用于短回复；千问走 `openai-compatible` adapter，默认使用
`DASHSCOPE_API_KEY`、阿里云 Token Plan 北京 compatible-mode endpoint 和 `qwen3.6-flash`。
环境变量和显式本机配置都必须精确使用该北京 Token Plan endpoint；只允许切换 Qwen 模型。二者都只做一次短响应调用。
runner 输出 provider alias、model、duration、usage、非空布尔值和 credential source，不输出 prompt、
response、key、完整 endpoint 或 error response body。credential 缺失和调用失败都是非零退出；mock
只验证 runner contract，不能替代 G1 真实结果。

## 12.4 TUI 与跨平台原则

默认测试由 `scripts/run-default-tests.ts` 编排，并为每个 test process 使用隔离的临时
`HOME`/`KITE_CODE_HOME`。真实 TUI scenario 按文件串行运行，具有单文件 deadline 和 owned process
tree cleanup。未知/重复 scenario 名 fail closed；teardown 失败不能掩盖测试失败。

跨平台发行与 effectful execution capability 分开。候选包能安装启动不代表 Shell、writer、MCP write
或 effectful Skill 获得 sandbox 资格；缺少原生隔离时对应 capability 继续关闭。Docker、WSL 或交叉编译
只能做开发预检，不能替代三平台 hosted artifact。

## 12.5 文档与状态门禁

`check:docs` 会验证 ADR-0069、首发终态 active 规则、全部 Phase 子计划和
`release/oss-first-release/task-status-v2.json`。状态注册表必须精确覆盖 108 个历史 Task：83
`completed`、25 `superseded`、0 optional，没有重复、遗漏或未知 ID。

`check:docs-impact` 按 `docs/documentation-map.json` 判断实现改动是否同步当前文档。提交前必须执行项目
`document-before-commit` skill；文档影响、测试和实现未共同收敛时不得提交或创建 PR。

唯一普通维护者检查清单位于 `release/oss-first-release/MAINTAINER_CHECKLIST.md`。正式 GitHub Release、
npm publish 或其他不可逆公开动作不属于测试流程，必须另行授权。
