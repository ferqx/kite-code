# 第十二章 测试与发布验证体系

当前版本只保留可复现的产品测试、Runtime fault/soak、TUI 系统测试和发布验证。旧 evaluation、
record/replay baseline、真实 Provider smoke、synthetic cassette/oracle 与相关 CI job 已整体移除；后续若重新
建设评测体系，必须从新的计划、数据边界和证据模型开始，不能恢复旧脚本或把产品 restore/replay 语义冒充评测。

## 12.1 测试层次

| 层次 | 目录/命令 | 目标 |
| --- | --- | --- |
| 单元与策略 | `tests/` | schema、分类、工具、配置与纯函数 |
| Runtime | `tests/runtime/` | Kernel、Scheduler、Store、Capability、Verification、恢复 |
| Model evidence | `tests/model-*.test.ts` | canonical Surface、私有 Artifact、逐 attempt ack、sealed response 与 no-bypass |
| Tool Pipeline | `tests/execution/`、`tests/runtime/tool-*` | prepared identity、ack-before-dispatch、receipt、unknown recovery 与 fail closed |
| Subagent | `tests/subagent-*`、`tests/runtime/agent.integration.test.ts` | grant、Artifact、Driver、continuation、approval 与 cleanup |
| Runtime 韧性 | `test:runtime:fault`、`test:runtime:soak` | SIGKILL、SQLite、故障收敛与有界资源 profile |
| TUI | `tests/tui-system/` | harness、真实 PTY、重连、取消与交互 |
| 发布 | `tests/release/`、`release:*` | 构建、manifest/checksum、安装、启动、回滚与卸载 |

默认测试不得连接真实 Provider、读取 credential 或写入开发机真实配置。产品的模型 transport 由
`ModelInvocationGateway`、configured-provider admission、Artifact 与 attempt receipt 测试覆盖；这类测试是产品契约，不是 eval。

## 12.2 本地完成门禁

整体收口时运行：

```bash
bun run test
bun run test:runtime:fault
bun run test:runtime:soak
bun run test:tui:system
bun run typecheck
bun run format:check
bun run lint
bun run check:core-boundary
bun run check:runtime-packages
bun run check:docs-impact
bun run check:docs
git diff --check
```

`bun run test` 由 `scripts/run-default-tests.ts` 编排，为每个测试进程隔离 `HOME` 与
`KITE_CODE_HOME`。有状态 PTY journey 在单个测试文件内串行执行具名 step，并由 runner 管理 deadline 和
owned process tree cleanup。单独运行某个测试文件仍必须自行隔离持久目录。

测试失败不能通过放宽 identity、approval、persistence、sandbox、network、secret 或 unknown recovery 约束来
消除。正确的修复顺序是先确认当前源码与 active 文档的唯一权威，再修正实现或更新已经过时的断言。

Tool Pipeline 的核心负向矩阵包括：

- prepared、binding、schema、revision、effects、availability mismatch 在 Provider 前零调用；
- durable attempt acknowledgement 之前零 dispatch；
- accepted attempt 只调用一次 Host port 和一次 registry executor；
- terminal/Artifact/commit 不确定收敛为 unknown，不重放、不 fallback；
- dynamic MCP catalog revision 与 Builtin projection revision 分离；
- `ask_user` 只走 Kernel interrupt；
- Subagent blocked continuation 只由 Kernel approval/resume 推进；
- production fixture 使用 Runtime State、SQLite Store 与当前 epoch；显式 SQLite Store fixture 只验证旧路径不读写、不迁移。

## 12.3 Runtime fault 与 soak

`test:runtime:fault` 验证确定性故障注入、SQLite 原子回滚、进程/Provider crash、lease 与恢复语义。
`test:runtime:soak` 使用固定 case、固定 seed 和有界次数运行资源与清理 profile。`failed` 或
`inconclusive` 都不能包装成通过；缺失 cleanup、orphan process/worktree、持久化漂移或资源阈值失败均为硬失败。

fault/soak 报告只保存低信息元数据，不保存 prompt、response、工具 payload、secret 或 workspace 绝对路径。
这些门禁不等于平台 production admission；平台能力仍由原生 probe、独立 verifier 和 support matrix 决定。

## 12.4 发布候选

候选构建命令：

```bash
bun run release:build
bun run release:verify
bun run release:smoke
```

build 生成当前平台 standalone CLI/TUI archive；verify 在执行 payload 前校验精确文件集、manifest、逐文件
SHA-256 与 archive SHA-256；smoke 在临时 managed prefix 中验证安装、CLI/TUI 启动、升级、回滚与卸载。

`.github/workflows/release-candidate.yml` 在 macOS、Ubuntu 与 Windows 原生 runner 上运行相同流程并上传未签名
候选。当前 workflow 不包含 live Provider 或 evaluation job，不读取模型 credential，也不录制 baseline。

## 12.5 文档与仓库卫生

行为变更必须同步更新相关 `docs/active/` 和 `docs/documentation-map.json`，并通过
`check:docs-impact` 与 `check:docs`。不得提交测试临时目录、credential、checkpoint、外部 worktree 或本地
fault/soak 输出。提交前还必须完整执行仓库的 `document-before-commit` Skill。
