# 第十二章 测试与发布验证体系

本章只提供导览。测试归属、发现和默认执行的 current authority 是
[tests/README.md](../../tests/README.md)；TUI PTY 细节见
[App 本地系统测试规范](../../apps/kite-cli/docs/tui-system-testing.md)。

## 12.1 测试层次

| 层次 | 目录/命令 | 目标 |
| --- | --- | --- |
| Package | `packages/*/test/` | 单 package contract、纯函数与 owner-local 行为 |
| Protocol/transport | `packages/runtime-{protocol,server,client}/test/` 与 App carrier tests | V1 codec/allowlist、Client/Server conformance、ack/ready、重连、背压与 carrier 生命周期 |
| App | `apps/kite-cli/test/` | CLI、TUI、配置、Session 与 composition |
| Integration | `tests/integration/` | 只通过正式 package exports 验证跨 workspace 边界 |
| Isolated | owner `test/isolated/`、`tests/isolated/` | 环境、cwd、SQLite 文件与真实进程 |
| Qualification | `tests/qualification/` | fault、soak、native 与安全证据 |
| TUI system | `tests/tui-system/` | 真实 PTY、取消、审批、恢复和 Session journey |
| E2E/Release | `tests/e2e/`、`tests/release/` | 本地 E2E、显式 live 边界和发布候选 |

默认测试不得连接真实 Provider、读取 credential 或写开发机真实配置。Live MCP/Model、native sandbox、
fault/soak 和完整 PTY 使用独立显式命令。

## 12.2 本地完成门禁

```bash
bun run test
bun run test:runtime:fault
bun run test:runtime:soak
bun run test:tui:system
bun run typecheck
bun run format:check
bun run lint
bun run check:core-boundary
bun run check:runtime-packages
bun run check:test-ownership
bun run check:docs-impact
bun run check:docs
git diff --check
```

`bun run test` 分层并行 parallel-safe workspace/integration，并逐文件隔离串行执行全局状态测试。
`test:all` 在默认门禁之后运行完整 TUI system suite。命令名称和默认覆盖语义保持稳定。

Runtime Server V1 还要求测试证明：未知/超限 Protocol 输入在 Host mailbox 前 fail closed；subscribe ack 不会被
notification 越过；Client 的旧连接消息不会污染新 generation；同一 scoped command ID 的重启 retry 不会再次 dispatch；
Store 6 receipt 与 Runtime decision 同事务提交；TUI/foreground CLI 不保留 direct Host/SQLite/Builtin/Kernel
生产路径；完整历史只经 `RuntimeHistoryClient → App safe projector → RuntimeLogQueryPort` 读取。

## 12.3 失败处理

测试失败不能通过放宽 identity、approval、persistence、sandbox、network、secret、unknown recovery 或 timeout
来消除。先确认源码、owner README/本地文档和跨包 active authority，再修正实现或过期断言。

Parity/cutover 测试不是长期 owner。删除前必须把每条独有断言映射到 package、App 或 integration 测试；
State 26 / Store 5 仅作为 source-only compatibility 和 fail-closed 历史读取继续保留领域化测试，不能再把它们
当作 current writer。

## 12.4 发布验证

```bash
bun run release:build
bun run release:verify
bun run release:smoke
```

发布候选继续验证 manifest、checksum、安装、CLI/TUI 启动、升级、回滚与卸载。文档/测试 V2 不改变 Runtime、
发布 artifact 或平台 admission 语义。

stdio 与 development loopback WebSocket 的同一 conformance matrix 还覆盖真实 child、fragment/JSONL、stdout
purity、EOF/signal、restart、Workspace admission、Host/Origin/cookie、ack/reset/ready 与慢连接。它们只是
reference/development evidence；在 macOS、Linux、Windows 的 PR required checks 返回前，三平台 qualification
必须标注为 pending，不能因 workflow 已定义或本地通过而声称已通过，更不能提升 Web production support。
