# 第十二章 测试与验证体系

测试以行为边界分层，不维护容易失真的固定用例数量。

## 12.1 测试层次

| 层次 | 目录/示例 | 目标 |
| --- | --- | --- |
| 单元 | `tests/tools.test.ts`、`tests/policies/` | 纯函数、schema、分类和工具行为 |
| Runtime | `tests/runtime/` | Kernel、Scheduler、Reducer、Store、Capability、Verification |
| Runtime 韧性 | `scripts/runtime/run-fault-soak.ts`、`tests/runtime/fault-injection.test.ts` | 固定故障矩阵、恢复不变量、资源趋势和 bounded soak evidence |
| Release contract | `tests/release/`、`scripts/release/` | canonical artifact/manifest、Profile 单调组合、behavior/evidence/Gate replay 与负向 platform conformance |
| Agent Task Evaluation | `tests/evals/agent-tasks/` | 隔离 fixture、oracle、重复运行、adversarial 与产品 Evidence contract |
| Observability/Operations | `tests/observability/`、`scripts/operations/` | 无正文 metric、consent、dashboard/SLO、alert、演练和 Gate replay |
| Compaction qualification | `tests/evals/compaction/` | synthetic schema、结构/语义/continuation、route/handoff 与 blocked evidence contract |
| Capability release | `tests/verification/`、`tests/mcp/write-*`、`tests/skills/`、`tests/evals/capabilities/` | Verification/MCP write/Skills profile、恢复、分类和 local blocked adapter |
| Execution | `tests/execution/` | gateway、permit、circuit breaker、doom loop、reliability |
| 集成 | `runtime/agent.integration.test.ts`、`session-manager.test.ts` | 模型、Runtime、会话组合行为 |
| Golden | `tests/golden/` | 审批、计划、失败恢复、required verification 的事件语义 |
| TUI 组件 | `tests/tui-*.test.*` | reducer、layout、输入、宽字符和渲染稳定性 |
| TUI Harness | `tests/tui-system/harness/` | 快速输入、PTY、screen、fixture 与生命周期契约 |
| TUI PTY | `tests/tui-system/scenarios/` | 真实终端进程中的完整交互链路 |

## 12.2 常用命令

```bash
bun run test                     # 默认测试；包含 TUI harness，排除真实 PTY scenarios/smoke
bun run test:runtime:fault       # SIGKILL、SQLite 与 fault-soak report contract
bun run test:runtime:soak        # 运行 7-case CI profile；不等同 release qualification
bun run test:sandbox:smoke:native # 显式运行 Seatbelt/bubblewrap 原生执行器 smoke
bun run test:tui:harness         # 快速 TUI harness 单元测试
bun run test:tui:system          # 按文件串行 TUI PTY scenarios（单文件硬超时）
bun run test:all                 # 默认测试 + 完整 TUI PTY suite
bun test tests/evals/agent-tasks # 当前只运行 synthetic/blocked 产品评估 contract
bun test tests/observability     # 无正文遥测与运营 contract
bun test tests/evals/compaction # 压缩本地 synthetic/non-distributable contract
bun test tests/verification tests/mcp/write-*.test.ts tests/skills # Phase 5 本地 conformance
bun test tests/release/ga-selection.test.ts tests/release/ga-compatibility.test.ts # GA 本地 blocked/synthetic contract
bun run typecheck
bun run check:core-boundary
bun run check:docs
bun run format:check
```

按改动范围优先运行目标 suite，再运行默认测试。Runtime 架构修改至少覆盖 kernel、scheduler、reducer、store 和相应 golden；MCP/Skill 修改还需覆盖 tool-controller、manager/workflow、policy 和 verification。

`test:runtime:soak` 默认使用 CI profile，每个固定 case 一次并输出版本化报告。Release qualification
至少运行 8 轮；必需资源指标或 descendant PID 检测不完整时结果是 `inconclusive`，不能按通过处理。
报告 v2 中 `runnerBudgetUsage` 与真实 Runtime ledger 的 `runtimeBudgetUsage` 分开；终态覆盖来自真实通过测试的 evidence，不由 case manifest 自动填充；单 attempt 资源增长超限、
持续增长、临时残留、Git worktree registry 差异或进程树残留均会 fail closed。完整契约见
`docs/active/runtime-resilience-qualification.md`。

Agent Task Evaluation 的本地 suite 在 D-07 未批准时固定为 unconfigured/dry-run，不能访问 live route
或产生 `MS:2B-DONE`。Observability 的合成 incident rehearsal 固定为 G4 `not_run`；Limited SLO Gate
单测的 pass fixture 只验证 verifier 分支，不是 external cohort observation。

Fresh Bun process 的 preload before/after 包含模块加载与 JIT 冷启动，只作为诊断并标记
`qualificationEligible: false`；只有 warm-up 后同进程 repeated lifecycle 样本才能进入 release
资源阈值。功能测试文件各运行一次；每个 case 只有 manifest 选定的真实代表 lifecycle 文件在
隔离 child 内执行 1 次 warm-up 加 8 次 rerun，避免把测试框架保留的大型 fixture 当成产品泄漏。
TUI 仅使用同一真实 Ink child 的 `InputLine`/`TerminalFocusStore` focus-listener repeated
mount/unmount lifecycle，session/tool/model PTY 场景不提供资源斜率结论。缺少任一声明 lifecycle、
attempt/PID/sequence/group nonce/OS process-start identity 绑定或 owned PID/worktree inspection 时
qualification 为 `inconclusive`。Required CI 运行 CI profile；release 证据通过手动
`Runtime Resilience Qualification` workflow 生成并上传 artifact。正式 workflow 固定
`seed=1729`、`iterations=8`，并把 repository、head SHA、ref、`workflow_ref`/`workflow_sha`、
run ID/run attempt 写入 v2 digest。报告保留逐 attempt 资源结构和 ledger provenance；上传前的
verifier 会重算 digest、从 attempt evidence 重建摘要，并重新检查 7 case/56 probe、清理、资源
阈值和 72 条 long-runtime ledger receipt。未绑定 GitHub Actions 来源的 qualification 只能是
`inconclusive`。
该 TUI lifecycle harness 不属于普通 PTY scenario 发现范围；fault-soak 通过
`--with-lifecycle-harness` 精确追加这一个文件，常规 `test:tui:system` 继续只运行 scenarios。

默认入口由 `scripts/run-default-tests.ts` 编排。每个 test process 都获得独立临时 `HOME`/`KITE_CODE_HOME`，默认测试不得读取、修改或依赖开发机真实 `~/.kite-code`；这也使 Plan Artifact、Session Logger 和“workspace 外部文件”边界测试在可控目录中运行。绝大多数用例保留在同一个主 suite，并使用 `--max-concurrency=1 --only-failures` 限制 Bun 共享进程中的 test 与输出资源竞争；会临时修改 `process.cwd()` 或 `KITE_CODE_HOME` 的路径解析测试仍逐文件启动独立进程。默认门禁同时排除 Seatbelt/bubblewrap 原生执行器测试；Shell 集成在统一 executor 上显式关闭 native sandbox，原生正向行为只由 opt-in smoke 与平台 workflow 验证。当前 Ink/Yoga ESM 与 Bun per-file isolate 不兼容，因此不要用 `--isolate` 替代该进程边界。

## 12.3 测试原则

1. 断言可观察行为和不变量，不锁定内部函数调用顺序。
2. Runtime 测试优先检查 Event、State 和 Effect，而不是 UI summary 文本。
3. 外部写入测试必须覆盖 intent、unknown、reconciliation 和禁止盲重放。
4. Required verification 测试必须证明 final 不能绕过门禁。
5. TUI PTY 默认使用真实生产入口和 mock model server，不 mock Ink 渲染主链路。需要成功执行
   远程 MCP 正文调用的场景使用显式测试组合根注入逐 invocation permit；默认生产组合根必须另有
   零请求拒绝场景，不能在共享 harness 中全局放行。跨进程持久化场景把终端提交、Runtime event
   落盘和重启 replay 作为独立证据边界；轮询 Store 只能使用 readonly SQLite 查询，不得重复运行
   带 journal/schema 写入的生产初始化，并应由精确 event 字段解析目标 thread。
   Scenario 必须通过语义 readiness 启动，mock response queue 一次性消费；每个 mock
   `tool_call_id` 必须由后续真实 Tool result 闭合；每个未取消 continuation 都要声明并验证结果
   marker，副作用还要检查磁盘或 Store，不能用 canned response 掩盖执行失败。普通消息提交绑定
   当前输入回显和显式 request baseline，只接受最新真实 user turn；raw action delta 不能授权下一次
   控制键。共享 helper 拥有并保持 end-cursor 的输入动作从 headless VT cell 投影恢复：末尾反色视觉
   光标不属于逻辑值，用户真实输入的 leading/trailing 与词间 whitespace 则必须保留；英文 soft wrap
   省略的词间空格按输入宽度恢复，hard wrap 直接拼接。这不是任意编辑光标位置的通用状态解析。
   main readiness 复用该 input projection 判断空输入，并以普通 viewport 验证其余可见
   chrome。输入重试对 replacement 的空基线做确定性回滚，不能让
   终端投影裁掉或虚构的空格把消息或 slash command 改义。可独立筛选的命令、持久化和思考矩阵使用独立
   fixture，不塞进共享 journey；真正依赖前序状态的流程才使用具名 step，超时先取消，并在有界
   settle window 内收敛当前 step 再 teardown。要求 semantic receipt 的提交只在原字段仍未变化时
   按短 delivery budget 重试 Enter；字段离开后只按独立的 request/event budget 等待 receipt，避免
   控制键进入新焦点，也避免慢 CI 过早失败；持久事件加 restart replay 的复合测试还要为两个阶段保留
   完整外层 deadline。runner 对未知或重复 scenario 名称
   fail closed，默认跑完所有隔离文件后汇总
   失败，显式 fail-fast 仅用于本地复现。teardown 先终止自有 TUI 进程组，再停止服务和清理
   workspace，任一清理失败不得跳过剩余资源。
6. 跨平台命令、路径和 sandbox 行为分别验证，不用 Unix 假设覆盖 Windows。

## 12.4 文档与边界检查

`check:docs` 校验文档目录和生命周期；`check:core-boundary` 防止 core 导入 app/TUI。架构行为变化必须同步 `docs/active`，技术全书用于解释当前结构但不高于源码、测试、active 和 ADR。
