# 第五章 Capability、工具与安全策略

## 5.1 工具不是顶层架构

Builtin Tool、MCP、Skill 和 Subagent 都是 Capability provider。`createAgentTools()` 只构造当前模型轮次可见的工具声明；执行始终由 Runtime 接管，模型侧工具没有绕过 Runtime 的 `execute` 通道。

当前内置能力包括文件读取与编辑、Shell、内容/文件搜索、MCP Resource、Web Fetch、Plan 操作、用户提问、Subagent、Skill 激活/引用和 capability search。具体集合按模式、feature flag、provider 能力和当前 binding 动态生成，因此不以固定数量作为契约。

## 5.2 执行网关

```text
tool call
  → 解析静态请求或 Runtime-issued binding
  → 参数 schema 校验
  → capability revision 校验
  → 副作用分类
  → mode policy
  → auto review / user approval
  → sandbox / network boundary
  → provider adapter
  → structured result + receipt + Runtime event
```

`ToolController` 是统一入口。未知动态工具、过期 binding、schema 漂移或不可解释参数必须 fail closed。

Tool Controller、Tool Runner、Builtin Tool factory 与 Verification 只通过 `McpRuntimeProvider` 访问 MCP capability、调用和资源读取，不依赖 Supervisor、Manager control API 或 TUI。连接重试与 `/mcp` 状态列表不构成执行授权。

## 5.3 Policy 分层

| 层 | 作用 |
| --- | --- |
| Effect classification | 判断 filesystem、network、external state 的 read/write/destructive/unknown |
| Mode policy | `accept_edits`、`auto`、`full` 下的交互和审批规则 |
| Approval policy | 形成 auto review 或单次用户审批 |
| Authorization grant | 对特定命令或会话范围授予有限权限 |
| Sandbox | 在获准后落实文件、网络和进程隔离 |

审批与 sandbox 是不同控制层。批准操作不自动关闭 sandbox；sandbox 可用也不代表操作已获授权。

## 5.4 Shell 与外部副作用

Shell 会结合命令、工作区、网络意图和 action envelope 分类。破坏性命令默认拒绝或要求明确用户决策。MCP 的远端 annotation 不是安全事实；未知、写入和破坏性外部副作用即使在高自主模式下也保持保守审批。

MCP Tool 的 allowlist、denylist 和精确 enabled override 只控制 catalog 可见性。逐 Tool effect、minimum approval 与 retry 进入 descriptor revision；unknown/write/destructive effect 不会因为 `minimumApproval: none` 或高自主模式而跳过用户审批。`safe_read` 仅对 effective read 生效，缺少可信 idempotency key 的写调用不自动重试。

## 5.5 执行结果

工具的人类可读 summary 只是 UI 投影。Runtime 还记录结构化结果、失败分类、副作用、文件变化、外部引用、artifact 和 retry safety。高风险执行随后进入 Verification，而不是以 `ok: true` 直接完成任务。
