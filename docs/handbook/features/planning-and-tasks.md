# 计划与任务

计划描述目标、步骤和验收，帮助在执行前确认方向。它不是已完成工作的证据，也不自动授予权限。

需要审核时，用户应能阅读当前方案并批准或补充要求。批准对应当前计划与执行方式；被替代的旧方案不能继续当成当前授权。

执行中的步骤可以完成、失败、阻塞或需要调整。需要的验证未满足时，不应只靠模型自报完成结束任务。验证功能的实际强度和可用性受当前配置影响，不承诺每个部署都自动执行全部验证。

会话计划不再按 30,000 字正文、12 步或固定标题／重规划理由长度拒绝保存。正文和标题须非空，步骤身份须互不重复，当前版本、摘要及持久产物仍需准确匹配。计划批准与验证通过仍是各自的完成条件。

通用路径的单次计划批准属于原 Run；同会话的后续 Run 不复用它。审核前只允许宿主核实的只读分析和计划管理，审核后的执行方式与当前权限共同限制实际派发。子任务沿原父计划义务核验，不重复创建单次计划意图，也不能借父计划批准替代自己的工具许可。计划完成仍需真实步骤回执与已启用的 required 验证；无效、缺失或已变化的批准保留为历史，不能继续派发效果。

[TUI 计划模式](../clients/tui/guides/planning.md)说明操作。Web 不提供计划批准入口，查看历史不相当于批准执行。
