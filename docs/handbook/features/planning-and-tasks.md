# 计划与任务

默认宿主已接入[方案文件持久化](../../../packages/agent/src/business/planning/README.md)：当前方案有真实 `plan.md`，可通过文件工具读取和编辑。编辑由 Planning 保存新版本，仍需对准确版本单独批准。文件与记录不同步、发布未完成或外部修改时阻断新执行效果；读取最新基线后可以显式保存新版本，不能从文件中的“已批准”恢复权限。客户端和异常过程的验证范围由该 owner 及对应客户端证据维护。

同一会话切回先前方案时仍保存新版本，历史正文和旧批准保留为历史，不重新取得执行授权。目标方案文件已被外部修改时，保留实际字节并拒绝覆盖；正常切换不应使当前方案陷入未完成发布。

计划描述目标、步骤和验收，帮助在执行前确认方向。它不是已完成工作的证据，也不自动授予权限。

需要审核时，用户应能完整阅读当前方案，明确选择批准、要求修改或拒绝。主动 `/plan` 与扩展显式请求的计划实施审批，在 Manual、Auto、Full 下都必须由用户回答；自动审核模型不代答，Full 也不跳过。批准只对应原 Run 的准确计划版本，不选择或修改工具权限模式；被替代的旧方案不能继续当成当前批准。

执行中的步骤可以完成、失败、阻塞或需要调整。Agent 通过 Shell 运行适当检查并如实报告结果；专用验证工具及自动强制验证机制已移除。计划批准仍按准确方案版本处理。

模型通过 read_plan 取得准确的 plan_ref 和 progress_ref，保存、审核和进度更新复制这些引用；运行时核原计划版本与当前任务，模型无需重建摘要、版本号或 Run 身份。引用不构成批准，步骤完成或补偿仍必须关联真实执行回执。

会话计划不再按 30,000 字正文、12 步或固定标题／重规划理由长度拒绝保存。正文和标题须非空，步骤身份须互不重复，当前版本、摘要及持久产物仍需准确匹配。

通用路径的单次计划批准属于原 Run；同会话的后续 Run 不复用它。审核前只允许宿主核实的只读分析和计划管理；批准后各 Tool/Job 沿当前真实权限执行，不附加计划答案派生的 Manual/Auto 上限。单独保存计划不自动要求审核，显式发起实施审核会先为原 Run 登记门禁。要求修改时保留门禁，按反馈修订后重新审核；拒绝时，计划请求工具返回简短的用户拒绝说明，直接结束当前轮次，不再调用模型续答或重新请求批准。已完成的效果保留，在途附着操作沿原停止与清理流程结算；你仍可发送新消息继续。子 Agent 沿原父计划义务核验，不重复创建单次计划意图，也不能借父计划批准替代自己的工具许可。计划完成仍需真实步骤回执；无效、缺失或已变化的批准保留为历史，不能继续派发效果。

等待计划答案时仍可切换工具权限或停止。单纯模式切换保留原计划卡及已提交的同一次答案，不要求重答；后续工具读取最新已应用权限。工具移除、硬拒绝、来源失效、计划正文变化和取消仍分别核验。答案提交结果未确认时查询原命令，不重复投递。各客户端的入口与展示限制由对应指南说明。

[TUI 计划模式](../clients/tui/guides/planning.md)说明操作。Web 不提供计划批准入口，查看历史不相当于批准执行。

本节是产品功能；仓库开发用的 Markdown 计划属于内部工程流程，不是用户会话的运行时存储。
