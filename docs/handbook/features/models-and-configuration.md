# 模型与配置

Native 的直接图片输入会把原图作为模型 user 消息的一部分交给所选 Provider；路径引用只作为文本发送。图片识别取决于实际模型和 endpoint，客户端不会把图片能力从名称或思考档位推导出来，也不把不支持图片的请求静默改为纯文本。支持格式、操作和草稿限制见[桌面输入说明](../clients/desktop/README.md#提示词与附件)。

模型选择包括 Provider 与具体模型，相同名称不代表同一请求目标。工具调用、推理深度和上下文能力取决于模型与配置。

每次模型尝试保存已收到的输入、输出、缓存命中、推理、服务端总数及原始用量明细。失败或取消不删除已经返回的统计，也不把用量当作执行成功或工具权限证明；未返回的字段保持未知，原始总数不从缺失的输入／输出拼算。旧记录不追补无法核实的用量。TUI 分别展示最近请求实际输入与下一请求上下文估算；累计实际用量保留统计覆盖情况，三者都不等于账户完整账单。

## 配置范围

所有客户端的模型统一使用用户配置 `~/.kite-code/kite-code.jsonc`，不区分用户模型和项目模型。现有 `provider`、`model` 和 `disabledModels` 字段继续有效；切换 Profile 或项目不改变模型配置来源。旧 `~/.kite-code/unified-agent/default/config.jsonc` 不再读取、创建或用作回退。项目 `kite-agent.jsonc` 仍可配置受支持的工具和扩展，其中的模型声明不参与模型解析。

客户端的语言、主题等偏好与服务的模型配置分开维护。修改 TUI 语言不承诺 Web 同步改变，修改模型也不改变已经开始的模型请求。

Provider 凭据通过实际支持的配置和认证入口维护，不在手册示例中填写真实 key。配置错误会阻止相应操作，不能静默切到另一个模型冒充成功。

用户文件缺失时模型列表为空，不猜测内置模型或改读其他文件；坏 JSONC 显示读取错误并保留原字节。相同模型名称和自定义 endpoint 仍按实际路由身份核对，不能继承其他路由的执行资格。

桌面设置的“模型”页打开时自动加载上述用户文件，沿用按提供商分组的完整列表、启用开关和默认模型下拉选择，不提供项目范围切换。禁用和配置不完整的条目仍显示，默认菜单只提供已启用且配置可用的模型，同名路由显示 ID。“刷新配置”重新读取本地文件，不查询远端目录。当前默认模型不能直接禁用，需先选择另一默认模型；禁用模型不出现在输入区的可选列表。保存保留无关注释、字段和其他模型；文件被外部修改时拒绝旧读取集保存，需重新读取。

## 生效与限制

活动执行使用开始时确定的配置，保存新的期望配置供后续执行使用。功能开关启用不替代授权和平台支持；默认关闭的扩展不能凭旧文档推断可运行。

当前 Runtime 的可信配置 `maxConcurrentSubagents` 接受正整数，缺省为 3，只调度真实同时运行的子任务；满额的普通 Task 等待空位。活动 Run 保留已选择配置。旧 JSONC 的 `resources.maxConcurrentSubagents` 和预算保存格式不自动成为新 Service 的用户配置项，实际支持的文件字段见[配置 owner](../../../packages/agent/src/config/README.md)。并发调度不构成整个 Run 的累计额度。

[V1.3 D17](../../plans/unified-agent-refactor-v1.md)明确退役旧隐式累计预算与隐藏子任务总步数。新 Run 不因累计 turn、模型请求、token、工具调用或产物字节超过旧门槛提前停止；实际 Provider 窗口、并发与明确运行策略仍约束执行。旧 Release Profile/活动 Run 的兼容转换属于历史实现，当前新数据基线不自动迁移旧用户数据。

项目 `CLAUDE.md`／`AGENTS.md` 的适用内容会完整进入模型上下文，不因来源数、目标数、目录深度、单文件或累计字节额度遗漏；相关文件新增、修改或删除后，待执行的副作用需要先刷新指令。路径范围、非符号链接、原文件身份及 UTF-8 完整性仍须成立。

默认 Service 在同一任务内根据上下文增长自动压缩，不要求用户另发第二条消息。默认上下文总量为 256K（262144 token），模型明确声明的窗口优先；当前请求输入达到总窗口的 75% 估算水位时触发，不先扣减输出预留。因此默认压缩阈值为 196608 token，1M（1048576 token）窗口的默认阈值为 786432 token。用户模型条目支持 `contextWindowTokens`，也兼容已有的 `contextWindow`；两者同时提供时以 `contextWindowTokens` 为准。`maxOutputTokens` 仍独立声明输出能力。这些值是配置声明，不表示 Provider 实际容量已经验证。摘要保留原目标、已完成结果和确实尚未满足的用户要求；未读文件和可选资料不自动成为新待办。随后继续原 Run，摘要、自定义说明和原历史不设固定裁剪额度。

已应用且仍在当前历史选择中的真实用户输入，包括运行中的引导，在压缩后仍按原顺序完整提供给模型，不只依赖摘要转述。子 Agent 收到的原始委派和父 Agent 后续有效指示也保留完整原文和原来源；较新的明确纠正覆盖同一任务较早的冲突要求，根用户的限制和实际工具权限保持。摘要作为背景，不能覆盖原始任务和引导。内部压缩要求只约束本次摘要生成，不是新的用户任务或委派变更；压缩后仍按原目标、有效引导和原授权继续，不能把“只做摘要／不调用工具”的维护说明当成后续业务限制。压缩不会重置已执行的历史，摘要承接过去步骤；不能仅因原工具回执退出当前模型窗口而重做已完成的操作，原任务的次数限制继续有效。摘要也不变成新回执、当前外部状态或新权限的证明，原结果未知时仍保留未知。保留历史不会重新提交旧任务或生成新的批准，已取消／中断／失败工作的历史边界保持。子返回的进度、最终结果和工具正文仍由摘要承接其事实，不能取得用户引导权限；引用某份材料不表示其全文会永久保留。

可在用户配置 `~/.kite-code/kite-code.jsonc` 中设置 `compression.thresholdTokens`，以正安全整数指定输入 token 压缩阈值。一旦设置，该值覆盖按模型窗口计算的 75% 阈值；删除该字段恢复默认比例。项目配置可按同一字段覆盖，活动 Run 保持开始时冻结的设置。例如下面的配置将阈值设为 131072 token：

```jsonc
{
  "compression": { "thresholdTokens": 131072 }
}
```

自动摘要必须实际缩小上下文；摘要连同保留的用户及父 Agent 任务原文、系统指令、项目来源与工具定义还须低于实际采用的压缩阈值。固定内容本身已达到该阈值，或摘要无法缩小、缩小后仍无继续空间时，该次 Run 明确失败并保留原历史，不反复摘要、静默裁掉引导或冒充完成。自定义阈值过小也遵守这一终止规则。

自动压缩的已知失败或中断保留旧上下文，不发布半份摘要，也不永久禁用压缩；同一未变化上下文只让出一次普通决策边界，之后仍可再次触发，新增上下文也可直接重试。明确取消 Run 或子 Run 到期仍终止该次执行；存储损坏、未知派发和无法核实的发布不能冒充安全压缩失败。真实 Provider 窗口／输出能力仍约束单次请求。

提供商页只列出用户实际添加的连接；尚未添加时显示空列表和“新增提供商”。OpenAI、DeepSeek、Ollama 与自定义兼容服务仅作为新增表单的快捷模板，不默认加入列表。同一种模板、同一地址可以添加多个独立命名的连接；修改名称、地址、协议或凭据不改变连接身份与既有模型 ID。旧用户配置和没有模型的旧提供商声明继续可见，读取不自动写入迁移；不能安全编辑的旧声明显示只读。

新增和编辑在应用最右侧面板完成。删除先展示连接、相关模型与引用影响并要求明确确认；连接包含当前默认模型时，须先选择其他默认模型。本机定时任务（包括停用任务）或未结束的定时运行仍引用其模型时，须先修改相关任务或等待原运行结束。删除移除该连接及其模型配置，不自动选择替代模型，不撤销系统凭据库中的秘密，也不更改其他连接；旧会话的原模型选择和历史不会被改写，后续需要使用可用的明确路由。未知删除结果仍须查询同一原提交。

通用 Native 的提供商设置支持 OpenAI、DeepSeek、OpenAI-compatible 和 Ollama 的明确连接与模型名称。手动填写名称时直接保存；留空时，只有这次显式保存才查询该连接的模型目录。新加入模型默认禁用，需先启用再选择。现有用户文件中的 API key 只由宿主私下读取，不进入模型列表、快照或日志；更换 key 时保存到用户级系统凭据库，文件改存引用，提交后清空表单。配置可用不表示远端账户或模型已验证成功。

OpenAI 和 OpenAI-compatible 连接可在“API 协议”中选择 Chat Completions 或 Responses。未设置协议的旧配置继续使用 Chat Completions，无需迁移；DeepSeek 和 Ollama 当前仍使用 Chat Completions。协议按连接保存，同一地址的两种协议是不同连接；Responses 失败不会自动回退或切换模型。用户 JSONC 的提供商条目可显式设置 `"protocol": "responses"`，基础地址仍填写 API 前缀（例如 `https://api.openai.com/v1`），无需追加 `/responses`。

Responses 使用原有运行、工具授权和定时任务执行链，支持流式文本、工具结果回传、多轮与取消；采用 `store: false`，用于继续推理的加密状态保存在本地私有运行记录中，不展示在输入/输出检查器。切换模型路由、地址或账户后不向新绑定回传旧加密状态。此配置仍使用提供商 API 凭据，不增加 ChatGPT 登录或 OAuth；本地模拟服务验证不代表真实付费模型、账户权限或所有第三方 Responses 实现均已验证。

用户文件中的协议配置示例（凭据另在提供商设置中保存，模型名按账户实际支持情况填写）：

```jsonc
{
  "provider": {
    "openai": {
      "protocol": "responses",
      "baseURL": "https://api.openai.com/v1",
      "models": ["gpt-5"]
    }
  },
  "model": "openai:gpt-5"
}
```

输入区从已启用且配置可用的模型中选择下一次运行的路由，选择按 Session 隔离，不修改全局默认或其他会话。新 Session 在首条输入前不绑定模型；首次输入保存实际选择，已有会话在下一次新运行采用其选择。活动运行保持原模型，运行中的普通发送仍是文本引导。

PC 输入区沿用原模型与思考程度浮层：模型列表按提供商分栏，同一提供商下的同名模型显示路由 ID 以便区分。滑块依次提供「轻度、中、高、极高、Max、Ultar」六档，对应请求值 `low/medium/high/xhigh/max/ultar`。模型按钮只显示已明确配置或临时选择的思考档位，未设置时不显示「默认」占位。同连接内切回已读会话时，控件先恢复该会话自己的上次确认值，再后台核对；核对期间保留标签，模型选择与发送等待新读取确认。浮层只保留模型切换与思考程度调节，不显示「配置默认」和「关闭思考」按钮；尚未临时选择时仍沿用已有配置。旧 `none`／`minimal` 配置继续按原值读取和执行。

Kite 对所有模型统一传递所选的 `reasoning_effort` 参数，不按提供商、模型名称或旧 `reasoning`／`reasoningSupported` 能力标记隐藏选项或拒绝合法档位。模型服务决定是否接受、忽略或拒绝参数；拒绝时如实显示该次请求失败。未选择时沿用配置或提供商默认值。临时档位按当前页面中的会话保留，切换模型或刷新页面后重置。它随原始开始／后继输入冻结到实际请求，不写全局配置，不改变活动运行；子任务仍按自己的角色配置选择。

设置保存分别显示凭据保存与配置发布结果。配置已发布但刷新失败时可重新读取；凭据已存而配置未发布时保留各自事实。结果未知只允许显式查询原提交，关闭面板或刷新不解除等待，不会自动重发或回滚。冲突需重新读取配置后提交新的明确意图。

统一 Agent 开发链路可在兼容模型 options 中设置推理强度，并为每个执行保存实际采用值；已开始的执行保留原选择，后续执行采用新配置。可传输的选项不保证远端模型接受，拒绝会如实显示失败。完整模型发现、输入区选择和设置界面范围仍按[实施进度](../../plans/unified-agent-refactor-v1-progress.md)逐项验证。

新的统一 Agent 压缩保存实际摘要模型请求、覆盖范围和来源，保留原历史。摘要在后续输入中作为低权限历史数据使用，不授予工具或审批权限；压缩命令已受理不表示摘要已发布。重置前需确认完整展开输入可安全采用，缺少准确预检或预检拒绝时保留当前压缩点，不调用模型。开发 Native 与 TUI 的具体入口及已验证范围见[实施进度](../../plans/unified-agent-refactor-v1-progress.md)，正式入口和真实模型窗口资格单独验证。

CLI 当前拒绝 `--feature` 等已退役覆盖选项。设置操作见[TUI 设置](../clients/tui/reference/settings.md)，命令支持见[CLI 参考](../cli/commands.md)。

统计分别保留累计实际用量、最近请求实际输入和下一请求上下文估算。默认自动压缩以可核实的原请求实测输入为基线，加上新增内容的通用估算；模型／工具或已测量内容变化、重排、压缩和重置使基线无法沿用时全量重估。未知提供商和自定义模型使用相同回退，不凭名称猜分词器或容量。累计统计显示缺失覆盖情况，不等于账户完整账单。
