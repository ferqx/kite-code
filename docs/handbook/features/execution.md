# 执行与结果

运行中引导、受管后台 Shell/service 与后台子 Agent 已接入 Native Runtime。用户行为以本页和对应客户端指南为准；实现边界由 Runtime Contract、Host、Client 与 Service owner 文档维护。

无关 MCP 故障不再阻止普通模型请求。沙箱不可用时，无需 Shell 的会话仍可继续；需要该执行环境的操作返回拒绝，不自动转为不受限执行。Git metadata 变化不会撤销普通工作区信任；外部读取由实际 Shell 的权限与精确路径范围检查，普通信任不自动授予外部目录。

一次输入可以触发多次模型调用、工具和用户交互。模型回答、工具终态和整轮终态分别表达不同层次，客户端不应仅凭一段文字判定完成。

| 结果 | 含义 |
| --- | --- |
| 完成 | 当前执行已达到正式完成边界，仍需阅读具体结果 |
| 失败 | 某步骤或执行失败，可能有部分副作用 |
| 取消 | 接受取消并收敛执行，不自动回滚外部改变 |
| 阻塞 | 缺少权限、输入、能力或必要验证 |
| 未知 | 结果或副作用无法可靠确定，不应盲目重跑 |

工具执行前拒绝与执行后失败必须区分。无输出或连接中断不等于未执行。需要重试时先核实是否安全重复。

各客户端可采用不同展示：TUI 有活动过程与终端历史，Web 按页面读取快照及增量，CLI 输出事件。共享的是结果含义，而不是布局和刷新频率。

## 运行中引导与后台执行

活动 Run 中再次发送纯文本会追加为定向引导，不取消正在进行的模型请求，也不创建第二个 Run。已派发工具继续按原身份收敛；新输入到达后尚未派发的旧工具和对应审批会以 `superseded_by_user_input` 闭合，再由同一 Run 的下一次模型决策处理。目标已经结束时客户端保留草稿，不把输入静默改投新 Run。多客户端输入按服务端受理顺序交付；命令响应丢失后重试读取原持久回执，不重复追加输入。

有限命令可通过 `shell_execute` 的 `yield_ms` 进入受管后台状态，并用 `shell_read` 读取增量输出或等待终态、用 `shell_stop` 精确停止。输出有界且支持独立读取游标；等待可因新引导让出，但不会因此杀死进程或重置原期限。本轮必需的有限 Shell 或子 Agent 尚未收尾时，Run 保持同一身份并显示等待，而不是空转调用模型或先完成再重开。

显式 service 可跨本宿主中的正常 Run 保留；`running` 不等于业务已经 ready。后台子 Agent 以稳定 task ID 返回，可用 `task_read` 重复读取持久结果、用 `task_cancel` 精确取消。具名结果以低权限来源进入模型上下文，不视为人类授权。只有结构化授权、正预算预留和原 deadline 都满足时，`after_turn` 结果才会至多触发一次新的汇报 Run；普通 Shell 完成不会触发该路径。

Desktop 展示当前及非选中会话的后台 Shell、service 与子 Agent，并只允许对新鲜、仍运行的准确执行发起停止。TUI 支持运行中引导和准确停止；Web 只读展示后台摘要，不获得 mutation 权限。宿主退出、崩溃或升级后不承诺本地进程续跑；历史结果保留，无法确认的清理保持 unknown。当前进程树清理已在 macOS 验证，Linux 与 Windows 的本次平台资格尚未实跑。
