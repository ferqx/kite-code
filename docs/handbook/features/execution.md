# 执行与结果

通用 Agent 链路的当前工作状态不会因会话历史增长而退回最早一批记录。当前 Run、它的模型执行和较早仍未结束的 Job持续使用原身份显示；停止仍针对用户明确选择的原工作，不能因列表刷新改成另一轮。状态投影保留最近的有限历史，完整消息与已保存输出继续按需读取；未知结果保持原事实，不因重新读取状态而变成成功或获得重执行许可。

运行中引导、受管后台 Shell/service 与后台子 Agent 已接入 Native Runtime。用户行为以本页和对应客户端指南为准；实现边界由 Runtime Contract、Host、Client 与 Service owner 文档维护。

默认子 Agent 是通用协作者，由父 Agent 用任务正文分工。可信宿主可以提供可选预设；省略预设仍使用通用默认，未知或不可用预设明确拒绝。预设只绑定已注册配置，不能扩大父任务权限、只读限制或工具上限。多个独立子任务可以并行，默认三个 child 槽位与每个已激活 child Run 最长 30 分钟期限保持。

父模型的委派工具说明展示实际默认角色及开放预设的注册能力限制。委派应覆盖子任务的必需步骤；只读研究角色不具备进程派发能力，不能通过选择角色获得额外权限。子结果需交代实际工作、证据及跳过或受阻步骤，父 Agent 核实影响结论的关键依据。

模型通过 `spawn_agent` 创建协作者，受理后得到稳定 `agent_id`；`follow_up_agent` 继续同一个协作者，`send_agent_message` 只排队消息，`interrupt_agent` 精确中断其被绑定的活动轮，`list_agents` 枚举直接 children，`wait_agent_events` 等待调用者自己的邮箱事件。旧协作工具名不再作为模型 alias。列表与事件水位只表示观察位置；完整原委派、最近追问和结果有各自可读来源，事件摘要不代替结果正文。

子 Agent 在首次激活前已明确取消，且可核实从未开始执行时，仍可用 `follow_up_agent` 复用同一个 `agent_id` 开始真实首次运行。同一工作保留原委派作为已取消的背景，以本次新指令为准；换工作不继承旧委派。新运行不恢复被取消的旧执行，也不把旧排队引导当作新指令；未知或无法证明未执行的情况仍须先核实。

无关 MCP 故障不再阻止普通模型请求。沙箱不可用时，无需 Shell 的会话仍可继续；需要该执行环境的操作返回拒绝，不自动转为不受限执行。Git metadata 变化不会撤销普通工作区信任。开发期已批准的 Native Shell 默认可按宿主文件权限读取工作区外文件，包括工具隐式使用的用户配置；非 Full 调用仍只能写工作区和隔离的运行时临时目录。封存生产执行继续按精确只读范围约束，结构化文件工具仍按各自路径权限执行。工作区信任本身不批准 Shell 命令。

一次输入可以触发多次模型调用、工具和用户交互。模型回答、工具终态和整轮终态分别表达不同层次，客户端不应仅凭一段文字判定完成。

默认 Agent 的行为合同要求在已有授权内继续完成可执行的必要工作，根据明确工具失败纠正方法；只有影响当前结论或剩余工作的具体疑问才继续取证。代码研究从当前入口、配置装配和可达调用链建立结论，文件或符号存在不证明它属于当前路径。证据足够后直接交付，以结果和关键依据为主，按任务规模控制细节，并说明未验证或受阻范围。该指导不新增审批、普通任务强制计划或通用完成判定器；Run 完成仍须按实际结果理解，可机器判断的必要验证沿原条件执行。

主 Agent 的 Run 不设执行期限，也不设 turn、模型请求、输入／输出 token、工具调用和产物字节的累计额度；实际用量仍会记录。独立子 Agent 同样不设这些累计额度，但每个新 Run 保留从自身激活时开始的最长 30 分钟执行期限。已在执行的旧主 Run 恢复时会持久记录额度与期限移除，让尚未结算的直接模型／工具调用按新规则收尾；已结束的历史记录与已签发的子授权不改写。子 Agent 并发、取消、权限、审批和未知外部效果的恢复边界继续生效。Provider 的单次上下文／输出能力与显式工具超时仍按各自规则执行。

主任务可以持续数小时、数天或数周；持续执行不因本地固定重试次数、来源数量或隐式 Shell 超时结束。可安全重试的暂时性模型故障在同一 Run 中退避重试，直到恢复、取消或子 Run 到期。Provider 单次输出达到长度上限时，完整收到的纯文本段保留并继续原任务；不完整工具批次不能派发。真实权限拒绝、损坏记录和未知外部效果仍须按原安全规则处理，不能靠无限重试绕过。

主／子 Agent 均有相同的重复失败保护：按模型给出的工具调用顺序，同一工具、语义相同的参数连续失败五次，取消该 Run，原因是 `repeated_tool_failure`。执行前因项目指令或工具能力变化而退回、等待模型重新决策的调用，不增加也不清空已有失败次数；已经派发的失败仍按真实结果计数。对象键顺序和 JSON 空白不改变参数语义；其他调用换工具、换参数或返回非失败结果时重置计数。并行批次先等待所有已启动调用保存真实结果，再判断顺序；原 Run 的显式安全接续会重建已有失败次数，不重放工具，也不重新获得五次额度。模型传输失败不计入这个工具计数。

主 Run 曾保存过输出达到长度上限的纯文本段，之后进程意外退出时，仍可从已有安全检查点显式恢复同一任务。已保存的回复和完成的工具结果保留原身份，不重复执行。尚未确认结束的调用、未知外部效果或末尾失败尝试不能作为恢复派发依据。

长任务会保留不同工具输入对应的项目指令来源，不因累计请求达到固定数量而结束；后续安全检查点仍核实当前指令及原调用来源。默认装配的连续文件读取和原任务接续已取得本机限定证据，正式客户端和平台范围见[实施进度](../../plans/unified-agent-refactor-v1-progress.md#2026-10-10长-run-完整来源与原任务安全接续)。

工具失败只结束对应调用；整轮失败须有正式失败终态。`ask_user` 发出后，Run 等待用户回答，等待时间不代表模型或工具持续执行。主 Run 不因等待达到 30 分钟而报额度耗尽；主动取消或真实执行错误仍按原流程收尾。

| 结果 | 含义 |
| --- | --- |
| 完成 | 当前执行已达到正式完成边界，仍需阅读具体结果 |
| 失败 | 某步骤或执行失败，可能有部分副作用 |
| 取消 | 接受取消并收敛执行，不自动回滚外部改变 |
| 阻塞 | 缺少权限、输入、能力或必要验证 |
| 未知 | 结果或副作用无法可靠确定，不应盲目重跑 |

工具执行前拒绝与执行后失败必须区分。无输出或连接中断不等于未执行。需要重试时先核实是否安全重复。

开发统一 caller 的普通申请与执行终态分开。start、steer、follow-up、原 Command cancel 和准确 Execution cancel 都在首次 POST 前保存完整原请求；单次 Plan/Workflow 不变成永久权限。崩溃或回执丢失后只读原 Command，未知不重投，详见[普通申请恢复](recovery.md#开发统一调用者的普通申请恢复)。`applied` Work 仍须读取实际 Run，`cancel_requested` 仍须读取准确 Job 状态；它们不能作为模型完成、工具效果成功或清理完成的证明。

开发 CLI 的 JSON Work start/follow-up 核原 Command 与实际 Run 后，继续原审批、问题及输出生命周期，completed 才成功退出。旧已封存的输入解释若为待澄清，查询会输出原澄清正文并以退出码 3 返回，原命令仍为 accepted、业务 Run 为空；该历史解释不冒充业务完成。新输入沿普通 Agent 轮次处理。排队期间只查询原关系，不借另一个活动 Run；EOF、未知原答案或结束本地观察保留未完成事实。共享连接结束只 detach，配对服务收尾可能中断仍活动的工作，不能把先前受理回执改称完成。Native 沿原 controller 观察执行，原申请面板的冷查回不重开业务；准确单 Job stop 先核原新鲜 Execution。原双 Job 窗口证明明确配置的 `shell.launch`/`shell.command` policy 下父 Run 已完成后只停止一项，另一项未取消。当前 macOS 默认 Native 已另验从页面明确选择 Full 后新建后台 Job、同一准确停止、完整输出及 Main/Service fault 的清理和冷读零重放；普通命令仍按现行权限准入，Workflow verifier 资格保持独立，具体范围见[Native owner](../../../apps/desktop/README.md#native-job-完整已保存输出)。

各客户端可采用不同展示：TUI 有活动过程与终端历史，Web 按页面读取快照及增量，CLI 输出事件。共享的是结果含义，而不是布局和刷新频率。

后台执行目录按页传输，不因累计命令或子任务较多而超过单条消息容量。缺省 Runtime Client 查询会读完版本一致的全部页，显式页查询只返回请求页；跨页状态变化时重新读取，超时或取消不会把部分目录当作完整结果。停止和输出续读仍使用准确的执行身份。

正式 Native 的「后台总览」可主动打开、刷新和关闭，展示当前连接下原主体可见的后台 Job、子 Agent／task，以及子会话中的 Job，切换阅读会话仍保留总览。每项分别显示来源会话、原执行、原父轮次、原子轮次和结果接纳状态；父轮次等待必需结果时保留同一身份，一项子任务结束不会把其他子任务改为完成。后台任务较多时，全部目录读取成功后才替换显示；读取失败保留上次完整事实并暂停停止入口。

总览中的完整已保存输出保留截至首次固定水位的原正文与缺口事实；子日志读取同一原子会话截至固定消息上界的全部消息和完整模型正文，不把较新的子轮次冒充原 task 的轮次。新内容通过显式刷新读取。只有当前连接中重新核实且仍活动的准确项可停止，停止请求受理与实际停止分别显示。关闭详情、总览或切换会话只结束读取；冷重新打开不重新发起任务、恢复旧执行或重复取消。当前开发 Native 总览已接入同原 Store 的公开目录；恢复为新 Store 的旧来源后台条目仍按兼容迁移范围核验，准确范围见[实施进度](../../plans/unified-agent-refactor-v1-progress.md)。

历史读取不因累计记录数或字节数超过旧门槛而被拒绝。客户端最多同时组装 4 份历史，其余按序等待；服务端暂时拥塞时，只读页可在时限内等待重试。分页保持准确的会话范围、水位和内容摘要，取消、单页超时及单条消息的解析安全检查仍生效。整份历史最终仍需要相应的实际内存，排队控制并发峰值。

## 工作选择、审批与恢复

用户的新消息直接进入当前会话的主 Agent，共用已有对话上下文。空闲时开始普通轮次；运行中按客户端选择在安全边界引导当前轮次，或排队等待。系统不预先调用另一个模型判定消息“属于哪个工作”，不生成额外的判定回复，也不按正文猜测暂停、继续或另选工作。补充要求、进度问题与改变方向由主 Agent 在普通执行中理解；确需澄清时由主 Agent 正常询问。

同一 Session 至多一个活动父 Run。已派发的动作按真实结果收束；引导不撤销已经开始的效果。新轮次采用用户当前明确选择的模型配置，保留原历史。停止按钮、精确工具调用、root stop、Rewind、删除和恢复仍核准确目标与权限，普通消息不能绕过未知效果的 fence，也不会自动恢复旧 Run。

子 Agent 保留稳定身份和原执行出处，后续父轮次可通过已授权工具继续联系自己的直接子 Agent。完成结果作为具名低信任来源进入当前主 Agent 的安全检查点，不凭技术工作编号隔离同一会话的后续消息；结果接纳仍精确去重，不能当作用户指令或批准。已有排队输入优先占用空闲父轮次，子结果仍可进入正在等待它的活动轮次。

用户引导保留原输入入口；子 Agent 普通消息与最终结果共用会话邮箱，在父轮的同一个接收检查点汇合。父轮仍在运行时接入本轮，结束后普通消息只排队，最终结果按原续跑资格与当前权限决定是否开启后续轮。每条消息保留发送来源和独立回执，重试不重复写入正文、结果或续跑轮；列表、等待与历史读取不代表模型已接收，也不触发续跑。

普通 Agent 邮件接收后，在实际接收轮次的处理过程中显示发送者和完整正文。活动父轮保持原 Run 和同一段处理过程，不新增独立邮件气泡；轮次结束及冷重开后仍可展开原过程阅读，不重复显示正文或耗时。来源证明损坏时明确显示不可读状态；邮件正文不取得用户指令或批准的权限。

所属根会话在运行中改变 `accept_edits`、`auto`、`full` 时，子孙尚未派发的动作按根当前模式重新判定；待人工批准、自动审核和资源等待也会刷新准确决定。放宽可以让原准确动作执行一次，收紧可能需要新的准确批准；旧卡片保持历史并停用，不伪造用户同意。Full 仍受可信只读预设、工具交集、工作区信任、取消和未知效果限制；兄弟及新轮不共享一次性批准。已经发生的效果保留当时事实，不声称模式变化回滚效果。

冷读取只查看已保存历史、稳定目录及来源，不启动模型。显式恢复继续核同一 Store、主体、原 Run／Command、配置、上下文、owner generation 与当前权限；不能验证时明确阻塞。原调用返回值丢失只查原持久回执，相同正文的新工具调用属于新意图，不按文本去重，也不以重做旧效果补回结果。

## 运行中引导与后台执行

子 Agent 完成通知是具名的低信任结果，不属于用户引导。通知在模型请求期间到达时，当前响应中的合法工具仍可继续；通知不会使这些工具被记为授权拒绝，也不会因此阻断后续相同查询。启用沙箱的受管 Shell 在启动确认持久化之后返回运行句柄；即使 `yield_ms: 0`，也不会把尚未准备或派发的命令提前报告为运行中。准备失败仍返回失败结果。同一批其他工具被拒绝或完成时，已经开始的 `shell_stop` 仍按原调用身份保存工具终态，不会因会话版本前进而持续显示执行中。

每次发送保留原 Command、正文和附件；相同文本的两次提交仍是两个独立输入。引导绑定原活动 Run，队列输入只在其前驱结束且会话空闲后创建自己的普通 Run。编辑队列输入先移除对应队列项，再把原文交给输入框，由用户手动重新提交；拖拽和删除不改变当前执行的授权。

有限命令可通过 `shell_execute` 的 `yield_ms` 进入受管后台状态，并用 `shell_read` 读取增量输出或等待终态、用 `shell_stop` 精确停止。普通有限命令完成后也返回 Shell 句柄；终态预览不能替代完整输出。完整输出保存在本机私有临时文件，`shell_read` 按返回的 cursor 分页续读，`moreOutput` 表示仍有未读内容，不因过去的 256 KiB 缓冲截掉历史。句柄和临时输出由当前 Runtime 管理；会话 owner 关闭且进程清理确认后释放该会话的全部临时输出，包括尚未读完的输出。宿主重启后不接管旧进程或旧句柄。等待可因新引导让出，但不会因此杀死进程或重置原期限。本轮必需的有限 Shell 或子 Agent 尚未收尾时，Run 保持同一身份并进入受管等待，而不是空转调用模型或先完成再重开。多个有限 Shell 与子 Agent 错峰完成时，局部终态只更新对应卡片和结果；其他必需工作继续等待，不消耗模型纠错次数。Shell 的 `sleep` 能力没有被全局移除，但不能代替受管后台通知。

新统一链路的子 Agent 在自己的 Run 激活时开始独立的最长 30 分钟执行期限；父 Run 先行耗时与激活前排队不扣减该期限。可信宿主 `maxConcurrentSubagents` 为正整数，默认 3，仅限制同时运行数量；满额的普通 `task` 持久受理并等待空位，不以固定排队数量或等待时长拒绝。旧 `resources.maxConcurrentSubagents` 不是新 Service 的用户配置入口。父 Run 的权限、审批、取消和真实派发资格仍须成立。新子 Run 不分配模型请求、turn、输入／输出 token、工具调用或产物字节的累计额度；已经尝试而结果不明的外部调用不能自动重放。

新子 Run 的单次私有任务／结果／checkpoint 产物、Provider 子任务报告与本地 lifecycle 记录不因过去的固定大小或数量阈值提前失败；内容身份、格式、完整性及实际存储能力仍须成立。模型临时错误的自动重试、工具纠错／安全重试、未显式设置超时的有限 Shell 和子 Run 活动期间的内部并发等待以该 Run 的剩余期限为边界；工具失败的固定纠错次数及“无进展”次数不再提前截断新子 Run，策略拒绝、未经证明可安全重复的外部操作和损坏的恢复记录仍须阻止派发。显式 Shell 超时、Provider 自身上下文／输出上限、取消和执行权限仍生效；未提供输出上限时不再以本地任意 4096 token 值截断新子 Run 的模型回答。

新建与已升级 Run 的工具不因累计 Artifact 额度进入 `artifact_capacity` 等待；没有文件变更证据的 Shell 不再被预留的 256 MiB 记作已知实际产物，因此其后的 `shell_stop` 和写工具仍可准入。历史有限预算记录在升级前沿原规则处理：未知产物上界可能暂时占满剩余额度，Service 为后续工具持久排队；已有工具结算后重新核对额度与执行权。旧活动 Run 升级后，尚在等待累计 Artifact 容量的工具会重新准入。普通工具的执行准备异常若能由持久状态确认未派发，只返回该工具失败并释放预留，让 Agent 在同一 Run 中继续；工具已经尝试而结果不明时保留恢复状态，不自动重试。旧式同步子任务的并发许可等待超时若已提交为 `task` 工具失败，也不再次升级为父 Run 错误。子 Run 期限与未知外部结果仍按各自的安全边界处理。

普通 `spawn_agent` 异步受理并保留有限完成订阅，父 Agent 可以继续独立工作或正常结束当前轮。child 与父分别使用独立 Session 上下文及同一个普通 Loop；父普通结束不取消已可靠受理的 child。完整结果在同工作活动父轮的安全边界接纳；父空闲时，当前资格仍成立的未消费结果最多创建一个普通后续轮，多个就绪结果可合并，每项仍有独立准确来源与回执。已明确要求本轮必需的内部 child 继续沿原 required 等待合同，不因普通协作入口简化而丢失义务。

父 Turn 已结束、某份子结果实际触发续跑时，Desktop 才在父会话显示独立消息气泡，头部标注“〔名称〕Agent 发送”，正文展示这次具体内容并支持 Markdown。气泡紧接原父回复、位于续跑的处理之前；新 Run 正在执行时也能看见。父 Turn 运行中接纳的结果继续由本轮工具与处理过程呈现，不产生独立气泡，父轮后来结束或冷重开也不会补发。同一子 Agent 后续符合上述条件的返回各自保留，刷新和重开不重复生成。较长消息会提示正文未完整展示，可通过“查看完整结果”进入对应子任务详情。失败、取消与结果未知分别显示，消息本身不授予执行权限；内部权限检查和标题生成不会显示为子 Agent 消息。

macOS 与 Linux 上的受管 Shell 不作为 login shell 启动，并移除 `BASH_ENV`、`ENV` 等非交互启动注入，不会在命令之外隐式执行用户的 shell profile、rc 或环境指定的启动文件。命令继承应用已经提供的受控工具链环境；启动文件的权限或内容不会污染本次命令输出，也不会绕过该次工具审批。
这不妨碍已批准的开发期命令按普通文件读取规则显式或间接读取 `~/.bashrc`、`~/.gitconfig` 等文件；读取权限与自动执行启动文件是两件事。

显式 service 可跨本宿主中的正常 Run 保留；`running` 不等于业务已经 ready。`wait_agent_events` 只等调用者邮箱，已有事件立即返回下一批，没有事件时持续有限分段；显式 `wait_ms:0` 为只读快照。有限等待超时与新输入都不取消 child，也不越过未返回的事件。旧事件缺口明确报告 `cursor_expired` 和可核实的恢复边界；重新观察不宣称缺失事件已读或结果已接纳。具名结果与邮件均为低信任数据，不能成为人类授权。Shell 完成不因此取得 child completion 的续轮资格。

Desktop 展示当前及非选中会话的后台 Shell、service 与子 Agent，并只允许对新鲜、仍运行的准确执行发起停止。所选会话的父 Run 正在等待多个子 Agent 时，已结算子 Agent 的卡片会更新为终态，其余卡片继续显示运行；父 Run 保持原身份与等待状态。重新进入会话时，历史中已持久化的后台子 Agent 结果会结束对应运行卡片；读取历史不会为了修正展示而写入新事件。TUI 支持运行中引导和准确停止；Web 只读展示后台摘要，不获得 mutation 权限。宿主退出、崩溃或升级后不承诺本地进程续跑；历史结果保留，无法确认的清理保持 unknown。当前进程树清理已在 macOS 验证，Linux 与 Windows 的本次平台资格尚未实跑。

父 Run 受管等待 required 子 Agent 时，独立子会话的执行权过期或其任务结果变为 `unknown`／不存在，会结束当前等待并提示需要恢复，不持续显示为运行中，也不把未知结果记为成功。历史有限额度的子 Run 若模型输入预算不足以覆盖预留上界，仍在 Provider 派发前以预算耗尽结算。

父子消息只在准确直接归属内受理，不启动空闲目标。活动 child 的同工作追问在安全边界接收，queued child 排入原轮，idle child 受理唯一新轮并保持同一 `agent_id` 与原配置；跨工作不能引导或中断仍 active/queued 的旧轮。已空闲的协作者可以由当前父工作复用，新 carrier 和结果归当前工作，旧结果归属保持。child 无法及时得到父答复时，有限观察后如实交付待决结果；父合法接纳问题或取得真实人类回答后，可对同一 child 发起追问继续，不以技术成功冒称业务已完成。

以下 v1/v2 规则仅说明封存的内部调用和恢复记录，不重新开放旧模型工具名。历史 v1 当前轮续行要求子 Agent 原 Run 仍有准确的未派发模型预算和输入边界；消息在下一次模型请求进入原 Run，已派发的模型请求与工具不会被改写。受限的 `explore`／`plan`／`review` 子 Agent 即使旧 grant 包含工具，也只在可证明的静态只读 `read_file`、`search_content`、`search_files` 模型 Surface 上接纳当前轮消息，之后原 Run 的工具调用继续受这组上界约束；新受理的 v2 请求等待原 Run 终态后尝试新轮。新委派的后续新 turn 在目标 Run 启动时独立开始最长 30 分钟期限，可使用原角色和现行策略共同允许的工具，不设模型请求、turn、token、工具调用或产物字节的累计额度；发送方 Run 的并发额度仍在受理时核验；发送方是子 Run 时还须核验其自身执行期限。父 Run 随后结束不取消已受理的后续新 turn，结果以持久回执和邮箱回复查看。旧 v1 会话继续按原期限、单次模型请求和零工具的持久 grant 回放。此前子 Run 若以外部效果未知结束，新 v2 续轮首个模型输入会明确提示这项未知及不能自动重放原调用；Agent 须先检查持久记录与外部现状。新 v2 续轮等待并发位时保持已受理状态，来源 Run 的原截止时间和较短的容量等待时限不使该排队受理过期；取得执行位后才启动目标 Run，并从此时计时 30 分钟。来源 Run 的用户取消仍按准确受理事实结算。旧有限备付仍按原有界等待规则，超期以 `capacity_timeout` 结算且不派发目标模型。发送方可通过 `list_agents` 或 `wait_agent` 查看具名失败；成功受理本身不承诺目标已经开始执行。

首轮 required 子任务的结果由原父 Run 以具名 `<subagent_result>` 接纳一次；已结算的 `followup_task`（含历史 v1 当前轮和新受理 v2 新轮）均向发送方邮箱发送一次来源明确的状态回复，完整结果仍由 `task_read` 读取。当前轮沿用原 task ID，原父 Run 的 required 结果不会因此重复导入。父 Run 已结束时，回复保留为可查邮件，不自动开启父 Run，也不注入以后的人类 Run。回复进入活动父 Run 的模型输入时仍按低信任 Agent 消息处理。

新独立续轮的 task ID 也可用于 `task_read`、`task_wait` 和 `task_cancel`。历史 ID 读取该次执行的已结算报告，取消已结束的旧任务不会停止同一子 Agent 后来的执行。缺少准确执行证明或清理无法确认时返回不可用或 unknown，不能作为成功报告。

每个子 Agent 拥有自己的持久会话线程和模型上下文，由父 Agent 树访问；内部子线程不出现在空间的普通会话列表、搜索或最近会话。父 Run 的必需子任务仍须等准确结果被父线程接纳才解除义务；子线程自行结束或消息已受理都不足以让父 Run 完成。必需结果义务及完整等待集合不设累计数量或字节额度。正式入口回归覆盖三个子 Agent 同时启动、错峰完成与单子创建失败后的父级结算；普通 Task 持久排队，激活后才开始自身期限。子线程启动失败若无法安全结算，且 Store 接纳需恢复诊断时，父 Run 会报告执行恢复错误，不再继续等待该必需结果。

当前开发版的独立子 Session 工具要求人工审批时，父会话会展示该子工具的待审批卡片；用户只在父会话回答，子工具在父决定持久化并由子 Session 接纳批准后才执行。父会话的订阅更新随真实 revision 推进，批准或拒绝后卡片会结算。子 Session ID 仍不能用于直接回答审批。真实进程重启的待答与父决定已持久化窗口均验证了原子 Session 续轮、子工具恰好一次派发和父结果一次接纳；审批请求、父决定或工具派发证据不完整时仍失败封闭。
