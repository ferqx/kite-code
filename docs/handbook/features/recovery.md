# 取消、继续与恢复

继续入口已支持严格识别的旧全局 MCP 准入等待：保持原任务和消息，不记录用户豁免；真实授权、未知副作用或清理未完成时仍拒绝。提交后派发前崩溃时，继续入口在取得执行权且完整日志证明尚未派发的情况下接续原 Run；有派发痕迹就不自动重放。

已完成且实际清理结束的会话释放执行权；休眠或重连后，下一条输入按需取得新的执行权。历史日志读取只读；进入会话时由 Service 核验并校正失效执行的状态，不重放旧操作。

取消尝试停止当前执行并等待清理，不能撤销已经发生的文件修改或外部调用。结果未知时应先检查实际状态，再决定继续或重新执行。

继续会话是基于已有历史输入新的任务；打开历史本身不应自动重放旧写操作。恢复点提供的是已保存边界，不是任意可见消息都可回滚。

恢复可以涉及会话、代码或二者，具体入口由客户端提供。分叉保留来源并建立新的继续路径；一次性授权不应自动复制成新会话的永久权限。

[TUI 恢复指南](../clients/tui/guides/cancellation-and-recovery.md)说明选择与确认。Web 可展示信息但不提供恢复控制。CLI resume 是继续任务，不能当成与 TUI `/rewind` 相同的代码恢复操作。

发生数据或连接错误时，先按诊断处理，不手工修改正在使用的存储来绕过恢复检查。

桌面和 TUI 在继续操作遇到恢复要求时，先核验持久清理与副作用事实；只有已确认清理且没有未决或未知副作用时自动恢复。桌面错误提示中的“检查恢复”仅核验并恢复允许恢复的会话，成功后重新校准，不自动发送草稿。执行被占用、清理未完成、需要恢复、外部结果未知与存储不可用分别反馈。无法证明旧执行已结束时，保留阻断；检查原执行者及相关外部结果后再处理，不能以租约过期、进程消失或用户接受未知结果替代清理证据。

恢复与发送使用各自命令身份。丢失响应时查询原命令的持久回执；无法查明结果则保持未知，不自动重新提交。尚缺清理证据的历史故障处理范围见[实施计划](../../plans/execution-recovery-optimization.md)。

Desktop、TUI 和 CLI 使用同一正式会话库。启动时可在维护保护下整理已验证的旧 Store 9、Store 11 子集及多个 Store 10 来源；不符合已验证格式、身份或执行事实条件时明确阻止启动，并保留原件供恢复。旧工作区目录不存在或信任失效，不会抹去该会话的历史；历史日志读取仍只读；进入会话时服务端另行核验失效执行，继续执行须重新满足原会话的工作区身份和授权条件，不能借迁移扩大权限。参见[会话连续性实施状态](../../plans/session-store-compatibility-and-continuity.md)。

数据整理保留的是已经提交到会话库的消息、事件、运行记录和关联资料。尚未发送的输入草稿、只在当前界面显示的流式片段不属于数据库保留承诺。Desktop 的草稿只在当前页面进程内按会话保留；完整刷新或退出后不保证恢复。TUI 的输入也不应当作已提交消息，退出前需要自行保存尚未发送的内容。收到结果未知提示时，应核对原任务与外部效果，不能把本地草稿重新发送当作恢复。其他平台与旧版本组合仍以已完成的资格测试为限。

启动整理会显示检查、取得维护权、等待、准备及发布阶段。确认存储被占用时，客户端会自动重新检查和尝试启动，最长等待10秒；占用解除后当前客户端继续启动，无需重开。等待期间可请求退出，程序不强停其他客户端。超时后保留明确的占用提示：Desktop可重新尝试，CLI/TUI可重新启动；身份不明、权限、损坏或未知格式不会被当作忙而反复重试。在已验证的macOS入口，Desktop的应用退出动作或CLI/TUI启动期Ctrl+C会请求安全退出：发布前在安全点取消，发布已经开始则先完成结算。请等待进程真正退出，不把发送请求当作取消成功。意外强停通过下一次启动核对固定发布意图后接续，不通过清空数据解决。CLI/TUI的启动错误会输出脱敏诊断段，可复制保存或重定向标准错误；诊断包含错误类别、阶段与格式数字，不包含原始stderr、路径或会话正文。

已完成的历史会话若仅残留旧执行权恢复标记，发送新消息时会自动核对持久状态。确认旧轮完成、清理已收尾、没有活跃或未知 Run、没有待确认副作用后，直接在原会话开始新一轮，不要求点击“检查恢复”。历史中已耗尽且明确在派发前被策略拒绝的工具记录保留原样，不被当成仍在执行的工具；真实未决执行仍按上述恢复规则处理。

进入已有会话或提交新的执行命令时，Service 自动核验旧执行，客户端不推断任务是否已退出。有有效执行租约的会话保留进度；旧执行被隔离后，Service 核对子 Agent 和沙箱资源，追加中断终态并更新旧 Run、工具与子 Agent 卡片。已完成结果保留，未知结果不改成成功且不自动重试。旧轮已经结束的未知调用不再阻塞新轮调度与完成。明确尚未派发、无其他执行资源的孤立旧审批可自动取消；无法证明已收尾的资源或仍可恢复的复杂交互保留恢复状态。恢复失败不能隐藏已有历史。

历史消息中的“正在工作”不作为执行存活依据。即使会话已结束或切换到后续任务，Service 也会核对旧子 Agent：父工具已失败或取消、子执行身份唯一匹配且子执行清理已确认时，补记缺失的终态。已成功的子任务在完成结果和清理记录一致时补记完成，不能因为原进程退出就改成失败。其他工具的沙箱清理仍待处理时，已经有确证的子任务状态也应更新；待清理资源继续保留原有诊断。重复进入不会重复追加。客户端只展示服务端结果，不自行把旧消息改成取消；仍在存活的执行不受影响。

旧子 Agent 状态校正后，同一次执行的父工具与子 Agent 不应重复显示为两个独立任务。历史记录足以确认归属时，内部工具及其失败信息归入对应任务；真实记录与执行结果保留，不按显示名称合并不同任务。


## 子 Agent 生命周期

子 Agent 具有独立于父工具的生命周期，由服务端持久事实决定；Desktop 和 TUI 展示同一语义。用户主动取消主 Agent 或终止会话时，服务级联停止其所有未完成子任务，包括正在创建、运行、等待或自动审批的子任务；确认停止后标记为已取消。服务关闭、异常失联、超时或执行权丢失导致主任务终止时，子任务同样停止，但标记为已中断。已经完成的子任务保留原结果。父工具卡片结束不能代替子执行停止确认；强制关机来不及写入的状态由下次服务恢复核验并补齐。

| 状态 | 含义 |
| --- | --- |
| 创建中 | 子执行身份及派发意图已保存，正在准备运行 |
| 运行中 | 子任务已经开始或从等待恢复执行 |
| 等待中 | 等待用户审批、输入或执行排队，尚未结束 |
| 自动审批中 | 服务已开始执行该子任务的自动审批；仅排入审批队列仍是等待中 |
| 已完成 | 子任务成功结束 |
| 已中断 | 异常退出、超时等导致执行中断，并有相应服务端依据 |
| 已取消 | 取消执行已确认；仅提交取消请求不立即成为此终态 |
| 已失败 | 明确执行错误或创建失败，不能混同于取消或中断 |

重新进入会话时核验旧执行，已确认的终态不会被迟到的开始／等待事件重新打开。旧记录缺少取消依据时，不把中断猜作用户取消；已完成的子任务也不会因父工具随后取消而改为取消。结果未知与待清理事实另行保留，状态展示不意味着可以重放原操作。
