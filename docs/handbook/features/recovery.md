# 取消、继续与恢复

继续入口已支持严格识别的旧全局 MCP 准入等待：保持原任务和消息，不记录用户豁免；真实授权、未知副作用或清理未完成时仍拒绝。提交后派发前崩溃时，继续入口在取得执行权且完整日志证明尚未派发的情况下接续原 Run；有派发痕迹就不自动重放。

已完成且实际清理结束的会话释放执行权；休眠或重连后，下一条输入按需取得新的执行权。打开历史只读，不接管执行、不重放旧操作。

取消尝试停止当前执行并等待清理，不能撤销已经发生的文件修改或外部调用。结果未知时应先检查实际状态，再决定继续或重新执行。

继续会话是基于已有历史输入新的任务；打开历史本身不应自动重放旧写操作。恢复点提供的是已保存边界，不是任意可见消息都可回滚。

恢复可以涉及会话、代码或二者，具体入口由客户端提供。分叉保留来源并建立新的继续路径；一次性授权不应自动复制成新会话的永久权限。

[TUI 恢复指南](../clients/tui/guides/cancellation-and-recovery.md)说明选择与确认。Web 可展示信息但不提供恢复控制。CLI resume 是继续任务，不能当成与 TUI `/rewind` 相同的代码恢复操作。

发生数据或连接错误时，先按诊断处理，不手工修改正在使用的存储来绕过恢复检查。

桌面和 TUI 在继续操作遇到恢复要求时，先核验持久清理与副作用事实；只有已确认清理且没有未决或未知副作用时自动恢复。桌面错误提示中的“检查恢复”仅核验并恢复允许恢复的会话，成功后重新校准，不自动发送草稿。执行被占用、清理未完成、需要恢复、外部结果未知与存储不可用分别反馈。无法证明旧执行已结束时，保留阻断；检查原执行者及相关外部结果后再处理，不能以租约过期、进程消失或用户接受未知结果替代清理证据。

恢复与发送使用各自命令身份。丢失响应时查询原命令的持久回执；无法查明结果则保持未知，不自动重新提交。尚缺清理证据的历史故障处理范围见[实施计划](../../plans/execution-recovery-optimization.md)。
