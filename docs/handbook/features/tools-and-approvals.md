# 工具、权限与审批

工具可以读取、执行命令、修改文件或访问外部系统。可发现、可请求、获准执行和执行成功是不同状态。

工作区信任确认项目及已展示的额外读取范围，不等同于批准任意命令。运行环境和平台能力限制也不因用户批准而消失。

## 权限模式

| 模式 | 产品含义 |
| --- | --- |
| Ask / Accept Edits | 按当前策略要求用户确认操作；界面名称不能代替具体审批内容 |
| Auto | 需要审批的 Shell 命令先由审批模型判断；模型可批准、拒绝或请求用户。模型调用失败时请求用户 |
| Full | 使用全权限执行模式，不走常规逐项审批；仍受实际可用能力及系统限制 |

计划模式是是否先规划的维度，与权限模式不同。一次审批只作用于当前提供的范围，不默认成为永久通行证。

Auto 下无法静态证明只读的 Shell 命令也先进入审批模型，即使先前审查触发熔断，也不能直接跳到人工审批。明确禁止的操作、执行能力门禁和工具明确要求的用户授权仍由固定规则处理；审查模型无法作出有效决定时请求用户。

审批模型确认通过后，同一调用直接使用单次授权，不再因普通风险分类或模式规则重复审批。调用身份不匹配、取消、必需执行能力不可用和实际执行失败仍会阻止或终止执行。

拒绝的调用没有执行；失败调用可能产生部分作用；未知结果需要核实。审批提交失败时，客户端应保留未解决请求，不显示虚假的已批准状态。

[TUI 审批](../clients/tui/guides/approvals-and-questions.md)提供交互入口；Web 只读查看，不回答审批。
