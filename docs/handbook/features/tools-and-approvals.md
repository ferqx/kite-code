# 工具、权限与审批

工具可以读取、执行命令、修改文件或访问外部系统。可发现、可请求、获准执行和执行成功是不同状态。

普通 CLI、TUI 和 Desktop 的 Agent 宿主默认提供工作区文件读取、列目录、搜索和编辑，以及工作区外用户文件读取、`ask_user`、`web_fetch` 和子 Agent 的创建、消息、追问、事件等待、列表与中断六工具；宿主具备合格 Shell 后端时也提供命令执行与管理工具。配置好模型后即可使用这些日常能力，无需先手工添加工具列表。外部读取使用 `read_user_file`，外部写入和编辑不随此默认开启。显式禁用或移除的工具仍不提供给后续运行；实际调用继续遵守工作区信任、三种权限策略与当前平台能力限制。

## 模型工具名称

模型使用以下名称调用能力；实际提供的集合仍由宿主、当前 Run 配置与平台资格决定。公开名称和参数不扩大原授权范围。

| 能力 | 模型工具名称 | 主要参数或含义 |
| --- | --- | --- |
| 工作区文件 | `read_file`、`list_directory`、`glob_files`、`search_content` | `path` 以工作区根目录为基准；读取用 `start_line`、`max_lines` |
| 文件修改 | `write_file`、`edit_file` | 保留 `base` 原完整文件基线；新建使用 `base:null`；精确编辑用 `old_text`、`new_text`、`expected_matches` |
| 工作区外用户文件 | `read_user_file`、`write_user_file`、`edit_user_file` | 独立绝对路径与准确目标权限；不进入工作区检查点 |
| Shell | `shell_execute`、`shell_launch`、`shell_read`、`shell_wait`、`shell_stop` | 前台执行、后台启动、读取、等待和停止分别处理；保留原操作 `key` |
| 问题与网页 | `ask_user`、`web_fetch` | 普通问题只收集信息；网页时限用 `timeout_ms` |
| 子 Agent | `spawn_agent`、`follow_up_agent`、`send_agent_message`、`interrupt_agent` | 默认通用协作者；稳定 `agent_id`，每次受理仍绑定准确 carrier/轮次；消息只排队，显式追问才续轮 |
| 子 Agent 等待与目录 | `wait_agent_events`、`list_agents` | 事件等待只读自身邮箱，使用 `after_seq/wait_ms`；列表按稳定身份分页，并提供原委派/最近工作/结果的可读来源 |
| 计划与验证 | `read_plan`、`write_plan`、`request_plan_review`、`update_plan_progress`、`define_validation_checks`、`run_validation_checks`、`rebind_validation_checks`、`request_validation_waiver`、`check_file_changes` | 计划保存、批准、进度及真实验证仍分别核实 |

了解、解释、检查或审查项目本身不授权修改项目。未要求保存时直接回复分析，不为探索创建占位文件或报告；误提出的写入仍须经过原审批与派发核验。

工作区文件工具收到工作区外路径时拒绝访问，把失败结果交给模型继续解释，不因该路径把整轮任务终止；不会读取外部文件或外部目录的项目说明。工作区自身必需的项目说明无法安全读取时，仍会明确停止并要求处理来源问题。

`shell_execute.execution_timeout_ms` 是执行截止时限；到期申请取消，并继续核实真实停止。`shell_wait.wait_timeout_ms` 与 `wait_agent_events.wait_ms` 只限制本次等待，不停止目标；Agent 等待省略或 null 时在内部持续有限分段，0 为当前只读快照。等待与取消回执不能冒充执行成功或停止确认。

`shell_read/shell_wait/shell_stop` 使用的本地引用明确不存在时，只结束这次调用并给出纠正信息，Agent 可以继续；本次预查不会启动或停止 Shell，也不取消同批正常读取。存储读取失败、已有引用无法核实或实际效果未知仍按原规则处理，不能编造新 ID 或重启旧命令来取回结果。

`read_file` 和 `read_user_file` 省略 `max_lines` 时默认返回 200 行；`start_line` 从 1 开始，可将结果的续读位置作为下一次 `start_line` 继续分页。工作区读取向模型简洁列出行窗、总行数和 `next_line`，原记录及外部读取仍保留 `selection.nextOffset`。每页保留完整文件的 hash、字节大小和对象基线，不能把页正文当成全文。`search_content` 默认 `mode:files`，按命中文件定位，不返回正文；需要命中行和上下文时使用 `mode:content`。每页默认最多100个文件或100条行命中，`limit` 单位随模式区分；同一文件的大量命中不会占满文件定位页。将返回的 `next_cursor` 交回 `cursor` 继续，保持查询、模式、路径和过滤条件不变；可以调整页大小和内容预览长度。结果仍列出实际范围、后页和未检查项；零命中只说明已检查范围，不证明代码可达性或全局无引用。显式读取范围仍可能很大，行数也不能限制单行字节数；大正文保留完整 Artifact，并继续接受上下文压缩与容量检查。

子 Agent 的事件摘要与结果正文分开：`wait_agent_events` 用于观察事件，`list_agents` 可重读最近一次终态的完整报告。目录中的旧报告不代表正在运行的后续轮次已经完成，也不保证能选择任意历史轮次。报告中的判断仍须结合实际来源核实；单独保存判断不会使其成为验证结果。

同一完整模型回复中的工具可以并行执行；需要同一串行资源的调用仍依次取得资源，每项调用分别核实完整参数、当前权限和执行来源。历史按实际结果保存顺序记录，下一次模型调用按原工具声明顺序接收完整配对结果。用户明确拒绝人工审批会终止本轮，已开始的工具须完成取消与清理。自动审核明确拒绝某项工具时，该项保留未执行与具体原因，不把审核器的拒绝当成用户停止整个任务；模型可继续原任务中已授权的路径，后续工具仍独立核权限，不重投原调用或换工具／路径绕过同一拒绝。结果不确定或保存失败仍停止推进并保留真实失败，不能提前继续调用模型或显示任务完成。

只读文件探索首次进入带有 `AGENTS.md`／`CLAUDE.md` 的目录时，读取、列目录、查找与搜索正常完成，新发现的指令和真实工具结果一起进入下一次模型请求，不把正常发现当成工具失败，也不要求整批重发。已被模型使用的指令发生修改或删除、能力变化和有副作用的调用仍须重新核实。用户补充输入及完成条件的并发变化在同一 Run 的安全检查点重新评估，不重放已完成的操作。

会话可持续多轮使用；正常执行和停止不以累计回复数、成功执行数或历史子会话数设置配额。同时运行的资源和单批读取仍有界，正常锁竞争或内部队列拥塞应等待资源释放并继续，取消和关闭仍可响应。子 Agent 每次 Run 的 30 分钟期限保持；主任务完成后正常结束，不为持续使用而继续空转。真实未知结果、权限拒绝、网络或程序错误仍如实保存，不能当成正常等待后自动重做效果。

工作区信任确认项目及已展示的历史额外读取范围，不等同于批准任意命令。开发期 Native Shell 在命令获准后默认具有宿主权限允许的广泛只读视图；文件工具和封存生产执行仍按各自的路径范围。运行环境和平台能力限制也不因用户批准而消失。

当前统一链路的 macOS 默认 Shell 使用宿主工具链，允许命令派生子进程并保留宿主 HOME。请求批准默认允许当前 Workspace 与本次私有临时目录写入，并关闭网络；Shell 可为本次调用明确请求外部写入或联网，取得准确批准后分别开放。外部写入批准不附带网络，联网批准不附带外部写入。Auto 按实际模型决定使用同一请求范围，Full 允许宿主权限内的普通外部写入及联网。所有范围保护实际 Profile、协调目录和运行资产，不能通过移动父目录绕过保护；私有临时目录中的 native 程序不能直接执行或映射，Workspace 网络范围也拒绝 Unix socket 绑定与外连。缺可信资产、最终范围或可核实监督后端时调用失败。Windows/Linux 的实际执行交后续 GitHub Actions，Windows 正式 Shell 后端仍缺失、继续失败关闭；不由 macOS 结果推定平台资格。

复杂 Shell 不能靠命令名称保证只读或无网络。正式入口使用有限字面量语法解析和固定极危险拒绝，其他脚本由已授权系统范围限制，所有子进程继承该范围。越界失败可能已有其他部分效果，不自动扩权重跑；极危险的关键系统删除等操作在三种策略下都先拒绝。

Linux 默认 Shell、调用 Shell 的 Task、Skill 验证和严格 Workflow 补偿已接入对应范围的源码后端，实际 Linux 运行资格仍待上述验证。验证脚本在原 Skill 目录执行，写范围仍受原 Workspace 授权约束。Profile Skill 的可信来源复核会只读开放准确原 Skill 子树，保留相对资源读取；其余 Profile 内容、来源写入和移动仍受保护，普通 Shell 不获得这个例外。macOS 已有实际来源验证，Linux 尚待原生验收。完整 Workflow 能力迁移仍未闭合，范围与证据见[实施进度](../../plans/unified-agent-refactor-v1-progress.md#2026-10-10profile-workflow-原来源与正式-verifier-迁移)。

Shell 启动、读取、等待和停止使用同一个持久 Job。提交停止只表示取消已受理；确认停止必须核实本次命令的完整后代，包括脱离原进程组的后代。Shell 自然退出和所属 Service 退出也执行这项清理。输出丢失区间和未知结果如实保存，冷读取不会重新运行旧命令。

子Agent的模型回复结束时，它发起的附着Shell可能仍在排队或运行；原子任务继续等待这些执行结算，父Agent不把模型结束当作整个子任务完成。明确选择独立后台关系的Shell保持自己的生命周期，不阻止已经完成的子任务交付。查看输出或切换主／子会话只结束相应读取；明确停止仍针对原任务，并等待实际执行结果。

Shell 输出读取故障会保存失败与可核实的错误原因，并收束原任务；它不显示为用户取消。停止无法确认时仍保未知，失败可能已有部分效果，不自动重跑。

## 权限模式

| 模式 | 产品含义 |
| --- | --- |
| 请求批准 / Request Approval（`accept_edits`） | 工作区内写入允许；工作区外写入及互联网访问需要准确调用的用户批准，包括 Shell 和 `web_fetch` |
| 自动审核 / Auto（`auto`） | 审批模型判断操作；批准后执行，明确不安全则拒绝并保留原因；模型不可用、无效决定或请求用户时按原流程人工处理 |
| 完全访问 / Full（`full`） | 使用宿主权限允许的普通文件和网络范围，不走常规逐项审批；仍保极危险拒绝、Runtime 权限对象保护及系统限制 |

自动审核属于权限系统的内部模型调用，记录名为 `authorization.check`。它不创建子 Agent 或子会话，不占子 Agent 并发槽，也不进入子 Agent 列表。`review` 只作为通用子 Agent 的代码审查类别；检查决定、原调用与人工回退记录仍可追溯。

正式权限入口、协议和持久控制仅支持上述三个选择。旧严格 `ask` 已退役；旧模式输入或控制记录明确拒绝，不静默转换。

计划模式是是否先规划的维度，与权限模式不同。一次审批只作用于当前提供的范围，不默认成为永久通行证。

新统一 Agent 链路的审批缺省为“仅此次”。只有当前原审批卡实际提供“本 Session 相同命令”时，用户才能显式选择该范围；它绑定真实来源 Session、定义版本、命令与执行环境，子会话和父会话不互借授权。命令、环境、版本或现行权限变化仍需重新核对。授权目录可查看原审批及执行出处，并按已观察版本清除该 Session 的授权；清除不改写此前效果，响应丢失时查询原意图。正式 CLI stdio、Terminal 共享面板及 Native 窗口已消费这一公共能力，完整权限行为与其他平台资格仍见[实施证据](../../plans/unified-agent-refactor-v1-progress.md)。Web 保持只读。

Auto 下需要审查的调用按当前任务、准确参数和授权进入审批模型；重复调用次数或此前拒绝次数不再自动拒绝调用或改成人工审批。同一路径的不同编辑按完整参数区分。明确禁止的操作、执行能力门禁和工具明确要求的用户授权仍由固定规则处理；审查模型无法作出有效决定时请求用户。审查请求保留完整任务、计划与已提供的拒绝理由，不用固定长度裁剪这些授权上下文。

审批模型确认通过后，同一调用直接使用单次授权，不再因普通风险分类或模式规则重复审批。调用身份不匹配、取消、必需执行能力不可用和实际执行失败仍会阻止或终止执行。

拒绝的调用没有执行；失败调用可能产生部分作用；未知结果需要核实。审批提交失败时，客户端应保留未解决请求，不显示虚假的已批准状态。

文件修改因基线冲突被拒绝时，本次请求没有发布，之前成功的其他修改仍保留。基线核对完整文件的身份与版本，冲突不证明两次编辑修改了同一段文字。旧读取不能证明冲突后的当前内容；需要继续编辑时，应在原任务授权范围内重新读取并使用新基线。冲突回执不代表整批回滚，也不自动授权重做。

通用 Agent 的大人工审批请求使用完整附件，有限卡保留原调用与可选授权范围；读取附件后再决定。正文大小不使后端截断参数或扩张授权。普通问题的回答只提供信息；即使问题用于 Workflow replan/waiver，也不等于批准后续工具。等待期间现行权限变化时，旧答案不能授予执行。

文件工具不再因过去的整文件、累计搜索匹配数、修改原文或模型结果长度上限拒绝操作。读取工具按显式 `start_line`、`max_lines` 或默认 200 行选择内容，并给出续读位置；搜索按下述分页和预览合同返回，未读范围不能冒充全文。读取大文件、搜索单个大文件以及读取完整 Artifact 正文期间，其他会话可以继续处理，取消会在读取检查点生效；返回成功前仍核所读完整文件和原引用。文件路径权限、目标身份、原文摘要和原子发布检查仍生效。数据能被读取不代表任意模型均能在一个请求中接收它；Provider 的真实请求容量仍生效。

Windows x64 本地 Workspace 的六文件工具及检查点原字节恢复已接入源码后端，完整 Windows 运行与安装版资格仍待验证。操作绑定原 Workspace 对象，不修改已有文件或目录的 ACL。Windows 的备用数据流、设备名、尾点／空格、重解析路径及短名别名会明确拒绝；受保护目录不能借大小写变体绕过。实际能力和验证边界见[Files owner](../../../packages/agent/src/tools/files/README.md#windows-workspace-文件源码)。

工作区文件工具接受相对路径和该工作区内的绝对路径；相对路径始终以当前工作区根目录为基准，不随 Shell 的当前目录变化。列目录、查找文件和搜索内容省略路径或使用 `.` 时选择工作区根目录。Windows 可使用原生反斜杠。绝对路径不会自动开放工作区外访问，目录穿越、受保护路径及实际文件身份检查继续生效。

`write_file` 新建文件（`base:null`）时会在工作区内逐级创建缺失的父目录，例如空项目中的 `examples/agent_demo.py`。创建沿同一物理目录边界，不跟随链接，不修改已有目录权限；覆盖、编辑和工作区外文件仍要求父目录已存在。审批通过只代表允许执行，不能消除路径占用、系统权限或保护边界限制。

写入失败会给出错误码、请求路径和处理建议，区分目标或父目录缺失、父路径被文件或链接占用、访问被拒绝、非法路径及受保护目标。Agent 应先处理原因，再决定下一次操作；重复相同路径和参数不能修复这些原因。失败后可能留下已创建的空父目录，文件检查点恢复也只恢复文件，不删除这些目录。创建或发布结果无法确认时保留未知结果，不能重放写入。

访问工作区外的用户文件使用独立绝对路径工具；外部写入遵守当前权限模式，获准后仍检查准确目标和原文件基线。Windows 的普通路径大小写变体可使用，受保护路径不能借此绕过限制。外部文件修改不进入工作区检查点，工作区恢复不会撤销它们；实际平台验证范围见上述 Files owner。

`glob_files` 的文件 glob 中，完整目录段 `**/` 匹配零层或多层目录，因此 `**/*.ts` 包含搜索根目录的 `.ts` 文件。`search_content` 按字面文本搜索单文件或目录，默认每页 100 条匹配、每行最多 2000 字符预览；可指定 `glob`、`context_lines`、`max_line_chars` 和 `respect_ignore`。沿 `next` 续页，预览标明 `truncated` 和原行长度，完整内容可用 `read_file` 读取。

文件查找和内容搜索默认遵循工作区根目录到所选子目录的 `.gitignore`，进入被忽略目录前即跳过其子树；例如在子目录搜索时仍排除根规则中的依赖和构建产物。两者均可用 `respect_ignore:false` 包含普通忽略项，直接读取文件和显式单文件内容搜索不被普通 ignore 隐藏。所有选项继续受原路径和权限约束。内容搜索的二进制、非 UTF-8 和链接等跳过项以当前页 `scope` 给出数量与有限样例；数量按条目计，忽略目录不统计其后代。`scope.complete:false` 或非空 `next` 不能当成完整无匹配证明，权限与 I/O 错误不作为二进制忽略。

文件查找和内容搜索在遍历期间允许其他会话继续响应，停止原任务可中断其在途遍历；分页仍按原完整路径游标继续，不以累计扫描额度隐藏后续结果。MCP 工具使用 `search_mcp_tools` 查找本轮已选择的工具；`list_mcp_sources` 查看来源目录，来源目录不代表全量工具清单。

`web_fetch` 默认返回完整提取正文，不再使用旧的 8K 默认长度或 16K 参数上限；显式 `max_chars` 是该次调用选择的内容长度。有效跳转链不再受默认 3 次限制，真实循环仍会被拒绝，每次跳转继续检查网络权限与 SSRF。默认总时限为60秒，从获准执行后开始，包含DNS、代理连接、robots检查、域名队列、正文读取和页面解析，不包含审批等待；可用 `timeout_ms` 为单次调用指定正整数毫秒时限。用户取消立即申请结束本请求，不需要等待60秒；实际资源停止仍按原取消规则核实。外网响应体在读取过程中按实际字节检查 5 MB 解析安全上限，防止远端无界响应耗尽内存；这不计入 Run 累计产物用量。

请求批准的 `web_fetch` 在用户批准前不开始 DNS 或连接；Auto 使用实际模型审查，明确拒绝无网络效果；Full 不走常规审批。普通开发配置下，获准的 `web_fetch` 可访问公开网站及其公开跳转目标；每次请求继续检查实际 DNS 地址并拒绝私有、保留和本机地址。封存执行配置仍按明确的网络关闭或主机名单限制执行，审批不会扩大该范围。

默认本机宿主的网页工具无需填写代理配置：优先读取大小写 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`（小写优先），没有 HTTP(S) 环境代理时读取 Windows 当前用户或 macOS 已登记的手动系统代理；Linux 使用环境变量。没有代理则直连。`NO_PROXY` 只选择是否绕过代理，不能允许访问私网。系统 DNS 的全部候选都是已识别的 Fake-IP（`198.18.0.0/15`、`2001:2::/48`）时，自动经相同出口向 Cloudflare 发起加密 DNS 查询，检查得到的全部真实 IP 后再连接；正常 DNS、混合地址或私网目标不会借此绕过检查。查询仅包含目标域名，不发送网页路径或正文。

代理只接收已检查的目标 IP；网页原域名仍用于 Host、TLS 名称与证书验证。每次重定向重新检查，不扫描本机端口、不自动执行 PAC/WPAD，也不会在代理失败后悄悄切换为直连。当前支持无需认证的 HTTP/HTTPS CONNECT 代理，不支持 SOCKS、代理账户认证或 PAC；遇到这些设置会明确报告对应网页工具失败，其他工具仍可使用。自动读取 macOS 设置发现已启用 SOCKS 时，即使同时登记 HTTP/HTTPS 代理也明确失败；可在用户配置显式选择受支持的 HTTP(S) 入口，而不是自动猜测混合设置的路由。特殊网络的备用设置见[网页网络配置](models-and-configuration.md#网页网络配置)。

[TUI 审批](../clients/tui/guides/approvals-and-questions.md)提供交互入口；Web 只读查看，不回答审批。

运行、等待审批、自动审核或等待资源期间都可以修改根会话的审批模式，使用自定义权限策略的宿主也保留这个入口。主 Agent 和已经运行的子孙 Agent 在后续工具进入审批层时读取根会话最新已应用模式；已经进入审批层但仍待批、尚未派发的动作也按新模式重新判断，无须新建任务或重建子 Agent。已派发工具按原授权收尾，切换模式不回滚效果或热修改正在运行的 Shell 范围。Desktop 普通工具待批保留输入区和权限选择器，切到 Auto／Full 后原待批项重新判断；浮卡逐项切换，批准范围仍分别属于原工具和来源会话。问答、计划及 MCP 来源／凭据等特殊交互继续沿各客户端自身显隐约定，具体入口见[桌面说明](../clients/desktop/README.md)。

旧卡片失效后保留历史，不准许迟到答案授权其他轮；Full 仍不能解除只读预设、工具范围、工作区信任、自定义策略的硬拒绝或明确人工要求，以及未知效果限制。TUI 与 Desktop 收到控制变更后重新读取当前权限，子会话的继承显示也同步更新。模式与一次性准确批准分别核实，详见[执行与结果](execution.md#工作选择审批与恢复)。
