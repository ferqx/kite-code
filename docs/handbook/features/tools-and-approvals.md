# 工具、权限与审批

工具可以读取、执行命令、修改文件或访问外部系统。可发现、可请求、获准执行和执行成功是不同状态。

宿主按原回执核对文件基线、计划版本、MCP 连接和工作身份。模型通过路径、会话号或协作者目标提出操作，已有授权条件和记录继续适用。

普通 CLI、TUI 和 Desktop 的主 Agent 默认有13项基础模型工具：5项文件与图片工具（读、写、编辑、看图、复看），以及 `ask_user`、`web_fetch` 和6项协作工具。Shell 提供启动、续读和停止三项，Git 工作树另占1项。浏览器能力按宿主配置提供。`read_file` 同时接受准确工作区外绝对路径，不加载外部项目指令。`read_file/write_file/edit_file` 在自动审核模式先经自动审批；只有具体高风险操作才请求用户确认，信息不足本身不要求确认，普通任务内必要的同目标文件校验由审核模型依据现有证据判断，不能默认放行；Auto 内外文件均按实际权限审核，工作区外路径本身不代表禁止或网络外传；请求批准模式在工作区内直接执行、普通外部路径先请求用户批准；完全访问模式按有效权限执行。父子权限、受保护资源、准确文件基线和原生安全检查仍有效。专用 `read_user_file/write_user_file/edit_user_file` 已移除。显式禁用或移除仍不向后续 Run 提供工具，实际调用继续核当前权限、工作区信任和平台能力。

`read_file` 按行读取 UTF-8 源码、脚本、工程配置和项目说明。覆盖已有文件时，宿主核对 Agent 实际读取过的版本。有并发变化时，需要先重新读取后再决定是否修改。PDF、Office 文档、CSV 和压缩包交给受管 Shell 和相应技能。长命令返回会话号，可继续读取原命令输出或停止该命令。

读取 PDF 时，Shell 的随包助手可以提取指定页文字。需要核对扫描件或版面时，渲染指定页，再用 `view_images` 查看返回的 PNG 路径。上传文件沿用发送时准备的工作区副本和当前权限。`read_file` 返回 `unsupported_file_type` 时，回执给出处理入口和原请求路径。

`view_images({paths:[...]})` 按文件只读权限一次读取1至10张本地 PNG、JPEG、WebP 或 GIF，也兼容单图 `view_images({path})`，两种参数不能同时传入，列表不能含重复路径。支持工作区路径、允许的外部绝对路径和当前有效的上传原件，不接受 URL。每张原图最多16MiB、3200万像素、单边16384；应用 EXIF，动画取首帧，最长边缩至2048且不放大，每张PNG结果最多8MiB、整批最多16MiB，实际缩放在结果中说明。按请求顺序处理和交图；任一图片失败、取消或超限，整批不向模型交付部分图片。失败不会授予换路径或绕过权限的许可。较早图片可以从当前请求移出，不能把之前见过当作本次已经收到；需要细节时可复看当前历史中的受管原图。工具读取不提供编辑基线。

`reinspect_images` 可以列出当前会话仍有权访问的图片来源，再按原来从1开始的序位复看（每次1至4张）。它不重新打开原文件，也不重做之前的工具操作。因此即使工作区文件已改名或删除，已保存的看图结果仍可使用。若选中的受管原图缺失，本次所选图片一张也不发；恢复后只需再次选择所需序位。即使复看的结果只含原第4张，再次复看时仍选原来源的第4张，不把它当作新来源的第1张。无法核实来源时不会泄露其他会话的图片。

上传原件和实际交给模型的图片保存于当前 Profile 的不可变 Blob 目录，后续历史、Fork和冷重开读取保存结果；工作区原路径删除不影响已完成的视觉记录。仍被引用的图片不按临时缓存过期删除，目录与生命周期见[Files owner](../../../packages/agent/src/tools/files/README.md#本地保存与缓存目录)。Native 成功工具消息显示“已查看 N 张图像”和圆角缩略图，默认展开，可折叠；数量只统计已核实的成功图像，读取中、失败和取消各保留原状态。

五个专用验证工具和自动检查文件变更、强制验证完成、waiver 机制已退役。Agent 使用普通 Shell 运行测试，并按实际输出报告结果。`request_plan_review` 和原计划审批继续保留。已退役工具在历史会话中以原工具 ID、状态和原结果通用显示，不再显示旧专属动作名称、推断目标或提供文件操作；历史记录不会因此删除。

Windows x64 桌面端按会话使用「集成终端 Shell」选定的命令方言。[常规设置](../clients/desktop/README.md#在-windows-上安装更新和卸载)只显示 Git Shell 和 PowerShell，默认优先 Git Shell。从 Kite 启动环境的 `PATH` 定位 Git 并识别同一安装的 Git Bash，未发现完整安装时使用已核验的 PowerShell。PowerShell 自动选择本机最高可用版本；只有系统版本时使用系统版本。保存失败后，设置页会重新读取当前选项。系统提示向模型标注当前工作区、操作系统、实际 Shell 方言、已核验的解释器版本及可用的 Windows 用户区域，并说明 Kite 按 UTF-8 解码命令输出。对 PowerShell 中的 `rg`，系统提示用目录作搜索路径、用 `-g` 筛选文件。工具自身的语言和区域格式取决于各程序。Git Shell 的 `ls`、`cp` 等命令由本机 Git for Windows 提供，可用命令和参数取决于所安装的版本。Git Shell 在各模式下均从原装 Git for Windows 启动，不复制解释器。它以当前普通 Windows 用户权限运行，可访问该用户可用的文件和网络，没有只读、工作区或断网沙箱。非完全模式下须对本次原装进程确认，旧的窄范围授权不通用；若任务必须隔离，不应使用此 Shell。所有解释器均可使用内置 `rg`。系统工作环境提示包含随包 `rg` 的已核验版本。分支和工作树操作需要 Git。实际运行与发布范围见 [Windows 状态](../../active/windows-shell-sandbox.md)。

Windows Shell 在后台执行，不弹出额外终端窗口。对于受限的 PowerShell，可核实的只读命令使用只读范围，可在首次可写执行准备工作区权限前运行。首次可写准备可能随文件数增长而耗时，等待或准备期间也可停止。再次执行会补全未完成准备，随后执行本次命令，已取消命令不会重跑。

每条 Windows Shell 命令从工作区根目录或指定的工作目录独立开始。切换目录或设置环境变量只影响本条命令和它启动的进程，指定工作目录本身不授予新的权限。不同会话可并发执行，输出和停止分别归属原任务。同一工作区内的文件仍然共享，修改相同文件或 Git 索引需要协调。

Windows Shell 确认具体命令查找未命中时，Kite 从本次启动 PATH、Windows App Paths 和显式工具目录提供本机候选路径及来源。脚本自行处理查找失败后仍可收到候选，最终退出码照常保留。可在 Windows 客户端启动环境中用 `KITE_SHELL_TOOL_DIRS` 指定以分号分隔的本机绝对目录，Kite 会将配置传给 Service。候选路径由后续普通 Shell 调用按现有授权核验和使用。

Windows Shell 命令退出时会停止它启动的剩余进程，后台执行也遵循同一规则。需要本地辅助进程时，在同一条命令中启动、使用、保存修改并关闭它。跨命令继续编辑时，下一条命令从磁盘重新打开文件核对已保存的内容。在使用受限 PowerShell 时，工作区权限可能拒绝双向访问按默认权限创建的命名管道。可以独立完成任务的 CLI，应优先使用它支持的单进程或独立批处理模式。确需双向访问受拒的本地管道时，可按现有授权流程为该条命令申请完整文件范围。仅以本地命名管道通信时，可保持 `network:none`。

内置技能和自装技能使用相同的 Shell 环境。需要核实本机依赖时，Agent 可在实际 Job 内检查命令解析和版本。PowerShell 会保留可确定的单条原生命令退出码，并报告未捕获的命令找不到和程序启动失败。多步脚本应显式检查关键步骤的退出状态。中间文件留在工作区。验证成品后，交付命令可同时返回已保存文件的绝对路径并复制成品到本次成功 Job 的 `KITE_OUTPUT_DIR`。Agent 在回复中引用实际保存位置。

PowerShell 的复合脚本在本次执行的顶层作用域运行，函数可读取本次脚本定义的 `$script:` 变量。脚本末尾未处理的失败按实际 PowerShell 语义报告；主动处理非零结果、提前返回及显式退出保持相应行为。Git Bash 支持超过 Windows 启动参数长度的脚本，脚本仍可通过管道和 here-document 给程序传入数据。

派发前仍完整检查运行资产，校验以异步方式进行，其他会话可继续执行和停止任务。在校验中取消的命令不会启动；停止会等待已开始的读取结束并关闭文件。

`git_worktree` 提供 `list/create/remove/observe/use/exit`。list 是来源 checkout 所属仓库的实时登记快照，不代表目录干净或可以删除。create 的意图身份由宿主绑定本次工具调用，模型不填写 key；省略 path 时默认在 `~/.kite-code/worktrees/` 下按原意图稳定分配目录，也可显式给出不存在的原生绝对路径。创建目标不能位于系统临时目录或其真实路径别名内。默认从来源 HEAD 的固定提交创建 detached 工作树；`base_ref` 指定起点，`new_branch` 创建新的本地分支。创建不复制未提交/未跟踪/忽略内容，不 fetch、不安装依赖，保留当前 Session cwd。变更使用顶层 `filesystem`，默认 `workspace_write`，network 固定 none；仓库公共元数据和目标均须在授权范围内，外部目标须明确请求 full_access 并获准，不能自动扩大权限。返回的 `operation_ref` 可用于 observe，只读取原意图和 Job 记录；未知结果不会因此重放创建或删除。

列表、创建和切换都先核当前执行目录所绑定的 Git 仓库。把仓库内的普通子目录单独作为工作区时，可以打开仓库根或已登记的工作树再发起操作。切换失败会说明是源仓库未绑定、目标未登记、目标属于其他仓库，还是已核实的目录发生变化。

模型指导要求所有工作树创建只通过 `git_worktree`，不通过 Shell 或脚本兜底；工具不可用时如实报告。此要求由提示词传达，普通 Shell 没有新增 Git 命令拦截器。list 和 prepare 不创建默认根；缺失父目录只在获批 mutation Job 中逐级创建，失败残留及未知效果继续保留。普通 Shell 不再自动遮挡 `~/.kite-code`、Profile、配置、认证或运行目录；原审批、文件／网络申请范围和非常危险系统级命令兜底保持。

remove 只接受同仓库的 linked worktree，保护主树、当前来源、已登记 Workspace 根、未确认任务、locked/prunable、所有本地内容（含 ignored 和额外空目录）、索引特殊标志、子模块、链接与挂载边界。当前 HEAD 及完整 HEAD reflog 的 old/new 提交必须由本地分支或 tag 保留；仅远程引用或 detached HEAD 不够。扫描、历史或占用证据不完整时拒绝，删除保留分支和 tag，不 force、prune 或递归清理。

默认可写 `general` 子 Agent 可以在父子工具与权限交集内使用这三个 action。子 Agent 的审批显示在主会话，仍归属原子会话和原调用；父 Agent 的委派文字不授予额外权限。Auto 模式下，准确注册的 `git_worktree` 及其封闭内部步骤不进入自动审核或人工审批；普通 Shell 不享受该例外。手动模式下，一次创建或删除的业务批准覆盖该原工具唯一的 prepare／mutation 两个内部步骤，正常外部范围场景各批准一次。每个 Job 继续独立核当前权限、固定步骤和最终派发，父子交集、独立人工上限及硬性限制保持。创建许可不自动授权后续删除或其他任务。只读 `explore` 子 Agent 和未批准计划下可以执行 list；`explore` 的 create/remove 是工具硬限制，Full 也不解除。

“使用此工作树”通过 `git_worktree` 的 `use` 和准确绝对路径，只改变当前会话执行目录；目标必须是同仓库的真实 linked worktree。`exit` 回到该会话原工作区，不删除目录、登记、分支或文件。创建本身不切换，路径通知、Shell `cd/workdir` 也不切换。使用／退出须独占一次模型工具响应，可在同一轮执行中完成；成功后下一步的 Files、Shell、项目指令、审批和代码恢复点使用一致的目录。已有后台任务、其他会话和既有子会话保持原目录，新子会话继承派发时的目录。权限、只读角色及 Planning 上限不因切换放宽。只有明确要求删除具体工作树才进入 remove；Auto 免审批不替代用户任务授权或删除保护。客户端“返回来源会话”是另一项阅读导航，不改变当前会话执行根。

子 Agent 创建真实成功并保存稳定回执后，通过现有持久消息通知主 Agent，包含准确路径、HEAD、分支及原操作出处。主 Agent 沿既有消息或明确 follow-up 将信息转给需要该路径的子 Agent；排队成功不代表对方已读。通知失败或结果未知只描述消息状态，不改写 Git 已成功事实，也不重跑创建。两个可写子 Agent 可以共享或分别使用工作树；通知不改变默认 cwd、编辑权限或现有并行能力；接收方须明确 use 才改变自己的执行目录。

审批可能在业务模型可见消息之外由用户处理；成功回执或模型未见弹窗，不能证明没有审批。模型只在原始证据支持时报告审批来源或次数，否则不作该结论。内部步骤复用原批准也不等于整项操作免审批；实际批准与派发仍按原记录核验。

变更 key 只用于观察同一次意图。改参数会冲突；旧成功回执保留原时间，即使路径重建也不再执行。结果未知时只观察原操作，不能换 key 重跑。中断可能留下目录、登记、分支或锁，工具如实报告且不自动清理。工作树共享 Git 对象与 refs，不是安全沙箱；删除前应停止使用目标。支持范围、具体错误和平台证据见 [Worktree owner](../../../packages/agent/src/tools/git-worktree/README.md)。

`git_worktree` 在失败回执中按已记录的实际阶段向模型提供指引。进程启动失败说明 Git 子进程未能启动，即使错误为 `spawn EPERM/EACCES` 也不表示用户拒绝审批；权限拒绝只依据原权限策略或操作系统明确的访问拒绝；Git 命令失败说明 Git 已启动并返回非零退出码。其他核验失败保留具体原因，旧记录没有分类时不猜测。Agent 应先解决准确原因，不能重复相同调用、换 key、改参数或改用 Shell 反复尝试，也不能自动扩大权限。部分作用、结果未知或清理未确认时，只核对原操作和原 Job 的保留证据。

## 网页搜索

自动模式优先使用已通过资格验证且获本次权限允许的官方 OpenAI 原生搜索。其他情况下，网页搜索沿用模型设置里已启用的官方 DeepSeek 提供商。无需为搜索再次输入密钥。若有多个 DeepSeek 提供商，优先使用本次明确选用的模型所属的提供商，其次使用明确配置的默认模型所属的提供商。仍不能唯一确定时，普通搜索不可用。模型列表的排列顺序不会决定使用哪个提供商。

桌面“设置 → 网页搜索”只显示搜索来源和备用状态。“管理提供商”打开已有的“提供商与模型”；无需另建搜索账户。打开此页不会发起搜索。Service 的显式测试使用固定查询 `Kite web search connectivity test`，成功但没有结果也可能计费。每次 Run 启动时固定搜索路线；切换提供商、轮换密钥或停用配置不改变已接受的执行。普通搜索工具按当前权限审核，每个 Run 最多预留六次请求。搜索超时、取消或断流后不会自动换账户重发。关闭搜索后仍可用 `web_fetch` 读取已知网址。

桌面会话中，展开普通搜索行可按顺序浏览来源标题。等待来源或没有可展示的来源时，来源区域留空。读取失败时在展开区提示。站点图标来自本次应用运行中同一会话手动打开的 HTTPS 页面所内嵌的 PNG；缺失时显示地球，不为图标访问网站。点击标题在内置浏览器打开；“来源详情”展示域名和已保存的摘要，超过八个来源时可以继续展开。收起、展开或重开会话不会重新发起搜索。

## 模型工具名称

模型使用当前 Run 提供的工具和参数。宿主按当前 Run 配置、权限与平台资格选择工具。Shell 的可选 `description` 用于展示执行目的，浏览器和技能根据实际操作生成显示。执行状态以实际回执为准。

| 能力 | 模型工具名称 | 主要参数或含义 |
| --- | --- | --- |
| 文件读取 | `read_file` | `path` 以工作区根目录为基准，工程文本使用 `offset/limit` |
| 历史图片复看 | `reinspect_images` | 先用 `{list:true}` 列来源，再用该来源的 `locator` 与递增的 `ordinals` 精确复看 |
| 本地图片 | `view_images` | `paths` 按序指定1至10张本地图片；也兼容单图 `path`，两者互斥 |
| 文件修改 | `write_file`、`edit_file` | `path,content` 写完整文本。`path,old_string,new_string,replace_all?` 做精确替换。覆盖或编辑前读取同一路径，宿主从模型已见的记录选用完整基线 |
| Git 工作树 | `git_worktree` | `action:list/create/remove/observe/use/exit`；create 不切换，use 明确路径，exit 回原工作区且不删除 |
| Shell | `exec_command`、`poll_command`、`terminate_session` | 以 `cmd` 启动，按 `yield_time_ms` 返回当前输出或原会话状态。使用返回的整数 `session_id` 续读或停止 |
| 问题与网页 | `ask_user`、`web_fetch` | 普通问题可直接收集自由文本或提供选项。网页时限用 `timeout_ms` |
| 子 Agent | `spawn_agent`、`follow_up_agent`、`send_agent_message`、`interrupt_agent` | 创建时提供 `task_name/message`，可选 `agent_type`。继续、留言或中断使用返回的 `target`。用 `dispatch_id` 核对每次派发的结果 |
| 子 Agent 等待与目录 | `wait_agent`、`list_agents` | `wait_agent(timeout_ms?)` 观察该父会话的邮箱。`list_agents()` 查看协作者、当前派发和最近结果 |
| 计划 | `read_plan`、`write_plan`、`request_plan_review`、`update_plan_progress` | 计划保存、批准和基于真实回执的进度分别核实 |

了解、解释、检查或审查项目本身不授权修改项目。未要求保存时直接回复分析，不为探索创建占位文件或报告；误提出的写入仍须经过原审批与派发核验。

`read_file` 可按当前模式授权读取工作区外的工程文本。可安全编辑的目标返回完整编辑基线，其他外部读取保持只读结果，也不因硬链接一律拒绝。统一权限仍检查禁止范围与实际路径，基线本身不授予写入权限。普通工作区或外部文件在本次读取中确认不存在时，返回正常观察 `File does not exist: "<path>".` 和 `exists:false`，界面不以失败红色呈现；不伪造空正文、行窗口或编辑基线。已存在的空文件仍返回真实空正文，并按原范围决定是否带编辑基线，不能与缺失混同。权限或保护路径拒绝、非法参数、私有附件／计划／输出文件损坏和未知效果继续保留原错误及恢复规则。外部目录不能成为新的项目指令来源。目录查看、文件查找和正文搜索统一通过 Shell；搜索使用随客户端封装的 rg；外部文件修改按下文的文件工具与权限边界执行。`list_directory/glob_files/search_content` 已移除。工作区自身必需的项目说明无法安全读取时明确停止。

`exec_command`、`poll_command` 的 `yield_time_ms` 只限制本次等待，`0` 立即返回当前状态。`wait_agent` 的 `timeout_ms` 只限制本次邮箱观察。发起 `terminate_session` 后以原执行的终态判定实际停止。

`poll_command` 或 `terminate_session` 找不到本会话的 `session_id` 时给出纠正信息，本次调用不会启动或停止其他命令。已有引用无法核实或实际效果未知时，应沿原执行记录核实，避免重启命令来取回结果。

宿主为每次 Shell 启动分配独立执行身份。使用原 `session_id` 观察或停止，使用原启动工具返回的 `execution_id` 查询执行证据或记录计划进度。等待返回和受理回执都需要结合原终态判断结果。

`read_file` 省略 `limit` 时默认返回 200 行，`offset` 从 1 开始。用结果的 `next_line` 作为下一次 `offset`。原记录保留 `selection.nextOffset` 和完整可编辑文件基线。所读取的窗口只代表已观察的范围，大正文仍受 Artifact 和上下文容量约束。

子 Agent 的事件摘要与结果正文分开。`wait_agent` 观察父邮箱，`list_agents` 可重读最近的终态报告。用原 `dispatch_id` 区分后续派发和较早结果，结合实际来源核实子报告的判断。

同一完整模型回复中的工具可以并行执行；需要同一串行资源的调用仍依次取得资源，每项调用分别核实完整参数、当前权限和执行来源。历史按实际结果保存顺序记录，下一次模型调用按原工具声明顺序接收完整配对结果。工具失败、抛出异常、被人工或自动审核拒绝，以及已保存的结果未知，都保留准确原调用和结果，交给下一次模型解释，不直接中断 Agent 的回复。人工或自动拒绝只结算原调用。同批其他调用各自核对权限，已开始的照常结算，等待中的按各自条件继续。发生结果未知时，停止同批后续派发并结算已开始的调用。模型须尊重原拒绝，未知效果须先核实。你明确选择“停止任务”才会取消整轮。回复正常结束不表示未知的网站效果已确认，也不表示后台进程已停止。原结果无法可靠保存、必要出处无法核实或数据损坏时不能编造结果继续；这些属于执行记录的完整性故障，须明确说明。

权限拒绝会把可公开的具体原因连同能确认的未执行事实交回模型，而不只返回通用错误码；原错误码和执行出处继续保留。私有适配器异常正文不因此公开，已经开始执行的失败或未知也不会被描述成未执行。

自动审核发生技术失败时，能够确认的审核服务不可用、连接失败或响应流不完整会以准确类别交给模型，并说明工具未执行、没有获得批准或拒绝决定。未知异常继续返回通用失败；HTTP 成功状态本身不表示审核完成，私有服务端错误正文不直接公开。

模型收到的工具异常说明使用简洁英文，区分失败、取消、明确未执行和效果未知；已知公开原因说明参数、当前限制及必要的下一步，未知原因保留通用解释，不公开任意私有异常。面向模型的说明不使用内部 Run／Session／Job／carrier／dispatch 术语或以裸机器码代替解释。该呈现规则不翻译或删改命令原始 stdout／stderr、MCP 业务数据和工具返回的原始业务正文；它们仍作为工具数据保留。完整原调用、错误码、身份、审批和恢复事实继续保存于原持久回执。参数／路径错误给出纠正方向；权限和真实拒绝不能靠换工具绕过；取消不代表已回滚或后台进程已停；效果未知时先核原操作，不能重投。Files 的参数、路径形式、编辑条件、工具范围和系统访问错误分别说明原因；失败不能自行改变用户指定的最终交付位置。只有实际进入父目录创建后才提示可能残留空目录，校验失败不暗示已有修改。网页错误保准确 HTTP 状态，远端工具保结构化错误与任务失败原因，目录搜索不完整不会冒充无匹配。浏览器批次中已经完成的动作和失败前输出继续保留，文件写入后再发生记录或读取错误也不会被描述成未写入。

最终提供给模型的 Files 工具及路径说明明确区分三种模式：请求批准模式直接允许工作区内操作，普通外部读取、写入和编辑请求用户批准；Auto 普通工作区读取免模型审核，外部文本先在宿主隔离读取，确定不存在直接反馈，存在的正文通过自动审核后才交给业务模型；写入和编辑仍请求自动审核；Full 按有效权限直接执行。Files 没有 Shell 的 `filesystem`／`network` 申请字段；获准的外部读取也只有可安全编辑目标才返回完整基线，基线不授予后续写入权限。附件和准确当前计划文件仍按各自的专用范围处理。每次调用继续核父子权限、工具集合、Planning、受保护资源和原生文件限制；人工／Auto 明确拒绝及已有未知效果不得靠换工具绕过。

只读文件探索首次进入带有 `AGENTS.md`／`CLAUDE.md` 的目录时，读取、列目录、查找与搜索正常完成，新发现的指令和真实工具结果一起进入下一次模型请求，不把正常发现当成工具失败，也不要求整批重发。已被模型使用的指令发生修改或删除、能力变化和有副作用的调用仍须重新核实。用户补充输入及完成条件的并发变化在同一 Run 的安全检查点重新评估，不重放已完成的操作。

会话可持续多轮使用；正常执行和停止不以累计回复数、成功执行数或历史子会话数设置配额。同时运行的资源和单批读取仍有界，正常锁竞争或内部队列拥塞应等待资源释放并继续，取消和关闭仍可响应。子 Agent 每次 Run 的 30 分钟期限保持；主任务完成后正常结束，不为持续使用而继续空转。真实未知结果、权限拒绝、网络或程序错误仍如实保存，不能当成正常等待后自动重做效果。

工作区信任确认项目及已展示的历史额外读取范围，不等同于批准任意命令。开发期 Native Shell 在命令获准后默认具有宿主权限允许的广泛只读视图；文件工具和封存生产执行仍按各自的路径范围。运行环境和平台能力限制也不因用户批准而消失。

当前统一链路的 macOS 默认 Shell 使用宿主工具链，允许命令派生子进程并保留宿主 HOME。请求批准默认允许当前 Workspace 与本次私有临时目录写入，并关闭网络；Shell 可为本次调用明确请求外部写入或联网，取得准确批准后分别开放。外部写入批准不附带网络，联网批准不附带外部写入。Auto 按实际模型决定使用同一请求范围，Full 允许宿主权限内的普通外部写入及联网。普通默认 Shell 不再额外遮挡 Profile、配置、认证、协调目录或整运行目录，`~/.kite-code` 也不再是 Shell 保护根；SDK 自定义宿主显式提供的限制及 confined 模式仍按各自合同执行。私有临时目录中的 native 程序不能直接执行或映射，Workspace 网络范围也拒绝 Unix socket 绑定与外连。可信资产身份、最终范围或可核实监督后端缺失时调用失败。各平台原生资格独立核验，不由 macOS 结果推定。

Windows Shell 使用受限令牌和目录权限限制写入，读取沿宿主权限。普通写入范围是工作区和本次临时目录，可核实的只读命令只开放临时目录写入。外部写入和联网分别申请，`network:none` 通过环境变量为常用工具提供离线约束。PowerShell 动态脚本或效果范围无法确认时，Auto 按原请求范围做风险审核。请求批准和 Full 继续要求本次人工确认。直接委托系统服务的命令会被拒绝，已启动的命令继续由原 Job 查询、停止和清理。

复杂 Shell 不能靠命令名称保证只读或无网络。正式入口使用有限字面量语法解析和固定极危险拒绝，其他脚本由已授权系统范围限制，所有子进程继承该范围。越界失败可能已有其他部分效果，不自动扩权重跑；极危险的关键系统删除等操作在三种策略下都先拒绝。

Linux 默认 Shell 与调用 Shell 的 Task 已接入对应范围的源码后端，实际 Linux 运行资格仍待上述验证。Skill Workflow 验证及补偿已移除；普通默认 Shell 同样不附加 Profile 或整运行目录保护，原生启动所需的准确可执行文件只读挂载和资产身份核验保留。源码接入不代替平台验收。

Shell 启动、读取、等待和停止使用同一个持久 Job。提交停止只表示取消已受理；确认停止必须核实本次命令的完整后代，包括脱离原进程组的后代。Shell 自然退出和所属 Service 退出也执行这项清理。输出丢失区间和未知结果如实保存，冷读取不会重新运行旧命令。

macOS Shell 启动时等待监督进程认证、执行资产核验和命令就绪。命令尚未发给监督进程时收到取消，会结束原启动流程并请求清理对应的监督服务。

`exec_command` 以 `cmd` 接收完整命令，可选 `description` 提供用户看得懂的执行目的。桌面会话工具行显示原命令的单行摘要。等待结束时若命令仍活动，工具返回原 `session_id`，用 `poll_command` 继续观察。新调用创建独立执行，普通命令随原父执行取消。

Windows Shell 指引要求模型在同一个 Shell 中解析路径和执行删除或移动，递归操作前核对绝对目标是否位于工作区或用户明确授权的目录。用 PowerShell `Start-Process` 启动后台辅助程序时，指引要求隐藏窗口，用户明确要求可见交互窗口时按请求执行。

文件和网络申请使用顶层 `filesystem`、`network`，省略分别为 `workspace_write`、`none`。`network:internet` 包括本机 localhost、127.0.0.1、::1、局域网和互联网；审核通过不会把 `network:none` 请求改成联网。`filesystem:full_access` 是外部写入申请，不代表切换 Full 模式或解除路径保护。实际范围仍由现有审批策略及执行边界决定。新模型不提供旧 permissions、key、cancellation 或 shell_launch；旧执行记录、引用及受限恢复仍按原合同解释。

Agent 在任务允许时为当前技能所需的命令显式申请 `filesystem:full_access`，包括验证和交付，遵守用户指定的较窄范围。普通工作区命令使用 `workspace_write`。Windows 本地辅助程序启动或双向管道确需完整文件范围时，可为该命令申请。文件和本地命名管道操作使用 `network:none`，每次实际执行由现有授权流程决定。

Shell 等待结束后原 Job 继续运行，主 Agent 和子 Agent 都用原 `session_id` 观察进度。需要停止时使用 `terminate_session` 并核实原终态。

子Agent的模型回复结束时，它发起的附着Shell可能仍在排队或运行；原子任务继续等待这些执行结算，父Agent不把模型结束当作整个子任务完成。历史或可信内部明确选择独立后台关系的Shell保持自己的生命周期，不阻止已经完成的子任务交付。查看输出或切换主／子会话只结束相应读取；明确停止仍针对原任务，并等待实际执行结果。

Shell 输出读取故障会保存失败与可核实的错误原因，并收束原任务；它不显示为用户取消。停止无法确认时仍保未知，失败可能已有部分效果，不自动重跑。

## 权限模式

| 模式 | 产品含义 |
| --- | --- |
| 请求批准 / Request Approval（`accept_edits`） | 工作区内文件操作允许；普通外部 Files 读取／写入／编辑、MCP 调用及 Shell 外部写入或联网、`web_fetch` 均需要准确调用的用户批准 |
| 自动审核 / Auto（`auto`） | 普通工作区 Files 读取免模型审核，外部文本缺失直接反馈、存在的正文审核后释放；Files 写入／编辑与 MCP 仍自动审核；内置 Shell 沿其风险审核合同。批准只覆盖准确调用，只有具体高风险请求人工确认，明确拒绝或审核技术失败不执行工具。其他可信内置工具按自身权限规则执行 |
| 完全访问 / Full（`full`） | 使用宿主权限允许的普通文件和网络范围，不走常规逐项审批；仍保极危险拒绝、Runtime 权限对象保护及系统限制 |

PowerShell 5.1 和 7 在有效的完全访问模式下，不会仅因条件分支、函数或动态调用无法静态确认而新增常规审批。工具独立要求的人工确认、父子权限上限及硬性限制仍然有效。

自动审核属于权限系统的内部模型调用，记录名为 `authorization.check`。它不创建子 Agent 或子会话，不占子 Agent 并发槽，也不进入子 Agent 列表。代码审查可作为通用协作者的任务，不需要独立默认角色；检查决定、原调用与人工回退记录仍可追溯。

Native 浏览器的内置操控在三种模式下均不经过自动审核或用户审批，不追加页面接管确认。宿主仍核实能力可用、准确页面／任务／控制权、取消与未知结果，不从页面文字取得指令或控制权。自动化完成或需要用户处理时释放控制、保留网页并正常回复说明；不创建人工等待或“继续并通知”流程。用户处理后发送新消息，Agent在新任务中重新绑定页面并获取新快照；旧句柄、元素和截图引用不能沿用。

桌面 Agent 的结构化浏览器使用受管页面的资源配额。配额用满时，打开请求等待资源，用户仍可停止本次任务。

正式权限入口、协议和持久控制仅支持上述三个选择。旧严格 `ask` 已退役；旧模式输入或控制记录明确拒绝，不静默转换。

Planning 仅表示计划模式，不定义 Agent 的 planning/building 阶段。主动 `/plan` 或扩展显式请求的计划实施，在三种模式下均必须取得准确计划的人类决定；批准、要求修改和拒绝都不修改工具权限模式。计划批准只满足原 Run 的业务门禁，后续每项 Tool/Job 仍沿当前实际权限，不产生额外 Manual/Auto 上限。单纯模式切换保留原计划卡和同一次已提交答案，硬拒绝、来源或正文变化、工具移除和取消继续核验。详见[计划与任务](planning-and-tasks.md)。

内置工具也可以由可信 owner 在执行前主动要求准确人工确认，例如文件恢复。这类确认在三种模式下都要人批；确认后，本次工具调用及确认前已声明的有限内部步骤，不再重复弹普通工具权限卡或调用默认审核模型。它不形成会话授权，后续独立工具、额外内部步骤和不同输入不能借用。当前能力、信任、父子上限、硬拒绝、取消、来源与最终派发检查继续生效；独立自定义权限策略无法消费这份确认时，明确失败，不把审批留在等待中。普通提问与计划批准不属于此种工具执行确认。

审批默认选择“仅此次”，仅展示当前可信策略能够兑现的后续范围。后续授权只属于真实来源 Session，父、子和兄弟会话不共享，关闭窗口不清除已保存的授权。

| 工具 | 可选后续范围 | 仍逐次检查 |
| --- | --- | --- |
| Shell | 本会话内相同完整命令 | cwd、环境、runner／资产、timeout、文件／网络范围和当前权限；无前缀、别名或模糊匹配 |
| 文件 edit／write | 本会话内同一精确文件位置的编辑和写入 | 当前普通文件与已核父目录、保护范围、当前 baseline 和内容冲突；不包含删除或递归目录 |
| worktree create | 同仓库、所展示父目录下的直接子工作树 | 固定本次展示的 base commit、detached／newBranch 模式、父目录真实身份、目标空闲及原保护；不包含 remove 或 force |
| worktree remove | 同仓库的本次精确目标 | dirty／untracked／ignored、占用、引用和原清理保护；不包含 create 或 force |

文件位置范围允许正常内容更新和原子替换，当前 baseline 冲突仍然零发布。初始文件不存在时，只能授权已验证父目录中的准确槽位；无法核实范围时保留单次审批。请求批准模式下普通工作区文件免常规人工审批，普通外部 Files 按准确调用请求用户批准；Auto 内外写入和编辑仍先自动审核；普通工作区读取免审，外部文本采用隔离读取后审核释放。不会仅为展示可复用范围新增审批卡。Auto worktree 也继续免常规审批。选择或复用 create 范围授权后，HEAD／ref 或父目录身份与批准范围失配会停止本次创建，保持零 mutation 并交回原调用者重新求权，不按新值解释旧批准或降级单次继续；单次及 Auto 免审路径保持各自原规则。

CLI stdio、共享 TUI 和 Native 使用相同的原卡选项、完整说明与有效会话；批准只提交所选原 optionId。目录显示规则、资源、真实消费工具及原批准出处，并按已观察版本清除本 Session 的授权。clear 阻止后续派发，已派发效果保持原事实；响应未知只查询原意图，重复点击不产生新批准。切换策略后仅在当前策略与范围重新完整匹配时恢复使用，clear 的授权不会复活。Web 保持只读。新版使用独立库格式，旧库明确拒绝，不自动转换、清空或改写原数据。

TUI 保留固定的审批选择和私人输入，当前选项的完整范围说明可用 PgUp／PgDn 阅读；翻页不提交答案，Enter 仍回答准确原卡的当前选项。

需要审核的 Auto Files 调用与 MCP 按原任务、准确参数及权限材料进行自动授权审核；信息缺失本身不转人工。内置 Shell 使用独立风险合同，模型只分类 ordinary／high／critical，分别由现行策略映射为批准、准确人工确认和拒绝。其他可信内置工具按自身权限规则执行。重复调用次数、先前技术失败及缺少业务上下文不形成高危。硬拒绝、工作区信任、真实注册、执行范围、受保护资源和工具独立要求的人工决定始终先行。

新 Shell 风险审核只接收完整命令、实际工作目录和执行范围、可核实的调用语法事实及允许读取的直接脚本快照，不发送任务、计划、委派或业务模型消息窗口，材料缺项也不回整窗。语法事实说明参数消费关系和可能调用的程序入口，不代表程序已执行或安全；未覆盖语法、程序身份和依赖明确保留未知。只有未知脚本正文且没有具体高危迹象时，不因此转人工；已识别的破坏目标或外发载荷不确定时继续判断实际风险。自定义审核器继续使用自己的明确合同；新版冷读只使用原封存输入和决定，不重新解释或触发模型。

默认 Shell 审核模型返回 `risk/reason`，由 Shell 工具的可信解释器生成通用执行决定。理由要求一句话、最多 30 词。Kite 不向默认 Shell 审核请求传入输出 token 上限，实际输出仍受提供商约束。提供商截断输出时，Kite 记录审核技术失败并结束本次调用，向业务模型返回准确原因。

Auto 默认使用独立 low reasoning preset（adapter 不支持时省略），保持当前模型和连接。已有许可与有效同命令人工授权先处理；该授权满足默认 Shell 风险审核时不再调用默认 reviewer，独立 checker 和人工上限继续保留。合格 `pwd`／`ls`／bundled rg 单命令及纯字面量 `&&` 链免模型审核，各叶沿同一可信解析／重写执行并保持失败短路；不支持的语法回原审核。

Windows 上，受限 PowerShell 可以在默认文件和网络范围内直接执行可核实的常见只读命令。它支持常见的 `rg` 参数、简单输出管道和有限的本地 Git 查询，例如 `git status --short`、`git diff --stat`、`git log -1 --oneline`、`git branch --show-current`。Git 查询使用已识别的本机 Git，关闭可选索引写入、按需取对象及外部程序。通过准入的其他普通 Shell 调用，包括运行工作区脚本，走同一 Auto 风险审核。普通风险自动执行，高风险才请用户确认，严重风险直接拒绝。静态分析无法确认效果时，审核仍按实际命令和可取得的证据判断。

所有实际审批模型请求，包括 Shell 风险审核、Files 和 MCP 审批，在确认超时或断连后最多重试两次，总计至多三次请求。默认每次最多 8 秒，可用 `autoApproval.timeoutMs` 设置；整个检查最多用三倍期限（默认 24 秒），包含同操作在途等待、准备和排队，并非保证一定发出三次请求。明确拒绝、要求人工确认、取消、格式错误及原因不明的异常不重试。各次审核只使用同一封存输入，不拼接失败的半截回复，也不重复执行工具。

重试耗尽或其他审核技术失败后，Kite 结束本次调用，工具不执行，不把失败转成人工审批卡或默认为批准。取消立即停止，重开会话不重新发送旧审批。业务会话仍可处理其他获准操作，迟到回复不能恢复原调用。

迟到的审核结果无法改写原调用。新调用独立判断权限，并遵守原任务限制和已明确的拒绝。

同一任务已有的有效 Auto 批准按准确命令、环境与范围、当前策略及已审核材料指纹复用；直接脚本完整不代表依赖完整，不能确认材料相同时不扩大跨调用复用。Tool 启动自己的准确 Job 可继承已接受的模型或人工依据；Auto 下当前有效的相同命令人工 grant 也仅沿准确父 Tool→自身 Job 继承，仍核未撤销和原权限。超时不是风险批准，不进入独立批准缓存。

Windows Auto 中，高风险的同一次 Shell 调用使用一张卡。批准覆盖原命令与范围下的自身执行，独立调用仍按其当前权限判断。

Windows 受限 PowerShell 在“请求批准”模式下，附着于原任务的命令需要人工确认时，由启动进程的 Shell Job 提出。批准一次只适用于该 Job，相同命令的新调用按当时的权限重新核对。独立后台命令和另有授权要求的操作分别确认。授权绑定准确命令、目录与范围，启动前仍检查当前限制。 [Windows 执行边界](../../active/windows-shell-sandbox.md)

Auto 的新默认 Shell 审核不判断业务任务授权：窄范围普通本地写入不因工作区外路径或未知普通内容被视为外发；GET 响应保存到本地也不等于上传。凭据外泄、整个 home／工作区破坏、严重持久安全弱化分类 critical 并拒绝；其他具体重大风险或其关键目标／外发载荷不确定分类 high 并请求准确人工确认。ordinary 只表示当前材料没有识别出具体高危，不证明任意未知程序安全。用户任务及明确限制仍由业务 Agent 遵守，现有权限和执行边界不因分类降低。

用户已授权某类操作，但明确保留具体目标的选择时，业务 Agent 应先请求用户决定。例如用户尚待选择删除两个文件中的哪一个，不能自行选定后执行。已确定的只读或禁写要求继续约束业务 Agent；新默认风险审核不读取任务，也不能替它确认目标或保证这些要求已被遵守。

新默认 Auto 审核 Shell 时区分执行权限上限和实际效果。workspace_write／无网络不表示此次命令写文件；process、unknown、record_write、复合命令和管道本身不构成高危。审核检查完整命令、实际调用脚本、目标和外发数据；低风险分类不扩大原 filesystem／network 请求，也不替业务 Agent 判断任务是否允许写入。

Shell 网络范围目前只有 none 和 internet，没有仅本机或指定域名的范围。internet 是联网请求可用范围，不能因缺少不存在的更窄范围或普通 GET 响应未知而升级高危。风险模型继续核实际目的地和外发载荷，执行器仍按本次请求及原权限交集执行；network=none 的请求不会因风险通过而自动联网。

文件范围只有 workspace_write 和 full_access，没有按单一路径授予的 Shell 范围。普通工作区外绝对路径仍是本地目标，不能仅因其超出默认范围而升级高危；实际破坏和安全配置变更另行判断。风险分类不改变目标、原请求或受保护资源边界。

默认 `explore` 接收明确的只读任务指导，工具集合也比 `general` 少；除原读取／Shell／知识工具外，允许在父选中集合内使用消息、Shell 停止、执行证据和网页读取，不因此获得协作者列表、追问或中断工具。子 Agent 不提供事件等待工具，发送成功后继续工作或结束；主 Agent 保留等待子任务结果的能力。当前版本同身份续作与冷恢复仍核冻结工具集合和当前父权限，不自动补新工具；升级前旧角色不提供兼容映射。Shell 继承父会话当前的审批策略和沙箱。`cat`、复合命令及管道可以按普通权限链执行，不受角色专属的三命令限制。rg 执行 hooks、外部解压及未知选项不能仅凭名称取得免审资格；正常搜索内容中的选项名称不被当成执行选项。前台与后台 Shell 均说明默认请求范围及显式联网申请，审批不替调用补齐缺失的联网能力。角色实现与验证范围见[Task owner](../../../packages/agent/src/extensions/task/README.md)。

只读是子角色的任务要求，不构成独立 Shell 禁写／禁网沙箱。业务 Agent 保持业务源码、配置和数据不变；必要探索可在原工具权限内使用临时脚本、临时产物，优先私有临时目录。新默认 Auto 只判断 Shell 高危效果，不代替任务合规检查；请求批准和 Full 沿各自策略执行，Full 不承诺技术上阻止子角色写入。主会话 Planning 业务门禁、真实工具交集、极危险拒绝和平台保护继续生效。

审批模型确认通过后，同一调用直接使用单次授权，不再因普通风险分类或模式规则重复审批。调用身份不匹配、取消、必需执行能力不可用和实际执行失败仍会阻止或终止执行。

拒绝的调用没有执行；失败调用可能产生部分作用；未知结果需要核实。审批提交失败时，客户端应保留未解决请求，不显示虚假的已批准状态。

文件修改因基线冲突被拒绝时，本次请求没有发布，之前成功的其他修改仍保留。基线核对完整文件的身份与版本，冲突不证明两次编辑修改了同一段文字。旧读取不能证明冲突后的当前内容；需要继续编辑时，应在原任务授权范围内重新读取并使用新基线。冲突回执不代表整批回滚，也不自动授权重做。

通用 Agent 的大人工审批请求使用完整附件，有限卡保留原调用与可选授权范围；读取附件后再决定。正文大小不使后端截断参数或扩张授权。普通问题的回答只提供信息；问题的答案不等于批准后续工具。等待期间现行权限变化时，旧答案不能授予执行。

文件工具不按过去的整文件、修改原文或模型结果长度上限拒绝操作。`read_file` 对文本使用 `offset/limit` 和续读位置。读取大文件与完整 Artifact 正文时，其他会话可继续处理，取消在读取检查点生效。工作区和已授权的外部可编辑目标仍以完整文件基线核实变更。文件权限、原引用、发布检查和 Provider 请求容量继续生效。

Windows x64 本地 Workspace 的三个文件工具及检查点原字节恢复已接入源码后端，完整 Windows 运行与安装版资格仍待验证。操作绑定原 Workspace 对象，不修改已有文件或目录的 ACL。Windows 的备用数据流、设备名、尾点／空格、重解析路径及短名别名会明确拒绝；受保护目录不能借大小写变体绕过。实际能力和验证边界见[Files owner](../../../packages/agent/src/tools/files/README.md#windows-workspace-文件源码)。

文件工具的相对路径始终以当前工作区根目录为基准，不随 Shell 的当前目录变化。Windows 可使用原生反斜杠；`read_file`、`write_file`、`edit_file` 均接受普通外部绝对路径并按当前模式授权，实际父子权限交集、工具集合及受保护路径仍生效。列目录、文件查找与正文搜索统一使用 Shell 命令；其相对路径按命令当前目录解释。

`write_file` 新建文件时逐级创建缺失的父目录，例如空项目中的 `examples/agent_demo.py`。按当前模式获准的外部新建沿同一原生文件机制处理。创建不会跟随链接或修改现有目录权限。覆盖和编辑要求父目录及目标均已存在。审批通过只代表允许执行，不能消除路径占用、系统权限或保护边界限制。

写入失败会给出错误码、请求路径和处理建议，区分目标或父目录缺失、父路径被文件或链接占用、访问被拒绝、非法路径及受保护目标。Agent 应先处理原因，再决定下一次操作；重复相同路径和参数不能修复这些原因。失败后可能留下已创建的空父目录，文件检查点恢复也只恢复文件，不删除这些目录。创建或发布结果无法确认时保留未知结果，不能重放写入。

工作区外文本通过 `read_file` 的绝对路径读取，沿准确目标、父目录和原生文件身份核验；Profile、凭据和 Runtime 资产在 Full 下也受保护。外部读取、写入和编辑不进入工作区文件检查点；成功文件修改仍保存准确的单次产物及变更回执。读取不授予外部写入；外部文件修改按请求批准、Auto 和 Full 的当前权限分别取得人批、自动审核或有效直接授权。

目录查看使用 Shell 的 `ls`，文件查找优先使用 `rg --files`，正文搜索优先使用 `rg`。命令不可用时，模型选用适合当前 Shell 的替代搜索方式。`rg -F` 按字面文本搜索，`rg -n` 显示行号。搜索须明确范围和过滤条件，零命中不证明代码不可达或全局无引用。需要命中处的正文时按行用 `read_file`。

Shell 检索使用 rg 自身的忽略规则和命令选项；需要包含普通忽略项或隐藏文件时，分别显式使用 `--no-ignore`、`--hidden`。命令输出不是旧工具的 `scope`／`next` 分页结果，须结合准确命令、路径、退出状态及 stderr 判断范围和失败，不能把空输出当成完整无匹配证明。

普通 Shell 命令保留最多 1 MiB 的头尾输出供原 `session_id` 续读，省略的字节数随原 Job 保存。运行中先提供稳定前缀，Job 终结前发布省略区间及保留的尾部。`exec_command` 和 `poll_command` 的 `max_output_tokens` 控制本次输出预览，默认 10,000，并受本次模型容量约束。退出码和输出缺口随原记录提供。

`terminate_session` 使用原 `session_id`，宿主为本次取消分配 Command ID。MCP 工具使用 `search_mcp_tools` 查找本轮已选择的工具，`list_mcp_sources` 查看来源目录。来源目录不代表全量工具清单。

已知多个地址时，可以用一次 `web_fetch` 提交 `urls` 列表，一次 1–5 页。审批时确认完整地址列表和限制。每页独立检查网络权限，按输入顺序返回正文预览或失败原因。最多同时读取两页，整批时限最多 60 秒。预览被裁剪的页面提供完整已选正文的产物引用；显式 `max_chars` 分别限制每页读取结果。取消批量读取会停止排队中的网页。

单页 `web_fetch({url})` 默认返回完整提取正文，不再使用旧的 8K 默认长度或 16K 参数上限；显式 `max_chars` 是该次调用选择的内容长度。有效跳转链不再受默认 3 次限制，真实循环仍会被拒绝，每次跳转继续检查网络权限与 SSRF。默认总时限为60秒，从获准执行后开始，包含DNS、代理连接、robots检查、域名队列、正文读取和页面解析，不包含审批等待；可用 `timeout_ms` 为单次调用指定正整数毫秒时限。用户取消立即申请结束本请求，不需要等待60秒；实际资源停止仍按原取消规则核实。外网响应体在读取过程中按实际字节检查 5 MB 解析安全上限，防止远端无界响应耗尽内存；这不计入 Run 累计产物用量。

抓取前按初始站点的 `robots.txt` 检查请求路径和查询部分。优先使用适用于 KiteCode 的规则组，缺省使用通用组；最具体的规则生效，同等匹配时 `Allow` 优先。站点规则拒绝时返回 `web_robots_denied`，结果注明站点及页面尚未请求，不回显 URL 路径、查询参数或站点规则文本。

同一次调用中，初始页面与同源 `robots.txt` 可共用已验证的 DNS 结果，各自执行准入和连接审计。初始解析计入总时限，`robots.txt` 的 3 秒读取预算从初始解析完成后开始。工具失败的原结果会记录阶段及资源类型，可区分系统 DNS、HTTPS DNS、目的地址检查、连接和正文提取等。

请求批准的 `web_fetch` 在用户批准前不开始 DNS 或连接；Auto 使用实际模型审查，明确拒绝无网络效果；Full 不走常规审批。普通开发配置下，获准的 `web_fetch` 可访问公开网站及其公开跳转目标；每次请求继续检查实际 DNS 地址并拒绝私有、保留和本机地址。封存执行配置仍按明确的网络关闭或主机名单限制执行，审批不会扩大该范围。

默认本机宿主的网页工具无需填写代理配置：优先读取大小写 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`（小写优先），没有 HTTP(S) 环境代理时读取 Windows 当前用户或 macOS 已登记的手动系统代理；Linux 使用环境变量。没有代理则直连。`NO_PROXY` 只选择是否绕过代理，不能允许访问私网。系统 DNS 的全部候选都是已识别的 Fake-IP（`198.18.0.0/15`、`2001:2::/48`）时，自动向 Cloudflare 发起加密 DNS 查询。若域名候选含 Teredo 地址（`2001::/32`），其余候选均为公网 IP，且网页与解析服务选中同一个代理，也会经该代理自动复核。复核后检查新响应的全部候选，只连接通过检查的 IP。私网、回环和其他保留候选继续拒绝。查询仅包含目标域名，不发送网页路径或正文。

代理只接收已检查的目标 IP；网页原域名仍用于 Host、TLS 名称与证书验证。每次重定向重新检查，不扫描本机端口、不自动执行 PAC/WPAD，也不会在代理失败后悄悄切换为直连。当前支持无需认证的 HTTP/HTTPS CONNECT 代理，不支持 SOCKS、代理账户认证或 PAC；遇到这些设置会明确报告对应网页工具失败，其他工具仍可使用。macOS 同时启用手动 HTTP(S) 和 SOCKS 时，自动选择已登记的 HTTP(S) 入口。两个协议均已登记时按目标协议选择；只登记一个 HTTP(S) 入口时，混合设置下两个协议共用该入口。只启用 SOCKS 时报告 `web_proxy_protocol_unsupported`。特殊网络的备用设置见[网页网络配置](models-and-configuration.md#网页网络配置)。

[TUI 审批](../clients/tui/guides/approvals-and-questions.md)提供交互入口；Web 只读查看，不回答审批。

运行、等待审批、自动审核或等待资源期间都可以修改根会话的审批模式，使用自定义权限策略的宿主也保留这个入口。修改审批模式是用户配置写入，不经过模型或工具审批，也不由审核策略拒绝；服务、连接或状态同步异常按修改失败或结果未确认反馈，不描述为用户没有修改审批模式的权限。主 Agent 和已经运行的子孙 Agent 在后续工具进入审批层时读取根会话最新已应用模式；已经进入审批层但仍待批、尚未派发的动作也按新模式重新判断，无须新建任务或重建子 Agent。已派发工具按原授权收尾，切换模式不回滚效果或热修改正在运行的 Shell 范围。Desktop 普通工具待批保留输入区和权限选择器，切到 Auto／Full 后原待批项重新判断；浮卡逐项切换，批准范围仍分别属于原工具和来源会话。问答、计划等待期间，Native 保留权限选择器和停止入口；文本输入沿原交互规则。MCP 来源／凭据等特殊交互继续沿各客户端自身显隐约定，具体入口见[桌面说明](../clients/desktop/README.md)。

旧卡片失效后保留历史，不准许迟到答案授权其他轮；Full 仍不能解除只读预设、工具范围、工作区信任、自定义策略的硬拒绝或明确人工要求，以及未知效果限制。TUI 与 Desktop 收到控制变更后重新读取当前权限，子会话的继承显示也同步更新。模式与一次性准确批准分别核实，详见[执行与结果](execution.md#工作选择审批与恢复)。

覆盖或编辑前对同一路径使用 `read_file`，宿主从这次模型请求实际见过的记录中选取完整文件基线。`edit_file` 默认替换唯一的精确匹配，只有明确要求替换所有匹配时使用 `replace_all`。发生基线冲突后先重新读取同一路径，再决定是否进行获准的新编辑。`exec_command` 的 `workdir` 只选择本次执行目录，工作区与网络范围仍按原权限核实。
