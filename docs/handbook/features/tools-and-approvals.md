# 工具、权限与审批

工具可以读取、执行命令、修改文件或访问外部系统。可发现、可请求、获准执行和执行成功是不同状态。

普通 CLI、TUI 和 Desktop 默认提供文件读写、`ask_user`、`read_execution_evidence`、`web_fetch` 和六个子 Agent 协作工具。具备合格 Shell 后端时模型侧默认共16项，否则12项。`read_file` 同时接受准确工作区外绝对路径，不加载外部项目指令；有效 Full 模式下，`write_file` 和 `edit_file` 也可直接修改普通外部绝对路径，其他模式的外部修改仍使用经过原权限检查的 Shell。专用 `read_user_file/write_user_file/edit_user_file` 已移除。显式禁用或移除仍不向后续 Run 提供工具，实际调用继续核当前权限、工作区信任和平台能力。

五个专用验证工具和自动检查文件变更、强制验证完成、waiver 机制已退役。Agent 使用普通 Shell 运行测试，并按实际输出报告结果。`request_plan_review` 和原计划审批继续保留。

Windows Git Bash 使用原无账户受限令牌：工作区写入按批准范围执行，读取沿宿主权限，离线使用环境提示；Full 明确绕过沙箱。业务放行与拒绝由统一审批层处理，获批外部写入不会被默认工作区范围再次拒绝。内置 rg 无需用户安装；Git Bash 需要本机 Git for Windows，实际运行与发布范围见 [Windows 状态](../../active/windows-shell-sandbox.md)。

## 模型工具名称

模型使用以下名称调用能力；实际提供的集合仍由宿主、当前 Run 配置与平台资格决定。公开名称和参数不扩大原授权范围。只有浏览器执行的新模型调用须填写最多10字的 `description`，用简短动作说明这次要做什么；加载技能和读取技能资料不接受这个入参。说明只表达目的，执行状态仍以实际结果为准。

| 能力 | 模型工具名称 | 主要参数或含义 |
| --- | --- | --- |
| 工作区文件 | `read_file` | `path` 以工作区根目录为基准；读取用 `start_line`、`max_lines` |
| 文件修改 | `write_file`、`edit_file` | 保留 `base` 原完整文件基线；新建使用 `base:null`；精确编辑用 `old_text`、`new_text`、`expected_matches` |
| Shell | `shell_execute`、`shell_read`、`shell_wait`、`shell_stop` | 统一执行以 `background:true` 选择后台；运行时管理执行身份，读取、等待和停止使用返回的原 `shell_id` |
| 问题与网页 | `ask_user`、`web_fetch` | 普通问题只收集信息；网页时限用 `timeout_ms` |
| 子 Agent | `spawn_agent`、`follow_up_agent`、`send_agent_message`、`interrupt_agent` | 默认通用协作者；稳定 `agent_id`，每次受理仍绑定准确 carrier/轮次；消息只排队，显式追问才续轮 |
| 子 Agent 等待与目录 | `wait_agent_events`、`list_agents` | 事件等待只读自身邮箱，使用 `after_seq/wait_ms`；列表按稳定身份分页，并提供原委派/最近工作/结果的可读来源 |
| 计划 | `read_plan`、`write_plan`、`request_plan_review`、`update_plan_progress` | 计划保存、批准和基于真实回执的进度分别核实 |
| 当前任务证据 | `read_execution_evidence` | 按真实任务分页列出 Tool／Job；`execution_id` 查询原公开结果，不重跑操作 |

了解、解释、检查或审查项目本身不授权修改项目。未要求保存时直接回复分析，不为探索创建占位文件或报告；误提出的写入仍须经过原审批与派发核验。

`read_file` 可读取工作区外的普通文件；有效 Full 模式下，可安全编辑的目标返回完整编辑基线，其他外部读取保持只读结果，也不因硬链接一律拒绝。统一权限仍检查禁止范围与实际路径，基线本身不授予写入权限。普通工作区或外部文件在本次读取中确认不存在时，返回正常观察 `File does not exist: "<path>".` 和 `exists:false`，界面不以失败红色呈现；不伪造空正文、行窗口或编辑基线。已存在的空文件仍返回真实空正文，并按原范围决定是否带编辑基线，不能与缺失混同。权限或保护路径拒绝、非法参数、私有附件／计划／输出文件损坏和未知效果继续保留原错误及恢复规则。外部目录不能成为新的项目指令来源。目录查看、文件查找和正文搜索统一通过 Shell；搜索使用随客户端封装的 rg；外部文件修改按下文的文件工具与权限边界执行。`list_directory/glob_files/search_content` 已移除。工作区自身必需的项目说明无法安全读取时明确停止。

`shell_execute.execution_timeout_ms` 是执行截止时限；省略不设置这次 Shell 的截止时限，显式期限到期申请取消，并继续核实真实停止。期限属于“本 Session 相同命令”的执行语义，无期限与显式期限不能混用授权。`shell_wait.wait_timeout_ms` 与 `wait_agent_events.wait_ms` 只限制本次等待，不停止目标；Agent 等待省略或 null 时在内部持续有限分段，0 为当前只读快照。等待与取消回执不能冒充执行成功或停止确认。

`shell_read/shell_wait/shell_stop` 使用的本地引用明确不存在时，只结束这次调用并给出纠正信息，Agent 可以继续；本次预查不会启动或停止 Shell，也不取消同批正常读取。存储读取失败、已有引用无法核实或实际效果未知仍按原规则处理，不能编造新 ID 或重启旧命令来取回结果。

新 Shell 调用由运行时分配独立执行身份，模型不填写 key；观察旧结果使用原 `shell_id`。历史显式 key 若已属于其他请求，工具仍会说明本次没有建立新 Job、命令没有启动；真实未知或已完成的操作不能通过新调用重放。

`read_file` 省略 `max_lines` 时默认返回 200 行；`start_line` 从 1 开始，可将结果的续读位置作为下一次 `start_line` 继续分页。已存在的工作区文件向模型简洁列出行窗、总行数和 `next_line`，原记录仍保留 `selection.nextOffset`；每页保留完整文件的 hash、字节大小和对象基线，不能把页正文当成全文。缺失观察没有这些文件内容字段，也不保证该路径之后始终不存在。显式读取范围仍可能很大，行数也不能限制单行字节数；大正文保留完整 Artifact，并继续接受上下文压缩与容量检查。

子 Agent 的事件摘要与结果正文分开：`wait_agent_events` 用于观察事件，`list_agents` 可重读最近一次终态的完整报告。目录中的旧报告不代表正在运行的后续轮次已经完成，也不保证能选择任意历史轮次。报告中的判断仍须结合实际来源核实；单独保存判断不会使其成为验证结果。

同一完整模型回复中的工具可以并行执行；需要同一串行资源的调用仍依次取得资源，每项调用分别核实完整参数、当前权限和执行来源。历史按实际结果保存顺序记录，下一次模型调用按原工具声明顺序接收完整配对结果。工具失败、抛出异常、被人工或自动审核拒绝，以及已保存的结果未知，都保留准确原调用和结果，交给下一次模型解释，不直接中断 Agent 的回复。拒绝和未知先停止当前批次的后继效果，并等待已开始调用结算；模型不能重投原调用或换工具／路径绕过同一拒绝或未知。你明确选择“停止任务”才会取消整轮。回复正常结束不表示未知的网站效果已确认，也不表示后台进程已停止。原结果无法可靠保存、必要出处无法核实或数据损坏时不能编造结果继续；这些属于执行记录的完整性故障，须明确说明。

权限拒绝会把可公开的具体原因连同能确认的未执行事实交回模型，而不只返回通用错误码；原错误码和执行出处继续保留。私有适配器异常正文不因此公开，已经开始执行的失败或未知也不会被描述成未执行。

自动审核发生技术失败时，能够确认的审核服务不可用、连接失败或响应流不完整会以准确类别交给模型，并说明工具未执行、没有获得批准或拒绝决定。未知异常继续返回通用失败；HTTP 成功状态本身不表示审核完成，私有服务端错误正文不直接公开。

模型收到的工具异常说明使用简洁英文，区分失败、取消、明确未执行和效果未知；已知公开原因说明参数、当前限制及必要的下一步，未知原因保留通用解释，不公开任意私有异常。面向模型的说明不使用内部 Run／Session／Job／carrier／dispatch 术语或以裸机器码代替解释。该呈现规则不翻译或删改命令原始 stdout／stderr、MCP 业务数据和工具返回的原始业务正文；它们仍作为工具数据保留。完整原调用、错误码、身份、审批和恢复事实继续保存于原持久回执。参数／路径错误给出纠正方向；权限和真实拒绝不能靠换工具绕过；取消不代表已回滚或后台进程已停；效果未知时先核原操作，不能重投。Files 的参数、路径形式、编辑条件、工具范围和系统访问错误分别说明原因；失败不能自行改变用户指定的最终交付位置。只有实际进入父目录创建后才提示可能残留空目录，校验失败不暗示已有修改。网页错误保准确 HTTP 状态，远端工具保结构化错误与任务失败原因，目录搜索不完整不会冒充无匹配。浏览器批次中已经完成的动作和失败前输出继续保留，文件写入后再发生记录或读取错误也不会被描述成未写入。

最终提供给模型的 Files 工具及路径说明明确区分三种模式：请求批准与 Auto 支持普通外部读取；直接普通外部写入／编辑只支持有效 Full，其他模式不会为该 Files 请求打开审批卡。Files 没有 Shell 的 `filesystem`／`network` 申请字段；Full 外部读取也只有可安全编辑目标才返回完整基线。附件、准确当前计划文件与宿主提供的输出路径仍按各自的专用范围处理。非 Full 外部 Files 修改在原持久回执保留 `file_full_access_required`，模型收到英文入口范围说明及本次未执行事实；它不代表用户已经拒绝整个业务任务，也不批准其他工具。原任务仍授权、当前工具和角色允许、且没有同效果的明确拒绝或未知结果时，可以对支持该目标的 Shell 等工具提交独立请求，继续经过其原审批，不能自动扩权或重做原效果。人工／Auto 明确拒绝、受保护资源和已有未知效果不得据此绕过。

只读文件探索首次进入带有 `AGENTS.md`／`CLAUDE.md` 的目录时，读取、列目录、查找与搜索正常完成，新发现的指令和真实工具结果一起进入下一次模型请求，不把正常发现当成工具失败，也不要求整批重发。已被模型使用的指令发生修改或删除、能力变化和有副作用的调用仍须重新核实。用户补充输入及完成条件的并发变化在同一 Run 的安全检查点重新评估，不重放已完成的操作。

会话可持续多轮使用；正常执行和停止不以累计回复数、成功执行数或历史子会话数设置配额。同时运行的资源和单批读取仍有界，正常锁竞争或内部队列拥塞应等待资源释放并继续，取消和关闭仍可响应。子 Agent 每次 Run 的 30 分钟期限保持；主任务完成后正常结束，不为持续使用而继续空转。真实未知结果、权限拒绝、网络或程序错误仍如实保存，不能当成正常等待后自动重做效果。

工作区信任确认项目及已展示的历史额外读取范围，不等同于批准任意命令。开发期 Native Shell 在命令获准后默认具有宿主权限允许的广泛只读视图；文件工具和封存生产执行仍按各自的路径范围。运行环境和平台能力限制也不因用户批准而消失。

当前统一链路的 macOS 默认 Shell 使用宿主工具链，允许命令派生子进程并保留宿主 HOME。请求批准默认允许当前 Workspace 与本次私有临时目录写入，并关闭网络；Shell 可为本次调用明确请求外部写入或联网，取得准确批准后分别开放。外部写入批准不附带网络，联网批准不附带外部写入。Auto 按实际模型决定使用同一请求范围，Full 允许宿主权限内的普通外部写入及联网。macOS 所有范围仍保护实际 Profile、协调目录和运行资产，不能通过移动父目录绕过保护；私有临时目录中的 native 程序不能直接执行或映射，Workspace 网络范围也拒绝 Unix socket 绑定与外连。缺可信资产、最终范围或可核实监督后端时调用失败。各平台原生资格独立核验，不由 macOS 结果推定。

Windows x64 的 Bun Service 已接入无账户 Git Bash：默认写范围限制在 Workspace 和本次临时目录，读取沿宿主权限；离线范围提供常见工具的环境提示，不承诺系统级断网。审批后的完整文件范围可实际写入工作区外，网络范围单独批准；Full 绕过沙箱。业务放行或拒绝由统一权限层决定，Shell 不按默认范围再拒绝已获批的操作。当前已在本机验证命令、子进程、审批、取消与清理；完整安装及发布资格仍独立核验。Git Bash 来自本机 Git for Windows，rg 随客户端内置。

复杂 Shell 不能靠命令名称保证只读或无网络。正式入口使用有限字面量语法解析和固定极危险拒绝，其他脚本由已授权系统范围限制，所有子进程继承该范围。越界失败可能已有其他部分效果，不自动扩权重跑；极危险的关键系统删除等操作在三种策略下都先拒绝。

Linux 默认 Shell 与调用 Shell 的 Task 已接入对应范围的源码后端，实际 Linux 运行资格仍待上述验证。Skill Workflow 验证及补偿已移除；普通 Shell 的 Profile 与运行资产保护保持。源码接入不代替平台验收。

Shell 启动、读取、等待和停止使用同一个持久 Job。提交停止只表示取消已受理；确认停止必须核实本次命令的完整后代，包括脱离原进程组的后代。Shell 自然退出和所属 Service 退出也执行这项清理。输出丢失区间和未知结果如实保存，冷读取不会重新运行旧命令。

`shell_execute` 只要求完整 `command`，可选 `description` 以简短目的辅助展示，省略时显示命令预览；描述不替代命令和审批，不作为风险或用户授权依据。默认前台执行；`background:true` 返回原执行句柄和受理状态，后台受理不等于成功或完成。模型无需生成 key，重复发起同一命令仍是新执行；找回旧结果应使用原 shell_id。普通模型前后台都随原父执行取消，历史内部独立取消关系保持。

文件和网络申请使用顶层 `filesystem`、`network`，省略分别为 `workspace_write`、`none`。`network:internet` 包括本机 localhost、127.0.0.1、::1、局域网和互联网；审核通过不会把 `network:none` 请求改成联网。`filesystem:full_access` 是外部写入申请，不代表切换 Full 模式或解除路径保护。实际范围仍由现有审批策略及执行边界决定。新模型不提供旧 permissions、key、cancellation 或 shell_launch；旧执行记录、引用及受限恢复仍按原合同解释。

前台 Shell 的执行时限不包含尚未派发时的审批和资源等待；进入执行后的超时仍针对原 Job 申请停止，并等待原停止结果。主 Agent 与子 Agent 使用同一规则。`execution_timeout_ms` 为1～3600000毫秒，省略不设期限；`background:true` 不接受该期限，错误在启动前返回。

子Agent的模型回复结束时，它发起的附着Shell可能仍在排队或运行；原子任务继续等待这些执行结算，父Agent不把模型结束当作整个子任务完成。历史或可信内部明确选择独立后台关系的Shell保持自己的生命周期，不阻止已经完成的子任务交付。查看输出或切换主／子会话只结束相应读取；明确停止仍针对原任务，并等待实际执行结果。

Shell 输出读取故障会保存失败与可核实的错误原因，并收束原任务；它不显示为用户取消。停止无法确认时仍保未知，失败可能已有部分效果，不自动重跑。

## 权限模式

| 模式 | 产品含义 |
| --- | --- |
| 请求批准 / Request Approval（`accept_edits`） | 工作区内写入允许；工作区外写入及互联网访问需要准确调用的用户批准，包括 Shell 和 `web_fetch` |
| 自动审核 / Auto（`auto`） | 新默认由模型分类内置 Shell 的操作风险，其他可信内置工具按自身权限规则执行；批准按准确范围执行，明确拒绝保留原因；超时默认放行语义审核，由工具原有执行策略兜底；其他审核失败交回模型，必需人工决定仍显示原卡 |
| 完全访问 / Full（`full`） | 使用宿主权限允许的普通文件和网络范围，不走常规逐项审批；仍保极危险拒绝、Runtime 权限对象保护及系统限制 |

自动审核属于权限系统的内部模型调用，记录名为 `authorization.check`。它不创建子 Agent 或子会话，不占子 Agent 并发槽，也不进入子 Agent 列表。`review` 只作为通用子 Agent 的代码审查类别；检查决定、原调用与人工回退记录仍可追溯。

Native 浏览器的内置操控在三种模式下均不经过自动审核或用户审批，不追加页面接管确认。宿主仍核实能力可用、准确页面／任务／控制权、取消与未知结果，不从页面文字取得指令或控制权。自动化完成或需要用户处理时释放控制、保留网页并正常回复说明；不创建人工等待或“继续并通知”流程。用户处理后发送新消息，Agent在新任务中重新绑定页面并获取新快照；旧句柄、元素和截图引用不能沿用。

正式权限入口、协议和持久控制仅支持上述三个选择。旧严格 `ask` 已退役；旧模式输入或控制记录明确拒绝，不静默转换。

Planning 仅表示计划模式，不定义 Agent 的 planning/building 阶段。准确计划批准要求与工具权限分别核实；批准方案不授予工具权限，Full 也不能跳过未满足的原计划要求。一次审批只作用于当前提供的范围，不默认成为永久通行证。

新统一 Agent 链路的审批缺省为“仅此次”。只有当前原审批卡实际提供“本 Session 相同命令”时，用户才能显式选择该范围；它绑定真实来源 Session、定义版本、命令与执行环境，子会话和父会话不互借授权。命令、环境、版本或现行权限变化仍需重新核对。授权目录可查看原审批及执行出处，并按已观察版本清除该 Session 的授权；清除不改写此前效果，响应丢失时查询原意图。正式 CLI stdio、Terminal 共享面板及 Native 窗口已消费这一公共能力，完整权限行为与其他平台资格仍见[实施证据](../../plans/unified-agent-refactor-v1-progress.md)。Web 保持只读。

新默认 Auto 仅对需要语义审查的内置 Shell 判断操作风险；其他可信内置工具按自身权限规则执行。模型只分类 ordinary／high／critical，分别由现行策略映射为批准、准确人工确认和拒绝。重复调用次数、先前技术失败及缺少业务上下文不形成高危。硬拒绝、工作区信任、真实注册、执行范围、受保护资源和工具独立要求的人工决定始终先行。

新 Shell 风险审核只接收完整命令、实际工作目录和执行范围、可核实的调用语法事实及允许读取的直接脚本快照，不发送任务、计划、委派或业务模型消息窗口，材料缺项也不回整窗。语法事实说明参数消费关系和可能调用的程序入口，不代表程序已执行或安全；未覆盖语法、程序身份和依赖明确保留未知。只有未知脚本正文且没有具体高危迹象时，不因此转人工；已识别的破坏目标或外发载荷不确定时继续判断实际风险。旧 Run 和自定义审核器保留各自原合同和封存输入。

新默认 Shell 审核模型仅返回 `risk/reason`，由权限策略生成执行决定；旧 Run 和自定义合同仍返回 `decision/reason`。理由要求一句话、最多30词。支持输出上限的普通模型接口使用审核专用的最多256 token，原设置更小时保留更小值；业务回复、摘要与标题的上限不变。当前登录渠道不支持该参数，只应用短理由要求和审核总期限，不声称具有256 token硬上限。触及输出上限属于审核技术失败，即使截断前出现批准JSON也不能放行；模型会收到准确原因和工具未执行事实。输出token限制与超时默认放行是不同分支。

Auto 默认最多用10秒完成本次审核，计时包含准备、排队和模型请求；可用 `autoApproval.timeoutMs` 显式配置。超时默认放行这道语义审核，交给工具原有执行策略兜底。Shell 保留本次文件和网络请求，与父子／宿主硬上限取交集，不额外附加超时专属沙箱规则：请求 `full_access` 时可写入允许的外部目标，请求 `internet` 时可在原策略允许下联网；省略请求仍为 `workspace_write/none`。日志记录“审核超时，默认放行”，不伪造模型批准。受保护资源、硬拒绝、取消、未知效果限制和独立人工要求保持；仅由模型任务指导及语义审核表达的业务要求，不能据此声称有沙箱保证。没有可兑现边界时，返回准确超时原因和工具未执行事实；连接失败、空输出或无效答案继续作为审核技术失败。独立必需的人工审批仍显示准确审批卡，不能被超时跳过。

原调用已经取得的拒绝不被迟到结果或该次超时改写。新调用仍独立判断；工具权限层不一定能识别跨工具的相同业务效果，因此超时默认放行不提供“新调用永不绕过历史语义拒绝”的技术保证。模型仍须遵守原拒绝和任务限制；硬拒绝与独立人工要求继续由执行链检查。

同一任务已有的有效 Auto 批准按准确命令、环境与范围、当前策略及已审核材料指纹复用；直接脚本完整不代表依赖完整，不能确认材料相同时不扩大跨调用复用。Tool 启动自己的准确 Job 可继承已接受的模型或人工依据；Auto 下当前有效的相同命令人工 grant 也仅沿准确父 Tool→自身 Job 继承，仍核未撤销和原权限。手动模式原 Tool／Job 分层授权不变。超时不是风险批准，不进入独立批准缓存。

Auto 的新默认 Shell 审核不判断业务任务授权：窄范围普通本地写入不因工作区外路径或未知普通内容被视为外发；GET 响应保存到本地也不等于上传。凭据外泄、整个 home／工作区破坏、严重持久安全弱化分类 critical 并拒绝；其他具体重大风险或其关键目标／外发载荷不确定分类 high 并请求准确人工确认。ordinary 只表示当前材料没有识别出具体高危，不证明任意未知程序安全。用户任务及明确限制仍由业务 Agent 遵守，现有权限和执行边界不因分类降低。

用户已授权某类操作，但明确保留具体目标的选择时，业务 Agent 应先请求用户决定。例如用户尚待选择删除两个文件中的哪一个，不能自行选定后执行。已确定的只读或禁写要求继续约束业务 Agent；新默认风险审核不读取任务，也不能替它确认目标或保证这些要求已被遵守。

新默认 Auto 审核 Shell 时区分执行权限上限和实际效果。workspace_write／无网络不表示此次命令写文件；process、unknown、record_write、复合命令和管道本身不构成高危。审核检查完整命令、实际调用脚本、目标和外发数据；低风险分类不扩大原 filesystem／network 请求，也不替业务 Agent 判断任务是否允许写入。

Shell 网络范围目前只有 none 和 internet，没有仅本机或指定域名的范围。internet 是联网请求可用范围，不能因缺少不存在的更窄范围或普通 GET 响应未知而升级高危。风险模型继续核实际目的地和外发载荷，执行器仍按本次请求及原权限交集执行；network=none 的请求不会因风险通过而自动联网。

文件范围只有 workspace_write 和 full_access，没有按单一路径授予的 Shell 范围。普通工作区外绝对路径仍是本地目标，不能仅因其超出默认范围而升级高危；实际破坏和安全配置变更另行判断。风险分类不改变目标、原请求或受保护资源边界。

explore／plan／review 接收明确的只读任务指导，工具集合也比普通协作者少；Shell 继承父会话当前的审批策略和沙箱。`cat`、复合命令及管道可以按普通权限链执行，不受角色专属的三命令限制。rg 执行 hooks、外部解压及未知选项不能仅凭名称取得免审资格；正常搜索内容中的选项名称不被当成执行选项。前台与后台 Shell 均说明默认请求范围及显式联网申请，审批不替调用补齐缺失的联网能力。

只读是子角色的任务要求，不构成独立 Shell 禁写／禁网沙箱。业务 Agent 保持业务源码、配置和数据不变；必要探索可在原工具权限内使用临时脚本、临时产物，优先私有临时目录。新默认 Auto 只判断 Shell 高危效果，不代替任务合规检查；请求批准和 Full 沿各自策略执行，Full 不承诺技术上阻止子角色写入。主会话 Planning 上限、真实工具交集、极危险拒绝和平台保护继续生效。

审批模型确认通过后，同一调用直接使用单次授权，不再因普通风险分类或模式规则重复审批。调用身份不匹配、取消、必需执行能力不可用和实际执行失败仍会阻止或终止执行。

拒绝的调用没有执行；失败调用可能产生部分作用；未知结果需要核实。审批提交失败时，客户端应保留未解决请求，不显示虚假的已批准状态。

文件修改因基线冲突被拒绝时，本次请求没有发布，之前成功的其他修改仍保留。基线核对完整文件的身份与版本，冲突不证明两次编辑修改了同一段文字。旧读取不能证明冲突后的当前内容；需要继续编辑时，应在原任务授权范围内重新读取并使用新基线。冲突回执不代表整批回滚，也不自动授权重做。

通用 Agent 的大人工审批请求使用完整附件，有限卡保留原调用与可选授权范围；读取附件后再决定。正文大小不使后端截断参数或扩张授权。普通问题的回答只提供信息；问题的答案不等于批准后续工具。等待期间现行权限变化时，旧答案不能授予执行。

文件工具不再因过去的整文件、修改原文或模型结果长度上限拒绝操作。读取工具按显式 `start_line`、`max_lines` 或默认 200 行选择内容，并给出续读位置；未读范围不能冒充全文。读取大文件及完整 Artifact 正文期间，其他会话可以继续处理，取消会在读取检查点生效。工作区读取继续保完整文件基线；有效 Full 下可安全编辑的外部读取也保完整基线，其他外部只读不生成编辑基线。文件路径权限、原引用和发布检查仍生效。数据能被读取不代表任意模型均能在一个请求中接收它；Provider 的真实请求容量仍生效。

Windows x64 本地 Workspace 的三个文件工具及检查点原字节恢复已接入源码后端，完整 Windows 运行与安装版资格仍待验证。操作绑定原 Workspace 对象，不修改已有文件或目录的 ACL。Windows 的备用数据流、设备名、尾点／空格、重解析路径及短名别名会明确拒绝；受保护目录不能借大小写变体绕过。实际能力和验证边界见[Files owner](../../../packages/agent/src/tools/files/README.md#windows-workspace-文件源码)。

文件工具的相对路径始终以当前工作区根目录为基准，不随 Shell 的当前目录变化。Windows 可使用原生反斜杠；`read_file` 另接受准确外部绝对路径；有效 Full 模式下 `write_file`、`edit_file` 也支持普通外部绝对路径，实际父子权限交集、工具集合及受保护路径仍生效。列目录、文件查找与正文搜索统一使用 Shell 命令；其相对路径按命令当前目录解释。

`write_file` 新建文件（`base:null`）时会逐级创建缺失的父目录，例如空项目中的 `examples/agent_demo.py`；有效 Full 下的外部新建沿同一原生文件机制处理。创建不跟随链接，不修改已有目录权限；覆盖和编辑仍要求父目录及目标文件已存在。审批通过只代表允许执行，不能消除路径占用、系统权限或保护边界限制。

写入失败会给出错误码、请求路径和处理建议，区分目标或父目录缺失、父路径被文件或链接占用、访问被拒绝、非法路径及受保护目标。Agent 应先处理原因，再决定下一次操作；重复相同路径和参数不能修复这些原因。失败后可能留下已创建的空父目录，文件检查点恢复也只恢复文件，不删除这些目录。创建或发布结果无法确认时保留未知结果，不能重放写入。

工作区外文本通过 `read_file` 的绝对路径读取，沿准确目标、父目录和原生文件身份核验；Profile、凭据和 Runtime 资产在 Full 下也受保护。外部读取、写入和编辑不进入工作区文件检查点；成功文件修改仍保存准确的单次产物及变更回执。读取不授予外部写入；有效 Full 才允许直接调用文件工具修改外部目标，其他模式沿原 Shell 权限链申请。

目录查看使用 Shell 的 `ls`，文件查找使用 `rg --files`，正文搜索使用 `rg`；`rg -F` 按字面文本搜索，`rg -n` 显示行号。搜索须明确范围和过滤条件，零命中不证明代码不可达或全局无引用；需要完整正文时使用 `read_file`。

Shell 检索使用 rg 自身的忽略规则和命令选项；需要包含普通忽略项或隐藏文件时，分别显式使用 `--no-ignore`、`--hidden`。命令输出不是旧工具的 `scope`／`next` 分页结果，须结合准确命令、路径、退出状态及 stderr 判断范围和失败，不能把空输出当成完整无匹配证明。

检索命令沿普通 Shell Job 读取、等待及停止；输出预览不代表完整正文，需要时继续读取原 Job 的已保存输出。`shell_stop` 使用原 `shell_id`，为本次取消创建新的 `command_id`，不能复制启动回执里的旧 Command ID。MCP 工具使用 `search_mcp_tools` 查找本轮已选择的工具；`list_mcp_sources` 查看来源目录，来源目录不代表全量工具清单。

`web_fetch` 默认返回完整提取正文，不再使用旧的 8K 默认长度或 16K 参数上限；显式 `max_chars` 是该次调用选择的内容长度。有效跳转链不再受默认 3 次限制，真实循环仍会被拒绝，每次跳转继续检查网络权限与 SSRF。默认总时限为60秒，从获准执行后开始，包含DNS、代理连接、robots检查、域名队列、正文读取和页面解析，不包含审批等待；可用 `timeout_ms` 为单次调用指定正整数毫秒时限。用户取消立即申请结束本请求，不需要等待60秒；实际资源停止仍按原取消规则核实。外网响应体在读取过程中按实际字节检查 5 MB 解析安全上限，防止远端无界响应耗尽内存；这不计入 Run 累计产物用量。

请求批准的 `web_fetch` 在用户批准前不开始 DNS 或连接；Auto 使用实际模型审查，明确拒绝无网络效果；Full 不走常规审批。普通开发配置下，获准的 `web_fetch` 可访问公开网站及其公开跳转目标；每次请求继续检查实际 DNS 地址并拒绝私有、保留和本机地址。封存执行配置仍按明确的网络关闭或主机名单限制执行，审批不会扩大该范围。

默认本机宿主的网页工具无需填写代理配置：优先读取大小写 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`（小写优先），没有 HTTP(S) 环境代理时读取 Windows 当前用户或 macOS 已登记的手动系统代理；Linux 使用环境变量。没有代理则直连。`NO_PROXY` 只选择是否绕过代理，不能允许访问私网。系统 DNS 的全部候选都是已识别的 Fake-IP（`198.18.0.0/15`、`2001:2::/48`）时，自动经相同出口向 Cloudflare 发起加密 DNS 查询，检查得到的全部真实 IP 后再连接；正常 DNS、混合地址或私网目标不会借此绕过检查。查询仅包含目标域名，不发送网页路径或正文。

代理只接收已检查的目标 IP；网页原域名仍用于 Host、TLS 名称与证书验证。每次重定向重新检查，不扫描本机端口、不自动执行 PAC/WPAD，也不会在代理失败后悄悄切换为直连。当前支持无需认证的 HTTP/HTTPS CONNECT 代理，不支持 SOCKS、代理账户认证或 PAC；遇到这些设置会明确报告对应网页工具失败，其他工具仍可使用。自动读取 macOS 设置发现已启用 SOCKS 时，即使同时登记 HTTP/HTTPS 代理也明确失败；可在用户配置显式选择受支持的 HTTP(S) 入口，而不是自动猜测混合设置的路由。特殊网络的备用设置见[网页网络配置](models-and-configuration.md#网页网络配置)。

[TUI 审批](../clients/tui/guides/approvals-and-questions.md)提供交互入口；Web 只读查看，不回答审批。

运行、等待审批、自动审核或等待资源期间都可以修改根会话的审批模式，使用自定义权限策略的宿主也保留这个入口。主 Agent 和已经运行的子孙 Agent 在后续工具进入审批层时读取根会话最新已应用模式；已经进入审批层但仍待批、尚未派发的动作也按新模式重新判断，无须新建任务或重建子 Agent。已派发工具按原授权收尾，切换模式不回滚效果或热修改正在运行的 Shell 范围。Desktop 普通工具待批保留输入区和权限选择器，切到 Auto／Full 后原待批项重新判断；浮卡逐项切换，批准范围仍分别属于原工具和来源会话。问答、计划及 MCP 来源／凭据等特殊交互继续沿各客户端自身显隐约定，具体入口见[桌面说明](../clients/desktop/README.md)。

旧卡片失效后保留历史，不准许迟到答案授权其他轮；Full 仍不能解除只读预设、工具范围、工作区信任、自定义策略的硬拒绝或明确人工要求，以及未知效果限制。TUI 与 Desktop 收到控制变更后重新读取当前权限，子会话的继承显示也同步更新。模式与一次性准确批准分别核实，详见[执行与结果](execution.md#工作选择审批与恢复)。
