# MCP 与 Skills 扩展

Desktop 设置中的“轨迹与集成”支持本地 Trace bundle 与官方 OpenTelemetry 参考集成。它消费已保存的实时／历史事实；普通可信生命周期通知继续按原有限通知合同工作。

安装后先配置，再明确选择当前会话范围、事件类型、时间／用量／输出检查点、可读取材料、原身份、历史权限、精确网络 Origin、私网和用途凭据，最后启用。各项独立选择，默认关闭；工具审批或 Full 模式不会自动允许数据外发。第三方程序在独立受限进程内运行，仅能调用获准的有限 broker。凭据只绑定该安装和 Origin，由宿主注入请求，不提供 secret 读取接口。

实时消费从启用时的最新位置开始。历史导出需另外发起，首次固定范围和上界；可暂停、继续、取消，连续确认、待投递和死信分别显示。更新、卸载或重新授权不会继承旧授权与投递租约；关闭集成不影响第一方轨迹读取／重放。源历史回收会使未读取部分或材料不可用，已复制的安全事件和旧确认保留；取消／撤权仍封住后续发送，已经交付的内容不能撤回。

OTel 的持久接受与远端 full／partial／失败／重试／未确认分别显示，Host ACK 不表示 Collector 已保存。部分拒绝或永久失败不自动当作成功，丢响应保留可能重复。SDK、固定映射与实际接收端证据见 [Trace owner](../../../apps/service/src/trace-extensions/README.md)、[公共 SDK](../../../packages/trace-extension-sdk/README.md)及 [OTel owner](../../../apps/service/src/trace-integrations/opentelemetry/README.md)。

程序化宿主可为扩展注册任务与模型调用开始、结束的只读通知，观察实际开始及真实成功、失败或取消结果；通知不阻塞任务，失败不改写已保存的结果。任务结束不等于后台进程、连接或其他资源已经释放。通知可能丢失，需要保证执行的后续业务仍通过获准的工具、Action 或 Job 发起；冷读历史不会重新触发这些通知，恢复不会补发原任务的开始事件。此入口由可信宿主装配，不增加客户端开关或权限，完整契约见[Agent 生命周期扩展](../../../packages/agent/README.md#生命周期扩展)。

MCP 离线、未登录或尚未批准，不阻止无需该能力的普通对话。实际使用工具时仍检查认证、项目批准和权限；继续普通对话不会记录用户豁免。旧 `required` 配置仅保留为兼容元数据，不再生成会话门禁。

MCP Server 可提供工具、资源和提示。Skills 提供可发现的知识指导。它们需要正确配置、发现和必要权限，不会因为仓库里出现一个文件就自动成为可执行能力。

Native 的 `computer-use` 是内置全局技能，目录发现不依赖项目安装；它描述内置浏览器的操作规范。使用时仍须具备并选中受控执行能力，技能正文和资源不授予页面或敏感业务操作权限。当前候选与验收边界见[桌面浏览器](../clients/desktop/README.md#agent-浏览器)。

MCP 连接成功不等于所有工具已披露给模型，也不等于写操作获准。工具可能按需加载；认证、项目 Server 确认和配置范围分别处理。

MCP 的完整参数和结果校验在所属的计算 Worker 中执行，较长校验期间其他会话仍可处理请求。取消或超时会停止这次计算并核实资源收尾，不因此省略校验或扩大权限。工具派发前校验失败不会调用远端；已经派发后无法确认结果时继续保留未知，不能自动重发。

macOS 通用 Service 的本地 stdio MCP 连接结束或所属 Service 退出时，会收束该连接派生的完整进程树，包括自行转组或脱离父进程的后代；其他连接和无关进程不受影响。实际停止或清理不能确认时保留未知，远端 Tool 已发生的效果不因此撤销。冷读旧连接结果不会重新连接或重做工具；具体当前平台与证据见[MCP owner](../../../packages/agent/src/mcp/README.md#显式-stdio-guardian-port)。

Windows x64 的同一来源、连接与工具入口使用独立 stdio 后端：底层配置指定绝对 `.exe` 和完整参数，可用明确 Node／Bun executable 执行脚本，不从 PATH 或 COMSPEC 猜测启动器，任意 `.cmd`／`.bat` 继续拒绝。桌面新增表单可填写已安装命令名，保存时解析为上述准确程序；已知 `npx`／`npm` 包装器转为 Node 与 CLI 脚本参数。进程归属覆盖原 Windows Job 的成员，取消须核原根退出、Job 空树及实际 HANDLE／管道关闭；通过其他系统 broker 另行启动的工作不计入归属，也不由此取得 Shell 文件隔离或远端效果撤销。本机用户设置已核 Node 参数／环境、官方 memory 服务发现和断开，具体证据见[Service owner](../../../apps/service/README.md#自定义-mcp-表单与启动配置)；完整 Run、安装恢复和其他 MCP 的 Windows 资格仍分别验证。

Linux 的同一声明、来源批准、连接申请和工具入口现已接入独立 stdio 后端源码：直接执行原绝对 command、完整 args／cwd 和明确环境，以原 PID namespace 收束所属后代，保完整工具输出。准确取消与 Service 关闭须等原根回收、原树结束和全部管道／FD 关闭；不能确认时保 unknown 和原资源。冷查历史保原身份与结果，不重新连接或重做工具。它保持原 MCP 程序权限和网络，具体实现归[MCP owner](../../../packages/agent/src/mcp/README.md#linux-stdio-所属-namespace)；Linux 实机、正式安装恢复与全部客户端资格仍待重构后验证。

## 当前模型入口与目录范围

桌面设置中的 MCP 与 Skills 只管理用户级配置：没有会话时也可打开，切换会话不改变列表，项目与工作区条目不显示。MCP 的用户认证和设置连接由明确的全局操作管理；项目来源及任务中的实际工具使用继续核对各自来源、认证、项目批准和权限。桌面端可以在设置中搜索公开 Skills 并安装到本机用户目录。具体操作见[桌面设置](../clients/desktop/README.md)。

| 能力 | 模型工具名称 | 用途 |
| --- | --- | --- |
| MCP 来源 | `list_mcp_sources`、`connect_mcp_server`、`refresh_mcp_catalogue` | 查看已选择来源，显式连接，以及刷新准确原连接的工具目录 |
| MCP 工具搜索 | `search_mcp_tools` | 查找本轮实际已选择、已发布的 MCP 工具，返回其可调用模型名称和原定义信息 |
| MCP 资源 | `list_mcp_resources`、`read_mcp_resource` | 先列出资源及绑定，再读取准确原资源；资源目录与工具目录分开 |
| MCP 提示 | `list_mcp_prompts`、`get_mcp_prompt` | 查看提示模板，再按原参数取得外部提示内容 |
| Skill 知识 | `load_skill`、`read_skill_resource` | 用 `skill_id` 读取已选择知识及声明资源，不执行资源代码 |

动态 MCP 工具使用包含来源、远端工具名与稳定摘要的公开名称；搜索结果的 `modelName` 对应本轮实际可调用名称。内置参数使用 snake_case，远端工具的原参数、prompt arguments 及其他任意 JSON 字段保持原样，不能按名称自行转换。

当前通用 Service 的 `search_mcp_tools` 只搜索本轮选择的 MCP 工具目录：`query` 最多 256 字符，候选默认 10 项、显式 `limit` 最多 20 项；`list_mcp_sources` 是来源目录，不是工具全量目录。以下保留的完整工具目录与无固定搜索额度是既有产品承诺，当前上述入口尚不能完整满足，CLI、TUI 和 Desktop 的同一通用宿主均受影响。本轮只调整名称与参数投影，不改变搜索能力或把这一差异视为已解决；实现范围见 [MCP owner](../../../packages/agent/src/mcp/README.md) 的工具搜索及来源目录说明。

已知模型上下文窗口能够容纳能力目录时，MCP 工具可直接披露，不受固定 20 个工具的数量限制；目录超过已知窗口时可由 `search_mcp_tools` 按需发现。窗口未知时不会套用旧的较小目录预算。搜索查询不按 512 字符截断，也不按固定 12 条候选或 4 条 Provider 结果截断；显式结果数量需是正安全整数。外部工具描述仍按信任来源清理，未获信任的远端正文不会直接进入模型请求；有效 schema、Skill 文件和指令不因旧本地大小额度静默丢弃。发现和披露仍不授予执行权限。

原工具全量目录的产品承诺是默认列出完整匹配清单；指定正安全整数 `limit` 时可按 cursor 分页，不再受旧 100 条上限约束。清理后的 Provider／工具名称保持完整。MCP Resource、动态工具的有效结果和 Skill 知识引用文件不再因旧 128 KiB 本地阈值被截断或拒绝；读取仍需通过原有路径、身份、格式和权限校验，较大的内容仍可能超过模型实际上下文窗口。

[TUI 扩展指南](../clients/tui/guides/mcp-and-skills.md)说明管理与动态命令；CLI 可通过支持的 `--skill` 请求已可用的 Skill。Web 当前不配置或执行这些扩展。

外部系统返回内容仍需核对，不能把工具描述或外部文档视为项目授权。

通用开发入口提供同源 Skill 知识目录：不可用项显示局部原因，不阻止未选择该项的普通任务；明确选择不可用项仍会拒绝，子任务继承的原项失效也不能静默换项。默认知识读取不再附加固定项目数、正文或引用数额度，宿主明确设置的额度、配置文件字节边界、路径与格式检查仍有效。TUI `/skills` 只读发现与状态，只展示知识元数据，见[开发目录操作](../clients/tui/guides/mcp-and-skills.md#通用开发-tui-的-skill-目录)。

项目指令和 Skill 正文／资源的文件资源关闭无法确认时，任务或目录读取保留失败，取消不会将其改为成功。应用保留原资源与使用权，不能把服务收尾或离线维护交接报告为完成；普通坏文件在关闭成功后仍按上述局部不可用处理。当前实际资源与验收范围见[知识目录 owner](../../../apps/service/README.md#同源-skill-知识目录)。

Skill Workflow 执行能力已退役，包括六个生命周期工具、CLI `--activate-skill`、TUI 动态 Skill 激活命令及 manual Workflow 目录。普通 Skill 知识读取、CLI `--skill` 和 TUI `/skills` 保留。旧 Workflow 配置文件不再启用执行，旧激活请求明确拒绝；历史记录仍可只读查看。
