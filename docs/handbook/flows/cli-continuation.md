# 从 CLI 发起并继续任务

CLI 适合明确命令和事件输出，但任务需要审批时仍可能读取 stdin，不默认等于无人值守。

## 1. 发起只读任务

```sh
bun run agent run --workspace . --task "阅读项目并解释测试入口"
```

先确认工作区信任；尚未信任时在 TUI 阅读范围，或明确使用 `--trust-workspace`。不能把这一选项当成对任意工具的无限授权。

## 2. 消费结果与交互

保存会话标识及重要事件，区分输出正文与正式终态。出现审批、问题或方案审核时按 stdin 提示处理；自动化运行需预先考虑等待交互的情况。

完成、失败、取消、阻塞和未知结果分别处理。连接结束或进程退出不证明所有副作用已回滚。

## 3. 继续同一会话

```sh
bun run agent resume --thread <会话标识> --workspace . --task "根据上次结果继续检查"
```

resume 必须带任务文字；它开始后续工作，不是重放旧命令，也不是恢复文件。需要 TUI 恢复点操作时切换到实际提供该功能的入口。

## 4. 排查命令问题

参数以[CLI 参考](../cli/commands.md)为准。旧帮助中的部分内部入口和覆盖选项已被实际解析拒绝。读取已有 trace 可以帮助诊断，但不因此执行新的任务。
