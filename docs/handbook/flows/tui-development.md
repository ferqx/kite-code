# 用 TUI 完成一次开发任务

本教程从一个可运行的源码 checkout 开始，串起输入、计划、工具、审批、验证与继续。不同项目的测试命令不同，不把示例命令当成通用修改权限。

## 1. 准备工作区

在项目环境运行 TUI，完成首次模型配置并阅读工作区信任范围。先用只读任务确认模型与连接可用，例如：“阅读项目，指出应用入口和测试命令，暂不修改文件。”看到结果后核对它确实属于当前工作区。

配置与按键细节见[入门](../clients/tui/getting-started.md)和[输入](../clients/tui/guides/input-and-queue.md)。

## 2. 提出可验收的变化

说明目标、约束和预期结果，例如：“修复这个输入校验问题，保留已有接口，并用相关测试证明。”影响较大时先用 `/plan`，确认方案后再执行；小修复不需要为了形式额外创建计划。

模型对意图理解不同，应先纠正正常行为，不让它用当前错误表现重新定义需求。见[计划](../clients/tui/guides/planning.md)。

## 3. 阅读过程与处理交互

工具和子任务可能并行推进，Thinking 或工具卡是过程，不是完成证明。审批出现时核对目标和操作，回答问题或提出修改。批准提交失败时仍需处理原交互，不能以面板关闭假定操作获准。

执行中可以排队后续输入，队列绑定当前会话。切换前台不会把消息改投另一会话，也不会自动取消后台执行。

## 4. 核对结果

阅读最终修改说明与测试结果，并等待正式终态。模型说“完成”或正文已经完整显示，不代表所有工具已收尾。检查改动、相关测试及未覆盖范围；测试失败应继续定位，而不是只改结论文字。

工具结果未知时先检查实际副作用，不能盲目重跑。见[结果阅读](../clients/tui/guides/conversation.md)。

## 5. 继续或恢复

输入后续要求继续同一会话；`/resume` 可重新打开历史。需要停止先取消并等待清理。需要恢复时使用实际恢复点与确认范围，取消本身不会撤销文件变化。

[恢复指南](../clients/tui/guides/cancellation-and-recovery.md) · [导出](../clients/tui/guides/history-and-export.md)。
