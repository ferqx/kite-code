# 审批、问题与方案确认

审批面板说明将执行的操作、目标及可选择的授权范围。确认前核对命令和目标；面板出现不代表工具已执行。

## 审批

上下选择、Enter 提交当前选项。只使用界面实际提供的授权选项；一次允许不应理解为永久开放所有命令。

Esc 拒绝当前审批，并结束当前轮的相关执行；当前目标应显示为拒绝，其他相关调用按取消结果收敛。Ctrl+C 是整轮取消，与选择某个授权选项不同。

提交中保持面板可见并屏蔽重复输入；正常的本地确认回执不会闪现等待页，只有回执明显变慢时才显示“正在提交确认”。连接、过期或状态变化错误发生时，交互不应伪装成已授权；读取提示，重新取得当前请求后重试。连续按键不能把旧请求的回答应用到后来切换的会话。

## 权限模式

通过 `/permissions` 选择模式。Ask/Accept Edits、Auto 与 Full 的含义见[共享权限说明](../../../features/tools-and-approvals.md)。计划模式与权限模式分别表达规划意图和执行授权。权限面板存在会话授权时，可按 C 清除这些授权；这不会撤销已经执行的操作。

## 回答问题

单题显示问题和选项，多题按步骤推进；按面板提示选择或输入自定义答案。选项提交保留内部 ID 用于服务校验、恢复和重放，交给 Agent 及历史摘要的是问题与选项文案；自由回答保持用户原文。多步骤返回键可能只回到上一题，不能一概当成取消整轮。

统一终端的默认 `ask_user` 一次提供 1–3 题，每题 2–3 个选项和自定义回答。推荐标记不会自动提交首项；必须明确选择。自定义答案即使与某个内部 ID 同字，也保留为用户原文。问题只提供信息，不增加工具执行授权；子 Agent 不能直接调用该问题工具。明确取消原工作会终结待决问题，不自动重问。

已经提交并确认的回答在恢复时不应再次要求回答。提交失败仍需处理原问题，不能只关闭面板继续假定模型已收到。

通用开发 TUI 提交回答后若回执未知，会保留原答复命令；Ctrl+L 查询该原命令并刷新当前会话，不再次 POST 答案。切换会话、刷新或取消当前工作不改绑这项未知答复，也不把后来卡片当作原问题。准确回执确认前，不显示已接受或要求重复作答。

通用开发 TUI 同时存在多张待决卡时，Ctrl+B 打开完整目录，上下选择、Enter 返回原卡，Esc 关闭目录。目录保留打开时的原卡身份；后来新增卡片不会改变原行的目标。每张卡分别保留回答或授权草稿，卡片 revision 改变后要求重新核对。原卡带全文附件时，必须先完成原范围正文读取；关闭读取或切换卡片不会批准执行。

通用 TUI 的普通问题按原请求显示单题或多步骤表单。上下键明确选择，Enter 进入下一题；最后一步才提交完整答案。初始没有默认选项，空白自由回答不提交。只有原问题明确允许自由输入时才提供自定义回答；封闭选项不能用自定义答案绕过。Esc 回上一题，已输入的后续草稿保留；可选题按 Tab 明确跳过。自由回答支持光标编辑、Shift+Enter 换行及多行粘贴，保留原空格和 Unicode；长度提示只阻止不合格答案，不截断原文。复杂或无法完整呈现的 schema 仍明确提示输入原 JSON。

Workflow 核验失败的问题可能要求 replan/waive 及非空 detail；合格 Workflow 声明补偿且宿主准入时，另提供 compensate。replan 是新的尝试，waive 保留原 failed；补偿启动独立 Job 并另需用户审批，不把核验改为通过。普通步骤面板先选择原 decision，再填写 detail；子审批与 verifier 审批仍需独立确认。

项目 MCP 来源的准确 Source Question 提供 approved、rejected、cancel 三个明确决定。初始不选答案，上下选择后 Enter 回答；空 Enter 不发送 Answer，Esc 清尚未提交的选择，Ctrl+C 关闭面板，均不代替 cancel 决定。此前独立 Review 确认和普通 Action 许可不预答这个问题；保存回答后还须原发布证明才能显示来源决定已保存，详见[项目来源与原决定](mcp-and-skills.md#项目来源与原决定)。其他问题继续按各自面板提示回答。

## 方案审核

方案审核允许阅读计划、批准或提出修改。批准时选定的执行方式应与后续运行一致。见[计划指南](planning.md)。

当前开发版本按 Esc 拒绝时，等待回执期间可能仍显示审批选项，没有与 Enter 相同的提交中反馈。不要因选项仍可见就判断拒绝未发送或立即改选批准；先等待结果或检查连接。这项反馈差异尚未修复。
