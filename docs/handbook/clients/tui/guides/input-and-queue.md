# 输入、编辑与排队

在普通输入框编写任务，Enter 提交。Shift+Enter 或终端能正确传递的 Alt/Option+Enter 在光标处换行。不同终端对组合键支持不同；组合键被终端拦截时，可粘贴多行文本。

左右移动光标，上下在多行输入中移动；达到输入边界时可浏览历史输入。Home/End 作用于当前视觉行。输入长文本时只显示光标附近的窗口，内容并未因此截断。

## 粘贴、文件引用与补全

长段粘贴可能显示为“已粘贴 N 字符”的占位块，实际提交使用原始内容。删除占位块会移除对应粘贴内容；不要把占位文字当成真正发送给模型的正文。

输入 `/` 开启命令候选，上下选择、Tab 补全，再提交完整命令。输入文件引用触发的候选遵循面板提示。Esc 可关闭候选；后续输入变化才重新打开。

## 运行中继续输入

普通任务运行时仍可提交消息。目标会话存在可引导的活动 Run（包括“等待后台结果”）时，纯文本通过服务端 `steer_turn` 追加到同一 Run；它不会取消已派发工具或 child，也不会创建第二个 Run。Runtime 处理引导后若 required child 仍未终态，同一 Run 会再次进入受管等待。

只有目标 Run 已结束、正在不可引导的收尾，或提交明确属于后继任务时，消息才按提交时的会话进入本 TUI 的后继队列；底部以 `↵` 逐条显示，并按顺序等待前一轮结束及清理完成。客户端不能仅凭本地 Working 图形决定 steer 或排队，须以服务端活动 Run 身份和回执收敛。

例如 A 会话正在执行或等待后台结果时提交“再检查测试”，然后切到 B：该条输入仍属于 A；若 A 的活动 Run 可引导，它进入该 Run，否则留在 A 的后继队列，均不能改投 B。相同正文的两次独立提交是两条输入，不应合并。

队列变化不能折叠正在显示的工具、拆分思考块或造成已有回答重复输出。非空输入的 Enter 只提交输入，不同时展开最后一个工具卡。

## 失败与离开

刚提交的即时回显不等于服务端已接受。提交失败应显示错误并撤销尚未接受的回显；不要把本地回显当成执行成功。后继排队消息属于当前 TUI 的临时状态，不应作为退出后必然恢复的承诺；已经由服务端接受的活动 Run 引导是持久会话事实，不再由本地队列代表。

需要终止当前执行时见[取消与恢复](cancellation-and-recovery.md)；审批或问题出现时先处理当前交互。

当前开发版本存在一项已知差异：切换会话后，原会话排队提交失败的提示可能出现在新会话中。出现“Message was not sent”时核对原提交会话和已接受消息，不把当前显示位置当成错误归属；这不改变输入应绑定原会话的预期。

## 通用开发 TUI 的未提交草稿

通用开发输入按完整字符簇移动和删除，中文、组合音标和 emoji 不被拆开；上下按真实视觉行移动，到编辑边界才浏览本会话历史，Home/End 到当前视觉行边界。运行中编辑仍绑定原草稿范围。固定 `/` 候选用 Tab 补全、不执行，Esc 关闭后需继续编辑才重开。

文件候选通过本机只读目录读取，绑定原 Store、Workspace 与目录版本。页面继续读取可取得全部候选，不把单页当整个目录；失败、目录变化或迟到页不发布成功前缀。目录遵守实际 `.gitignore` 的注释、否定与嵌套规则，只读取有限配置和文件名，不读取候选文件正文。坏 UTF-8 配置、硬链接配置或越出目录的 symlink 局部显示 unavailable，不改用其他目录。

候选面板中的 Tab 和首次 Enter 只补全原文件引用；补全后另一次 Enter 才提交。空格、引号、反斜杠和中文文件名使用完整闭合引用，不拆成多个参数。Esc 或 Ctrl+C 关闭目录读取，切换 Workspace 后原迟到页丢弃，均不创建 Run 或取消执行。真实 80×24 终端已验证 605 项完整分页与这些边界；源码外构建使用已安装的固定 `ignore@5.3.2`，没有源码回退。

终端 bracketed paste 结束前不提交；多行 LF/CRLF 和 UTF-8 正文保留，显示占位也不替换实际发送内容。真实 80×24 终端已验证该编辑路径，终端不能传递的组合键仍受其自身限制。

通用开发入口会自动保存真实未提交文本，按原 Store、Workspace、Session 分开。切换会话、输入结束和正常退出保存最后编辑；服务端接受成功只清除当时提交的版本，迟到结果不删除新编辑。失败或结果未知保留文本，不自动重发。它不持久后继队列、审批回答或执行状态，也没有因此新增主题/语言设置。正式旧TUI入口仍按上面的现行行为负责。

`/drafts`查看已保存目录，`/draft <id>`只读原全文与关联状态，不自动填入或发送。删除会话或恢复换Store后保留原草稿身份，无法关联时明确unavailable。保存冲突保留当前编辑和磁盘版本，坏格式不重建；未保存的内存编辑不冒称已经出现在目录。正常退出若保存失败会保留编辑器并提示错误。SIGTERM强制退出保存失败返回非零；强杀可能丢失尚未落盘的文本。完整文件超过16MiB或记录超过4096时明确失败，不静默截断或淘汰。

## 新开发入口的持久提交凭证

普通 Work、steer、follow-up、原 Command 取消和准确 Job Stop 在首次发送前保存完整申请。`/recovery` 可选择原申请，Ctrl+L 只查询原 Command，Ctrl+V 查看完整内容；Ctrl+D 只清理已核实的终态记录。prepared/submitting 或丢回执在冷重开后都只查原 ID，不自动发送；查不到、错身份或无法核实保持 unknown。相同 ID 但任一原 scope、完整请求或草稿版本不同都会拒绝。

凭证位于明确选定 profile 的私人 `ui/caller-intents.json`，最多 128 项、16MiB 全文件；满额、坏格式、硬链接或持久化失败阻止首次发送，不截断正文或淘汰 unknown。独立草稿版本使旧回执不会清除新编辑或后来 Plan toggle。命令已应用不等于 Run 已完成，Job Stop 的取消请求也不等于已监督结束。源码外默认 paired 与真实终端强杀、丢 POST/首 GET、完整 UTF-8/CRLF 的当前资格见[CLI owner](../../../../../apps/cli/README.md)；这不代表普通 CLI JSON Work、Native 或完整 Workflow 业务崩溃已经同样验证。
