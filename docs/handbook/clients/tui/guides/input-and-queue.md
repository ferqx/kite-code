# 输入、编辑与排队

在普通输入框编写任务，Enter 提交。Shift+Enter 或终端能正确传递的 Alt/Option+Enter 在光标处换行。不同终端对组合键支持不同；组合键被终端拦截时，可粘贴多行文本。

左右移动光标，上下在多行输入中移动；达到输入边界时可浏览历史输入。Home/End 作用于当前视觉行。输入长文本时只显示光标附近的窗口，内容并未因此截断。

## 粘贴、文件引用与补全

长段粘贴可能显示为“已粘贴 N 字符”的占位块，实际提交使用原始内容。删除占位块会移除对应粘贴内容；不要把占位文字当成真正发送给模型的正文。

输入 `/` 开启命令候选，上下选择、Tab 补全，再提交完整命令。输入文件引用触发的候选遵循面板提示。Esc 可关闭候选；后续输入变化才重新打开。

## 运行中继续输入

普通任务运行时仍可提交消息。目标会话存在可引导的活动 Run（包括“等待后台结果”）时，纯文本通过服务端 `steer_turn` 追加到同一 Run；它不会取消已派发工具或 child，也不会创建第二个 Run。Runtime 处理引导后若 required child 仍未终态，同一 Run 会再次进入受管等待。

只有目标 Run 已结束、正在不可引导的收尾，或提交明确属于后继任务时，消息才按提交时的会话进入本 TUI 的后继队列；底部以 `↵` 逐条显示，并按顺序等待前一轮结束及清理完成。客户端不能仅凭本地 Working 图形决定 steer 或排队，须以服务端活动 Run 身份和回执收敛。

例如 A 会话正在执行或等待后台结果时提交“再检查测试”，然后切到 B：该条输入仍属于 A；若 A 的活动 Run 可引导，它进入该 Run，否则留在 A 的后继队列，均不能改投 B。相同正文的两次独立提交是两条输入，不应合并。

队列变化不能折叠正在显示的工具、拆分思考块或造成已有回答重复输出。非空输入的 Enter 只提交输入，不同时展开最后一个工具卡。

## 失败与离开

刚提交的即时回显不等于服务端已接受。提交失败应显示错误并撤销尚未接受的回显；不要把本地回显当成执行成功。后继排队消息属于当前 TUI 的临时状态，不应作为退出后必然恢复的承诺；已经由服务端接受的活动 Run 引导是持久会话事实，不再由本地队列代表。

需要终止当前执行时见[取消与恢复](cancellation-and-recovery.md)；审批或问题出现时先处理当前交互。

当前开发版本存在一项已知差异：切换会话后，原会话排队提交失败的提示可能出现在新会话中。出现“Message was not sent”时核对原提交会话和已接受消息，不把当前显示位置当成错误归属；这不改变输入应绑定原会话的预期。
