# 上下文查看与压缩

`/context` 查看当前请求上下文。上下文代表下一次模型请求的输入，不等于屏幕上所有历史文本；累计使用量与当前上下文大小也不是同一指标。

明确备份恢复后，`/context` 可继续读取当前选择中保存的完整消息与结果来源。结果保留恢复前的 Store、执行和版本出处，不会因为新 Store 而重做原任务；当前连接或会话不能核实时仍拒绝读取。查看不会调用模型、重新纳入结果或授予旧工作执行权限。

在 `/context` 中用上下键选择已有结果，按 `i` 明确纳入当前上下文。恢复后的申请使用当前连接与会话身份，结果仍保留原执行、版本和 Store 出处。会话空闲时只保存来源，用户随后明确提交新任务才会读取它；活动任务上的申请绑定准确原 Run，并等待安全检查点。已保存或已受理不等于模型已经读取结果，也不会重放原 Job。当前观察失效或结果身份不能核实时，先刷新并核对，不发送猜测申请。

## 手动压缩

输入 `/compact`，或 `/compact <希望保留的重点>`。自定义说明影响摘要重点，不绕过“需要有新增可压缩内容”的检查。

准备、总结和验证进度出现在消息区。压缩期间可继续编辑输入；同一会话后续写操作等待当前压缩完成。重复提交不应并行改变同一会话的上下文。

`No new messages to compact.` 表示当前压缩已覆盖可用内容；`Not enough reducible context to compact` 表示收益不足。两者不是模型连接失败，不需要反复重试同一内容。

## 切换与结果

切换会话会清除原展示中的瞬时进度，但迟到结果仍属于原会话。重新打开历史不应重现上一界面的瞬时动画。压缩影响后续模型输入，不是删除用户可见历史或回滚文件。

自动压缩只在相应能力启用时发生。`/auto-compact` 是自动过程可能显示的语义标记，不是用户可调用的命令。

`/compact reset` 预检后清除活动压缩点，使后续上下文按未压缩的历史重新计算；它不删除会话历史。正在压缩时先等待，无活动压缩点时提示无需重置。失败会保留旧压缩点；内容无法安全放回上下文时不能强行清除。
