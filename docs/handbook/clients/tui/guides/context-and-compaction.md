# 上下文查看与压缩

`/context` 查看当前上下文选择与最近一次已核实请求的输入用量。当前选择用于后续模型输入，不等于屏幕上所有历史文本；累计使用量、最近请求的输入大小和下一次请求的实际输入也不是同一指标。

最近请求输入优先使用准确原 Model 请求已保存的服务端 `inputTokens`，合法的 0 也保留；当前请求尚未返回统计，或该字段缺失／无效时，回退到完整原输入的本地估算，包含系统材料、消息、工具调用和工具 Schema。面板分别标明服务端统计和本地估算；它们都不保证下一次请求完全相同，也不借用上一请求的实测数替代当前输入。

只有原请求对应的冻结模型明确提供窗口和输出预留时才显示占比；分母仍扣除输出预留和安全余量，最近请求的占比分子优先用该请求实测输入；下一请求的占比分子使用明确标为估算的预测总数。容量未知时只显示数量并说明容量不可用，不凭模型名称猜窗口。当前分块 cl100k 只是跨模型回退估算，不承诺符合每个 Provider 的分词与请求封装。累计用量和缓存比例单独计算。

正在运行时使用原请求的实际模型名和上下文；同一请求由运行中转为完成、失败或取消后，新返回的实际统计会替换显示估算。空闲后切换下一模型，不把上一模型的占比放在新模型名下。`/context` 仍可明确查看最近一次已核实的统计或估算，当前选择的消息和结果来源另行读取，二者不混作同一份输入。

明确备份恢复后，`/context` 可继续读取当前选择中保存的完整消息与结果来源。结果保留恢复前的 Store、执行和版本出处，不会因为新 Store 而重做原任务；当前连接或会话不能核实时仍拒绝读取。查看不会调用模型、重新纳入结果或授予旧工作执行权限。

在 `/context` 中用上下键选择已有结果，按 `i` 明确纳入当前上下文。恢复后的申请使用当前连接与会话身份，结果仍保留原执行、版本和 Store 出处。会话空闲时只保存来源，用户随后明确提交新任务才会读取它；活动任务上的申请绑定准确原 Run，并等待安全检查点。已保存或已受理不等于模型已经读取结果，也不会重放原 Job。当前观察失效或结果身份不能核实时，先刷新并核对，不发送猜测申请。

输入 `/context requests`，或在 Context 面板按 K，可查看本次客户端运行中保存的上下文与会话原申请，包括压缩、重置、纳入结果、改名、分叉和删除。上下选择准确原 ID，K 或 Enter 只查询原结果，V 查看完整原申请；列表保留来源会话，查看另一会话的申请不会切换当前会话、创建分支或重发工作。Ctrl+C 只停止本次读取，Esc 关闭；换选项或切会话后，旧读取的迟到结果不进入当前页面。已核实的终态不会因同 ID 的旧回复或随后失联变为未知。列表保留当前客户端已保存的申请，不承诺退出后自动发现未保存的原 ID。

列表分别显示原命令回执和操作状态。accepted／queued 不代表派发、纳入或压缩维护完成；压缩与重置只有查询到准确原维护 Run 的完成状态才显示 applied。删除受理仍保留“停止未确认”的含义，查询结果不会自动新建或打开会话。

本次查询不能核实时，会明确显示“本次原结果未核实；保留已保存的原事实”。已有 applied／failed 等原终态继续保留，不能据此把本次失联当成刷新成功；未核实的回执不会作为已核原命令回执展示。

Context 内容超出终端时，使用 PgUp／PgDn 翻页阅读完整消息、结果来源和统计；当前页范围显示在面板底部。翻页只改变阅读位置，不改变上下文选择、纳入结果或发起模型请求。上下键仍选择已有结果，`i` 仍是明确纳入操作。

## 手动压缩

输入 `/compact`，或 `/compact <希望保留的重点>`。自定义说明影响摘要重点，不绕过“需要有新增可压缩内容”的检查。

准备、总结和验证进度出现在消息区。压缩期间可继续编辑输入；同一会话后续写操作等待当前压缩完成。重复提交不应并行改变同一会话的上下文。

`No new messages to compact.` 表示当前压缩已覆盖可用内容；`Not enough reducible context to compact` 表示收益不足。两者不是模型连接失败，不需要反复重试同一内容。

## 切换与结果

切换会话会清除原展示中的瞬时进度，但迟到结果仍属于原会话。重新打开历史不应重现上一界面的瞬时动画。压缩影响后续模型输入，不是删除用户可见历史或回滚文件。

自动压缩只在相应能力启用时发生。`/auto-compact` 是自动过程可能显示的语义标记，不是用户可调用的命令。

`/compact reset` 预检后清除活动压缩点，使后续上下文按未压缩的历史重新计算；它不删除会话历史。正在压缩时先等待，无活动压缩点时提示无需重置。失败会保留旧压缩点；内容无法安全放回上下文时不能强行清除。

## 三项统计

`/context` 分别展示累计实际用量、最近请求实际输入和下一请求上下文估算。累计值覆盖本会话当前 Store 的原模型尝试，包含已报告用量的摘要、失败和取消；显示输入／输出统计覆盖的请求数，未返回的部分仍未知。完整累计读取失败时只能显示“当前已核实的实际用量”，不把有限历史冒充完整累计。最近实际输入缺失时明确显示不可用，原请求本地估算另行标明。

底部优先标明“下次上下文估算”：以同一路由可沿用的原请求实测输入为基线，仅估算新增内容；基线失效或没有统计时使用通用回退，未知自定义模型无需专用词表。预测采用已保存来源与所选历史，不为显示重新捕获指令或请求模型；之后输入、来源和配置变化仍可能改变实际请求。无有效预测时说明不可用。模型切换后不把旧预测放在新模型名下，`/context` 仍可核对原模型的记录。
