# 使用计划模式

计划模式用于先分析目标、形成方案并按审核结果推进任务。它与权限模式不同：进入计划不代表已经获得工具执行授权，批准方案也不能越过运行环境的能力限制。

## 进入与提交

输入 `/plan` 进入计划模式；`/plan <任务>` 以给定任务开始规划。Shift+Tab 可切换计划模式。进入计划流程时使用产品规定的权限边界，不继承此前 Full 的任意执行假设。

描述目标、约束和验收条件。计划生成后，阅读步骤和影响范围，在审核面板批准或补充修改。补充输入中的 Esc 可能返回审核选项，不应直接理解为取消整轮。

## 执行与完成

批准后按照选定的执行方式运行。任务进度不是单纯勾选清单；需要的执行和验证未收敛时，不能只因模型写了“完成”就视为完成。

计划发生变更时，确认当前展示的版本和目标。已经被替代的计划不能继续作为当前实施依据。取消、阻塞和需要补充信息都会影响下一步，按面板说明处理。

产品中的计划与仓库开发文档的实施计划不是同一个存储对象。此页仅说明 TUI 功能。相关限制见[共享计划语义](../../../features/planning-and-tasks.md)。

## 通用开发入口

通用开发 TUI 的 `/plan`、`/plan <任务>` 与 Shift+Tab 使用同一单次计划意图；切换草稿模式本身不提交任务。模式和文字按当前 Store、Workspace、Session 保留。活动任务中提交计划请求会固定原任务作为排队目标，待原任务结束后才开始新的计划 Run，不把原普通任务改成计划任务。

审核前允许准确只读分析和计划管理，Full 也不能提前写文件、启动 Job 或子任务。审核批准绑定本 Run 的计划版本、摘要和原回答；下一任务不能借用旧批准。选择 Auto 或 Accept Edits 后仍受当前权限、Workspace 信任与独立 Tool/Job 审批限制。大计划在审核卡使用原完整附件，核对后读取全文，不以摘要或截断预览代替批准对象。

回答结果未知时只查原回答命令；计划请求结果未知时只查原任务命令。当前进程内查回、活动任务排队和跨会话草稿已验证；客户端强杀后的计划申请持久查回、其他平台与正式旧入口切换仍未完成。
