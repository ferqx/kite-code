# 如何阅读回答与执行过程

一轮任务可以包含用户消息、思考过程、工具执行和最终回答。正文出现、工具完成、整轮结束是不同事件，不能只靠最后一段文字判断任务已完成。

## 普通回答

普通回答按完整 Markdown 段落、列表项或结构组件逐步显示，不保证每个 token 都立即成为独立可见内容。未完成的尾段可以等待后续文本；完成的正文不应因为底部状态变化而重复写出。

没有待确认工具归属时，已完整的正文可直接显示。存在活动思考过程时，一些带工具调用的过程旁白不会作为独立回答显示；工具与下一次模型思考可能继续同一阶段。最终确认不再调用工具的正文才作为独立回答发布。

## 思考与工具

只读探索可聚合在一个 Thinking 块中。活动窗口在已完成的思考内容和工具步骤之间切换，不是为每次模型调用建立一张新卡。独立操作或用户交互会结束前面的探索阶段。

思考内容并非完整持久化对话的承诺；阶段结束后可以只保留摘要。相同阶段不应出现两份 Thinking 题头。工具是否属于探索由执行系统决定，界面不能仅凭命令看起来只读重新判断。

## 结果与完成

工具拒绝表示没有执行；执行后失败和执行前拒绝应有不同说明。Shell 输出存在时，成功卡片应能看到结果，不应只剩一个退出码。

最终正文已经显示时，底部仍可能显示 `Working`，直到执行正式结束。取消期间显示 `Cancelling`，不是立即把所有卡片伪装成已取消。

## 返回历史

同一会话中的持久消息应只显示一次；内容相同但身份不同的两次输入仍是两条。重新打开历史不保证重现瞬时动画或思考原文，但不能复制回答、把其他会话消息串入或凭空补出工具结果。
