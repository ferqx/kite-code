# 开始使用 TUI


TUI 适合在终端中发起任务、查看执行过程并处理审批。需要可交互终端、可用模型配置，以及对工作区的访问权限。它不会自动打开 Web。

## 第一次任务

1. 在仓库根目录执行 `bun install`，再执行 `bun run tui`。这是从源码运行的方式；已安装版本直接使用 `kite-tui`，自动启动发布包内配套服务，无需 Bun 或先运行 server start。
2. 如果显示首次配置向导，按提示选择 Provider、模型并保存凭据。配置错误时修正错误，不要把启动失败当成空会话。
3. 阅读工作区信任提示及额外只读目录。只有确认范围后才继续；拒绝时不会开始任务。
4. 输入一个明确任务，例如“只阅读项目，解释启动入口”，按 Enter 提交。消息出现后，状态栏显示 `Working`。
5. 若出现问题或审批，在当前面板作答。最终结果出现后，等待运行状态结束；正文已经出现不必然表示工具和执行都已收尾。

模型可通过 `/model` 修改。第一次使用建议先做只读任务，再尝试文件修改。权限模式见[审批指南](guides/approvals-and-questions.md)。

## 离开与再次进入

`/exit` 退出终端界面。退出与取消当前任务是不同操作：希望停止执行时先按 Ctrl+C 并等待取消结果。已有会话可从 `/resume` 查找；默认自有服务随客户端退出而关闭并清理执行；显式连接共享 daemon 时只断开连接。退出不删除会话，也不等于回滚已经修改的文件。

默认 TUI 使用自己启动的本机 App Server；显式连接已有 daemon 的方式见[服务手册](../../server/lifecycle.md)。源码与安装版本可能使用不同会话数据位置，不要用“列表为空”判断数据已删除。

继续阅读[界面导览](interface.md)、[输入与排队](guides/input-and-queue.md)和[命令参考](reference/commands.md)。

安装升级只影响新打开的客户端；正在运行的 TUI 与服务仍固定原版本。配套服务缺失或版本不符时修复安装，不通过结束无关 daemon 绕过。
