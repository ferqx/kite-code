# kite 桌面客户端（开发中）

通用 PC 客户端现在复用原桌面的项目侧栏、对话区、输入框、可调整宽度的右侧栏，以及主题、字体与样式。顶部“设置”打开原有全屏双栏布局，配置模型、提供商、MCP 与 Skills；“返回应用”回到当前会话。“会话工具”打开右侧栏查看任务、Runtime logs、Context、权限、恢复、草稿与会话管理，关闭侧栏继续阅读当前对话。打开面板不停止任务或重发原命令。

项目默认展开，点击名称独立展开或收起；空项目显示“暂无聊天”。上下键移动当前项目列表焦点，确认后打开原历史。侧栏先显示五个会话，可点“展开更多”继续查看已读目录。新建等待仍可阅读其他会话，迟到结果不覆盖后来选择和草稿。未进入本次项目目录的原会话仍保留在“项目待读取的会话”，可重新读取目录更新归属。目录按真实更新时间从新到旧排序，“展开更多”每次再显示十条；悬浮会话可查看状态和本地时间。未打开的会话也显示实际运行或待用户输入，等待必需后台结果显示通用活动指示。断线或读取失败保留原目录和时间，标为“上次确认状态”及“目录状态待核实”，仍可阅读；刷新成功恢复当前状态。未记录的时间不补造，未声明目录状态能力的服务保持待读取。空间批量移除与离线历史清理的当前范围见下段；单会话清理已接同一显式离线维护，macOS 安装版常用维护已有有限验证，其余维护恢复和剩余旧页面行为仍在迁移中。

通用 Native 已沿用空间行「移除」和默认保留的原生确认。确认后一次从目录移除全部根与子会话并请求取消，工作目录文件保留；重新添加同一目录成为新的空间。回复丢失显示结果未知，重开不会重做，明确「查询原移除」才查询原结果。现行产品承诺要求永久删除历史；新内核在移除受理时先保留准确旧ID的历史。确认框说明：所有任务结束并过宽限期后，退出客户端再明确调用[离线GC](../../cli/commands.md#通用开发入口离线维护)可清理该空间历史正文；活动、未知和待核对执行保留证据，原回执、删除边界及未发送草稿保留。准确旧会话页面在正文已清理时显示维护结果。默认宽限7天。单独删除的会话执行组也按相同条件清理；存活分支及其他未清理会话依赖的来源保留，最后一个依赖删除并符合条件后可一起清理。macOS 安装版常用维护的已验范围见[Native owner](../../../../apps/desktop/docs/native-release.md#macos-安装版离线维护)，其余恢复和完整平台资格仍未闭合；空间移除受理不能直接声称完成永久清理。

代码回滚只切换版本，保留现有数据。旧客户端不能识别私有存储格式时，草稿与原申请操作提示存储不可用；兼容的会话历史仍可阅读。切回支持该格式的版本后，继续查询原操作，不自动重做或恢复旧备份。macOS 当前已验证的代码组合见[Native owner](../../../../apps/desktop/docs/native-release.md#真实代码升级与冷回退)。

通用 Native 的左栏「安排任务」已沿用原页面，点击新建可在最右侧填写名称、任务说明、当前已读项目、频率及运行环境，主区域保留任务页。当前服务尚未提供保存或后台调度，页面明确说明限制，保存禁用；填写内容只属于页面草稿。顶部「返回会话」或点击原会话恢复未保存的输入和问题答案，点击其他会话按原身份读取其历史；这些导航不停止或重新执行任务。工作台入口继续隐藏。

通用 Native 的全局与项目「新对话」现在沿用原准备页，尚无项目也可写需求；建议仅追加草稿，进入页面或切换项目不会创建空会话。已有会话与准备页草稿分别保留，项目／分支选择保留模型、思考档位与权限选择。首次发送才创建原会话、应用所选权限并提交输入，立即清空准备框、显示等待消息，真实消息到达后接管。失败保留已创建会话与原文；结果未知须「查询原首次提交」，核实后明确继续，不重复创建或自动发送。项目授权涉及额外宿主只读目录时，创建后的权限面板仍须明确确认实际范围。空间、Git、分支和命令失败按下文现行约定用单个「确定」按钮的 AlertDialog 提示，确认后继续编辑。

通用 Native 准备时只读取已登记项目的真实 Git 分支；普通目录或缺 Git 不影响准备。未选另一分支时按发送时实际环境执行，只有明确选择另一分支才在首次创建前受控切换。任何空间仍有活动任务、项目有未提交改动或目标与客户端私有数据／制品目录交叠时，切换明确失败并保留草稿，不自动停止任务。新 Run 读取并冻结该项目配置，客户端无需重启 Service；现行手册中的旧配套服务重启描述只属于原 kite-desktop 路径。

通用 Native 的当前会话显示主轮次状态，并另列“后台状态”的未结束 Job 数量和未知数量。主轮次完成后，后台任务仍可存续；已请求停止但尚未终态的项仍计入未结束。计数使用当前会话、当前 Store 的已保存状态，旧 Store 的恢复历史不计入；观察或视图暂不可用时标为“上次确认状态”。准确停止和完整输出继续从原任务入口操作，不能仅凭数量判断实际进程已经退出。

通用 Native 的当前会话已接入原「环境信息」卡，按 Shell 与子 Agent 分组，保留宽窗口停靠、窄窗口浮层和手动开关。可准确停止正在运行的任务；受理后仍等待真实状态，结果未知须从原申请核实。子 Agent 名称来自原子会话，点击详情在原阅读区查看完整子日志；详情只读，顶部「返回主会话」恢复原草稿和父轮次提示。目录失效或读取失败保留上次名称与状态，停止入口等待重新核实；切换会话不停止任务。恢复历史保持只读，终态不表示进程清理已确认。

通用 Native 的「后台总览」通过“打开后台总览”读取当前连接下的完整后台目录，按原会话展示 Job、子 Agent／task 和子会话中的 Job，切换主阅读会话仍可查看原任务。父轮次是否等待必需结果、原子轮次状态和结果接纳分别显示；较新的子轮次不会替换原 task 身份。可读取完整已保存输出或完整子日志，全部固定上界内容读取成功后才发布。新链路备份恢复为新 Store 后，历史条目保留原 Store、原任务与原输出，并显示“恢复历史，只读”；旧任务不提供停止入口，新 Store 明确创建的任务仍可正常控制。刷新失败保留上次完整事实并停用停止入口；“关闭后台总览”只结束读取。停止只针对按钮标明的准确原执行，请求受理后仍等待实际终态。关闭、会话切换与冷重新打开均不重新发起任务。实际恢复读取、默认 Shell 和平台范围见[Native owner](../../../../apps/desktop/README.md#native-跨会话后台总览)。

当前根正式入口已使用通用 Agent V1.3 候选，旧参数、State/stdio 拓扑及旧桌面截图只作历史参考；新入口的实际参数与行为以本页“通用”段落和[当前进度](../../../plans/unified-agent-refactor-v1-progress.md)为准，未实现能力不能借旧描述启用。发行、安装与跨平台仍有未取得资格，详见[发布边界](../../../active/release-control.md)。

正式 Native 的 Runtime logs「已保存执行」中，展开准确 Job 后可主动读取完整已保存输出、刷新或关闭。页面保留 stdout/stderr/progress 的原文与已记录缺口，读完固定上界才展示完整内容；新输出需显式刷新。完整范围包括已保存内容和缺口，无法恢复丢失的字节；缺口字节数无法确定时明确说明。同一 Job 刷新失败保留上次完整内容并标未更新，空输出与读取失败分别显示。关闭输出、折叠详情、切换会话或冷重开只读历史，不取消或重新运行 Job。精确停止仍是独立明确操作，不能从读取完成判断执行成功或实际停止。macOS 正式默认宿主 Shell 已验证从页面新建后台 Job、完整保存输出、准确停止、所属 Main/Service 意外退出后的清理，以及同原身份的冷读零重放。Service 来不及保存停止结果时，历史记录仍保留未完成事实，读取完成不能把它判为已停止。当前 macOS 范围与剩余资格见[Native owner](../../../../apps/desktop/README.md#native-job-完整已保存输出)。

设置以全屏双栏页面呈现，沿用桌面主界面的当前主题与基础字号；宽窗口下设置侧栏固定为 236 px，不随主页面侧栏拖拽变化。左侧直接切换“常规”“提供商”“模型”“MCP”“Skills”，不提供设置搜索。返回应用与主侧栏新对话入口采用一致的单行按钮尺寸和悬停、聚焦交互，并紧邻设置分类；macOS 沉浸式标题栏下单独避开窗口交通灯，不让交通灯覆盖按钮。其他平台不增加该标题栏留白。“常规”显示默认文件打开应用和当前模型；编辑器选择只在当前页面进程内保留。返回应用关闭设置页，不修改任务或会话。参考图中的权限、语言及窗口行为等开关尚无对应设置能力，页面不提供这些控件。

> 已实施范围：[会话存储兼容性与连续性 V1](../../../plans/session-store-compatibility-and-continuity.md)已统一正式数据入口，并验证 macOS 已知格式的自动整理、历史来源归并和原会话保留。未知格式保留原数据，不切换空库；Linux 产品入口与 Windows 原生迁移资格仍待验证，具体边界见方案中的交付记录。


侧栏底部用户区通过上边框与空间列表分隔，用户按钮只显示单行“个人工作区”，不再另行显示“本地用户”；点击仍打开设置与主题菜单。

桌面客户端采用 Electron + React/shadcn UI + 独立 Kite Runtime Host。迁移实现和本机自动原生验收已完成，已验证流式执行、窗口隐藏恢复、刷新重接与正常退出；制品身份和剩余人工验证见[原生验收](../../../../apps/kite-desktop/docs/native-validation.md#electron-本机迁移验收)。

明确退出客户端时，只有存在排队、运行或等待用户交互的会话任务才显示二次确认；所有会话均空闲时直接进入安全清理并退出。任务状态无法完整核实时仍显示确认，避免误停任务。关闭窗口仍只隐藏客户端，不等同于退出。

退出先等待配套服务安全收尾；清理报错时会提示结果需要核对并允许退出，持续等待超过 20 秒时可选择继续等待或强制退出。退出检查、确认或清理期间再次明确退出也会走紧急退出。强制退出会尝试终止本应用拥有的服务进程；正在执行的任务和文件副作用可能尚未确认，下次启动后应按持久会话记录核对。

侧栏空间行只显示名称；会话行显示标题，并在最右侧用旋转图形表示 Run 仍在进行（包括受管等待必需子 Agent），用高亮圆角文字“待用户输入”表示等待回答、审批等交互，待输入优先于运行图形。受管等待的详情浮层使用通用“任务进行中”，不显示“等待后台结果”。空闲和正常完成不显示行内状态。会话数量、完整状态和更新时间在详情浮层中查看。浮层首次悬停 500 毫秒后出现；浮层出现后快速移到其他列表项会立即切换详情，移开一段时间再返回则重新等待。首次等待期间移开不会弹出。键盘聚焦也可查看，Escape 关闭。会话顶栏右上角的环境信息按钮控制“环境信息”卡片显隐，卡片默认展开，CSS 宽 300 px（2 倍显示比例的截图约为 600 像素），按 Shell／子智能体分组；卡片内文案使用常规字重。卡片停靠展开时消息阅读列和输入区最大宽度为 720 px，并为卡片预留右侧空间；会话滚动条始终保持在中栏最右侧。会话实际可用宽度不足 1092 px 时，停靠卡自动收起；之后即使宽度恢复也保持关闭，需用户再次点击。宽度不足时用户仍可点击按钮，以不压缩会话区域的右上角浮层查看；浮层打开期间宽度恢复则自动转为停靠卡。手动隐藏与自动收起均以短暂淡出、向右缩合和会话区域同步扩展完成；从其他主会话或子详情返回时直接显示卡片，不重新播放入场动画；系统启用减少动态效果时立即切换。除用户主动打开的窄宽浮层外，卡片不覆盖消息、工具输出或输入区。Shell 组显示新鲜、仍在运行或正在停止的执行；同一连接内返回已读主会话、正在核对新状态时，卡片暂时保留上次已确认的 Shell 和子智能体行并标明“上次状态 · 正在核对”，不提供停止操作。首次读取或没有可复用展示快照时，子智能体组仍保留已验证的全部子会话；名单已到但后台状态尚未匹配时保留详情入口并标记“状态待确认”。新鲜后台状态明确报告不可用时才标记“不可用”。有公开名称时只显示名称与状态，不附加执行 ID；旧记录缺少名称时才回退显示执行 ID。后台 service 与诊断字段不在该卡片中展示；上次状态只用于阅读，实时订阅与操作权限仍须重新核对。任一分组没有项目时显示对应空状态。

required 后台子 Agent 尚未终态时，Runtime 保持同一 Run 的受管等待及准确 task 关联；Desktop 侧栏保留通用活动标记；所选父会话的历史已加载、投影身份匹配且 Run 确认因 required 子 Agent 等待时，在消息阅读列末尾显示“正在等待子 Agent 结果”。这是随 Run 状态出现和消失的临时提示，不写入会话消息，也不把先前一段模型正文标为最终回复；最终回复只在 Turn 完成后确认。侧栏不另设等待徽标，输入框上方不设状态行，也不延续模型思考动画。子 Agent 的实时状态由环境信息卡片展示。此时输入框保持可发送；新文本引导恢复原 Run，不取消 child，也不创建第二个 Run。切换会话或刷新重接后，内部等待原因及关联 task 由持久投影恢复，不靠客户端轮询补正。after-turn 结果因已有用户活动 Run 而被 `human_start_preferred` 抑制时，只展示持久结果可用事实，不把结果伪装成已注入该活动 Run。

桌面与 Web 共用会话主页面；可用操作按各端权限提供。桌面保留本地项目、任务输入、审批与执行控制，Web 当前只读。当当前会话已观测到提示缓存 token 时，输入框底部工具栏显示该会话累计缓存命中率；无样本时不显示 `0%`，切换会话不沿用上一会话的指标。macOS 窗口采用沉浸式标题栏：同一个顶部 header 横跨侧栏和会话区，左段以实色背景层级放置侧栏收起图标，右段只显示会话标题和操作，并在会话页 header 底部显示分隔线，不重复显示所属空间；会话标题最多显示 10 个字符，超出时以省略号收尾，悬停仍可查看完整标题。侧边栏按浅色或深色主题使用实色背景，不启用透明窗口、系统 vibrancy 或 Liquid Glass。内容背景延伸到窗口顶边，原生交通灯、窗口拖拽及双击 header 缩放保持可用。窗口底层与页面使用相同背景色，快速拉伸时不应露出黑色空白。

迁移前的 Tauri 客户端曾完成首轮本机接入与原生验收；该记录只作为历史行为证据，不能证明当前 Electron 制品与窗口。桌面客户端尚未作为正式入口发布，[首版计划](../../../plans/desktop-client.md)保留完整目标；当前不能据首版范围推导所有功能已可用。

后续已确认以 Codex 的客户端功能和日常交互体验为对标目标，具体差距与迭代入口见[日常体验方向](../../../plans/desktop-client.md#首轮验证后的日常体验方向)。这是后续研发目标，下文仍说明当前已交付行为。

桌面客户端产品名为 **kite**，**kite-code** 为 TUI 名称；两栏界面、Electron 窗口与当前开发包均使用 kite。通用日常工作、shadcn/ui 界面及覆盖空间、会话、交互、结果、子代理、设置和恢复的整体目标稿见[界面与协作体验](../../../plans/kite-client-experience.md)，不据设计稿宣称这些能力已交付。

[工具消息结构与状态](../../../plans/kite-client-experience.md#会话消息与工具渲染)按 Runtime 提供的展示分类呈现：同一准确 Turn 内相邻且各有明确分组 ID 的探索工具可跨批次视觉聚合，原始分组与每项结果保留；正文、独立工具、不同 Turn 和缺失分组构成边界，缺少准确 Turn 时只合并同组探索；有明确子 Agent 归属的内部工具及异常只进入所属子 Agent 容器，归属随工具 queued 和 terminal 生命周期保留，因此只恢复终态时也不会产生顶层重复；缺少归属的旧异常仍保留独立入口，子 Agent 结果不会丢失。queued、running、waiting、completed、failed、rejected、cancelled 与 unknown 使用不同文字状态。Shell 的 stdout/stderr、退出码及输出限制按真实字段放入可展开输出，文件修改显示工具报告的差异；缺失信息时不补造。当前可读内容和交互限制仍以下文为准。

一轮 Agent 回复以准确的 Turn 身份组织：运行中的过程默认展开，按发生顺序显示阶段说明和工具活动；轮次完成、失败、取消或中断后，过程整体默认折叠，已确认的最终回复独立可见。中断前已生成但未确认完成的正文仍保留在可展开过程中，不冒充最终回复。即使本轮直接给出最终回复、没有可展开过程，也保留状态行；可靠终态耗时显示“用时 …”，缺少可靠时间时显示“已完成”。可展开的状态行只显示常规字重的状态或可靠耗时，以及始终可见、紧邻文字的箭头；高度与工具消息标题一致，悬停不填充背景，不使用前置状态图标，不汇总工具拒绝等结果，也不显示“展开过程／收起过程”文案；展开和收起沿用工具消息的动画，具体异常仍在工具消息内查看。状态分隔线到下方首条可见消息均留 16 px（展开时为过程消息，折叠时为最终回复）；运行中的过程末尾不绘制分隔线，只有过程下方有已确认最终回复时才绘制；用户可重新展开过程，手动展开或收起的选择在当前会话阅读状态中保留。失败、取消、中断、等待与需要恢复仍显示明确状态。工具聚合自身从出现起默认折叠，执行时标题更新当前工具动作与目标；排队、等待不计入“正在执行”数量，标题变化会向辅助技术播报；进度和结束都不自动改变展开状态。原始模型思考正文不进入消息列表；活动 Turn 没有正在执行的工具且确有思考活动时，顶部只显示“正在思考”。有可靠 Turn 起点时，运行中显示“已处理 …”；思考、等待等明确阶段保留阶段状态并附已处理时长。成功结束且终点可靠时改为“用时 …”，秒、分、小时、天按时长切换；失败、停止或中断保留明确状态并附可靠用时，旧历史缺少可靠时间时不补造。

当前 Run 需要恢复时，其当前轮尚未结算的工具在页面上显示“需要恢复”，不继续显示“正在工作”。这是对 Run 状态的临时展示，不写入或伪造工具终态；Run 状态更新后以真实工具事件为准。

开发版在当前父会话的“环境信息 → 子智能体”和对应的子 Agent 工具消息中提供详情入口；子会话创建并进入父作用域列表后，无需手动刷新即可打开只读详情，重新打开已完成的父会话也会自动恢复完整子会话列表，没有匹配子会话的旧后台记录只显示状态。切到其他会话后返回时，先保留此前已核对的子会话详情入口，再静默更新名单；同连接重新核对或当前页断线重接时保留上次已确认的环境状态并标明正在核对，期间不能停止执行；已有条目不额外显示读取提示。没有可复用展示摘要时，名单先显示“状态待确认”；新鲜快照到达后更新真实状态与操作资格。父会话读取明确被拒绝或身份核对失败时，立即移除其暂存的子会话入口和环境展示；子详情明确返回不存在或无权读取时，从父会话名单移除该入口。详情复用主会话的消息与工具渲染，先显示独立历史，再持续显示子 Agent 的实时过程；进入子详情时脱离父页面的实时订阅，返回后重新校准父页面，期间服务端任务继续运行。已读过的父会话和子详情在同一连接内再次打开时立即显示有容量限制的已读正文，空历史也不重复显示整页加载；后台继续核对最新历史与实时订阅，失败时保留已读内容和重试入口。非当前页缓存淘汰后按首次读取处理；临时断线期间，已读主会话可从有界缓存继续阅读，切回时仍核对会话与空间身份，连接恢复后必须重新读取历史并校准。子详情的非当前页缓存随断线清除；当前子详情只保留已读内容供等待核对。缓存不赋予发送或子会话读取权限。断线重连期间保留正在阅读的子详情和已读子名单，不先显示空的父页面；名单待核对时不授予子详情读取资格。核对父子身份后才恢复该详情；用户明确返回父会话或切换其他会话时取消自动恢复，迟到结果不能再跳回子详情。子线程不进入侧栏顶层会话目录。子 Agent 列表仍可在环境信息中刷新，读取失败也可在原处重试。详情读取和订阅按准确父子血缘授权，面板内不能对子线程发送、停止或修改。此入口的正式运行验收仍见[后台 Agent 协调方案](../../../plans/background-agent-shell-conversation-coordination.md)。

Agent 邮箱状态依据当前会话的持久事件显示为独立状态行：发送方的“已受理，等待目标读取”不表示子 Agent 已读；接收方的“已准备进入目标模型输入”表示输入已绑定；续轮结果结算另有终态提示。重复历史记录更新同一消息状态，私有消息正文不出现在状态行中。

开发版可选择本地项目、确认工作区信任、配置 Provider 和选择模型、新建和查看最近会话、提交任务、读取文本与工具过程并取消执行。安装与运行方法见[开发入口](../../../../apps/kite-desktop/README.md)。

左栏默认以 200 px 最小宽度展开，可拖拽至 420 px；窗口缩放时保持当前像素宽度，由中间栏及已展开的右栏适应剩余空间；空间不足时仍受面板最小宽度约束。调整后的宽度在本机保存并于重启后恢复。拖拽分隔线把左栏收起后，顶栏显示展开按钮，点击可重新展开左栏。左栏保留已添加的项目，所有空间默认展开并自动读取会话列表；新添加的空间进入列表首位，之后切换执行空间只改变当前选择，不调整已有空间顺序。展开或收起只改变显示，不切换项目。工作台入口暂时隐藏；会话继续按空间出现在左栏，点击直接进入原会话，不创建副本或改变执行状态。各空间的会话可展开或收起，不提供会话标题搜索。点击会话直接加载消息，无需二次确认；上下键移动列表焦点，Enter 打开会话。切换会话不停止当前任务，也不会发出新消息；首次发送正在创建会话时，已有空间和会话导航也不整体禁用，用户切换阅读目标不会改变该消息所属的新会话。目录在连接和新建时自动读取；侧栏中已有会话的运行与待输入状态随会话索引更新，包括切到新对话、安排任务等非会话页面后完成的后台 Run，不依赖当前阅读页的订阅。各空间内会话按最新更新时间倒序排列，单纯点击阅读不更新时间；侧栏不再显示“切换项目”、“断开项目”和刷新按钮。返回已连接窗口只更新本地目录是否存在，不重新加载会话列表。其他端新建且尚未进入本地目录的会话仍需下一次目录读取才显示。

已加载且没有会话的空间在项目名称下方显示“暂无聊天”，并与项目名称的文字左边缘对齐。

“空间”标题右侧的 `+` 打开系统目录选择器，选中一个本地目录后将其登记为空间并进入该目录的新对话准备页；取消选择不创建空间。标题的添加按钮和空间行的新对话、移除按钮仅在各自行悬停或获得键盘焦点时显示；触屏设备上常显。空间行的两个操作按钮紧邻排列。新对话入口使用编辑图标，添加空间仍使用加号；操作按钮平时为次级文字色，鼠标移到按钮或键盘聚焦时高亮。空间行的移除按钮先显示原生二次确认，明确提示会停止该空间正在运行的会话、永久删除相关会话历史及本机项目登记，工作目录文件不受删除操作影响。默认选择保留空间；确认后显示正在移除的空间及处理提示，移除按钮暂时禁用。空间和会话删除是数据删除：对应会话正在运行时由服务端发出取消，后续资源收尾由服务端处理，不要求用户先停止任务、恢复会话或等待历史工具变为终态。空间内全部会话及子会话批量删除，不逐条处理，也不要求额外收尾确认。成功后移除本机登记及对应页面；失败显示可信结果，缺少可信回执时保持结果未知。迟到任务结果和刷新不会重新带回已删数据。工作目录文件不属于删除范围。

左栏提供“安排任务”入口，页面展示任务空态与列表契约；点击创建后，表单在页面最右侧的通用侧栏中打开，主区域继续显示任务页。表单包含名称、任务说明、项目、运行频率及独立 Git worktree／本地项目环境选择。当前 Service 尚未提供定时任务的保存、调度、运行记录或通知协议，因此保存保持禁用，页面明确说明限制；填写内容只属于当前页面草稿，不宣称已创建或会在后台运行。

已登记 Git 仓库在连接准备时直接授权 Agent 访问空间，不展示“信任此项目”或重试授权提示；用户主动添加或选择的普通目录同样视为访问授权，具体工具继续遵循执行授权。授权由 Service 保存。需要访问工作区外的关联目录时，仍单独展示确切路径并确认；授权失败时保留输入，不伪造成功。空间、Git 仓库、分支或命令失败不作为 notice 插入客户端页面内容，统一使用带单个“确定”按钮的 shadcn `AlertDialog` 告知，确认后关闭并清除本次错误。会话内容按所属会话展示，输入草稿、阅读位置和过程展开状态在当前进程按项目与会话保留；退出后的恢复尚未提供。会话切换不取消原会话执行。助手正文支持统一排版的 Markdown 标题、段落、列表、代码块、引用与表格，正文不增加内边距或独立限宽，与消息阅读列同宽；明确类型的连续读取／搜索聚合为轻量摘要，从出现起默认折叠，执行中在摘要显示当前工具的动作与目标；展开后以统一图标轨道和单行“动作＋目标”排列，不显示重复的完成徽标。读取不展开文件内容，Shell 可展开有界输出、修改可展开工具报告的差异；单条进行中工具直接显示一行，运行、等待与异常状态继续保留，组合工具标题显示当前操作摘要；具体错误摘要只在展开后显示于对应工具项内。主会话只显示子 Agent 入口；子 Agent 的工具消息与步骤仅在该入口的过程容器内展示，列表最大高 320 px，超出时在容器内滚动，不常驻过程正文或结果段落；展开过程时不重复显示完成状态，失败工具的完整提示通过该工具行展开查看；子 Agent 已结束而工具缺少终态时显示“结果未知”，不继续播放运行中动画；有明确可见父工具时在该 task 展开区的子 Agent 容器查看，完成后仍保留；缺少可见父工具时保留子 Agent 容器入口，内部工具不进入主消息列表。独立子会话的只读详情从当前父会话的环境信息卡片打开，不能作为平级会话直接进入。

已提交任务执行失败时，会话中保留一条“本轮回复失败”提示，即使模型尚未生成任何回复。模型服务认证失败会明确提示检查当前提供商的凭据和账号权限；已分类的模型重试耗尽、服务不可用、会话存储不可用和工具纠错耗尽显示对应原因。缺少可靠分类时只提示检查会话失败详情和任务状态，不将后台任务、工具或 Runtime 错误推断为模型服务故障。模型给出的工具参数不符合当前格式时，该工具显示脱敏的参数错误，不展示原始模型响应。重新打开会话仍可查看失败记录。用户主动取消不显示为执行失败，读取历史不会重新发送任务。模型切换仍按会话保存的提供商和模型执行，不要求与设置中的默认模型一致。

发送与停止共用输入框右下角同一个 `26×26` 圆形主控位：消息准备与发送期间显示 loading 并禁止重复提交；失败或发送结果待确认时停止旋转。任务运行且草稿为空或正在停止时显示停止；输入运行中引导后切换为发送；两个动作不得同时出现。

任务运行或内部受管等待后台结果、且未等待用户交互时，输入框继续可编辑；发送运行中引导和停止操作保持可用，纯文本通过 `steer_turn` 追加到同一 Run。审批、补充问题或计划审核等真实交互仍独占回答区域并暂时隐藏主输入框。切换会话后，已保存为展开的工具详情直接恢复完整内容，不再播放一次展开动画；用户在当前会话中主动展开或收起时仍保留短暂过渡。

Ctrl+A／Cmd+A 在会话页面只全选消息内容，在输入框中只全选当前输入。会话消息支持原生选词、拖选与复制，段落和列表行选区限制在内容范围。侧栏、标题、按钮、提示等非消息展示文字不可选中复制；输入框保留正常的选择、复制与编辑能力。会话消息和左栏分别滚动；工具消息中可独立滚动的输出和文件差异在还有内容可滚动的边缘显示渐隐提示。首次进入显示最新消息；向上阅读后不再被流式更新拉到底部，可点击“回到最新消息”。输入框上方不展示独立状态信息，也不保留状态行空白；输入框底部工具栏集中展示按 Provider 分组的已配置模型，以及带有审批方式说明、图标和简短行为描述的权限模式菜单；模式名称与说明按系统语言显示中文或英文，不展示快捷键教学；选择文字与下拉图标使用固定间距。点击左下角“本地用户”按钮打开选项浮层，可进入设置，或在主题区域选择“暗”“亮”“跟随系统”。默认跟随系统；选择立即应用到主界面、设置与原生表单控件，并在本机保存，重启后恢复。跟随系统时，系统外观变化会自动更新界面；固定暗色或亮色时不受系统切换影响。Full 选项与已选状态的图标、文字以及风险弹窗标题使用警示色，确认按钮使用危险操作样式；桌面客户端每次从其他权限切换到 Full 前，说明 Full 允许代理无需逐项征得同意，在当前环境允许的范围内运行命令、读取或修改文件、访问互联网；提示文件被覆盖或删除、敏感数据传输及难以撤销的损失风险，并说明可以切回其他审批方式、系统限制仍有效；取消不更改权限，明确确认后才继续；点击当前已选中的权限不重复提示或提交。切换会话后，模型选择器先显示目录中该会话的模型，投影加载后再按最新状态更新；已有会话选择并确认权限后立即显示目标模式，保留静态下拉箭头，后台确认期间暂时禁用重复选择；服务端确认后落定，失败时恢复已确认模式。权限命令提交给该会话，按该会话所属工作区核对信任；即使当前正在查看其他项目或尚未选择执行项目，也不需要切换执行项目，不停止其他会话任务。修改历史会话权限不要求先恢复任务，也不依赖该会话原模型配置仍可用；修改成功不会启动任务或解除其恢复要求。若当前服务丢失执行权后仍保留旧会话 Runtime，需要重新启动服务后再修改，不会自动接管。另一服务进程持有该会话执行权时仍会拒绝修改，版本冲突需要读取最新状态后重新选择。若会话在修改期间被其他进程删除，本次修改明确失败，不按未知结果处理。工作区未信任或不可用时不修改权限；新对话的选择在创建会话后、发送首条消息前生效。没有活动人机交互时，输入框位于下方，Enter 发送、Shift+Enter 换行；空白输入和加载期间不能发送。任务运行但未等待交互时，输入框继续可编辑，Enter 把纯文本作为定向引导追加到同一 Run，不取消当前请求、不新建 Run；目标在提交前结束时保留草稿，不改投新任务。停止仍由独立按钮发起；提交后显示等待收尾，只有服务终态才显示已停止，已有修改保留。审批、补充问题、计划审核或其他等待交互出现时，主输入区隐藏，避免与当前交互争夺操作；交互结束后恢复原草稿。这不是新 Run 的后继队列。会话侧边显示后台 Shell、service 和子 Agent 的准确身份与状态；只有当前连接代次中新鲜且仍运行的项显示停止入口，断线后的旧运行项不可操作。

左栏品牌下方的“新对话”是与空间区域同级的全局入口；工作台入口暂时隐藏；尚未打开项目也可以进入并写下需求。欢迎区的四个建议只追加可编辑草稿、聚焦输入框并将光标移到新增文本末尾，不发送；首次发送时才创建会话并进入正常消息流，重复点击入口不会创建空会话或清空草稿。首次发送后输入框立即清空，内容区原位显示“正在发送”的用户消息；真实消息到达后在同一位置接管，失败则原位提示并把内容恢复到输入框供重试。准备草稿跨项目／分支选择保留，与已有会话草稿独立；切回历史会话恢复它原有的输入。发送失败后保留已创建会话，不重复创建。

空间标题右侧的“新对话”图标进入该项目的新对话准备页，不改变列表展开状态，也不提前创建空会话。选择其他空间时只校验已登记目录并读取该目录的 Git 分支，立即更新准备页上下文；不关闭当前 Service、不切换执行连接，也不读取项目列表、会话目录、信任或模型。左侧空间和会话列表保持原对象与交互状态，目标分支读取完成后一次替换。首次发送前才沿用现有执行项目切换流程；届时有活动任务会先确认停止，再激活目标空间并核对信任和分支，继续使用应用已经持有的模型目录与本次选择。普通非切换断线仍禁用会话导航。

预选空间不是当前执行空间时，输入区继续使用应用已读取的 Provider 目录和当前权限选择；模型与权限选择器不属于空间，切换空间不重新加载、不清空也不短暂禁用。模型选择只在准备页暂存，不修改当前或目标空间的默认配置。外部目录授权仍只在实际激活目标空间后读取和提交。发送前观察到分支或 HEAD 变化时采用当时的真实环境继续执行，不要求用户重复发送；只有用户明确选择了另一分支，才在首次发送流程中执行受控 Git 切换。会话一旦创建就立即绑定该身份；随后权限设置明确失败或回执未知时恢复草稿并在同一会话核对或重试，不再创建第二个空会话。用户取消停止旧任务和切换空间时同样恢复准备草稿并重新开放发送。

输入框聚焦不增加额外边框，右下角没有手动调整尺寸的拖动柄；多行输入由内容撑开。发送与停止使用同一位置的图标按钮，悬停提示和可访问名称说明当前动作；停止提交期间保持禁用，避免重复请求。

已发送的用户消息可逐条复制；Agent 复制按钮按 Runtime `turnId` 归属，同一 turn 内只在没有后续工具调用的最终回复下显示一次，并只复制该完整最终回复，不包含同轮工具前说明、思考、工具、子 Agent 或其他非最终文本。用户气泡和 Agent 最终回复与后续内容的间距为 32 px；非最终回复到后续工具保留 8 px；工具记录到下一段非最终正文为 8 px，到最终回复为 16 px，工具组内保持紧凑。悬停消息或用键盘聚焦可显示复制按钮；成功时显示较大的勾，两秒后恢复复制图标；发送状态未定、失败或流式回复不提供复制。Agent 正文下的“正在回复”在最终回复落定后移除。发送回执未知时保持“待确认”并阻止重复提交，等待新的运行时事实或显式会话恢复。

新 Run 在持久提交前明确遇到 revision 冲突时，客户端可重新读取投影并且仅重提一次；刷新后已有活动 Run 则保留草稿，不自动改投为 steer。这不改变回执未知时禁止自动重发的规则。

输入框上沿以无底色的紧凑上下文条选择已打开项目或添加本地目录，Git 仓库旁边直接显示真实分支，不重复展示固定的本地环境提示；非 Git 项目完全不显示分支选择器，仍可正常发送。Git 只是空间的可选能力：`.git` 标记无法确认、Git 未安装或 Git 探测失败时按普通空间继续，不阻止创建对话；只有用户主动执行分支操作时才要求 Git 能力可用。上下文条与输入正文共用左侧视觉基准，只承担轻量元信息层级，不作为独立大卡片与输入框争夺视觉重心。选择项目或已有本地分支后立即生效；切换分支时有运行、排队或等待中的任务，或存在暂存、未暂存、未跟踪的改动，都会阻止切换。不会自动提交、丢弃修改或创建 worktree。分离 HEAD 和尚无提交的仓库显示真实状态；只允许在仓库根目录切换分支。分支菜单可以刷新，失败或回执未知时检查刷新后的实际状态，不自动重试。

应用启动先显示独立启动页，完成本地服务连接、首屏空间会话目录及当前项目的准备检查后再显示主界面，不展示主界面逐项加载的过程。服务连接或首屏目录全部读取失败时，启动页显示原因并提供“重新尝试”；空目录可以正常进入，局部目录失败、项目失效或模型未配置不阻止进入主界面处理。启动页没有人为最短停留时间；进入主界面后发生断线仍保留页面与草稿，不重新遮挡为启动页。

应用重启会恢复已打开项目列表并自动读取应用历史，不创建会话或发送任务。项目目录失效、Git 不可用或模型配置错误不妨碍阅读已有历史，各自显示局部提示。发送前核对目录、信任和模型；普通资料文件夹无须 Git。本地服务的启动、连接与恢复由客户端内部负责，不提供重连或断开操作，内容页不展示连接中断或服务未就绪提示。内部恢复期间保留会话内容与草稿；侧栏会话点击立即改变阅读选择，连续点击只恢复最后选择的会话，不等待旧会话完成连接才响应。已选会话在校准期间仍显示阅读页，不误显“新对话”欢迎页；发送、停止与审批继续等待新连接就绪。操作结果未知仍会明确提示检查实际效果。未发送草稿不承诺应用重启后恢复。

关闭窗口保留应用与任务，再次激活显示原窗口；明确退出或实际切换执行项目会停止自有服务中的执行，已有修改不撤销。只有存在活动任务或任务状态无法核实时才显示退出确认；清理失败或长时间等待时提供紧急退出。异常收尾会提示检查结果，不自动重发请求。连接断开后不能使用旧的就绪状态提交操作；回执丢失时显示“操作提交结果未知”，自动恢复后仍应检查会话及实际文件，再决定继续。

工具审批会显示具体命令与说明，可以选择“仅批准这一次”或拒绝；结果仍由服务核实。补充问题使用紧凑的 Questionnaire 展示单选项和允许的自由回答；一次请求包含多题时可通过上一题／下一题自由查看，最后一次提交全部答案，每条答案以 `q1`、`q2`、`q3` 题目 ID 保留协议归属。选项提交同时保留内部 option ID 供校验与恢复，但交给 Agent 和历史摘要的是选项文案；自由回答保持用户原文，不把 `q1-o1` 等内部编号当作语义答案展示。选项不常驻显示字母顺序或详细描述；有描述的选项在右侧显示 info 图标，鼠标悬停或键盘聚焦后显示该选项的标题与完整描述。第一页只显示下一题，最后一页才显示提交回答；可以在当前题未答时先查看后续问题，但尚有任一题未回答时提交按钮不可用。交互块不使用内部滚动条，完整内容直接占据底部布局并让会话阅读区收缩。取消回答会把取消结果交给模型，模型仍可继续；当前交互期间不提供停止按钮。计划面板显示完整正文与步骤，支持 Accept Edits/Auto 批准、修改要求及取消；未能完整读取正文时不能批准，较大正文先加载完整附件。扩展或验证交互仍显示限制，用户可取消。高级恢复尚未交付。

新 `apps/desktop` Native 候选现已通过本机 macOS 的默认 ask_user 问卷窗口验证：未作答可浏览、多题一次明确提交、会话切换保留问卷草稿、取消问卷后原任务继续；问题出现时隐藏主输入，回答或取消后恢复原主草稿。原值、文案和原 Run 分别核对。问卷草稿的页面生命周期另有 DOM 证据；计划审核另有下述验收，全部设置与完整视觉迁移仍未完成。实际范围见 [Native 问题 owner](../../../../apps/desktop/README.md#native-普通问题与页面草稿)。

Native 主输入通过“先审核计划”选择当前提交：空闲时发送新的计划任务，当前有任务时排队等待它结束，再开始新的计划任务。审核时显式选择 Auto 或 Accept Edits；补充修改要求后，新版本仍需重新批准。拒绝本版计划与停止原任务各有入口，停止不撤销已有结果；结果未知时退出仍会要求确认。计划审核及工具审批期间隐藏主输入，交互结束后恢复原主草稿。具体可用范围和本机验收见 [Native 计划 owner](../../../../apps/desktop/README.md#native-计划入口与完整审核)。

补充回答和计划修改意见在当前页面进程内保留：切到其他会话、新对话或安排任务再回来，可以继续编辑原文。它们与主输入框草稿分开，也不会带入其他会话或下一道问题。提交失败保留输入，确认提交或取消成功后清理对应交互的草稿；完整页面刷新和应用退出后不保证恢复。

点击顶栏“文件变更”打开页面最右侧的通用侧栏，展开文件操作可阅读成功文件工具保存的差异或写入内容。最右栏与左侧导航在展开、收起时以短暂的实际宽度过渡推移中间会话区，并保留用户最近拖拽的栏宽；系统启用减少动态效果时立即切换。最右栏与左侧导航、中间会话区同为全客户端高度的同级栏，三栏相邻边界均可拖拽调整宽度；会话侧栏使用标签页结构，当前只有“文件变更”一个有事实支撑的标签。关闭或 Esc 返回顶栏按钮，切换会话自动关闭，输入草稿保持不变。这不是当前工作区 Git diff，也不覆盖 Shell/MCP 等工具未报告的逐文件修改。输出可能截断，空列表不代表磁盘没有变化。在设置中可选择 VS Code、Zed 或 TextEdit 打开当前项目内仍存在的文件；同一选择也用于消息中的路径链接和读取文件路径，默认 VS Code，在当前进程保留。打开的是当前磁盘内容，编辑器需已安装。迁移前 Tauri 版本曾在本机 macOS 确认 VS Code 实际打开；TextEdit 仅确认启动分发，Zed 未安装。Electron 版本的实际编辑器窗口仍待重新验收。

首次打开或缓存已被淘汰的会话显示加载进度，长历史分批读取后完整展示。已保存的正文先于实时连接校准展示；实时状态查询或订阅失败不会挡住已读历史，也不会使任务自动重跑。单次会话加载或校准超时后保留已读正文，可重新加载或切换其他会话；超时本身不主动断开其他会话共用的连接。实时校准完成前可阅读、复制和编辑草稿，发送、停止与审批保持不可用。已打开的会话若出现实时消息缺口，会保留正文并自动补读历史；消息补齐且实时订阅重新就绪后才恢复操作，补读失败仍可阅读并重新加载，不会自动重发任务。首次发送选择的权限模式与当前一致时保持原模式并继续提交。同一连接内再次打开已缓存会话，立即显示上次正文并恢复阅读位置和展开状态；空会话也会缓存。后台仍会完整校准历史，期间可以阅读、复制及编辑草稿，发送、停止与审批等操作等待校准成功。校准失败保留已读正文并提供“重新加载会话”；明确不存在或拒绝读取时清除正文。缓存容量有限，超长会话离开后可能需要重新加载；非当前会话缓存不跨连接重建、页面刷新或应用重启保存，普通断线仍保留当前正文供阅读。每个空间的目录默认读取并返回全部会话，不提供手动加载更早会话的入口；页面按最新更新时间从新到旧排序，默认显示前 5 条，点击列表末尾辅助文字色的“展开更多”每次再显示 10 条，最后不足 10 条时显示剩余会话。收起空间后再次展开恢复为 5 条，其他空间不受影响。一个空间读取失败不清空其他空间。点击其他空间的会话直接阅读，不停止原任务；在已有会话发送时按原会话身份路由，不切换当前执行项目，也不停止其他会话任务。本地目录不存在时，空间名称变浅，仍可打开会话，不常驻提示目录关联情况。已有会话继续发送不以本地目录存在、Desktop项目登记或当前选中项目为前提。服务按会话持久身份与既有授权执行；原目录被删除时仍可对话，依赖该目录的Shell和文件工具在实际调用时返回错误，不自动创建目录或改用其他目录。新建项目会话仍核对所选目录与授权。自动重接恢复所选会话和进程内草稿，不重发任务。

设置页的“提供商”以列表展示当前支持的 OpenAI、DeepSeek、OpenAI-compatible 与 Ollama，按实际快照显示可用状态；点击“配置”或“编辑”在页面右侧面板打开对应 Provider 表单，关闭后返回原列表按钮，不承诺连接或执行已验证。切换提供商会清空上一提供商尚未保存的密钥、地址和模型名称。必填 API key 与服务地址格式在面板内提示错误并聚焦对应字段，不弹出浏览器原生校验提示。“模型”页按 Provider 展示已发现模型，可启用或禁用，并通过下拉框从已启用且可用的模型中选择默认模型；当前默认模型须先更换才能禁用。切换默认模型、启用或禁用模型、刷新配置和保存提供商时，页面保留当前分类与滚动位置，不整体变灰；等待期间阻止重复配置操作；关闭再打开设置不会解除等待，完成后才恢复配置操作。启停开关先保持用户选择的位置，提交失败则按服务确认的状态恢复并显示错误；提供商保存期间输入只读。无可选模型时显示空态和服务提供的诊断代码，不将未配置误报为可用。输入区模型选择器只展示已启用的模型路由，并暂存本次选择。新会话在首条消息创建时绑定该路由，已有会话在下一条消息开始时更新自身路由，不覆盖其他会话；活动任务继续使用开始时冻结的模型。通用 Native 的 API key 通过选定 Profile 的系统凭据库保存，JSONC 只保存引用，输入在提交后清空；保存仅更新选定连接，保留同一 Provider 的其他连接。模型名称留空时查询模型列表，手动填写时直接保存，是否可执行仍需实际任务验证。提交结果未知时只能显式查询原提交；最新配置读取不能代替原保存回执，不自动重试。

输入区的模型与思考选择器先展示紧凑思考浮层，点击模型名称进入提供商与模型双栏；两列分别滚动，模型数量变化不改变浮层高度。选择器统一使用 14 px 文字。滑块按极低、低、中、高、极高、最大六档选择，蓝宝石星光随档位加速，最大档为融合蓝色的紫宝石；白色按钮保持静态，松手时短暂扩散粒子，系统减少动态效果时停止装饰动画。思考调节只对服务声明支持的 OpenAI／OpenAI-compatible 提供商且未明确关闭推理的模型开放；其他模型显示不支持提示。未选档位继续沿用服务配置或提供商默认值，界面显示“默认”或原配置值。选择在当前页面进程内按对话保留，切换模型清除原模型的临时档位；新对话首条消息使用准备页的选择，之后继续发送沿用该对话的选择。模型与档位只作用于下一次新运行，不修改全局默认，也不改变正在运行的任务；运行中发送仍为文本引导。页面刷新后临时档位回到服务配置，活动运行仍使用其已冻结档位。


保存 Provider 与刷新配置分别确认结果：已保存但刷新失败时，提示刷新后选择模型，无需重复保存；服务明确拒绝时保留拒绝原因。写入结果未知时，即使后续刷新成功也不改称保存成功；刷新同样失败时明确说明两者，避免将查询错误误认为写入未发生。

迁移前 Tauri 版本在本机 macOS 完成过配置、问题/计划、项目与会话草稿、修改与测试、结果阅读、VS Code 跳转、重启继续、长会话、与 TUI 的同会话写入保护、损坏制品提示和手动替换应用后的数据保留。Electron 已在隔离原生窗口中用真实 DeepSeek 模型验证：A 的两个 required 子会话运行时反复进入子详情、返回父会话并切换 B/A，返回 A 仍能连接，同一 Run 随后完成；此证据只覆盖该定向场景，详见[原生验收](../../../../apps/kite-desktop/docs/native-validation.md)。包内 Service 的 MCP OAuth、原生凭据保存与重启恢复不能自动证明 Electron 窗口流程。系统输入法、实际外部编辑器、原生授权和工具进程树崩溃等剩余场景尚未重新取得窗口证据。桌面端仍是开发版本；正式签名、公证、下载分发与签名包升级、其他平台尚未完成资格验证。从其他程序导入已有凭据的系统授权行为也未完成验收，不承诺无提示迁移。

本次两栏界面通过真实服务回归、DOM 交互测试与浏览器布局检查；系统中文输入法、preload/IPC 和 Electron 窗口仍需单独验收。验证范围见[两栏会话界面](../../../../apps/kite-desktop/docs/conversation-ui.md)。

设置中的 MCP 分类显示配置来源、连接与认证状态，可展开连接详情；按实际状态开始／取消认证或重新连接。操作完成后查看最新状态，浏览器认证完成后点击刷新；结果未知时不自动重试。Skills 分类展示当前项目可发现的名称、描述、来源与可用状态，没有安装入口。此功能不改变 Web 的只读权限。

正式 Native 左侧的 Skills 分类读取所选会话工作区当前可信配置目录；需先核对并信任所显示的读取范围。完整读取成功后展示名称、描述、来源标签与可用／禁用／不可用状态，可展开查看详情。点击“刷新 Skills 目录”重新读取文件及配置；刷新失败时保留当前工作区上次完整目录并说明未更新，切换会话或工作区时清理旧目录。可用空目录与目录不可用分别说明，关闭分类只停止目录读取。它没有安装或 Workflow 激活入口，当前发现范围由默认 Service 的可信配置决定。本机 macOS 已完成实际窗口、切换和冷重启验收；范围与其他待验能力见 [Native Skills owner](../../../../apps/desktop/README.md#native-skills-只读目录)。

页面完整刷新后，若原项目服务仍在运行，应用自动接回服务、恢复原会话并继续读取任务状态，无需重新添加项目或确认清理，也不停止原任务。普通界面热更新保留客户端连接；完整刷新不保证保留未发送草稿。应用或服务真正退出后的恢复不自动重放已停止的任务。

客户端启动以 300ms 内完成本地连接和首屏目录为优化目标；目录无需先恢复所有历史或准备模型。迁移前 Tauri 宿主的部分热缓存服务至目录测量曾低于该预算，但首次运行和完整系统启动仍未满足资格；Electron 需要重新取得从系统启动到窗口绘制的端到端证据。测量条件与负载限制见[启动说明](../../../../apps/kite-desktop/docs/history-and-recovery.md#启动预算与验证边界)。

点击未缓存的会话后，右侧消息区保持原尺寸并在中央显示无底色的浅色风筝图标，以不改变布局的轻微闪光表达加载；系统要求减少动态效果时显示静态图标。页面不显示加载文字或欢迎内容，历史分批读取完成后直接渲染完整正文，避免加载节点引起布局抖动。已有缓存正文的后台校准继续保留正文，不显示该覆盖层。

通用 Native 的工具过程现在沿用原轻量工具行与结果展开。执行中、失败、停止和结果未知按已核实的原执行展示；消息完整不表示工具成功。读取文件失败保持单行状态；只有已确认成功且可用的文件操作提供路径按钮。目标文字来自已读的原请求，有歧义时不补目标。Shell 启动受理与后台任务完成分别表达，完整输出和准确停止继续从环境信息／Runtime logs 操作。未知工具或版本显示原名称、版本和可展开原文；无法核实状态时保留原结果，可明确重新核对。关闭结果或切换会话只结束读取，不停止或重新运行工具。

Native 已接原轮次阅读：按已核实的 Run 显示过程、耗时与终态，结束后过程默认折叠，确认的最终回复独立可见；可重新展开过程，同轮相邻的已知文件读取／搜索等沿原工具聚合。复制最终回复使用准确正文，大输出须先展开并读完已验证全文，关闭全文后撤销复制。恢复时已保存的旧 Store 终态可作为历史展示，原出处保留；Fork／Include 封存内容不借来源 Run 后来的状态补最终回复。状态无法核实时保原消息或“上次确认状态”。

默认问答工具的已保存结果沿原组件显示实际问题和人类回答；取消信息回答显示“已取消回答”，任务按真实状态继续。人工审批已接原按钮与范围菜单，完整大请求读完并核实后才能回答。工具上的原审批事实分别显示已提交待核对、已人工批准、自动批准／拒绝／等待或未知；停止后保留可核对的已有记录，批准不代表工具执行成功。首次和冷启动的人工审批记录已核实，原记录可从下文“交互记录”阅读。当前会话输入区已沿原菜单切换 Ask／Auto／Full，只改该会话，Full 取消或切会话后的旧确认不生效；原停止按钮按准确活动任务提交取消，等待原状态核实。macOS 当前 Store 已核自动批准、拒绝、转人工、无效结果回到人工及审批中停止；转人工保原原因，拒绝或停止时没有文件作用，冷读不重发。全部封存／恢复组合和完整 PC 验收仍待核对。当前范围与证据见 [Native owner](../../../../apps/desktop/README.md#原审批面板与授权观察)。

工具消息按已确认原型统一为轻量行：上下各留 8 px，读取／搜索聚合展开后不缩进；hover 高亮文字与图标，不增加背景色。仅具体文件名 hover 时显示下划线并可打开。Shell 摘要点击展开输出，容器最大高 320 px、内部可滚动，结果固定在容器底部；手动上滚后停止跟随，可回到最新输出。运行中的文字有轻微扫光，减少动态效果设置下静态显示。

“会话工具”中的“交互记录”可展开阅读原问题、计划和审批请求，查看已保存答案、取消与回答被执行接收的事实。这里只阅读，当前待回答记录仍从原待输入卡操作。计划保留格式化阅读和准确修改反馈，大附件须完整读取并核实后才能展开原文。分页期间状态变化会保留本会话上次完整记录并说明未更新，可点击“重新读取交互记录”；切换会话清理旧范围，关闭只结束读取。当前范围和恢复限制见 [Native owner](../../../../apps/desktop/README.md#原交互记录只读历史)。

自动审批状态附在所属工具上：审批中、已自动批准、未通过或等待人工审批，等待使用中性色，原因按服务提供的文本显示。人工审批主按钮为“仅批准这一次”，服务允许时右侧菜单可直接“批准本次及本会话相同命令”；左侧为“拒绝”。授权范围仍以服务匹配规则为准，批准不等于执行成功，停止后保留已有批准记录和输出。上下文自动压缩以轻量分隔消息显示进行中、完成或失败；问题回答完成后可在轻量回执中展开查看。

读取工具失败保持单行状态，不另附原始错误段落；审批拒绝原因仍正常显示。聚合内的 Shell 也可点击命令查看输出，收起聚合后再打开会保留先前展开选择。

在另一空间的已有会话发送时，直接按原会话ID提交，不要求切换当前项目，不关闭配套服务，也不停止其他空间任务。新会话属于所选空间，已有会话按持久空间身份执行；授权、模型和草稿继续分别隔离。明确退出、显式取消及真实工作目录冲突仍按各自规则处理。

原 kite-desktop 历史路径以会话页面顶部 Toast 提示操作失败；通用 Native 的空间、Git、分支和命令失败遵循上文现行 AlertDialog 约定，保留草稿，确认后清除本次提示。会话因执行权失效而不可继续时，仍需区分被占用、清理未完成与外部结果未知；实际恢复入口和取得资格见[Native owner](../../../../apps/desktop/README.md)。核对原效果不发送输入框草稿，旧执行结束缺少证据时不能以重发消息代替核对；详情见[恢复语义](../../features/recovery.md)。

原 kite-desktop 的 Git 切换会影响其项目配置加载，需要在所有空间任务结束后重启配套服务，不自动取消任务。通用 Native 的新对话切换与配置冻结遵循上文当前入口约定；普通项目选择和发送消息不关闭 Service。

Ask 请求出现时，消息列表立即显示“询问用户”工具记录和问题，等待用户回答；回答或取消后在同一位置更新。Ask 历史保留唯一可展开工具记录：单题标题展示“询问用户”和问题，内容为“回答：”及答案；多题标题展示“询问用户 · 已回答 N 项”，明细带有序前缀，每项按“问题：回答”展示。取消后内容只显示“已取消”。内容与标题文字对齐，换行对齐前缀后的正文，每项最多 5 行，超出截断，连续字符自动换行。仍按 toolCallId 去除重复工具记录，不展示结果 JSON。

Shell 只展示部分日志且服务提供的总行数超过当前内容时，状态区显示“输出已截断”。自动审批期间停止且没有执行记录时，明确说明命令未开始执行；执行后停止则保留实际输出，不标为“未执行”。

可展开消息的箭头紧贴标题内容（6 px），位于状态文字之前；收起时仅悬停图标与文字组成的紧凑标题区或键盘聚焦时显示，展开后持续显示。文件修改的文件名与 diff 按钮保持独立操作；不可展开的读取不显示箭头。轮次过程有独立折叠控制，箭头紧跟状态与耗时，思考正文不提供展开入口。

思考状态只在活动 Turn 顶部用简短“正在思考”表示；过程结束后由轮次状态替代。客户端不展示思考正文，也不把思考段时间当作整轮处理耗时。

阶段说明、工具与最终回复的间距由同一轮的外层布局维护；隐藏的思考内容不占用消息间距。

本轮回复异常失败时，以类似工具消息的轻量行显示“回复失败”和简要原因，默认收起；点击或通过键盘展开后可查看一段简洁的失败说明。开发模式还显示服务已提供的原因代码、执行结果、直接重试是否已确认安全和后续处理方式；生产模式不显示这些额外诊断字段。失败提示始终显示在本轮过程之外，收起过程或没有回复正文时仍可见；详情补充和会话重新加载保留展开选择。缺少分类信息时显示通用失败说明，不推断具体原因，也不自动重试。

工具消息展开后，标题文字、图标和箭头持续高亮；收起后恢复默认辅助色，悬停和键盘聚焦仍可高亮。详情展开与收起有短暂过渡；系统启用减少动态效果时直接切换。

源码与打包版使用同一正式会话入口，不再按代码目录或 epoch 自动分库。已验证来源会自动整理；`STORE_INCOMPATIBLE` 表示未证明可安全读取的格式，`STORE_ACCESS_DENIED` 提示检查数据访问权限，`STORE_CORRUPT` 表示数据库或已识别结构校验失败，`STORE_INSUFFICIENT_SPACE` 提示释放磁盘空间后重试。原数据不会因这些检查失败而被清空或替换。

启动失败且Service提供了有效诊断时，可点击“保存诊断”，在系统文件对话框选择新的JSON文件。报告只包含错误分类、准备阶段、格式版本与处理提示，不包含会话内容、目录或原始服务输出。取消选择不会写文件；已有文件不覆盖，保存失败时选择新的文件名重试。迁移期间会显示阶段；确认其他客户端或整理流程占用存储时先自动等待，最长10秒，占用解除后在当前窗口继续启动，超时再提供重试。应用菜单中的退出先请求安全退出，发布前在安全点取消，发布已开始则等待结算；等待超过 20 秒可由用户明确强制退出，届时下一次启动按持久恢复资料核对。窗口关闭仍按原行为隐藏窗口；请求退出本身不表示取消已完成。

正式 Native 已迁入上述文件变更面板：与“会话工具”互相切换右栏，逐次列出成功的文件写入/编辑；展开才读取已保存差异。预览截断时明确标示，旧记录未保存差异时保留操作与可用路径，并说明不会按当前文件补造。关闭和切换只结束读取，输入草稿和实际执行保持。原来源属于另一项目或不能确认当前项目时只读历史，不提供编辑器按钮。常规中的编辑器选择已接文件变更路径按钮，当前 renderer 默认 VS Code；消息正文和已核实的文件读取／写入／编辑行也已接原路径入口，打开当前项目文件；跨项目历史、子详情或未知格式只读。缺失目标沿原弹窗告知。常规摘要显示当前项目的配置默认模型，无会话和新对话准备页显示用户默认；临时会话选择和活动轮次保持各自语义。macOS 新 Native 的原面板与消息入口首次/冷读、常规摘要、作用域校验和选择已取得有限证据，实际外部编辑器窗口的重新验收范围仍保持上文所述；准确边界见 [Native owner](../../../../apps/desktop/README.md#原文件变更面板与编辑器)。

## 开发 Native 的文件检查点恢复

新 `apps/desktop` Native 入口在当前主会话提供“文件检查点”面板。先按需读取目录，再读取所选点的当前文件预览与准确会话边界；仅会话、仅代码、代码与会话三个范围必须明确选择和确认。仅会话生成新会话而不恢复磁盘；仅代码保留当前会话与选择，仍单独展示普通恢复动作的人类审批；代码与会话先恢复代码，只有核对原代码成功后才出现“明确继续原会话分支”，不会自动执行第二步。

两步的原申请身份在第一次提交前全部保存在当前 Profile。退出、崩溃、读取取消或回应丢失后，“查询原恢复”只核对原 Command/restore ID，不重发写入、不另建 ID。代码成功但分支未知时保留两种事实。明确继续前还会重新核对原检查点的完整当前文件预览，所有文件必须仍是已确认的恢复结果；独立编辑或随后完成的写入会拒绝继续，原代码成功记录保留，分支尚未执行。读取和提交之间没有对独立编辑器的全局锁。换 Store 恢复的旧申请保留原来源，作为只读历史，不重标或自动取得新 Store 执行许可。

切换 Session、修改范围或标题、隐藏面板和关闭读取都会使旧观察失效，迟到响应不能覆盖新页面；已提交的申请继续按原身份保存。完整文件来源、媒体、保护路径或当前后像无法核实时，代码恢复可能不可用或冲突；准确的会话边界可以独立成立，不因此授予文件或媒体访问。当前范围已由实际 macOS default Service、Node SQLite 和 Electron 开发制品验证，测试和剩余制品边界见 [Desktop owner](../../../../apps/desktop/README.md#native-files-检查点恢复)。这没有切换原正式入口，也没有为只读 Web 增加恢复按钮。

通用 Native 已接入上述四类 Provider 的设置、手动模型名称与显式空名称发现，以及每个 Session 的下一次模型和临时思考选择。新模型先禁用，启用后才进入输入选择器；默认模型禁用门禁保留。活动 Run 的模型与档位保持原值，普通引导不携带新模型或档位。新 Session 首次输入才保存模型路由，冷启动保留原 Session 路由，临时档位回到服务配置。提供商保存分别展示凭据和配置结果，已发布后的刷新失败与写入未知分别处理；未知只能查原提交。完整行为见[模型与配置](../../features/models-and-configuration.md)，当前本机窗口证据与限制见[Native owner](../../../../apps/desktop/README.md#native-provider-与下一次模型选择)。

通用 Native 的 MCP 设置、来源操作、认证、连接与完整工具详情已集成；当前本机正式窗口已核两范围来源操作、独立审批、连接与重连、完整工具正文、下一Model schema和一次效果，当前原完整默认615文件/489主作业通过。macOS默认Chrome和系统凭据库的登录、刷新、清除、撤销、取消登录及重启恢复组合已实际验收；测试使用本机自有认证服务，这份证据不承诺其他平台或任意外部服务兼容。[当前方案](../../../plans/unified-agent-native-mcp-settings.md)保留整片独立审查和剩余资格状态，上文旧客户端的 MCP 描述继续定义迁移预期。
