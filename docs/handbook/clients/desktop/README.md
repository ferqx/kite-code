# Kite 桌面客户端（开发中）

Windows 客户端启动后会在任务栏通知区域创建 Kite 托盘图标。双击图标可显示并聚焦主窗口，最小化时先恢复窗口；右键菜单提供“打开 Kite”和“退出”。关闭窗口后客户端继续在后台运行，可从托盘重新打开；选择“退出”沿用活动工作确认和服务清理，取消退出后仍可继续使用。

Agent 流式回复按元素更新，未变化的段落、列表项、表格和代码块保留已有展示。新追加的普通正文按可见字符依次渐显，中文和组合 emoji 均保持完整；单字渐显约240ms，较大批次会缩短字间间隔，整批最多约420ms，已经可见的文字不重新播放。历史加载、正文纠正与缓存返回直接显示内容，系统开启“减少动态效果”时直接显示新增文字。Markdown语法补全时，受影响的元素继续更新，例如后补链接定义或闭合强调标记。

正常流式输出按已保存消息的变更增量更新，不因每批文字重新读取全部历史。首次打开、重开、断线重连或历史变更凭据失效时重新核对完整历史；核对期间保留已读正文，相关操作等待恢复。消息按原身份更新，独立发送的相同文字仍是两条消息。同步连续时发送前不额外全量重读；消息保存、发送准入和任务执行仍各自核实。

会话正文与底部输入区居中显示，最大宽度为 740px；窄窗口下随可用空间缩小。向上阅读时，“回到最新消息”以带浅阴影的圆形图标按钮显示在正文区域底部中央，位于消息内容之上，并随环境信息占位和窗口宽度保持对齐；会话进行中显示依次跳动的三个点，静态时显示向下箭头。手动滚动接近底部时保持阅读位置，实际滚到底部才恢复跟随；点击按钮则立即回到最新消息并恢复跟随；减少动态效果模式下三个点静止。

图标按钮统一采用以下尺寸，按用途选择；普通图标按钮沿公共按钮规范使用8px圆角。提示词输入框内的按钮采用两端圆滑的胶囊形，发送／停止、附件移除和回到最新消息保留各自的圆形轮廓。

| 用途 | 按钮尺寸 | 图标尺寸 | 单侧视觉留白 |
| --- | --- | --- | --- |
| 紧凑操作，如代码复制、审批翻页、关闭标签 | 24px | 16px | 4px |
| 常用操作，如消息复制、空间操作、面板工具 | 28px | 16px | 6px |
| 顶栏导航与输入区控件 | 32px | 16px | 8px |
| 较大独立操作 | 36px | 20px | 8px |

消息复制按钮悬停或键盘聚焦消息时显示，复制成功和失败仍在原按钮反馈。消息工具栏内的复制按钮与时间文本间距统一4px；用户消息气泡或 Agent 正文到下方工具栏保留2px，工具栏与下一条消息至少间隔8px。

用户消息与 Agent 正文在同一信息栏显示记录时间，随消息悬停或键盘聚焦一起出现。用户消息按“时间、复制”靠右排列，Agent 正文按“复制、时间”靠左排列；时间不进入消息复制或聊天全选文本。

“处理过程”里的 Agent 阶段说明、流式中间正文和普通 Agent 邮件不显示消息复制、记录时间或其占位留白。最终回复移到过程外后显示原信息栏；用户输入、用户引导及过程外独立消息保留各自原有操作。复制仍须满足完整正文资格。

| 记录日期（设备本地时区） | 显示格式 |
| --- | --- |
| 当天 | `11:45` |
| 昨天 | `昨天 11:45` |
| 本年更早日期 | `10月18日 11:45` |
| 其他年份 | `2025年12月31日 11:45` |

悬停时间可查看含年份、秒和 UTC 偏移的完整日期；再次悬停或聚焦消息会按当时日期更新“昨天”等显示。时间取自消息首次保存，流式追加、复制、刷新和重开不重置；原输入由业务消息接替时保留原输入时间。未取得可核实时间的旧历史或投递占位显示“时间未知”，不使用打开页面的时间补齐。

## 提示词与附件

已保存的会话输出可以在对应处理过程里展开“查看本次交付的文件”，阅读当次交付的内容。后续修改不会改变旧版本；“打开当前文件”另行打开最新工作文件。较长历史正文可继续读取下一段。PDF 按页读取生成的页图显示在原工具过程下，源文件删除或重开会话后继续读取已保存的原件与历史页图。

附件原件、输出文件和当前方案均持久保存。本文说明当前操作行为；已验证的操作过程与完整安装资格见 [Desktop owner](../../../../apps/desktop/README.md)，PDF 读取与实际模型范围见 [Files owner](../../../../packages/agent/src/tools/files/README.md#会话文件与-pdf)。

普通回复与历史正文直接完整显示，不附“回复预览”“完整回复”标题或查看／收起按钮。读取期间保留已有正文，核实完整内容后即可复制；原回复未完成时仍明确提示。真实读取失败保留原文并说明失败，回复内不提供“重新读取”按钮，不重新发送任务，也不展示内部错误代码。

消息正文新增以下 Markdown 内容；输入框保留其可编辑源码，发送后在正文展示。

| 内容 | 写法与阅读方式 |
| --- | --- |
| Mermaid 图表 | 使用 `mermaid` 代码围栏，支持 `graph`／`flowchart` 流程图、时序图、类图、状态图和 ER 图。图表可切换到源码，复制仍复制原始代码。 |
| 代码高亮与 diff | 围栏填写 `typescript`、`python`、`json`、`sql`、`bash`、`diff` 等语言标记；diff 用文字颜色区分增删，不铺背景色。未知语言或较大的代码块保留原文。 |
| 提示块 | 引用以 `[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]` 或 `[!CAUTION]` 开头，显示中文标签与侧边线。 |
| 公式 | 行内使用 `$E=mc^2$`；独立公式放在上下各一行的 `$$` 中。较宽公式可横向阅读，错误公式保留可读内容。 |
| 标题与脚注跳转 | `[跳转](#标题)` 跳到当前消息的对应标题；脚注支持 `[^名称]` 引用、`[^名称]: 说明` 定义和返回正文。相同标题依次使用 `标题`、`标题-1` 等目标。 |

图表围栏尚未闭合时先显示源码，闭合后绘制；错误修正后重新绘制。图表使用透明底与细线，节点边框与箭头使用蓝色，生命线、分组和注释边框使用青色，两者随深浅主题调整；文字保持正文颜色。图表按自然尺寸显示，较宽或较高时在图表内滚动。包含自定义配置／样式、HTML、图片、点击行为、不支持类型或超出绘图限额的内容显示源码，正文不被截断。Markdown图片仍只显示描述，附件图片沿原附件流程展示。上述新增展示适用于桌面客户端；独立Web与TUI不因此取得相同支持。

Markdown 以文字层级、留白和细线区分内容：引用使用左侧竖线，代码块使用细描边与标题分隔线，表格使用完整细边框及横纵单元格分隔线，行内代码使用等宽文字和细底线。上述内容不铺独立底色，深浅主题沿用各自的文字与线条颜色；输入框中的代码采用同样的线条风格。

界面优先使用 Geist 字体，中文按系统界面字体回退；全客户端默认字号固定为 14px，普通正文、表单、按钮与列表主标签共用这一基准，宽窄窗口不切换字号。标题、Markdown 内容层级、代码、徽标与辅助说明按各自用途保留字号差异。普通文字使用常规字重，界面标题使用中等字重，减少厚重感。

输入框默认使用 14px 字号；提示词输入框内的模型、思考档位和审批方式选择器使用 13px，项目／分支选择器、模型列表及选择菜单统一使用13px；项目／分支菜单的单行选项为28px高、18px行高，上下内边距4px，长名称换行时自然增高；上下文浮层保持14px；模型双栏浮层默认宽320px，其中提供商列为128px，窄窗口下仍限制在可用宽度内；模型列表的提供商与模型名称使用常规字重，列表项高度与输入框内选择器一致，均为28px，上下内边距为4px；项间距及列表上下留白保持2px，两列外层留白统一为4px，标题上下内边距为6px，与审批方式菜单一致；标题与条目文字沿相同的8px左右内边距对齐，保留原默认高度。未选中模型与未选中提供商使用相同的弱化文字色，当前模型使用正常文字色并显示勾选图标；提供商和模型项只在鼠标悬停时显示底色，移开后恢复透明背景，键盘导航保留焦点提示；输入框内选择器的图标与上下文状态圆环为 14px，缓存率文字为 13px；项目／分支与模型选择入口的图标为14px，附件、发送／停止和展开菜单的操作图标保持16px。底部工具栏按 32px 高居中对齐，选择器为 28px 高、上下 4px／左右 6px 内边距：附件、模型和审批方式放左侧，缓存率与上下文圆环放右侧，与发送／停止按钮留出间距。空间不足时，右侧状态和发送／停止按钮整体换到下一行并保持右对齐，模型名称可省略显示；权限弹层宽度随标题、名称和说明自适应，达到窗口可用宽度时自然换行。弹层采用更紧凑的排版：标题与名称为 13px、说明为 11px，均保持常规字重；常规宽度下标题区单行排列，弹层、标题、选项和分隔线的内外边距遵循组件库默认规范，较窄区域的说明自然换行。输入时实时渲染 Markdown，支持标题、强调、列表、引用、代码和链接；发送的仍是 Markdown 文本。Enter 发送，Shift+Enter 换行，中文输入法确认候选不会发送；不同会话的草稿与撤销记录分开保留。消息受理、任务运行且输入为空时，原发送位置显示实心方块停止图标；任务结束后恢复发送箭头。

切换会话后，迟到的已保存草稿不会覆盖你刚输入或清空的内容。确认受理的提示词会从原会话草稿中清除，切回或完全重启客户端后不会再次填入；提交失败、拒绝或结果未知时保留原文。结果未知的原提交后来被确认受理时，也会清除当时提交的草稿，不覆盖后续编辑。

同一次输入经过内部关联判定后，正文仍只显示一条用户消息，并保持在这次输入所产生的回复之前；首次发送的临时消息在原输入被核实保存后由历史消息接替，刷新或重开不会重复显示或把回复移到用户消息上方。用户明确提交两次相同文字仍保留两条，各自在对应回复之前，队列取出编辑后重新提交也保留其新的输入身份。尚未形成业务消息的输入及真实澄清继续可读。

首条消息已受理后，客户端会继续核实任务是否实际启动。启动准备失败时在原会话显示简洁的“回复失败”说明；即使尚未形成消息历史，重新打开也保留失败提示，不显示为空白欢迎页。原文尚在当前窗口且没有后续编辑时可恢复到输入框；重新发送由用户明确操作，切换、刷新和重新打开均不会自动重发。

运行中选择“引导当前轮次”发送的补充消息，保留在对应 Turn 的同一段处理过程中，按原顺序与该轮说明和工具结果一起阅读。收起“处理过程”或完成后的“用时”面板时，引导正文一起收起；展开后显示完整正文和原 Markdown。首条任务输入与最终回复仍在过程外，多次引导不把原 Turn 拆成多段。发送占位与保存后的原消息在过程内接替，完成、切回和冷重开不重复正文或耗时；提交失败与结果未知继续保留原文和原恢复提示。

点击 `+`，在输入框上方打开与输入框等宽的“添加”列表，只有一个带图标的“添加文件”入口，保持 12px 字号；同一次选择可混选图片、PDF 及其他文件，系统自动区分处理。附件统一显示在横向列表，可单独移除；移除按钮常显，采用深色圆底、白色叉号和浅色描边，在不同缩略图上保持清晰。数量较多时横向滚动，不把文件名、路径或图片编码插入输入正文。

发送后的图片和普通文件在文字气泡上方的独立附件区并排显示，整体靠右，与正文间隔8px；图片显示缩略图和文件名，普通文件显示图标和文件名。卡片宽148px、预览区高80px、圆角12px，卡片间隔8px。放不下时保持单行与卡片尺寸，在附件区内横向滚动；出现附件总数、左右翻动按钮和滚动条，边缘渐隐提示还有内容。可用触控板、触屏、滚动条或按钮查看，键盘聚焦按钮后可翻动；到达两端时对应按钮禁用。文字气泡不随附件横向移动。仅有附件时不显示空文字气泡；整条消息仍共用一套时间与复制，复制只取正文。发送占位保留文件名和固定大小的图片占位，保存后接替为历史附件；图片预览失败仍在原卡片内重试。

新添加的普通文件先复制完整字节，准备期间显示“正在保存附件…”并可“取消添加”；取消保留输入草稿，迟到结果不再加入附件，之后可重新选择。源文件在复制中变化或保存失败会提示重试，不显示为已准备成功。准备完成后再随发送绑定独立原件；原路径随后被删除、移动或修改，不改变已发送附件。最多 128 个普通附件，单文件和窗口准备总字节上限均为 256 MiB。未发送草稿不承诺跨窗口重载恢复。旧历史中只有名称和 URI 的附件仍是路径引用，需要用户重新添加才能取得独立原件。

Agent 通过现有文件工具按需读取附件。文本支持严格 UTF-8／BOM 和行范围；PDF 默认读取物理第 1 页的文字，可指定页码范围或页面图片，每次最多 20 页文字或 4 张页图。文件类型与读取选项不匹配时明确失败并给出纠正方法。没有提取到文字不表示页面空白；没有本地 OCR，复杂排版的阅读顺序可能需要结合页图核对。已识别的字体损坏或解析错误会明确失败，不将替代字体生成的降级内容当作准确读取结果。PDF 页图进入模型需要模型本身支持视觉，远端限制仍可能使请求失败。

会话独立输出和当前 Plan 保存为可编辑文件，后续对话可继续读取和修改；历史交付保留原快照。打开文件入口只开放当前会话已登记的准确文件。Plan 修改形成新版本，旧批准不能授权新内容，方案保存和批准是两个步骤。备份包含最新工作文件，包括未再次交付的修改；解析缓存可以重建，不代替原件或交付记录。

若提示“文件选择功能尚未加载”或“图片附件功能尚未加载”，请从应用菜单完全退出后重新启动。开发热更新可能已经更新输入界面，但刷新页面或关闭窗口不会加载新的主进程附件接口。

通过“添加文件”选择、直接粘贴或拖入的 PNG、JPEG、WebP、GIF 自动作为图片发送并显示缩略图。每条消息最多 10 张，每张最多 16 MiB；窗口内所有会话的待发送图片合计最多 128 张、64 MiB。数量按已有附件与本次新增累加，超限在读取和编码前提示，移除后释放对应名额；本次超限选择不开始编码。图片按顺序异步准备，移除会取消准备。图片准备完成后可单独发送，也可附带文字，实际图片以 Base64 内联进入模型请求，不依赖公网图片存储。Base64 大约增加三分之一体积，本地上限不代表 Provider 一定接受，实际模型的大小、格式和图片能力限制仍可能使请求失败。待发送附件只保留在当前窗口，重载或退出前请先发送；成功受理的附件随历史保存，后续轮次和 Fork 可继续使用。历史图片接近可见区域后自动显示缩略图，无须点击查看；流式回复和普通刷新保留当前可见的图片，远离可见区域或隐藏窗口时释放预览；切换会话取消未完成的读取，预算内已核验的缩略图随正文保留，缓存淘汰时释放。读取失败时可在卡片内重试。

输入区和消息中的图片使用独立的小尺寸预览，保持比例、长边最多512像素，GIF显示静态首帧；保存和发送给模型的仍是原图。首次预览在后台按序生成，同图在当前窗口的缓存预算内复用，刷新、切换和重新选择时避免重复转换。预算不足时回收较早使用的缩略图，连接／存储范围变化或退出窗口清空；预览固定占位，准备时不挤动正文。输入框显示“预览不可用”时仍可发送已准备好的原图；历史预览失败可在卡片内重试。

中性操作控件采用随深浅主题变化的半透明高亮，叠加在当前实色或系统材质背景上；左侧栏按钮的悬停与按下使用相同底色，覆盖空间与会话列表、导航项、用户按钮和设置左侧分类；悬停效果立即变化，不添加过渡动画；当前会话与页面导航项保留和悬停相同的底色，鼠标移开后仍显示，不额外改变文字颜色或字重；进入新对话或安排任务时，只标记当前页面，不同时高亮旧会话。设置分类移开后仍恢复透明背景，按下也不超过悬停强度。其他中性按钮保留分级的按下反馈。主要操作与危险操作保留各自的配色，键盘焦点提示独立保留。

切换会话时，旧会话立即退出选中状态；读取目标会话期间不会重新选中其他会话，确认后才标记目标。普通刷新保留当前会话的选中状态；选中语义不增加视觉高亮。切换目标的确认请求返回前，当前正文保持可读，相关操作暂停；确认后按目标历史的加载进度更新。最近查看的最多 3 个非当前会话会保留正文 DOM，切回命中项时直接显示原内容、滚动和展开状态，同时在后台校准历史；校准完成前不会恢复旧操作资格。恢复不重播展开动画，手动开合照常。缓存按内容体积和节点数提前回收，超限长会话仍完整显示，离开后可能重新构建；重载窗口会清空 DOM 缓存。命中缓存时，已核验图片、复制反馈和组件高亮保持原有显示，不因临时禁用而闪现或变淡；复制反馈仍按原到期时间恢复。显示缓存不授予新的读取或操作资格。会话确认前，输入框保留当前草稿并暂时只读；确认后再显示目标会话自己的草稿。审核方式、模型和发送／停止控件在普通校准期间保留已知标签、图标、透明度和悬停显示，相关操作仍按当前读取结果开放。真实权限或观察失败继续显示不可用状态；尚未读到审核方式时显示静态“审核方式”标签。未命中模型展示缓存的会话会先准备目标模型名和思考档位，再显示目标页面，避免先出现“选择模型”又变成真实名称而带动工具栏抖动；等待期间当前内容保持可读，相关操作暂停。命中模型缓存时仍立即恢复并后台校准。模型读取失败仍进入目标历史并显示实际错误，不借其他会话或全局默认模型代替目标选择。

首次打开或切换到未缓存的已有会话时，目标确认、历史及首次轮次／工具分组准备完成后再显示正文，避免先展开原消息、再收起处理过程和合并工具而挤动阅读位置；等待期间不显示欢迎页或空会话提示，只有确认没有历史消息后才显示空状态。图片、完整大正文和用量信息继续按原方式读取，不延迟这次正文显示。已显示内容、缓存返回和新发送的消息继续即时更新；读取失败仍保留可读原文并按原方式恢复。

鼠标操作按钮、输入框、菜单、滑块或调宽分隔条后，不遗留焦点外框；菜单和弹窗关闭后回到原控件也遵循这一规则。键盘导航保留可见焦点提示。空间标题旁的添加按钮与空间行内编辑按钮保持相同的交互反馈：悬停时图标变色，按钮背景保持透明。

开发模式使用 `npm run desktop:dev`：页面、组件和样式保存后自动更新；Service 源码变更会自动构建并重启本应用的配套服务，在同一窗口重载页面。Service 重启会停止本应用当前开发任务并等待收尾，不自动重发任务；历史、配置与显式保存的草稿保留，未保存的页面状态可能重置。编译失败时旧服务继续运行，修正后再次保存会重试。Main／preload 和 Worker 资产变更仍需完全退出并重新启动。准备步骤与失败处理见[本地开发](../../../development/local-development.md)，正式发行入口按原固定候选运行。

Windows 开发启动会自动检查当前安装的 Electron 运行资源，缺少沙箱所需的读取／执行权限时就地补齐；重新安装依赖后也会重新检查。修复只作用于 Electron 的物理运行目录，保留沙箱和项目、用户数据权限；遇到链接或明确拒绝权限时停止启动并提示原因。

通用 PC 客户端现在复用原桌面的项目侧栏、对话区、输入框、可调整宽度的右侧栏，以及主题、字体与样式。左下角“个人工作区”的用户菜单打开设置，以原有全屏双栏布局配置模型、提供商、MCP 与 Skills；“返回应用”回到当前会话。

普通新对话的首条消息按[自动命名](../../features/sessions.md#自动命名)生成可读 AI 标题。发送前和名称尚未保存时显示“新对话”占位；生成后侧栏和当前会话标题随原目录／视图刷新更新。

普通界面切换审批方式时，提交过程由原审批控件提示忙碌状态，发送按钮保留原图标，只有实际发送消息时才转圈。会话正文与阅读位置保持，不临时插入“选择已保存”或“正在提交”提示。失败和结果未知由后台核对原权限选择，会话外不追加状态说明或查询按钮；不能重复提交。

任务运行时可通过输入区修改所属根会话的审批方式，主 Agent 与已经运行的子孙 Agent 后续进入审批层的工具读取最新已应用方式；已经待批但尚未派发的工具也按最新方式重新判断，已派发的工具继续原执行。普通工具待批时保留提示词输入框与权限选择器，切到 Auto 或 Full 后原待批工具重新判断，无须逐项手动批准。其他客户端的模式修改也会自动同步；查看子会话时同步继承的根模式。子会话不单独保存模式，切换会话后的迟到读取不会覆盖新会话。根会话自己的问答、计划答复和 MCP 来源／凭据授权仍沿各自交互隐藏输入区。

普通工具审批以独立浮卡显示在整个输入组件上方，高度不超过默认输入框。多项审批在右上角通过“‹ 1/3 ›”逐项切换；主 Agent 不显示名称，子 Agent 名称紧跟“需要批准”，前置固定图标池分配的彩色图标。同一子 Agent 在翻页、重新打开和后续轮次中保持图标与颜色；名称无法核实时显示“子 Agent”。工具类型与具体指令分层，长指令单行省略，悬停或键盘聚焦查看全文，不另设详情入口。默认“批准一次”，原审批提供相同命令授权时，右侧菜单可选“本次会话批准”，范围仍仅为本次及本会话相同命令，不批准其他工具或其他会话。完整附件核对完成前不能批准。

运行中的排队消息属于提示词输入组件，显示在同一外框的输入框上方，可收起或展开。每条以 Markdown 单行展示，超出省略，悬停或键盘聚焦查看完整 Markdown；没有数字序号或额外状态串。使用左侧手柄拖拽调序，也可在手柄上按 Alt+↑／↓；右侧可编辑或删除。编辑先从真实队列移除原消息，核实成功后将完整原文放入普通输入框，由用户自行修改并手动重新提交；没有编辑模式、取消编辑或自动放回。原消息带附件等不能无损转入普通输入框时禁用编辑，删除和调序仍可用。

删除或编辑只撤回尚未消费的原输入，不停止正在执行的任务。竞争中消息已被接收时刷新队列，不把旧文字回填为可撤回成功。操作结果未知时保留原操作，由后台查询原 ID；编辑确认已移除后把原文交付输入框，不覆盖后来输入，会话外不追加核对提示或临时按钮。关闭页面或重开不会自动重发、恢复排队或覆盖新草稿。实现与验证归[Desktop owner](../../../../apps/desktop/README.md#原审批面板与授权观察)。

同一会话正常校准权限和后台信息时，空间列表保留上次核实的运行标记，环境信息保留已有文字、按钮位置和阅读布局。空间行内操作仍按悬停或行内聚焦显示，不因临时禁用而出现；触屏保持常显。校准期间相关操作仍禁用；初次读取仅保留忙碌状态，会话读取失败和结果未知由后台自动重新核对，保留已读内容，不追加会话外状态文字。

首次打开包含运行中处理过程的会话时，正文直接按已有展开高度显示；恢复历史也不重播展开动画，后续手动开合照常。流式回复时，消息列表在原来位于底部时继续跟随新内容，“正在回复…”状态文字完整显示；用户主动上翻后保持阅读位置，可用“回到最新消息”恢复跟随。自动滚动产生的延迟通知不会被当作用户上翻，图片加载及普通历史校准保持附件位置的高度。

“正在回复…”的字号、字体和文字颜色与工具消息一致，默认14px，并随当前主题使用相同的辅助文字颜色。状态行与上方内容沿用会话的正文／工具间距，不与过程区底部留白叠加；尚无正文或收起处理过程时也保留相同节奏的留白。

子 Agent 工具消息以紧凑单行保留原操作：稳定彩色图标、子会话名称与“创建子 Agent”“继续子 Agent”等工具标题。成功受理后的原操作是静态历史，不随子任务完成、失败、中断或后续工作改成“已完成工作”“已停止工作”等状态，也不因子任务仍在运行而播放运行动画。工具调用本身真实失败、取消或结果未知时仍显示该次调用的结果。点击整行直接打开准确子任务的右侧详情标签，不提供折叠箭头或独立“查看详情”按钮，也不在父会话中展开受理回执；旧的展开记录不会显示原始 JSON。准确详情目标暂不可用时仅暂停点击。普通目录刷新保留已有名称、原操作和详情目标；子任务当前状态仍在现有环境信息及详情中查看。

活动轮次的展开入口使用固定的“处理过程”标签；思考阶段集中在底部回复状态行显示“正在思考…”，其余活动阶段显示“正在回复…”，状态文字后不附运行时长。思考／回复文字带流光效果；系统启用减少动态效果时使用静态文字。尚无可展开内容时只显示底部状态行。真实等待、停止与恢复结果，以及终态与最终耗时继续保留；连接或执行权观察失败不追加“上次确认状态”“执行状态待核实”等通用异常文案。

底部回复状态行属于整轮 Turn：从轮次受理到真实终态期间，始终在该轮底部显示一次，包括尚无助手正文、思考、阶段说明、工具调用、等待审批或子任务，以及停止请求尚未结束轮次的阶段。单段文本或工具完成不移除状态行，思考／回复切换和收起处理过程仍保持同一位置。轮次真实完成、失败、取消或中断后移除；普通读取暂时失败时保留上次已确认轮次的展示并后台重读，不追加会话外状态未核实说明，也不从旧显示恢复操作资格。原执行者已释放或执行权无法核实时，回复状态行停止，具体恢复展示见下文。

会话中的连续工具紧凑等距排列，文本与工具之间保留适中留白；连续文本片段与正文段落保持一致的节奏。处理过程衔接最终回复时按相邻内容统一留白，不叠加两层间距；底部不显示分隔线，展开的工具列表沿用同一节奏。正文标题前后留白按正文尺寸保持层级，列表中的代码前后间距一致，不因源文是否留空行而忽松忽紧；复制操作与下一轮消息保留明确分隔。

打开会话、子 Agent、安排任务或设置，以及读取日志、文件差异和图片预览时，不显示“正在读取”“加载中”等临时文案。附件准备保留忙碌图标与取消入口，不显示“正在保存附件”等过程文字。环境信息无已知名称时显示“Shell”或“子 Agent”，不显示内部执行标识；安排任务的运行记录使用中文状态，区分失败与结果未知。已有内容和控件标签保持，等待期间相关操作仍暂停；读取完成后才显示相应空状态。真实执行失败和未知结果保留在所属消息中；会话观察异常和原提交回执核对在后台处理，消息区外不追加异常文字或临时操作。

## 配置编辑交互

模型、提供商、MCP 和 Skills 设置只展示名称、配置、可用状态与必要操作，不显示内部提交记录、Store／Session／提交标识、原始状态枚举、调试 JSON 或实现机制底注。保存期间由原控件表达忙碌，不额外插入保存过程文字；保存或删除成功后直接更新列表和编辑面板，不保留成功提示。保存结果未确认时，保留简短提示和“查看结果”；MCP 进行中的操作仍可取消。查看结果只核对这次操作，不重新保存或执行。

Kite 的通用交互约定是：配置的新增和编辑从应用最右侧面板打开，沿用定时任务编辑的交互；主区保留列表或当前上下文，不把表单塞入主内容分栏或另开模态弹窗。

所有右侧栏统一与主内容区顶部、底部对齐，覆盖会话工具、文件变更、安排任务编辑以及提供商、MCP、Skills 设置面板。并排展示时，两者直接相连，接缝没有外边距或圆角，只保留分隔／调宽线。右侧栏开合时主区同步调整宽度，避免动画期间左侧导航短暂伸缩；拖拽调宽继续直接跟随操作。窄窗口的设置继续使用右侧覆盖面板，并保持相同的上下边界。

会话阅读区与右侧工具共用一个内容外框，右栏从外框内部的右侧展开，收起时也在框内消失。外框到应用右边缘的留白始终固定，阅读区随右栏开合同步平滑调整宽度；开合途中外框边缘持续可见，内容不进入外侧留白，主区不出现额外滚动条。

左栏与各类右栏的显示、隐藏统一采用180毫秒缓出动画，环境信息、窄窗导航和设置编辑面板也保持同一节奏；两种方向均平滑过渡，不直接跳到显示或隐藏的终态。首次进入页面时，正文与输入框直接使用环境信息的最终占位，不从宽列动画缩窄；随后环境内容到达不会改变阅读列，手动开合及窗口调宽仍沿原动画。拖拽调宽继续紧跟指针，系统启用减少动态效果时遵循系统设置。

环境信息从会话区域右侧滑入，隐藏时向右滑出；滑动期间保持原尺寸，超出会话右边界的部分隐藏。连续开合从当前位置反向过渡。

会话右侧栏收起时不保留可拖出的空栏。把已打开的右栏拖拽或用键盘调宽至收起时，同步关闭当前面板并释放它的详情读取，主区回收空间，随后可以正常重新打开。

窗口缩窄使已打开的右栏暂时收起时，保留展开选择，拉宽后恢复显示；环境信息因空间不足自动收起后，也会在宽度足够时重新停靠。手动关闭的右栏和环境信息保持关闭，窗口缩放不会重新打开。

原生客户端窗口最小宽度为800px，缩放窗口时不能继续向下缩小。主内容header及底部“个人工作区”的内边距不随窗口宽度切换。

左侧栏只通过顶部按钮展开或收起。缩小窗口不会自动折叠，也不会切换为导航浮层；拖动分隔线只调整宽度，选择会话、新建对话或按 Escape 均不收起左栏。窄窗口按可用空间调整侧栏宽度，拉宽后恢复保存的宽度；手动收起后，窗口缩放仍保持收起。左栏展开时只在左栏内显示收起按钮，收起时只在会话标题旁显示展开按钮，按钮与实际可点击区域保持一致。开合过程中使用同一个按钮连续移动，避免裁切、短暂重复和焦点丢失；标题与按钮占位同步过渡，减少动画时同步直接切换。

当前提供商配置已采用该规则：点击提供商卡片打开最右侧编辑面板，连接、协议、凭据和模型表单在面板内独立滚动，底部保留取消与保存。关闭、取消或第一次 Escape 收起编辑面板并返回原卡片；再次 Escape 才返回应用。确认保存并成功刷新后回到列表，验证或保存错误保留当前表单；API key 在提交时仍立即清空，保存结果未知时仍需查询原提交。窄窗将面板贴到应用右边缘，主列表不变成表单。切换设置分类或返回应用会清理未提交字段，不发送模型任务。

MCP 与 Skills 采用同一列表、状态标签、标题与留白。MCP 的“新增 MCP”、连接管理、来源管理、准确操作复核和工具详情在应用最右侧面板中处理；已有来源没有直接更新地址的后台接口，界面不提供虚假的编辑保存。Skills 仅列出已发现技能、现有状态和只读详情，不提供手动新增、编辑、安装或启停写入。关闭或第一次 Escape 收起当前详情／操作面板并返回入口，切换设置分类清理未提交字段；查看和关闭不授予执行权限，也不取消业务执行。模型与常规设置仍有直接编辑控件，尚未完成同轮迁移。实现和验证分别见 [Native 提供商](../../../../apps/desktop/README.md#native-provider-与下一次模型选择)、[MCP](../../../../apps/desktop/README.md#native-mcp-完整设置)及 [Skills](../../../../apps/desktop/README.md#native-skills-只读目录)。

进入设置的“模型”分类即自动读取 `~/.kite-code/kite-code.jsonc`，按提供商显示原模型列表、启用开关和默认模型选择；关闭重开会重新读取。模型统一使用用户配置，不提供项目范围选择。“刷新配置”只重新读取本地文件，远端发现仍按[提供商保存规则](../../features/models-and-configuration.md)显式触发。默认模型不能直接关闭；保存失败恢复原开关并提示重新读取，结果未知时只能查询原提交。打开、读取和关闭设置均不发送任务，返回后保留原会话与草稿。实现和验证见[模型设置 owner](../../../../apps/desktop/README.md#native-模型设置与列表)。

桌面面板、卡片、输入框、列表与弹层默认采用16px圆角，普通文字按钮、图标按钮及菜单项统一采用8px圆角。提示词输入框内的按钮与项目／分支、模型选择入口采用胶囊形，两端圆角随按钮高度达到半圆；展开到输入框外的菜单项仍为8px。macOS 的主内容和设置内容采用直角，直接铺满所在区域；其他平台沿用原内容圆角。圆形控件、滚动条和调宽把手保留原轮廓，相连控件的内侧边和全屏容器保留直角。

主体内容区采用细的半透明描边，边框外保留一层范围较小的柔和阴影，亮色与深色主题分别调整强度；聊天页与设置内容使用同一风格。会话阅读区与右栏由共同外框绘制外沿描边、圆角和阴影，右栏自身只保留左侧细分隔边；接缝只绘制一次，左侧透明材质保持。

玻璃导航中的常用入口、空间列表、顶部按钮与底部用户区按导航的两侧视觉边界等距排布，调宽分隔和内容留白不再额外挤出一侧间距；拖拽、键盘调宽和侧栏收展继续可用。

Windows 左侧导航采用更紧凑的左右留白，Kite 标题与下方导航和空间图标左边缘对齐；底部“个人工作区”上方的分隔线铺满侧栏宽度。Kite 标题行高度随内容自适应，不保留固定52px高度；标题行与下方主导航相隔8px。Kite、侧栏收展按钮、会话标题与右侧操作按钮的垂直中心对齐，侧栏收起后仍保持同一水平线。Mica 下侧栏展开时，聊天面板与侧栏之间只保留调宽分隔条。收起侧栏或使用窄窗口时，聊天面板恢复左右各6px留白；分隔线拖拽只调宽，不改变展开状态。

应用准备中、启动失败和重新尝试时，启动页占满内容区，顶部 header 和菜单在进入主界面后显示。原错误提示、保存诊断和重试入口仍可使用。

进入应用后，macOS 的原生红黄绿窗口按钮与侧栏、会话标题共用顶部52px的一行，侧栏顶部不再重复显示 kite 标题，也不另占一行空白顶栏。收起侧栏后，展开按钮和会话标题自动避开窗口按钮；设置页的“返回应用”和窄窗口侧栏也保留这一安全间距。Windows／Linux 继续采用独立一行的32px沉浸式窗口顶栏，右侧保留最小化、最大化／还原和关闭，业务页面从顶栏下方开始。按钮外观跟随应用主题，顶栏空白处可拖动窗口、双击缩放，业务控件仍可正常点击。关闭窗口仍沿原隐藏行为，不等同于退出应用。

Windows 顶栏左侧提供“文件、编辑、视图、帮助”四个菜单，文字与悬停背景跟随主题，下拉项使用原生菜单；打开设置后仍可使用顶栏菜单。“文件”可进入新对话、添加空间、打开设置、隐藏窗口或退出；进入新对话保留原草稿，添加空间沿原目录选择，退出按下文单次确认、立即关闭界面与后台收尾执行。“编辑”对当前编辑区执行撤销、重做、剪切、复制、粘贴、删除与全选；“视图”可调整缩放、恢复实际大小或切换全屏；“帮助”显示关于 kite。准备中或提交操作期间，文件菜单的前三项暂不可用。可用 F10 聚焦菜单，左右键切换、下键打开，或用 Alt+F／E／V／H 直接打开；Ctrl+N、Ctrl+O、Ctrl+, 分别进入新对话、添加空间与设置。

Windows 11 22H2及以上在左侧导航与最上方独立窗口顶栏使用原生 Mica 云母背景，两处直接显示相同材质，跟随应用深浅主题；“新对话”等会话标题栏、聊天正文、输入区和卡片保留实色背景。内容面板以圆角、窄留白和淡边缘衔接 Mica，左栏分界不再常驻整条竖线，调宽把手在悬浮或键盘聚焦时提示，拖拽和键盘调宽仍可用。设置页的分类导航和返回区域也直接显示 Mica，右侧设置内容保持实色圆角面板。打开设置时主页面保留会话、草稿和阅读状态，但退出绘制与交互，玻璃区域不叠出下层聊天页面；返回或 Escape 恢复原页面。任何窗口宽度下，返回设置前的页面都保留左侧栏原有的展开或收起状态。Mica 的具体外观由 Windows 管理；系统关闭透明效果、启用高对比度或节电等情形下可能显示实色。Windows 10、较早的 Windows 11、Linux 及无法核实材质的窗口保留原实色背景，不需要用户额外配置。[实现与验证](../../../../apps/desktop/README.md#windows-原生-mica)说明当前范围。

macOS 在左侧导航、原生窗口按钮所在区域和设置左栏使用系统 Vibrancy 玻璃材质，亮暗外观跟随应用主题，窗口失焦时仍保留材质。聊天正文、输入框、会话标题栏和设置右侧保持实色，主内容与设置右侧采用直角并铺满各自区域，外侧没有额外留白和面板描边；会话标题栏继续与原生窗口按钮对齐，不增加顶部空行。侧栏调宽、收展、窄窗口侧栏以及设置往返沿用上述交互和草稿保留规则，启动与失败页面也使用相同材质。玻璃的最终外观由 macOS 管理。[实现与验证](../../../../apps/desktop/README.md#macos-原生玻璃)说明当前范围。

普通会话的滚动条从标题栏下边缘一直延伸到主面板最底部，覆盖在右侧，不挤压标题栏宽度。内容滚动区域仍从标题栏顶边开始，保留标题栏的玻璃效果。正文从固定的磨砂标题栏后方经过，输入框悬浮在滚动区底部；标题和按钮保持清晰，底部分隔线与右侧标签栏对齐。首尾消息分别预留标题栏和输入区空间，输入区增高时留白同步更新，环境信息卡保持原位。实际可见的顶部提示、读取错误和其他页面保留正常布局；空提示容器不影响全高滚动。

深色主题的主体采用炭黑 `#191919`，亮色主题的主体采用柔和浅灰；会话标题、正文、设置内容和右侧详情保持同一底色，会话和右侧栏标题栏下方显示颜色一致、彼此对齐的细分隔线。深色输入框采用略浅的 `#202020`，与阅读区保留轻微层次，并用淡的半透明边框和随主题调整的中性轻阴影衔接。亮色输入框保留清晰的细边框，主内容区的边框和阴影保持轻淡；键盘聚焦时加深边色并显示淡外圈。卡片与浮层保留原有明度层级，左侧导航继续显示原系统透明材质或平台实色回退。

普通启动和 `desktop:dev` 使用同一用户界面，不显示顶部“会话工具／设置”、左栏“本地 Agent／重新读取目录”、输入区“先审核计划”“保留草稿”及无默认模型的辅助提示，也不常驻机器 ID、完整协议 JSON、已完成申请账本、正常历史校准或缓存诊断。Windows 使用上述中文顶栏菜单，Linux 窗口继续不显示菜单栏。模型选择仍可用，未配置可用模型时发送禁用；实际模型读取错误和已选模型失效仍会提示。测试专用调试功能只允许在隔离测试夹具或单独测试制品中启用，dev 和 prod 不能开启。测试界面的“会话工具”可打开任务、执行记录、Context、权限、恢复、草稿与会话管理侧栏，下文涉及此侧栏的路径按此测试范围理解。打开面板不停止任务或重发原命令，测试开关不改变执行与审批权限。

主输入区已移除“保留草稿”按钮。页面和会话往返继续保留未发送文本，已有私有草稿仍按原会话读取；关闭页面不保证恢复尚未持久保存的输入。问答或计划面板中的未提交答案另按其原作用域保留，不能与主输入草稿混用。隔离测试中的保存控件只用于验证原私有草稿的作用域、修订及迟到回执处理，不向 dev／prod 提供入口。实现及验证范围见[Native草稿owner](../../../../apps/desktop/README.md#native-普通问题与页面草稿)。

项目默认展开，点击名称独立展开或收起；空项目显示“暂无聊天”。上下键移动当前项目列表焦点，确认后打开原历史。侧栏先显示五个会话，可点“展开更多”继续查看已读目录。新建等待仍可阅读其他会话，迟到结果不覆盖后来选择和草稿。未进入本次项目目录的原会话仍保留在“项目待读取的会话”，可重新读取目录更新归属。目录按真实更新时间从新到旧排序，“展开更多”每次再显示十条；悬浮会话可查看状态和本地时间。未打开的会话也显示实际运行或待用户输入，等待必需后台结果显示通用活动指示。断线或读取失败保留原目录和时间，标为“上次确认状态”及“目录状态待核实”，仍可阅读；刷新成功恢复当前状态。未记录的时间不补造，未声明目录状态能力的服务保持待读取。空间批量移除与离线历史清理的当前范围见下段；单会话清理已接同一显式离线维护，macOS 安装版常用维护已有有限验证，其余维护恢复和剩余旧页面行为仍在迁移中。

通用 Native 已沿用空间行「移除」和默认保留的原生确认。确认后一次从目录移除全部根与子会话并请求取消，工作目录文件保留；重新添加同一目录成为新的空间。回复丢失显示结果未知，重开不会重做，明确点击「查看结果」才查询原结果。现行产品承诺要求永久删除历史；新内核在移除受理时先保留准确旧ID的历史。确认框说明：所有任务结束并过宽限期后，退出客户端再明确调用[离线GC](../../cli/commands.md#通用开发入口离线维护)可清理该空间历史正文；活动、未知和待核对执行保留证据，原回执、删除边界及未发送草稿保留。准确旧会话页面在正文已清理时显示维护结果。默认宽限7天。单独删除的会话执行组也按相同条件清理；存活分支及其他未清理会话依赖的来源保留，最后一个依赖删除并符合条件后可一起清理。macOS 安装版常用维护的已验范围见[Native owner](../../../../apps/desktop/docs/native-release.md#macos-安装版离线维护)，其余恢复和完整平台资格仍未闭合；空间移除受理不能直接声称完成永久清理。

代码回滚只切换版本，保留现有数据。旧客户端不能识别私有存储格式时，草稿与原申请操作提示存储不可用；兼容的会话历史仍可阅读。切回支持该格式的版本后，继续查询原操作，不自动重做或恢复旧备份。macOS 当前已验证的代码组合见[Native owner](../../../../apps/desktop/docs/native-release.md#真实代码升级与冷回退)。

已登记 Native 的独立 Terminal 正常卸载后，Native 自带入口仍可使用，后续 Native 升级不要求重装 Terminal。升级不会重建已卸载的前门或自动重新登记；需要独立前门时，先安装 Terminal，再明确登记 Native。

Windows x64 的正式安装和 `kite-desktop.exe` 启动链已实现源码接线：在窗口与业务数据打开前核完整候选和可信创建链，运行中的窗口固定原版本，切换只影响后续启动。缺交接或身份不符仍拒绝启动；实际 Windows 窗口、版本切换和维护恢复尚未验收，不能据本机验证宣布可用资格。操作与限制见[Native owner](../../../../apps/desktop/docs/native-release.md#windows-managed-native-当前实现)。

在“会话工具”的 Context 中读取当前所选上下文后，可对已结束且被排除的 Job 使用“Include this exact historical result”。候选来自完整历史目录，原 Job 不会因后续轮次超过最近执行窗口而消失；目录显示总数和当前范围，可点击“读取下一页历史任务结果”继续读取同一次固定目录。明确备份恢复为新 Store 后仍可纳入准确原结果，结果保留原出处；这是一次新的上下文选择操作，原任务不重新执行。空闲时只保存来源，须再明确发送新轮次才进入模型；活动时必须绑定按钮标明的准确轮次，排队后等待该轮次检查点确认。回复丢失只查询原上下文命令，不重发；切换会话或当前选择变化后须重新读取。纳入不恢复旧任务的停止、继续或自动交付权限。当前已验范围与剩余平台资格见[Native owner](../../../../apps/desktop/README.md)。

同一会话的活动压缩卡可点击“查看此压缩的原模型输入”，再确认读取敏感内容，查看这次准确调用保存的完整输入与原元数据。明确备份恢复为新 Store 后，压缩卡保留原 Store、会话、Model 与 Run，入口仍可使用。读取完成核对全文后才展示，不用当前配置重建原请求；关闭检查器清除正文，切换会话取消所属读取，冷重开须再次确认。跨会话封存压缩卡不提供这个快捷入口。查看不调用模型或恢复旧任务权限，实际范围见[Native owner](../../../../apps/desktop/README.md)。

手动压缩或重置后，可在 Context 面板点击“查询原压缩命令与执行”，核实窗口已保存申请的原结果。后续轮次增多不会让原执行从查询入口消失；命令受理和执行完成分别显示。查询失败保留已确认结果并提示本次失败，不自动重做压缩或重置。该入口的窗口内记录与当前已验范围见[Native owner](../../../../apps/desktop/README.md)。

通用 Native 的左栏「安排任务」支持保存、编辑、暂停／启用、删除、立即运行和最近运行记录。任务填写名称、说明、已登记项目、已配置启用模型，以及每日／工作日／每周的时间和 IANA 时区。当前只支持本地项目，独立工作树禁用。保存失败保留输入；缺项目或模型不能保存。每次运行创建独立会话，运行记录可打开原会话查看结果或处理审批；沿用普通会话的权限，不自动同意工具调用。

定时任务只在桌面应用运行时触发。关闭窗口隐藏应用，继续调度；真正退出时停止新调度并沿原流程收尾。重新打开或机器睡眠恢复，错过的时间最多补最近一次；同一任务已有运行／待审批／未知结果时不叠加执行。夏令时不存在的时间跳过，重复时间仅触发第一次。暂停不取消正在执行的会话；运行未结束或未知时不能删除任务。最近记录显示全局最多128次、每任务最多20次；大记录按响应大小减少展示条数，原会话结果仍保留。回执未知只核实原申请，不自动重新发送；创建与启动之间发生中断时也可能保持未知。备份恢复为新 Store 后原任务保持旧身份，不自动执行；需明确编辑保存到当前 Store 后才可重新启用。旧 Store 的运行记录保留为只读历史，不阻止明确重新绑定后的新 Store 运行或删除任务；同一 Store 的未知结果仍阻止后继运行。保存中的编辑器关闭后再打开其他任务，旧保存结果不会收起新面板。

新对话的项目选择菜单只显示项目名称与当前选中标记，不显示项目 ID；菜单宽度随名称自适应，长名称在窗口范围内换行。

从全局“新对话”进入时，按左栏顺序默认选择第一个空间；没有当前会话的首次进入也使用这一默认值。从某个空间行内新建时选择该空间。手动切换后，普通刷新保留当前选择；重新从全局入口进入时按最新列表顺序选择首项。没有空间时仍可编辑草稿，添加空间后才能发送。

通用 Native 的全局与项目「新对话」现在沿用原准备页，尚无项目也可写需求；首页只保留欢迎标题和输入区，直接填写需求。进入页面或切换项目不会创建空会话。已有会话与准备页草稿分别保留，项目／分支选择保留模型、思考档位与权限选择。首次发送才创建原会话、应用所选权限并提交输入，立即清空准备框并显示首条消息，创建成功后自动进入该会话，真实消息到达后接管；正常过程不增加提交提示或手动打开步骤。失败保留已创建会话与原文；结果未知由后台查询原首次提交；若仅完成创建或权限准备，保留原文供用户明确继续，不重复创建或自动重发任务。普通发送使用会话已绑定的项目，不再额外要求确认项目读取范围。发送前由主进程准备当前项目与宿主声明的读取授权，保留所选审批模式和工具硬限制；打开历史本身不授予读取范围或重发任务。准备失败保留原文，结果未知由后台查询原权限申请，不继续发送；期间切换会话或范围变化使旧观察失效。独立空间、Git 与分支管理操作的错误沿原业务对话框显示。

通用 Native 准备时只读取已登记项目的真实 Git 分支；普通目录或缺 Git 不影响准备。未选另一分支时按发送时实际环境执行，只有明确选择另一分支才在首次创建前受控切换。任何空间仍有活动任务、项目有未提交改动或目标与客户端私有数据／制品目录交叠时，切换明确失败并保留草稿，不自动停止任务。新 Run 读取并冻结该项目配置，客户端无需重启 Service；现行手册中的旧配套服务重启描述只属于原 kite-desktop 路径。

通用 Native 的当前会话在原轮次区域显示进度和终态；普通 dev 与 prod 不显示“后台状态：…项未结束，…项未知”汇总、原始轮次状态列表或子日志的内部读取序号和轮次 ID，这些信息仅在显式测试诊断中显示。实际后台任务仍从「环境信息」查看，准确停止和完整输出沿原任务入口操作；主轮次完成不表示后台任务已经结束。真实执行失败和结果未知保留在所属消息中，会话外不追加恢复提示或临时核对操作；不能仅凭计数或轮次终态判断实际进程已经退出。

通用 Native 的当前会话已接入原「环境信息」卡，按 Shell 与子 Agent 分组，保留宽窗口停靠、窄窗口浮层和手动开关。可准确停止正在运行的任务；受理后仍等待真实状态，结果未知须从原申请核实。子 Agent 名称来自原子会话，点击详情在最右侧栏打开对应任务的标签页，查看完整子日志；同一任务重复打开会切回已有标签，同一协作者的不同任务分别保留。已核实准确子任务的首次打开不等待后续整份后台目录刷新，加载期间保留已知名称。详情只读，主会话正文、草稿、输入区和父轮次提示继续显示，父轮等待子 Agent 时也可同时阅读。切换标签、关闭详情标签或收起侧栏会结束该详情读取，原任务继续执行。工具、轮次或文件信息尚未核实只影响相应条目，不遮住整段父正文；父元数据刷新也不阻塞同一会话的已保存历史读取，发送、停止与权限操作继续等待新资格。目录失效或读取失败保留上次名称与状态，停止入口等待重新核实；切换会话不停止任务。恢复历史保持只读，终态不表示进程清理已确认。

通用 Native 的「后台总览」通过“打开后台总览”读取当前连接下的完整后台目录，按原会话展示 Job、子 Agent／task 和子会话中的 Job，切换主阅读会话仍可查看原任务。父轮次是否等待必需结果、原子轮次状态和结果接纳分别显示；较新的子轮次不会替换原 task 身份。可读取完整已保存输出或完整子日志，全部固定上界内容读取成功后才发布。新链路备份恢复为新 Store 后，历史条目保留原 Store、原任务与原输出，并显示“恢复历史，只读”；旧任务不提供停止入口，新 Store 明确创建的任务仍可正常控制。刷新失败保留上次完整事实并停用停止入口；“关闭后台总览”只结束读取。停止只针对按钮标明的准确原执行，请求受理后仍等待实际终态。关闭、会话切换与冷重新打开均不重新发起任务。实际恢复读取、默认 Shell 和平台范围见[Native owner](../../../../apps/desktop/README.md#native-跨会话后台总览)。

当前根正式入口已使用通用 Agent V1.3 候选，旧参数、State/stdio 拓扑及旧桌面截图只作历史参考；新入口的实际参数与行为以本页“通用”段落和[当前进度](../../../plans/unified-agent-refactor-v1-progress.md)为准，未实现能力不能借旧描述启用。发行、安装与跨平台仍有未取得资格，详见[发布边界](../../../active/release-control.md)。

正式 Native 的 Runtime logs「已保存执行」中，展开准确 Job 后可主动读取完整已保存输出、刷新或关闭。页面保留 stdout/stderr/progress 的原文与已记录缺口，读完固定上界才展示完整内容；新输出需显式刷新。完整范围包括已保存内容和缺口，无法恢复丢失的字节；缺口字节数无法确定时明确说明。同一 Job 刷新失败保留上次完整内容并标未更新，空输出与读取失败分别显示。关闭输出、折叠详情、切换会话或冷重开只读历史，不取消或重新运行 Job。精确停止仍是独立明确操作，不能从读取完成判断执行成功或实际停止。macOS 正式默认宿主 Shell 已验证从页面新建后台 Job、完整保存输出、准确停止、所属 Main/Service 意外退出后的清理，以及同原身份的冷读零重放。Service 来不及保存停止结果时，历史记录仍保留未完成事实，读取完成不能把它判为已停止。当前 macOS 范围与剩余资格见[Native owner](../../../../apps/desktop/README.md#native-job-完整已保存输出)。

设置以全屏双栏页面呈现，沿用桌面主界面的当前主题与基础字号；宽窗口下设置侧栏固定为 236 px，不随主页面侧栏拖拽变化。左侧直接切换“常规”“提供商”“模型”“MCP”“Skills”，不提供设置搜索。返回应用与主侧栏新对话入口采用一致的单行按钮尺寸和悬停、聚焦交互，并紧邻设置分类。设置整页位于独立窗口顶栏下方，返回按钮无需额外避让窗口按钮。“常规”显示默认文件打开应用和当前模型；编辑器选择只在当前页面进程内保留。返回应用关闭设置页，不修改任务或会话。参考图中的权限、语言及窗口行为等开关尚无对应设置能力，页面不提供这些控件。

明确退出客户端时，只有存在排队、运行或等待用户交互的会话任务才显示一次确认；所有会话均空闲时直接关闭界面。任务状态无法完整核实时仍显示同一个确认框，默认保留服务；选择退出后立即关闭客户端窗口，不等待任务清理。重复请求退出不会增加提示。普通关闭窗口仍只隐藏客户端，不等同于退出。

确认退出或空闲直接退出后，窗口立即销毁，未完成的清理由原主进程在后台继续；macOS 同时隐藏应用与 Dock 图标，点击激活也不会重新打开界面。原轮次、工具及子 Agent 仍沿原流程取消、保存终态和清理资源，完成后主进程自行退出；不会因为清理超过 20 秒就强杀服务，也不追加提示。服务启动或开发热重载尚未完成不阻止界面关闭。清理确实失败时仍终止本应用拥有的服务并结束主进程；未确认的任务和文件副作用按持久会话记录核对，界面关闭本身不表示清理成功。

侧栏空间行只显示名称；会话行显示标题，并在最右侧用旋转图形表示 Run 仍在进行（包括受管等待必需子 Agent），用高亮圆角文字“待用户输入”表示等待回答、审批等交互，待输入优先于运行图形。空闲和正常完成不显示行内状态。会话悬浮提示只显示完整名称和最近更新时间，无可用时间时仅显示名称；空间悬浮提示显示名称和会话数量。浮层首次悬停 500 毫秒后出现；浮层出现后快速移到其他列表项会立即切换详情，移开一段时间再返回则重新等待。首次等待期间移开不会弹出。键盘聚焦也可查看，Escape 关闭。会话顶栏右上角的环境信息按钮控制“环境信息”卡片显隐，卡片默认展开，CSS 宽 300 px（2 倍显示比例的截图约为 600 像素），按 Shell／子智能体分组；卡片内文案使用常规字重。没有任务时，两组各占一行，在右侧分别显示“空闲”和“暂无”，不再重复显示数字0和整行空状态；有记录时显示数量与任务列表。环境状态自动更新，读取失败时保留已核实内容并在后台重读，不追加异常文案或临时重试按钮。子智能体展示名称、状态和只读详情入口；Shell 与子智能体仅在当前目录已核实新鲜、仍可停止的准确任务时提供停止操作。状态旧、未知或读取失败时停止不可用，重新核实后才能操作；停止绑定按钮所示原任务，不转向同一协作者后来一轮。卡片停靠展开时优先利用右侧已有留白；留白足够时，消息文本和输入区保持原位置与宽度。留白不足时才同步让出必要空间，消息阅读列和输入区最大宽度仍为 844 px，并随可用空间收窄；会话滚动条始终保持在中栏最右侧。会话实际可用宽度不足 1092 px 时，停靠卡自动收起；宽度恢复后自动重新停靠；手动关闭则保持关闭。宽度不足时用户仍可点击按钮，以不压缩会话区域的右上角浮层查看；浮层打开期间宽度恢复则自动转为停靠卡。手动隐藏与自动收起均以短暂淡出、向右缩合和会话区域同步扩展完成；从其他主会话或子详情返回时直接显示卡片，不重新播放入场动画；系统启用减少动态效果时立即切换。除用户主动打开的窄宽浮层外，卡片不覆盖消息、工具输出或输入区。Shell 分组只显示后台启动且仍在运行或正在停止的命令；前台执行的命令不会出现，无法核实启动来源的历史记录也不会作为后台 Shell 显示；同一连接内返回已读主会话、正在核对新状态时，卡片暂时保留上次已确认的 Shell 和子智能体行，相关操作等待新资格，不追加正常校准文案。首次读取或没有可复用展示快照时，子智能体组保留已验证的任务子会话，自动命名会话产生的内部任务不在此处显示；名单已到但后台状态尚未匹配时保留详情入口并标记“状态待确认”。新鲜后台状态明确报告不可用时才标记“不可用”。有公开名称时只显示名称与状态，不附加执行 ID；旧记录缺少名称时才回退显示执行 ID。后台 service 与诊断字段不在该卡片中展示；上次状态只用于阅读，实时订阅与操作权限仍须重新核对。任一分组没有项目时显示对应空状态。

重新选中会话或连接恢复时，桌面会向服务端核实整个主／子 Agent 执行组，并保存原执行者丢失后的中断、未执行或结果未知状态。未派发的子任务不再挂在排队中，未被接纳的审批结束等待；已有答案、结果和历史保留，重开不会自动重试。核实成功后按持久状态显示，移除运行转圈、回复／思考、工具等待动画与停止按钮。检查失败或证据不足时在后台继续核实，不在消息区外显示“执行状态待核实”；已中断轮次不会被旧目录缓存重新标为活动。仍持有执行权的共享服务继续原工作。接续与副作用边界见[恢复说明](../../features/recovery.md#重开会话时核实执行状态)。

required 后台子 Agent 尚未终态时，Runtime 保持同一 Run 的受管等待及准确 task 关联；Desktop 侧栏保留通用活动标记；所选父会话的历史已加载、投影身份匹配且 Run 确认因 required 子 Agent 等待时，在消息阅读列末尾显示“正在等待子 Agent 结果”。这是随 Run 状态出现和消失的临时提示，不写入会话消息，也不把先前一段模型正文标为最终回复；最终回复只在 Turn 完成后确认。侧栏不另设等待徽标，输入框上方不设状态行，也不延续模型思考动画。子 Agent 的实时状态由环境信息卡片展示。此时输入框保持可发送；同工作补充在原活动 Run 的安全边界接收，不取消 child；独立新工作先保存选择并排队，待原工作安全收束后交接；关联不明确时先澄清。切换会话或刷新重接后，内部等待原因及关联 task 由持久投影恢复，不靠客户端轮询补正。普通协作结果按[工作选择与结果接纳](../../features/execution.md#运行中引导与后台执行)处理：父空闲且同工作资格成立时可创建后续普通轮。旧 `human_start_preferred` 抑制记录只说明当时的接纳决定，不因后来刷新改写，也不代表结果已注入当前活动 Run。

桌面与 Web 共用会话主页面；可用操作按各端权限提供。桌面保留本地项目、任务输入、审批与执行控制，Web 当前只读。当当前会话已观测到提示缓存 token 时，输入框底部工具栏以文字显示该会话累计缓存命中率；普通后台校准及新一轮用量等待期间保留已核实的累计值，取得新样本后再更新；无样本时不显示0%，切换会话只恢复目标会话自己的指标。旁边的小圆环为无点击操作的状态图标，表示上下文占用比例：当前上下文输入估算除以对应模型的完整窗口容量，与缓存命中率独立。悬停或键盘聚焦圆环，在上方查看三行详情：上下文窗口、约多少百分比已用、已用与总窗口标记数；较大数字简写为k／m等，Escape可关闭。容量未知时显示未知，不补0%；还没有可用模型请求或读取失败时隐藏圆环。估算按最近已保存的当前模型请求及当前选中历史计算，不计入未发送草稿，也不能代替实际账单或Provider容量证明；切换会话、上下文或已选模型不沿用旧比例。macOS 窗口采用沉浸式标题栏：同一个顶部 header 横跨侧栏和会话区，左段在原生玻璃导航上放置侧栏收起图标，右段只显示会话标题和操作，并在会话页 header 底部显示分隔线，不重复显示所属空间；会话标题最多显示 10 个字符，超出时以省略号收尾，悬停仍可查看完整标题。侧边栏使用上文的系统 Vibrancy，内容面板保留实色背景并延伸到窗口顶边，原生交通灯、窗口拖拽及双击 header 缩放保持可用。

新 Native 候选已接回原用户菜单的暗色、亮色与跟随系统，并同步原生窗口底色，沿本机偏好重启恢复。原菜单、实际窗口和外观更新的当前验收范围见[主题 owner](../../../../apps/desktop/README.md#原主题与窗口背景联动)；高速拉伸的产品要求保持，底色状态测试不代表完整视觉资格。

通用 Native 已接回原标题栏双击缩放的宿主回调，单击及标题栏内按钮、链接不触发缩放。当前实际窗口效果与原交互过滤的证据见[窗口 owner](../../../../apps/desktop/README.md#原消息复制与标题栏缩放)；DOM 事件验证不代证物理鼠标双击与拖拽的完整验收。

新Native候选沿用原输入框的累计缓存命中率显示，缺少缓存用量的模型记录不算作0%样本；指标读取失败时可重新读取。当前接入和首次／重启后读取的验收范围见[Native owner](../../../../apps/desktop/README.md#原输入区累计缓存命中率)，不代表完整桌面迁移已完成。

后续已确认以 Codex 的客户端功能和日常交互体验为对标目标，具体差距与迭代入口见[日常体验方向](../../../plans/desktop-client.md#首轮验证后的日常体验方向)。这是后续研发目标，下文仍说明当前已交付行为。

桌面客户端产品名为 **Kite**，**kite-code** 为 TUI 名称；两栏界面、Electron 窗口与当前开发包均使用 Kite 展示名。通用日常工作、shadcn/ui 界面及覆盖空间、会话、交互、结果、子代理、设置和恢复的整体目标稿见[界面与协作体验](../../../plans/kite-client-experience.md)，不据设计稿宣称这些能力已交付。

[工具消息结构与状态](../../../plans/kite-client-experience.md#会话消息与工具渲染)按 Runtime 提供的展示分类呈现：同一准确 Turn 内相邻且各有明确分组 ID 的探索工具可跨批次视觉聚合，原始分组与每项结果保留；正文、独立工具、不同 Turn 和缺失分组构成边界，缺少准确 Turn 时只合并同组探索；有明确子 Agent 归属的内部工具及异常只进入所属子 Agent 容器，归属随工具 queued 和 terminal 生命周期保留，因此只恢复终态时也不会产生顶层重复；缺少归属的旧异常仍保留独立入口，子 Agent 结果不会丢失。queued、running、waiting、completed、failed、rejected、cancelled 与 unknown 使用不同文字状态。Shell 的 stdout/stderr、退出码及输出限制按真实字段放入可展开输出，文件修改显示工具报告的差异；缺失信息时不补造。当前可读内容和交互限制仍以下文为准。

一轮 Agent 回复以准确的 Turn 身份组织：运行中的过程默认展开，按发生顺序显示阶段说明和工具活动；轮次完成、失败、取消或中断后，过程整体默认折叠，已确认的最终回复独立可见。中断前已生成但未确认完成的正文仍保留在可展开过程中，不冒充最终回复。即使本轮直接给出最终回复、没有可展开过程，也保留状态行；可靠终态耗时显示“用时 …”，缺少可靠时间时显示“已完成”。可展开的状态行只显示常规字重的状态或可靠耗时，以及始终可见、紧邻文字的箭头；高度与工具消息标题一致，悬停不填充背景，不使用前置状态图标，不汇总工具拒绝等结果，也不显示“展开过程／收起过程”文案；用户手动展开和收起沿用工具消息的动画；轮次进入终态时直接收起过程，最终回复出现后不会再短暂绘制旧过程文字。具体异常仍在工具消息内查看。状态分隔线到下方首条可见消息均留 16 px（展开时为过程消息，折叠时为最终回复）；运行中的过程末尾不绘制分隔线，只有过程下方有已确认最终回复时才绘制；用户可重新展开过程，手动展开或收起的选择在当前会话阅读状态中保留。失败、取消、中断、等待与需要恢复仍显示明确状态。连续工具在执行中即组成默认折叠的聚合，不等工具完成才收成一组；执行回执逐项到达、展示信息仍在核对时，原聚合及用户手动选择保持。聚合不继承此前单条工具详情的展开选择，标题按实际动作组合更新；排队、等待不计入“正在执行”数量，标题变化会向辅助技术播报；进度和结束都不自动改变展开状态。原始模型思考正文不进入消息列表；活动 Turn 没有正在执行的工具且确有思考活动时，底部回复状态行显示“正在思考…”，其余活动阶段显示“正在回复…”，状态文字带流光且不附运行时长。上方普通活动入口使用“处理过程”，等待等必要状态继续明确显示。成功结束且终点可靠时在过程摘要显示“用时 …”，秒、分、小时、天按时长切换；失败、停止或中断保留明确状态并附可靠用时，旧历史缺少可靠时间时不补造。

只有思考、尚无正文的阶段，底部回复状态行仅显示“正在思考…”，不创建空的助手回复、空过程展开入口或正文读取控件。正文首段到达即开始流式展示，后续思考片段不会使已有正文退回思考状态。纯思考期间取消或中断，仍在原轮次位置显示准确终态。

进入会话时，历史消息及其轮次、工具信息核对结束后一次呈现，等待期间显示正常聊天加载，避免压缩状态和工具核对占位先后闪现、重新聚合造成抖动。首次显示后，持续更新和同一会话的历史校准不反复遮挡正文；真实读取失败保留原记录、错误提示及重试入口。

重复点击当前正在查看的会话不会重新加载消息，草稿、滚动位置和展开状态保持；同一会话尚在打开时再次点击，会继续等待原打开过程。选择其他会话，或从子会话详情、新对话准备页、安排任务页返回，仍正常切换页面。

当前 Run 需要恢复时，其当前轮尚未结算的工具在页面上显示“需要恢复”，不继续显示“正在工作”。这是对 Run 状态的临时展示，不写入或伪造工具终态；Run 状态更新后以真实工具事件为准。

开发版在当前父会话的“环境信息 → 子智能体”和对应的子 Agent 工具消息中提供详情入口；子会话创建并进入父作用域列表后，无需手动刷新即可打开只读详情，重新打开已完成的父会话也会自动恢复完整子会话列表，没有匹配子会话的旧后台记录只显示状态。切到其他会话后返回时，先保留此前已核对的子会话详情入口，再静默更新名单；同连接重新核对或当前页断线重接时保留上次已确认的环境状态并标明正在核对，期间不能停止执行；已有条目不额外显示读取提示。没有可复用展示摘要时，名单先显示“状态待确认”；新鲜快照到达后更新真实状态与操作资格。父会话读取明确被拒绝或身份核对失败时，立即移除其暂存的子会话入口和环境展示；子详情明确返回不存在或无权读取时，从父会话名单移除该入口。详情复用主会话的消息与工具渲染，先显示独立历史，再持续显示子 Agent 的实时过程；进入子详情时脱离父页面的实时订阅，返回后重新校准父页面，期间服务端任务继续运行。同一连接内再次打开父会话时，保留有容量限制的已读正文及阅读状态，待本次轮次、工具展示信息核对结束后恢复显示；核对期间使用正常聊天加载，失败时保留原内容和重试入口。子详情再次打开时仍立即显示已读正文，空历史不重复显示整页加载；后台继续核对最新历史与实时订阅。非当前页缓存淘汰后按首次读取处理；临时断线期间，已读主会话可从有界缓存继续阅读，切回时仍核对会话与空间身份，连接恢复后必须重新读取历史并校准。子详情的非当前页缓存随断线清除；当前子详情只保留已读内容供等待核对。缓存不赋予发送或子会话读取权限。断线重连期间保留正在阅读的子详情和已读子名单，不先显示空的父页面；名单待核对时不授予子详情读取资格。核对父子身份后才恢复该详情；用户明确返回父会话或切换其他会话时取消自动恢复，迟到结果不能再跳回子详情。子线程不进入侧栏顶层会话目录。环境信息中的子 Agent 列表自动更新，读取失败时可在原处重试。详情读取和订阅按准确父子血缘授权，面板内不能对子线程发送、停止或修改。此入口的正式运行验收仍见[后台 Agent 协调方案](../../../plans/background-agent-shell-conversation-coordination.md)。

Agent 邮箱状态依据当前会话的持久事件显示为独立状态行：发送方的“已受理，等待目标读取”不表示子 Agent 已读；接收方的“已准备进入目标模型输入”表示输入已绑定；续轮结果结算另有终态提示。重复历史记录更新同一消息状态，私有消息正文不出现在状态行中。

开发版可选择本地项目、确认工作区信任、配置 Provider 和选择模型、新建和查看最近会话、提交任务、读取文本与工具过程并取消执行。安装与运行方法见[开发入口](../../../../apps/kite-desktop/README.md)。

左栏默认以 200 px 最小宽度展开，可拖拽至 420 px；窗口缩放时保持当前像素宽度，由中间栏及已展开的右栏适应剩余空间；空间不足时仍受面板最小宽度约束。调整后的宽度在本机保存并于重启后恢复。拖拽分隔线把左栏收起后，顶栏显示展开按钮，点击可重新展开左栏。左栏保留已添加的项目，所有空间默认展开并自动读取会话列表；新添加的空间进入列表首位，之后切换执行空间只改变当前选择，不调整已有空间顺序。展开或收起只改变显示，不切换项目。工作台入口暂时隐藏；会话继续按空间出现在左栏，点击直接进入原会话，不创建副本或改变执行状态。各空间的会话可展开或收起，不提供会话标题搜索。点击会话直接加载消息，无需二次确认；上下键移动列表焦点，Enter 打开会话。切换会话不停止当前任务，也不会发出新消息；首次发送正在创建会话时，已有空间和会话导航也不整体禁用，用户切换阅读目标不会改变该消息所属的新会话。目录在连接和新建时自动读取；侧栏中已有会话的运行与待输入状态随会话索引更新，包括切到新对话、安排任务等非会话页面后完成的后台 Run，不依赖当前阅读页的订阅。各空间内会话按最新更新时间倒序排列，单纯点击阅读不更新时间；侧栏不再显示“切换项目”、“断开项目”和刷新按钮。返回已连接窗口只更新本地目录是否存在，不重新加载会话列表。其他端新建且尚未进入本地目录的会话仍需下一次目录读取才显示。

已加载且没有会话的空间在项目名称下方显示“暂无聊天”，并与项目名称的文字左边缘对齐。

“空间”标题右侧的 `+` 打开系统目录选择器，选中一个本地目录后将其登记为空间并进入该目录的新对话准备页；取消选择不创建空间。标题的添加按钮和空间行的新对话、移除按钮仅在各自行悬停或获得键盘焦点时显示；触屏设备上常显。空间行的两个操作按钮紧邻排列。新对话入口使用编辑图标，添加空间仍使用加号；操作按钮平时为次级文字色，鼠标移到按钮或键盘聚焦时高亮。空间行的移除按钮先显示原生二次确认，明确提示会停止该空间正在运行的会话、永久删除相关会话历史及本机项目登记，工作目录文件不受删除操作影响。默认选择保留空间；移除期间相关操作暂时禁用，当前页面保持原有内容，不插入“正在移除”过程文字；成功后直接更新空间列表。空间和会话删除是数据删除：对应会话正在运行时由服务端发出取消，后续资源收尾由服务端处理，不要求用户先停止任务、恢复会话或等待历史工具变为终态。空间内全部会话及子会话批量删除，不逐条处理，也不要求额外收尾确认。成功后移除本机登记及对应页面；失败显示可信结果，缺少可信回执时保持结果未知。迟到任务结果和刷新不会重新带回已删数据。工作目录文件不属于删除范围。

左栏提供“安排任务”入口，页面展示任务空态与列表契约；点击创建后，表单在页面最右侧的通用侧栏中打开，主区域继续显示任务页。表单包含名称、任务说明、项目、运行频率及独立 Git worktree／本地项目环境选择。当前 Service 尚未提供定时任务的保存、调度、运行记录或通知协议，因此保存保持禁用，页面明确说明限制；填写内容只属于当前页面草稿，不宣称已创建或会在后台运行。

已登记 Git 仓库在连接准备时直接授权 Agent 访问空间，不展示“信任此项目”或重试授权提示；用户主动添加或选择的普通目录同样视为访问授权，具体工具继续遵循执行授权。授权由 Service 保存。需要访问工作区外的关联目录时，仍单独展示确切路径并确认；授权失败时保留输入，不伪造成功。空间、Git 仓库、分支或命令失败不作为 notice 插入客户端页面内容，统一使用带单个“确定”按钮的 shadcn `AlertDialog` 告知，确认后关闭并清除本次错误。会话内容按所属会话展示，输入草稿、阅读位置和过程展开状态在当前进程按项目与会话保留；退出后的恢复尚未提供。会话切换不取消原会话执行。

助手正文支持 Markdown 标题、段落、列表、引用、代码块、任务清单、表格和脚注，正文固定为14px、行高1.8，宽窄窗口保持同一字号；标题、代码、表格与脚注按正文比例保留层级，工具标题、过程摘要和压缩状态同步使用14px。步骤之间、步骤内段落和子列表分别留白，代码块前后的间距保持一致。引用使用透明底和侧边线；行内代码与代码块使用等宽字体，代码保留原始缩进和换行。表格保留完整细边框和单元格网格线，表头下边框与其他分隔线同色同宽，宽表格和长代码在各自区域内滚动；表格可通过键盘聚焦后用方向键横向阅读，流式追加表格内容时保留横向阅读位置。深浅主题保持清晰的文字和边界。正文不增加内边距或独立限宽，与消息阅读列同宽。

连续工具统一聚合为轻量摘要，从第一项起默认折叠，摘要只显示动作短句、图标与展开箭头，后面不追加数量、状态或异常文本；展开后以统一图标轨道和单行“动作＋目标”排列，不显示重复的完成徽标。聚合展开后的整体高度最高 400 px，超出部分在内部滚动；读取不展开文件内容，Shell 可展开有界输出、修改可展开工具报告的差异。运行、等待与异常状态保留在各工具行；执行失败或审批未通过的完整原因，仅点击对应工具展开后显示。主会话只显示子 Agent 入口；子 Agent 的工具消息与步骤仅在该入口的过程容器内展示，列表最大高 320 px，超出时在容器内滚动，不常驻过程正文或结果段落；展开过程时不重复显示完成状态，失败工具的完整提示通过该工具行展开查看；子 Agent 已结束而工具缺少终态时显示“结果未知”，不继续播放运行中动画；有明确可见父工具时在该 task 展开区的子 Agent 容器查看，完成后仍保留；缺少可见父工具时保留子 Agent 容器入口，内部工具不进入主消息列表。独立子会话的只读详情从当前父会话的环境信息卡片打开，不能作为平级会话直接进入。

已提交任务执行失败时，会话中保留一条“本轮回复失败”提示，即使模型尚未生成任何回复。模型服务认证失败会明确提示检查当前提供商的凭据和账号权限；已分类的模型重试耗尽、服务不可用、会话存储不可用和工具纠错耗尽显示对应原因。缺少可靠分类时只提示检查会话失败详情和任务状态，不将后台任务、工具或 Runtime 错误推断为模型服务故障。模型给出的工具参数不符合当前格式时，该工具显示脱敏的参数错误，不展示原始模型响应。重新打开会话仍可查看失败记录。用户主动取消不显示为执行失败，读取历史不会重新发送任务。模型切换仍按会话保存的提供商和模型执行，不要求与设置中的默认模型一致。

发送与停止共用输入框右下角同一个 `26×26` 圆形主控位：消息准备与发送期间显示 loading 并禁止重复提交；失败或发送结果待确认时停止旋转。任务运行且草稿为空或正在停止时显示停止；输入运行中引导后切换为发送；两个动作不得同时出现。

任务运行或内部受管等待后台结果时，普通输入框继续可编辑，发送运行中输入和停止操作按当前准入保持可用。Native 普通工具审批也保留输入区和权限选择器；根会话的补充问题、计划审核和 MCP 特殊授权继续独占回答区域并暂时隐藏主输入框。已发送输入由真实输入和工作选择链决定所属任务，尚未消费的排队消息按上方规则编辑、删除和调序。切换会话后，已保存为展开的工具详情直接恢复完整内容，不再播放一次展开动画；用户在当前会话中主动展开或收起时仍保留短暂过渡。

Ctrl+A／Cmd+A 在会话页面只全选消息内容，在输入框中只全选当前输入。会话消息支持原生选词、拖选与复制，段落和列表行选区限制在内容范围。侧栏、标题、按钮、提示等非消息展示文字不可选中复制；输入框保留正常的选择、复制与编辑能力。会话消息和左栏分别滚动；工具消息中可独立滚动的输出和文件差异在还有内容可滚动的边缘显示渐隐提示。首次进入显示最新消息；向上阅读后不再被流式更新拉到底部，可点击“回到最新消息”。输入框上方不展示独立状态信息，也不保留状态行空白；输入框底部工具栏集中展示按 Provider 分组的已配置模型，以及带有审批方式说明、图标和简短行为描述的权限模式菜单；模式名称与说明按系统语言显示中文或英文，不展示快捷键教学；选择文字与下拉图标使用固定间距。点击左下角“本地用户”按钮打开选项浮层，可进入设置，或在主题区域选择“暗”“亮”“跟随系统”。默认跟随系统；选择立即应用到主界面、设置与原生表单控件，并在本机保存，重启后恢复。跟随系统时，系统外观变化会自动更新界面；固定暗色或亮色时不受系统切换影响。Full 选项与已选状态的图标、文字以及风险弹窗标题使用警示色，确认按钮使用危险操作样式；桌面客户端每次从其他权限切换到 Full 前，说明 Full 允许代理无需逐项征得同意，在当前环境允许的范围内运行命令、读取或修改文件、访问互联网；提示文件被覆盖或删除、敏感数据传输及难以撤销的损失风险，并说明可以切回其他审批方式、系统限制仍有效；取消不更改权限，明确确认后才继续；点击当前已选中的权限不重复提示或提交。切换会话后，模型选择器先显示目录中该会话的模型，投影加载后再按最新状态更新；已有会话选择并确认权限后立即显示目标模式，保留静态下拉箭头，后台确认期间暂时禁用重复选择；服务端确认后落定，失败时恢复已确认模式。权限命令提交给该会话，按该会话所属工作区核对信任；即使当前正在查看其他项目或尚未选择执行项目，也不需要切换执行项目，不停止其他会话任务。修改历史会话权限不要求先恢复任务，也不依赖该会话原模型配置仍可用；修改成功不会启动任务或解除其恢复要求。若当前服务丢失执行权后仍保留旧会话 Runtime，需要重新启动服务后再修改，不会自动接管。另一服务进程持有该会话执行权时仍会拒绝修改，版本冲突需要读取最新状态后重新选择。若会话在修改期间被其他进程删除，本次修改明确失败，不按未知结果处理。工作区未信任或不可用时不修改权限；新对话的选择在创建会话后、发送首条消息前生效。没有活动人机交互时，输入框位于下方，Enter 发送、Shift+Enter 换行；空白输入和加载期间不能发送。任务运行但未等待交互时，输入框继续可编辑，Enter 把纯文本作为定向引导追加到同一 Run，不取消当前请求、不新建 Run；目标在提交前结束时保留草稿，不改投新任务。停止仍由独立按钮发起；提交后显示等待收尾，只有服务终态才显示已停止，已有修改保留。审批、补充问题、计划审核或其他等待交互出现时，主输入区隐藏，避免与当前交互争夺操作；交互结束后恢复原草稿。这不是新 Run 的后继队列。会话侧边显示后台 Shell、service 和子 Agent 的准确身份与状态；只有当前连接代次中新鲜且仍运行的项显示停止入口，断线后的旧运行项不可操作。

左栏品牌下方的“新对话”是与空间区域同级的全局入口；工作台入口暂时隐藏；尚未打开项目也可以进入并写下需求。欢迎区只显示标题，需求直接在输入框编辑；首次发送时才创建会话并进入正常消息流，重复点击入口不会创建空会话或清空草稿。首次发送后输入框立即清空，内容区原位显示“正在发送”的用户消息；真实消息到达后在同一位置接管，失败则原位提示并把内容恢复到输入框供重试。准备草稿跨项目／分支选择保留，与已有会话草稿独立；切回历史会话恢复它原有的输入。发送失败后保留已创建会话，不重复创建。

空间标题右侧的“新对话”图标进入该项目的新对话准备页，不改变列表展开状态，也不提前创建空会话。选择其他空间时只校验已登记目录并读取该目录的 Git 分支，立即更新准备页上下文；不关闭当前 Service、不切换执行连接，也不读取项目列表、会话目录、信任或模型。左侧空间和会话列表保持原对象与交互状态，目标分支读取完成后一次替换。首次发送前才沿用现有执行项目切换流程；届时有活动任务会先确认停止，再激活目标空间并核对信任和分支，继续使用应用已经持有的模型目录与本次选择。普通非切换断线仍禁用会话导航。

预选空间不是当前执行空间时，输入区继续使用应用已读取的 Provider 目录和当前权限选择；模型与权限选择器不属于空间，切换空间不重新加载、不清空也不短暂禁用。模型选择只在准备页暂存，不修改当前或目标空间的默认配置。外部目录授权仍只在实际激活目标空间后读取和提交。发送前观察到分支或 HEAD 变化时采用当时的真实环境继续执行，不要求用户重复发送；只有用户明确选择了另一分支，才在首次发送流程中执行受控 Git 切换。会话一旦创建就立即绑定该身份；随后权限设置明确失败或回执未知时恢复草稿并在同一会话核对或重试，不再创建第二个空会话。用户取消停止旧任务和切换空间时同样恢复准备草稿并重新开放发送。

输入框聚焦不增加额外边框，右下角没有手动调整尺寸的拖动柄；多行输入由内容撑开。发送与停止使用同一位置的图标按钮，悬停提示和可访问名称说明当前动作；停止提交期间保持禁用，避免重复请求。

已发送的用户消息可逐条复制；Agent 复制按钮按 Runtime `turnId` 归属，同一 turn 内只在没有后续工具调用的最终回复下显示一次，并只复制该完整最终回复，不包含同轮工具前说明、思考、工具、子 Agent 或其他非最终文本。用户气泡和 Agent 最终回复与后续内容的间距为 32 px；非最终回复到后续工具保留 8 px；工具记录到下一段非最终正文为 8 px，到最终回复为 16 px，工具组内保持紧凑。悬停消息或用键盘聚焦可显示复制按钮；成功时显示较大的勾，两秒后恢复复制图标；发送状态未定、失败或流式回复不提供复制。轮次底部的回复状态行在准确 Turn 终态后移除。发送回执未知时保持“待确认”并阻止重复提交，等待新的运行时事实或显式会话恢复。

块级代码使用带语言标题的代码框；未标注语言时显示“代码”。完整最终回复通过原文读取核验后，可在代码框中单独复制代码内容，不包含语言标题；预览、流式回复或最终身份未确认时不提供代码复制。复制失败可重试，暂时只读时暂停操作，关闭完整正文即撤销资格；长代码仍可通过键盘聚焦后在自身区域内滚动，行内代码的阅读方式保持。

新 Run 在持久提交前明确遇到 revision 冲突时，客户端可重新读取投影并且仅重提一次；刷新后已有活动 Run 则保留草稿，不自动改投为 steer。这不改变回执未知时禁止自动重发的规则。

输入框上沿以无底色的紧凑上下文条选择已打开项目或添加本地目录；没有项目时菜单只显示“添加项目…”，不显示空列表与分隔线。Git 仓库旁边直接显示真实分支，不重复展示固定的本地环境提示；非 Git 项目完全不显示分支选择器，仍可正常发送。Git 只是空间的可选能力：`.git` 标记无法确认、Git 未安装或 Git 探测失败时按普通空间继续，不阻止创建对话；只有用户主动执行分支操作时才要求 Git 能力可用。上下文条与输入正文共用左侧视觉基准，只承担轻量元信息层级，不作为独立大卡片与输入框争夺视觉重心。选择项目或已有本地分支后立即生效；切换分支时有运行、排队或等待中的任务，或存在暂存、未暂存、未跟踪的改动，都会阻止切换。不会自动提交、丢弃修改或创建 worktree。分离 HEAD 和尚无提交的仓库显示真实状态；只允许在仓库根目录切换分支。分支菜单可以刷新，失败或回执未知时检查刷新后的实际状态，不自动重试。

应用启动先显示独立启动页，完成本地服务连接、首屏空间会话目录及当前项目的准备检查后再显示主界面，不展示主界面逐项加载的过程。服务连接或首屏目录全部读取失败时，启动页显示原因并提供“重新尝试”；空目录可以正常进入，局部目录失败、项目失效或模型未配置不阻止进入主界面处理。启动页没有人为最短停留时间；进入主界面后发生断线仍保留页面与草稿，不重新遮挡为启动页。

Windows 原生 Mica 与 macOS Vibrancy 窗口的启动页不铺实色底，准备中和初始化失败时均直接显示系统玻璃材质，文字与操作按钮沿当前主题保持可读；其他窗口保留原背景。

重构后的正式 Native 已迁入原启动页，并接入当前服务连接与首屏完整目录读取：首次准备未完成时等待，初始化失败显示原因并可明确重试；初始目录观察确认不可用时也提供重试，原连接恢复完整目录可直接进入，用户重试后旧连接的迟到目录不能覆盖新页面。进入后断线保留页面与草稿。切换或重试后，旧选择、草稿与状态读取的迟到失败不影响新页面；普通会话操作失败也不弹出“操作未完成”。可恢复读取与未知原提交在后台自动核实，原草稿和消息保留。设置、启动和空间管理等独立业务继续显示其实际错误。实际迁入范围及 DOM／macOS 首次和冷启动证据见[Native owner](../../../../apps/desktop/README.md#原启动页与初始化重试)；有效服务诊断时的“保存诊断”也已接回，见[诊断保存范围](../../../../apps/desktop/README.md#原启动诊断保存)；其余安装恢复要求继续按原方案验收。

应用重启会恢复已打开项目列表并自动读取应用历史，不创建会话或发送任务。项目目录失效、Git 不可用或模型配置错误不妨碍阅读已有历史，各自显示局部提示。发送前核对目录、信任和模型；普通资料文件夹无须 Git。本地服务的启动、连接与恢复由客户端内部负责，不提供重连或断开操作，内容页不展示连接中断或服务未就绪提示。内部恢复期间保留会话内容与草稿；侧栏会话点击立即改变阅读选择，连续点击只恢复最后选择的会话，不等待旧会话完成连接才响应。已选会话在校准期间仍显示阅读页，不误显“新对话”欢迎页；发送、停止与审批继续等待新连接就绪。操作结果未知由后台查询原申请，真实执行结果保留在所属消息中。未发送草稿不承诺应用重启后恢复。

普通关闭窗口保留应用与任务，再次激活显示原窗口；明确退出或实际切换执行项目会停止自有服务中的执行，已有修改不撤销。只有存在活动任务或任务状态无法核实时才显示退出确认；确认后立即销毁窗口，未完成的清理在后台继续，不再弹异常收尾提示，也不自动重发请求。连接断开后不能使用旧的就绪状态提交操作；回执丢失时自动查询原申请，消息区外不追加“操作提交结果未知”或临时查询按钮；未知效果仍按所属消息的真实结果保留。

通用 Native 的退出检查未得到服务回答时按状态未知显示一次确认，默认保留服务；取消后保留窗口和草稿。明确退出期间暂停页面自动读取，退出前旧状态、目录、选择或私有草稿读取的迟到失败不弹“操作未完成”；取消退出后恢复原页面读取，不重发任务。当前会话操作的真实失败和写入结果未知保留在所属消息中，后台只核对原申请。确认退出后立即关闭界面，清理在原主进程后台完成，不追加收尾警告或确认。服务非零退出仍是清理失败，不把界面已关闭当作成功。当前 macOS 的窗口、所属进程与有限故障验证范围见[退出 owner](../../../../apps/desktop/README.md#原窗口关闭与退出收尾)，不代表完整安装恢复或平台资格。

工具的准备状态与执行结果分别展示。Core 已核实尚未派发、因上下文或工具信息变化而失效的调用，显示“上下文已更新，此次未执行”或“工具信息已更新，此次未执行”；聚合标题不追加状态计数，逐项原因不计为执行成功或实际失败。实际派发失败、拒绝、停止、未知结果和无法核实的旧记录继续保留原状态。正常只读探索发现新目录指令时，读取继续完成，下一次模型判断使用新指令。

工具审批会显示具体命令与说明，可以选择“仅批准这一次”或拒绝；结果仍由服务核实。补充问题使用紧凑的 Questionnaire 卡片展示问题、进度、单选项和允许的自由回答，整行选项可点击，推荐项显示中文标记；作答区不显示内部状态、执行身份或原始 JSON，取消与翻页／提交位于同一操作栏；一次请求包含多题时可通过上一题／下一题自由查看，最后一次提交全部答案，每条答案以 `q1`、`q2`、`q3` 题目 ID 保留协议归属。选项提交同时保留内部 option ID 供校验与恢复，但交给 Agent 和历史摘要的是选项文案；自由回答保持用户原文，不把 `q1-o1` 等内部编号当作语义答案展示。选项不常驻显示字母顺序或详细描述；有描述的选项在右侧显示 info 图标，鼠标悬停或键盘聚焦后显示该选项的标题与完整描述。第一页只显示下一题，最后一页才显示提交回答；可以在当前题未答时先查看后续问题，但尚有任一题未回答时提交按钮不可用。交互块不使用内部滚动条，完整内容直接占据底部布局并让会话阅读区收缩。取消回答会把取消结果交给模型，模型仍可继续；当前交互期间不提供停止按钮。计划面板显示完整正文与步骤，支持 Accept Edits/Auto 批准、修改要求及取消；未能完整读取正文时不能批准，较大正文先加载完整附件。扩展或验证交互仍显示限制，用户可取消。高级恢复尚未交付。

新 `apps/desktop` Native 候选现已通过本机 macOS 的默认 ask_user 问卷窗口验证：未作答可浏览、多题一次明确提交、会话切换保留问卷草稿、取消问卷后原任务继续；当前父轮的问题出现时隐藏主输入，回答或取消后恢复原主草稿。原值、文案和原 Run 分别核对。问卷草稿的页面生命周期另有 DOM 证据；计划审核另有下述验收，全部设置与完整视觉迁移仍未完成。实际范围见 [Native 问题 owner](../../../../apps/desktop/README.md#native-普通问题与页面草稿)。

Native 主输入通过“先审核计划”选择当前提交：空闲时发送新的计划任务，当前有任务时排队等待它结束，再开始新的计划任务。审核时显式选择 Auto 或 Accept Edits；补充修改要求后，新版本仍需重新批准。拒绝本版计划与停止原任务各有入口，停止不撤销已有结果；结果未知时退出仍会要求确认。当前父轮自己的计划审核期间隐藏主输入，交互结束后恢复原主草稿；普通工具审批保留输入区与权限选择器。具体可用范围和本机验收见 [Native 计划 owner](../../../../apps/desktop/README.md#native-计划入口与完整审核)。

子 Agent 等待批准或回答时，其准确交互卡继续显示，父会话仍可输入新请求；一项子任务待批不会占住其他协作工作的父输入。每张批准卡仍只授权所显示的原执行；旧卡答复不会批准同一协作者后来一轮，停止也保持原准确任务范围。

补充回答和计划修改意见在当前页面进程内保留：切到其他会话、新对话或安排任务再回来，可以继续编辑原文。它们与主输入框草稿分开，也不会带入其他会话或下一道问题。提交失败保留输入，确认提交或取消成功后清理对应交互的草稿；完整页面刷新和应用退出后不保证恢复。

点击会话标题栏的“标签页”图标打开最右侧栏，默认显示“新标签页”。标题栏采用48px紧凑高度，标签本身高度保持不变，缩小上下留白。顶部标签条支持切换、关闭和用 `+` 新建网页标签；网页、变更与子 Agent 详情合计最多同时打开8个标签，已满时打开新的详情会提示先关闭一个标签。关闭最后一个标签会自动收起右侧栏，再次点击“标签页”图标会显示新的空白页。新标签页的“工具”目前只有“变更”，点击后打开或切回唯一的变更标签，展开文件操作可阅读成功文件工具保存的差异或写入内容。这不是当前工作区 Git diff，也不覆盖 Shell/MCP 等工具未报告的逐文件修改。输出可能截断，空列表不代表磁盘没有变化。在设置中可选择 VS Code、Zed 或 TextEdit 打开当前项目内仍存在的文件；同一选择也用于消息中的路径链接和读取文件路径，默认 VS Code，在当前进程保留。打开的是当前磁盘内容，编辑器需已安装。迁移前 Tauri 版本曾在本机 macOS 确认 VS Code 实际打开；TextEdit 仅确认启动分发，Zed 未安装。Electron 版本的实际编辑器窗口仍待重新验收。

网页标签提供后退、前进、刷新／停止和地址栏。输入 HTTP／HTTPS 网址可直接访问，普通文字按 Bing 搜索；localhost 可用于本机页面。网页独立运行，不读取应用接口、会话正文或本地文件，也不会把网页自动发送给模型。新窗口网页链接在当前标签打开，暂不支持导入浏览器数据、安装扩展、下载或外部协议。加载失败时可修改地址或重试。

侧栏沿原宽度动画与调宽操作开合，明暗主题的标题栏均显示与会话标题栏对齐的底部分隔线。收起、Esc 或切换标签会结束变更内容与子 Agent 详情的读取，当前会话的标签与网页历史保留；窗口缩窄后拉宽也保留它们。关闭网页标签、切换会话或重载窗口会释放旧网页；重载和退出不恢复标签或浏览记录，浏览器 Cookie 只在当前窗口进程内保存。关闭侧栏后焦点返回顶栏按钮，输入草稿和实际执行保持。

首次打开或缓存已被淘汰的会话显示加载进度，长历史分批读取后完整展示。已保存的正文先于实时连接校准展示；实时状态查询或订阅失败不会挡住已读历史，也不会使任务自动重跑。单次会话加载或校准超时后保留已读正文，可重新加载或切换其他会话；超时本身不主动断开其他会话共用的连接。实时校准完成前可阅读、复制和编辑草稿，发送、停止与审批保持不可用。已打开的会话若出现实时消息缺口，会保留正文并自动补读历史；消息补齐且实时订阅重新就绪后才恢复操作，补读失败仍可阅读并重新加载，不会自动重发任务。首次发送选择的权限模式与当前一致时保持原模式并继续提交。同一连接内再次打开已缓存会话，立即显示上次正文并恢复阅读位置和展开状态；空会话也会缓存。后台仍会完整校准历史，期间可以阅读、复制及编辑草稿，发送、停止与审批等操作等待校准成功。校准失败保留已读正文并提供“重新加载会话”；明确不存在或拒绝读取时清除正文。缓存容量有限，超长会话离开后可能需要重新加载；非当前会话缓存不跨连接重建、页面刷新或应用重启保存，普通断线仍保留当前正文供阅读。每个空间的目录默认读取并返回全部会话，不提供手动加载更早会话的入口；页面按最新更新时间从新到旧排序，默认显示前 5 条，点击列表末尾辅助文字色的“展开更多”每次再显示 10 条，最后不足 10 条时显示剩余会话。收起空间后再次展开恢复为 5 条，其他空间不受影响。一个空间读取失败不清空其他空间。点击其他空间的会话直接阅读，不停止原任务；在已有会话发送时按原会话身份路由，不切换当前执行项目，也不停止其他会话任务。本地目录不存在时，空间名称变浅，仍可打开会话，不常驻提示目录关联情况。已有会话继续发送不以本地目录存在、Desktop项目登记或当前选中项目为前提。服务按会话持久身份与既有授权执行；原目录被删除时仍可对话，依赖该目录的Shell和文件工具在实际调用时返回错误，不自动创建目录或改用其他目录。新建项目会话仍核对所选目录与授权。自动重接恢复所选会话和进程内草稿，不重发任务。

设置页的“提供商”以简洁列表展示用户已添加的独立连接、名称、类型、配置状态与编辑/删除入口，空列表不预置提供商。点击“新增提供商”直接打开应用最右表单，通过“服务商预设”下拉框选择 OpenAI、DeepSeek、Ollama 或自定义兼容服务模板，再填写连接名称与配置；同一模板可添加多个实例。编辑沿用同一右栏；删除另显示相关模型、默认模型和本机定时任务影响，明确确认后才移除配置，存在默认/定时引用时拒绝删除且不自动换模型。系统凭据库秘密保留。关闭后回到原按钮；删除成功后回到新增按钮。列表中的配置状态不承诺远端连接或执行已验证。切换提供商会清空上一提供商尚未保存的密钥、地址和模型名称。必填 API key 与服务地址格式在面板内提示错误并聚焦对应字段，不弹出浏览器原生校验提示。“模型”页按 Provider 展示已发现模型，可启用或禁用，并通过下拉框从已启用且可用的模型中选择默认模型；当前默认模型须先更换才能禁用。切换默认模型、启用或禁用模型、刷新配置和保存提供商时，页面保留当前分类与滚动位置，不整体变灰；等待期间阻止重复配置操作；关闭再打开设置不会解除等待，完成后才恢复配置操作。启停开关先保持用户选择的位置，提交失败则按服务确认的状态恢复并显示错误；提供商保存期间输入只读。无可选模型时显示空态和服务提供的诊断代码，不将未配置误报为可用。输入区模型选择器只展示已启用的模型路由，并暂存本次选择。新会话在首条消息创建时绑定该路由，已有会话在下一条消息开始时更新自身路由，不覆盖其他会话；活动任务继续使用开始时冻结的模型。通用 Native 的 API key 通过选定 Profile 的系统凭据库保存，JSONC 只保存引用，输入在提交后清空；保存仅更新选定连接，保留同一 Provider 的其他连接。模型名称留空时查询模型列表，手动填写时直接保存，是否可执行仍需实际任务验证。提交结果未知时只能显式查询原提交；最新配置读取不能代替原保存回执，不自动重试。

输入区的模型与思考选择器先展示紧凑思考浮层，点击模型名称进入提供商与模型双栏；展开和返回时尺寸平滑过渡，内容轻微淡入，系统减少动态效果时直接切换。两列分别滚动，模型数量变化不改变浮层高度。选择器及思考浮层统一使用 13 px 文字，档位名称、模型名称与轨道之间的可见间距一致，顶部与底部留白均衡。滑块按极低、低、中、高、极高、最大六档选择，蓝宝石星光随档位加速，最大档为融合蓝色的紫宝石；轨道高度为24px，不绘制边框，白色按钮在悬停或拖动时放大25%，结束后恢复，松手时短暂扩散粒子；系统减少动态效果时关闭尺寸过渡与装饰动画。思考调节只对服务声明支持的 OpenAI／OpenAI-compatible 提供商且未明确关闭推理的模型开放；其他模型显示不支持提示。已有会话优先显示当前手动选择；没有当前选择时，恢复该会话最近一次运行中同一模型使用的具体档位，再读取模型配置。新会话从所选模型的配置读取档位。模型按钮、浮层标题与滑块显示同一具体档位；只有实际调整后才改变当前选择。没有已知档位时保持未指定，不把服务商默认值猜成某个固定档位。选择在当前页面进程内按对话保留，切换模型清除原模型的临时档位；新对话首条消息使用准备页的选择，之后继续发送沿用该对话的选择。模型与档位只作用于下一次新运行，不修改全局默认，也不改变正在运行的任务；运行中发送仍为文本引导。页面刷新后，未发送的临时选择清除；已有会话恢复上次实际使用的档位，新会话读取模型配置，活动运行仍使用其已冻结档位。


保存 Provider 与刷新配置分别确认结果：已保存但刷新失败时，提示刷新后选择模型，无需重复保存；服务明确拒绝时保留拒绝原因。写入结果未知时，即使后续刷新成功也不改称保存成功；刷新同样失败时明确说明两者，避免将查询错误误认为写入未发生。

客户端启动以 300ms 内完成本地连接和首屏目录为优化目标；目录无需先恢复所有历史或准备模型。迁移前 Tauri 宿主的部分热缓存服务至目录测量曾低于该预算，但首次运行和完整系统启动仍未满足资格；Electron 需要重新取得从系统启动到窗口绘制的端到端证据。测量条件与负载限制见[启动说明](../../../../apps/kite-desktop/docs/history-and-recovery.md#启动预算与验证边界)。

点击未缓存的会话后，右侧消息区保持原尺寸并在中央显示无底色的浅色风筝图标，以不改变布局的轻微闪光表达加载；系统要求减少动态效果时显示静态图标。页面不显示加载文字或欢迎内容，历史分批读取完成后直接渲染完整正文，避免加载节点引起布局抖动。已有缓存正文的后台校准继续保留正文，不显示该覆盖层。

通用 Native 的工具过程现在沿用原轻量工具行与结果展开。执行中、失败、停止和结果未知按已核实的原执行展示；消息完整不表示工具成功。读取文件失败在行内保留简短状态，点击该工具展开完整原因；只有已确认成功且可用的文件操作提供路径按钮。目标文字来自已读的原请求，有歧义时不补目标。Shell 启动受理与后台任务完成分别表达，完整输出和准确停止继续从环境信息／Runtime logs 操作。工具记录的展示信息尚在读取时，原始结果默认收起，状态显示“状态待核对”，不会先显示整段 JSON 再换成简洁工具行，也不把待读取误报为执行结果未知。未知工具或版本显示原名称、版本和可展开原文；无法核实状态时保留可主动展开的原结果，也可明确重新核对。关闭结果或切换会话只结束读取，不停止或重新运行工具。

Native 已接原轮次阅读：按已核实的 Run 显示过程、耗时与终态，结束后过程默认折叠，确认的最终回复独立可见；可重新展开过程，同轮相邻的已知文件读取／搜索等沿原工具聚合。完整正文自动依次读取，回复内不提供“重新读取”按钮；真实读取失败保留已显示内容并说明失败。复制最终回复使用已完整读取并核验的准确正文。恢复时已保存的旧 Store 终态可作为历史展示，原出处保留；Fork／Include 封存内容不借来源 Run 后来的状态补最终回复。状态无法核实时保原消息或“上次确认状态”。

Native 从父会话环境卡打开的子 Agent 只读详情显示在右侧栏独立标签，复用父会话的消息组件：按已核实的轮次显示过程、耗时与终态，完成后过程默认折叠，最终回复独立显示；相邻的工具调用沿相同工具聚合，Markdown 和准确全文复制也共用原组件。详情标签保持只读，没有输入、审批或文件打开操作；主会话保留自己的输入、审批和原操作资格。详情会自动跟随已保存的新消息和回复前缀；正在生成的前缀仍标为未完成。已完整读取并核实的正文直接显示。切换标签、关闭详情标签、收起侧栏或打开设置会结束该详情的读取，原任务继续执行；父会话正文继续更新，草稿、阅读位置与展开状态保持。再次选中已缓存的详情标签时，先核准其仍属于当前父会话，再显示上次正文并在后台校准；读取失败保留上次内容并说明未更新。仅轮次或工具展示信息读取失败时，已经核实的正文仍可阅读，页面明确提示并可通过刷新重新核对。缓存和阅读状态都有容量限制，超长或已淘汰的会话重新进入时需要读取，页面不会为全部历史会话保留隐藏消息组件。

通用 Native 的复制按钮现已接系统剪贴板，保原完整正文与成功／失败反馈。原宿主复制上限为 1 MiB UTF-8 字节，超限显示复制失败，不复制预览或截断正文；全文阅读能力保持独立。macOS 当前首次与冷启动的实际剪贴板证据见[复制 owner](../../../../apps/desktop/README.md#原消息复制与标题栏缩放)。

默认问答工具的已保存结果沿原组件显示实际问题和人类回答；取消信息回答显示“已取消回答”，任务按真实状态继续。人工审批已接原按钮与范围菜单，完整大请求读完并核实后才能回答。工具上的原审批事实分别显示已提交待核对、已人工批准、自动批准／拒绝／等待或未知；停止后保留可核对的已有记录，批准不代表工具执行成功。首次和冷启动的人工审批记录已核实，原记录可从下文“交互记录”阅读。当前会话输入区仅提供请求批准／自动审核／完全访问，选择直接使用三策略的实际权限值，只改该会话；完全访问取消或切会话后的旧确认不生效；原停止按钮按准确活动任务提交取消，等待原状态核实。macOS 当前 Store 已核自动批准、拒绝、转人工、无效结果回到人工及审批中停止；转人工保原原因，拒绝或停止时没有文件作用，冷读不重发。全部封存／恢复组合和完整 PC 验收仍待核对。当前范围与证据见 [Native owner](../../../../apps/desktop/README.md#原审批面板与授权观察)。

通用 Native 在新链路明确备份恢复为新 Store 后，原源会话和分支的已回答问答仍沿原工具记录展示相同问题、选项标签与完整自由文本。查看、展开、切换和冷重开只读取保存记录，不重新回答或调用模型；封存记录不会借来源任务的后来状态获得执行或回答资格。macOS 当前安装版范围见[问答 owner](../../../../apps/desktop/README.md#原轮次阅读聚合与问答回执)，其他问答／审批恢复组合仍待核对。

工具消息按已确认原型统一为轻量行：上下各留 8 px，工具聚合展开后不缩进；hover 高亮文字与图标，不增加背景色。仅具体文件名 hover 时显示下划线并可打开。Shell 行以终端图标、实际操作状态和单行省略的命令摘要显示，点击展开带边框与圆角的 Shell 卡片。卡片采用 CodeBlock 的固定 Header、滚动输出和底部结果结构：带 `$` 提示符的执行命令在 Header 按原始换行完整显示，长行自动折行、不省略，可复制完整原始命令；Header与输出之间不绘制分隔线，滚动区通过scroll-fade显示随位置变化的边缘渐隐；仅输出区滚动，右下角显示实际结果；已确认成功时显示“成功”与勾号，不追加退出码，失败时保留具体退出码。独立输出滚动区最高 256 px，聚合内随剩余空间收缩，状态保留在卡片底部；手动上滚后停止跟随，滚回底部后恢复；不显示“回到最新输出”按钮。实时记录被已保存回执接替、命令全文读取完成时保持展开及阅读位置。运行中的文字有轻微扫光，减少动态效果设置下静态显示。

同一轮中连续的工具调用统一聚合，读取、搜索、修改、Shell、MCP 和 Agent 协作均适用；可读的阶段说明、用户引导或另一轮次开始新的分组。聚合从第一项起默认收起，后续新增工具、回执接替和展示信息补齐保持原容器及展开选择。仅用于声明工具、且当前能确认没有正文的模型消息不占独立消息行，也不拆开连续工具；历史从未完成更新为完成时保持原聚合。存在正文或正文仍需读取时保留原阅读入口。标题按组内动作去重组合，例如“编辑文件读取文件运行命令”，不加“了”或顿号，不显示工具总项数。标题后不追加任何数量、状态或异常文本。各工具行仍按实际状态表达执行、等待、审批、失败、结果未知、停止或此次未执行，不推断成功。展开后的整体高度最高 240 px，超出部分在聚合内部滚动；聚合内工具列表项之间的纵向间距为 0，聚合与工具详情统一使用带滚动条的 ScrollArea，并在滚动边缘显示随位置变化的淡出提示；列表、输出与长详情均可聚焦后使用键盘滚动。摘要随实际动作组合更新，不切换成最后一个工具的名称或路径。展开聚合后，可继续逐项查看命令输出、修改差异、问答、原始记录或准确的子 Agent 详情。

已核实的工具尚未派发时显示“等待执行”，已派发且尚未返回结果时显示“执行中”；读取、修改和其他工具保持相同含义。Shell在排队、审批和执行过程中即可显示具体命令，不等执行完成；命令来自准确工具记录，不按模型正文猜测。已保存会话重新打开时直接读取原命令及结果，不需要新建对话或重新提问。自动审批、等待人工审批和拒绝保留各项事实；执行权不可核实时停止活动提示。派发不代表执行成功，最终结果以实际保存状态为准。

“会话工具”中的“交互记录”可展开阅读原问题、计划和审批请求，查看已保存答案、取消与回答被执行接收的事实。这里只阅读，当前待回答记录仍从原待输入卡操作。计划保留格式化阅读和准确修改反馈，大附件须完整读取并核实后才能展开原文。分页期间状态变化会保留本会话上次完整记录并说明未更新，可点击“重新读取交互记录”；切换会话清理旧范围，关闭只结束读取。新链路明确备份恢复为新 Store 后，可继续阅读实际保存的问题、计划和审批记录及完整附件，原出处保留并显示“恢复历史，只读”；旧未完成记录按实际恢复结果显示取消。查看不会重新回答、执行或获得审批权，分支不自动取得来源后来的交互记录。当前验证范围见 [Native owner](../../../../apps/desktop/README.md#原交互记录只读历史)。

自动审批状态附在所属工具上：审批中、已自动批准、未通过或等待人工审批。已自动或人工批准不再常驻文字，在命令后以14px低对比度盾牌勾图标表示，悬停或键盘聚焦可读完整说明，Escape可关闭；审批中、等待人工、拒绝等仍显示13px辅助文字。实际执行失败、超时与结果未知保留异常提示。确认未派发的审批拒绝或取消只显示对应审批状态，不再追加“未执行”或重复的停止状态；Shell展开后的状态区也不重复审批等待。已批准后的真实执行结果独立保留。需要阅读原因时点击对应工具展开，保留服务提供的完整文本。人工审批主按钮为“仅批准这一次”，服务允许时右侧菜单可直接“批准本次及本会话相同命令”；左侧为“拒绝”。授权范围仍以服务匹配规则为准，批准不等于执行成功。上下文压缩在正常消息区以类似工具消息的左对齐轻量行显示状态，文字两侧不绘制横线，字号、行高和上下留白与工具消息标题一致。同一次压缩由进度接管为已保存记录时保持原行和阅读位置，不因历史刷新先消失再出现；后续压缩使用各自状态行。实时进度显示“正在压缩上下文”；只有旧进行中记录、没有当前进度确认时不显示该状态行。实际结果包括已发布完成、失败、取消或未发布；模型摘要成功但未提交不能显示完成。压缩摘要不作为最终回答或复制内容，普通完整回复也须等准确 Run 完成后才取得最终回复资格。问题回答完成后可在轻量回执中展开查看。

读取等工具失败或审批未通过时，行内只保留简短状态，完整异常内容通过点击该工具展开阅读，不跟在工具消息后。聚合内的 Shell 也可点击命令查看输出，收起聚合后再打开会保留先前展开选择。

在另一空间的已有会话发送时，直接按原会话ID提交，不要求切换当前项目，不关闭配套服务，也不停止其他空间任务。新会话属于所选空间，已有会话按持久空间身份执行；授权、模型和草稿继续分别隔离。明确退出、显式取消及真实工作目录冲突仍按各自规则处理。

原 kite-desktop 历史路径以会话页面顶部 Toast 提示操作失败；通用 Native 的空间、Git、分支和命令失败遵循上文现行 AlertDialog 约定，保留草稿，确认后清除本次提示。会话因执行权失效而不可继续时，仍需区分被占用、清理未完成与外部结果未知；实际恢复入口和取得资格见[Native owner](../../../../apps/desktop/README.md)。核对原效果不发送输入框草稿，旧执行结束缺少证据时不能以重发消息代替核对；详情见[恢复语义](../../features/recovery.md)。

原 kite-desktop 的 Git 切换会影响其项目配置加载，需要在所有空间任务结束后重启配套服务，不自动取消任务。通用 Native 的新对话切换与配置冻结遵循上文当前入口约定；普通项目选择和发送消息不关闭 Service。

Ask 请求出现时，消息列表立即显示“询问用户”工具记录和问题，等待用户回答；回答或取消后在同一位置更新。Ask 历史保留唯一可展开工具记录：单题标题展示“询问用户”和问题，内容为“回答：”及答案；多题标题展示“询问用户 · 已回答 N 项”，明细带有序前缀，每项按“问题：回答”展示。取消后内容只显示“已取消”。内容与标题文字对齐，换行对齐前缀后的正文，每项最多 5 行，超出截断，连续字符自动换行。仍按 toolCallId 去除重复工具记录，不展示结果 JSON。

Shell 输出已确认截断时，状态区显示“输出已截断”；尚未取得完整输出时不将空白解释为成功且无输出。启动受理只显示已受理，等待超时与命令仍在运行分别表达，停止请求保留等待结束的状态，不能据此宣称后台命令成功或已停止。自动审批期间拒绝或停止且没有派发时只保留对应审批状态和可展开原因，不追加“未执行”；实际执行后的输出、失败、超时及结果未知保留。命令全文尚在读取时可显示明确标注的命令摘要；工具结果先于模型调用记录到达时，仍按准确工具原输入读取命令，保持原卡片和展开选择。无法核实时保留原记录阅读入口。

可展开消息的箭头紧贴标题内容（6 px），位于状态文字之前；收起时仅悬停图标与文字组成的紧凑标题区或键盘聚焦时显示，展开后持续显示。文件修改的文件名与 diff 按钮保持独立操作；不可展开的读取不显示箭头。轮次过程有独立折叠控制，箭头紧跟状态与耗时，思考正文不提供展开入口。“用时”等轮次状态仅在鼠标悬停文字区域时变亮，右侧空白、按钮内边距和箭头不触发文字高亮；展开后移开文字也恢复原色。可折叠标题保留键盘聚焦提示，静态耗时仍不提供点击动作，停止与失败等状态保留原提示颜色。点击“用时”收展时，过程高度和后续正文的留白同步过渡，不先跳动再收起；系统启用减少动态效果时一同直接切换。

思考状态只在活动 Turn 底部回复状态行用简短“正在思考…”表示；正文或工具活动到达后切换为“正在回复…”，准确终态后移除。客户端不展示思考正文，也不把思考段时间当作整轮处理耗时。

阶段说明、工具与最终回复的间距由同一轮的外层布局维护；隐藏的思考内容不占用消息间距。

本轮回复异常失败时，以类似工具消息的轻量行显示“回复失败”和简要原因，默认收起；点击或通过键盘展开后可查看一段简洁的失败说明。显式测试诊断模式可增加服务已提供的原因代码、执行结果、直接重试是否已确认安全和后续处理方式；普通开发启动与正式启动均不因环境类型展示这些额外诊断字段。失败提示始终显示在本轮过程之外，收起过程或没有回复正文时仍可见；详情补充和会话重新加载保留展开选择。缺少分类信息时显示通用失败说明，不推断具体原因，也不自动重试。

工具消息展开后，标题文字、图标和箭头持续高亮；收起后恢复默认辅助色，悬停和键盘聚焦仍可高亮。详情展开与收起有短暂过渡；系统启用减少动态效果时直接切换。

“列出目录”未指定路径时，工具行显示 `.`，表示工作区根目录；显式指定的路径沿原文显示。只有能核实原调用及工具版本时才补默认目录。

源码与打包版使用同一正式会话入口，不再按代码目录或 epoch 自动分库。已验证来源会自动整理；`STORE_INCOMPATIBLE` 表示未证明可安全读取的格式，`STORE_ACCESS_DENIED` 提示检查数据访问权限，`STORE_CORRUPT` 表示数据库或已识别结构校验失败，`STORE_INSUFFICIENT_SPACE` 提示释放磁盘空间后重试。原数据不会因这些检查失败而被清空或替换。

启动失败且Service提供了有效诊断时，可点击“保存诊断”，在系统文件对话框选择新的JSON文件。报告只包含错误分类、准备阶段、格式版本与处理提示，不包含会话内容、目录或原始服务输出。取消选择不会写文件；已有文件不覆盖，保存失败时选择新的文件名重试。迁移期间会显示阶段；确认其他客户端或整理流程占用存储时先自动等待，最长10秒，占用解除后在当前窗口继续启动，超时再提供重试。应用菜单中的退出先请求安全退出，发布前在安全点取消，发布已开始则在后台等待结算；新对话的分支读取／切换和打开文件的启动请求也纳入退出收尾，不继续启动新的请求。确认退出后立即销毁客户端窗口，后台保留原清理与恢复资料，完成后结束主进程，不再确认。普通窗口关闭仍按原行为隐藏窗口；请求退出本身不表示取消已完成，已打开的外部编辑器仍由系统管理。

正式 Native 已迁入上述文件变更面板：通过“标签页”里的“变更”工具打开，逐次列出成功的文件写入/编辑；展开才读取已保存差异。预览截断时明确标示，旧记录未保存差异时保留操作与可用路径，并说明不会按当前文件补造。关闭和切换只结束读取，输入草稿和实际执行保持。原来源属于另一项目或不能确认当前项目时只读历史，不提供编辑器按钮。常规中的编辑器选择已接文件变更路径按钮，当前 renderer 默认 VS Code；消息正文和已核实的文件读取／写入／编辑行也已接原路径入口，打开当前项目文件；跨项目历史、子详情或未知格式只读。缺失目标沿原弹窗告知。常规摘要显示当前项目的配置默认模型，无会话和新对话准备页显示用户默认；临时会话选择和活动轮次保持各自语义。macOS 新 Native 的原面板与消息入口首次/冷读、常规摘要、作用域校验和选择已取得有限证据，实际外部编辑器窗口的重新验收范围仍保持上文所述；准确边界见 [Native owner](../../../../apps/desktop/README.md#原文件变更面板与编辑器)。

离线备份恢复后，原会话和已封存分支的成功文件历史仍可阅读，原差异保留原始出处，不随当前磁盘的独立编辑改变。文件变更、工具行与普通消息的路径仍可打开已重新确认属于同一项目的当前文件；来源属于另一项目或无法确认时保持只读。阅读和关闭不重跑原文件操作，打开当前文件也不会恢复历史内容。当前恢复读取与目标资格已有真实 Main/HTTP 消费者证据；整窗口恢复点击、实际外部编辑器和跨平台资格仍按上述范围核对。

## Native 的扩展能力

当前正式Native可在主会话的“会话工具→扩展能力”展开已注册扩展目录，按动作提供的表单填写并执行，或明确查询已保存结果。动作显示原命令的受理与实际执行结果；已受理表示仍须核实执行。结果未知时“查询原命令”只查该次申请，冷启动也可从已保存的原命令查回。确定结果后点击“新动作”才开始下一次明确申请；需要新业务标识的动作由用户填写，不能复用未知申请自动重跑。

通用结果显示完整内容、类型／版本、附件引用和扩展提供的原结果动作。查询、刷新目录、收起面板和切换会话都只影响阅读，不启动模型或取消工作。刷新期间保留上次完整结果供阅读，其动作待重新查询后才可使用；失败或迟到的结果不能改绑到新会话。换Store恢复的旧申请保原身份，不能自动成为新Store的执行许可。可用动作继续遵循当前宿主的权限、工作区信任和准确执行定义；没有注册或没有权限的能力不能由页面补造。参考mini-review只用于明确测试装配，不是默认产品功能。实现与已验范围归[Native owner](../../../../apps/desktop/README.md#native-公共扩展完整能力)。

## 开发 Native 的文件检查点恢复

新 `apps/desktop` Native 入口在当前主会话提供“文件检查点”面板。先按需读取目录，再读取所选点的当前文件预览与准确会话边界；仅会话、仅代码、代码与会话三个范围必须明确选择和确认。仅会话生成新会话而不恢复磁盘；仅代码保留当前会话与选择，仍单独展示普通恢复动作的人类审批；代码与会话先恢复代码，只有核对原代码成功后才出现“明确继续原会话分支”，不会自动执行第二步。

两步的原申请身份在第一次提交前全部保存在当前 Profile。退出、崩溃、读取取消或回应丢失后，“查询原恢复”只核对原 Command/restore ID，不重发写入、不另建 ID。代码成功但分支未知时保留两种事实。明确继续前还会重新核对原检查点的完整当前文件预览，所有文件必须仍是已确认的恢复结果；独立编辑或随后完成的写入会拒绝继续，原代码成功记录保留，分支尚未执行。读取和提交之间没有对独立编辑器的全局锁。换 Store 恢复的旧申请保留原来源，作为只读历史，不重标或自动取得新 Store 执行许可。

切换 Session、修改范围或标题、隐藏面板和关闭读取都会使旧观察失效，迟到响应不能覆盖新页面；已提交的申请继续按原身份保存。完整文件来源、媒体、保护路径或当前后像无法核实时，代码恢复可能不可用或冲突；准确的会话边界可以独立成立，不因此授予文件或媒体访问。当前范围已由实际 macOS default Service、Node SQLite 和 Electron 开发制品验证，测试和剩余制品边界见 [Desktop owner](../../../../apps/desktop/README.md#native-files-检查点恢复)。正式 Native 已消费同一公共恢复能力；只读 Web 保持阅读入口。

通用 Native 已接入上述四类 Provider 的设置、手动模型名称与显式空名称发现，以及每个 Session 的下一次模型和临时思考选择。新模型先禁用，启用后才进入输入选择器；默认模型禁用门禁保留。活动 Run 的模型与档位保持原值，普通引导不携带新模型或档位。新 Session 首次输入才保存模型路由，冷启动保留原 Session 路由，临时档位回到服务配置。提供商保存仅显示简短成功或失败反馈，不展示历史提交结果。已发布后的刷新失败与写入未知分别处理；未知保留简短提示与原提交查询入口。完整行为见[模型与配置](../../features/models-and-configuration.md)，当前本机窗口证据与限制见[Native owner](../../../../apps/desktop/README.md#native-provider-与下一次模型选择)。

正式 Native 的 MCP 设置已接入来源、认证、连接与完整工具详情：先核当前会话，再明确选择范围、审查来源或已有凭据引用，连接与工具各自审批。当前macOS正式窗口已核两范围来源操作、连接与重连、完整工具正文、下一Model schema和一次效果。建立失败且可靠停止时，查询原申请可确认本次未建立，再独立新申请；原证据不完整仍未知，不自动重发。macOS默认Chrome和系统凭据库的登录、刷新、清除、撤销、取消登录及重启恢复组合已实际验收；测试使用本机自有认证服务，不承诺其他平台或任意外部服务兼容。本机局部设置方案已收束，实际行为、正式消费者与本轮完整回归范围由[Native owner](../../../../apps/desktop/README.md#native-mcp-完整设置)维护；完整平台与整体阶段门禁保留，上文旧客户端的 MCP 描述继续定义迁移预期。
