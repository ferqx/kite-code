# kite 桌面客户端（开发中）

侧栏空间行只显示名称；会话行显示标题，并在最右侧用旋转图形表示正在运行，用高亮圆角文字“待用户输入”表示等待回答、审批等交互，待输入优先于运行图形。空闲和正常完成不显示行内状态。会话数量、完整状态和更新时间在详情浮层中查看。浮层首次悬停 500 毫秒后出现；浮层出现后快速移到其他列表项会立即切换详情，移开一段时间再返回则重新等待。首次等待期间移开不会弹出。键盘聚焦也可查看，Escape 关闭。

桌面与 Web 共用会话主页面；可用操作按各端权限提供。桌面保留本地项目、任务输入、审批与执行控制，Web 当前只读。macOS 窗口采用沉浸式标题栏：同一个顶部 header 横跨侧栏和会话区，左段以更明确的背景层级放置侧栏收起图标，右段显示会话标题和操作；内容背景延伸到窗口顶边，原生交通灯、窗口拖拽及双击 header 缩放保持可用。窗口底层与页面使用相同背景色，快速拉伸时不应露出黑色空白。

Tauri 桌面客户端已完成首轮本机接入与原生验收，尚未作为正式入口发布。[首版计划](../../../plans/desktop-client.md)保留完整目标；当前不能据首版范围推导所有功能已可用。

后续已确认以 Codex 的客户端功能和日常交互体验为对标目标，具体差距与迭代入口见[日常体验方向](../../../plans/desktop-client.md#首轮验证后的日常体验方向)。这是后续研发目标，下文仍说明当前已交付行为。

桌面客户端产品名为 **kite**，**kite-code** 为 TUI 名称；两栏界面已使用 kite，原生窗口与安装包名称尚待统一。通用日常工作、shadcn/ui 界面及覆盖空间、会话、交互、结果、子代理、设置和恢复的整体目标稿见[界面与协作体验](../../../plans/kite-client-experience.md)，不据设计稿宣称这些能力已交付。

[完整工具消息结构与状态](../../../plans/kite-client-experience.md#会话消息与工具渲染)为已确认设计，尚未完整实现；当前可读内容和交互限制仍以下文为准。

[子会话下钻](../../../plans/kite-client-experience.md#子代理在消息与详情中的展示)为已确认设计，尚未实现：从主会话进入子任务，复用相同的消息与工具渲染，返回保留父会话阅读现场；不把子任务变成侧栏中的平级会话。

开发版可选择本地项目、确认工作区信任、配置 Provider 和选择模型、新建和查看最近会话、提交任务、读取文本与工具过程并取消执行。安装与运行方法见[开发入口](../../../../apps/kite-desktop/README.md)。

左栏保留已添加的项目，所有空间默认展开并自动读取会话列表；展开或收起只改变显示，不切换项目。顶部“工作台”按现有目录事实汇总正在推进和最近会话，不提供独立的“需要我处理”入口、分组或筛选页；等待回答、审批或恢复的会话仍按真实状态出现在最近会话中，点击条目直接进入原会话，不创建副本或改变执行状态。主题分类和时间筛选尚未接入，界面不从标题猜测分类。各空间的会话可展开或收起，不提供会话标题搜索。点击会话直接加载消息，无需二次确认；上下键移动列表焦点，Enter 打开会话。切换会话不停止当前任务，也不会发出新消息；首次发送正在创建会话时，已有空间和会话导航也不整体禁用，用户切换阅读目标不会改变该消息所属的新会话。目录在连接、新建和当前订阅运行结束时自动更新，已有会话行保持顺序；侧栏不再显示“切换项目”、“断开项目”和刷新按钮。返回已连接窗口只更新本地目录是否存在，不重新加载会话列表。未订阅的后台会话在刷新前仍可能滞后，不代表全会话实时监控。

用户主动添加或选择项目即授权 Agent 访问该工作区，不再追加“信任此项目？”确认；具体工具继续遵循执行授权。授权由 Service 保存，启动或普通重连不会自动授予新权限。需要访问工作区外的关联目录时，单独展示确切路径并确认；授权失败时保留输入并提供重试。会话内容按所属会话展示，输入草稿、阅读位置和过程展开状态在当前进程按项目与会话保留；退出后的恢复尚未提供。会话切换不取消原会话执行。助手正文支持统一排版的 Markdown 标题、段落、列表、代码块、引用与表格，正文不增加内边距或独立限宽，与消息阅读列同宽；明确类型的连续读取／搜索聚合为轻量摘要，进行中显示近期步骤，完成后默认折叠；失败数量保留，展开可查看明细和文件路径。独立工具输出按需展开；子代理摘要保留名称与结果，有明确父工具关系时显示在该工具下。独立子代理详情尚未提供。

Ctrl+A／Cmd+A 在会话页面只全选消息内容，在输入框中只全选当前输入。会话消息支持原生选词、拖选与复制，段落和列表行选区限制在内容范围。侧栏、标题、按钮、提示等非消息展示文字不可选中复制；输入框保留正常的选择、复制与编辑能力。会话消息和左栏分别滚动。首次进入显示最新消息；向上阅读后不再被流式更新拉到底部，可点击“回到最新消息”。输入框上方不展示独立状态信息，也不保留状态行空白；保留模型选择、项目／分支选择和发送／停止操作。输入框始终保留在下方，Enter 发送、Shift+Enter 换行；空白输入和加载期间不能发送。运行或等待交互时可以先写草稿，右侧主控变为停止；目前不能像 TUI 一样排队发送后续消息。停止提交后显示等待收尾，只有服务终态才显示已停止，已有修改保留。

左栏品牌下方的“新对话”与“工作台”使用同一组左对齐导航行样式，是与空间区域同级的全局入口；尚未打开项目也可以进入并写下需求。欢迎区的四个建议只追加可编辑草稿并聚焦，不发送；首次发送时才创建会话并进入正常消息流，重复点击入口不会创建空会话或清空草稿。准备草稿跨项目／分支选择保留，与已有会话草稿独立；切回历史会话恢复它原有的输入。发送失败后保留草稿和已创建会话，不重复创建。

空间标题右侧的“新对话”图标进入该项目的新对话准备页，不改变列表展开状态，也不提前创建空会话。选择其他执行项目时沿用现有项目切换流程，有活动任务会先确认停止。

输入框聚焦不增加额外边框，右下角没有手动调整尺寸的拖动柄；多行输入由内容撑开。发送与停止使用同一位置的图标按钮，悬停提示和可访问名称说明当前动作；停止提交期间保持禁用，避免重复请求。

输入框上沿可以选择已打开项目或添加本地目录，旁边显示“本地”和真实 Git 分支。选择项目或已有本地分支后立即生效；切换分支时有运行、排队或等待中的任务，或存在暂存、未暂存、未跟踪的改动，都会阻止切换。不会自动提交、丢弃修改或创建 worktree。非 Git 项目仍可发送，分离 HEAD 和尚无提交的仓库显示真实状态；只允许在仓库根目录切换分支。分支菜单可以刷新，失败或回执未知时检查刷新后的实际状态，不自动重试。

应用启动先显示独立启动页，完成本地服务连接、首屏空间会话目录及当前项目的准备检查后再显示主界面，不展示主界面逐项加载的过程。服务连接或首屏目录全部读取失败时，启动页显示原因并提供“重新尝试”；空目录可以正常进入，局部目录失败、项目失效或模型未配置不阻止进入主界面处理。启动页没有人为最短停留时间；进入主界面后发生断线仍保留页面与草稿，不重新遮挡为启动页。

应用重启会恢复已打开项目列表并自动读取应用历史，不创建会话或发送任务。项目目录失效、Git 不可用或模型配置错误不妨碍阅读已有历史，各自显示局部提示。发送前核对目录、信任和模型；普通资料文件夹无须 Git。本地服务的启动、连接与恢复由客户端内部负责，不提供重连或断开操作，内容页不展示连接中断或服务未就绪提示。内部恢复期间保留会话内容与草稿，仍可编辑，恢复就绪后才允许发送；操作结果未知仍会明确提示检查实际效果。未发送草稿不承诺应用重启后恢复。

关闭窗口保留应用与任务，再次激活显示原窗口；明确退出或实际切换执行项目会停止自有服务中的执行，已有修改不撤销。当前退出确认覆盖整个服务连接，尚未根据活动任务省略空闲提示。异常收尾会提示检查结果，不自动重发请求。连接断开后不能使用旧的就绪状态提交操作；回执丢失时显示“操作提交结果未知”，自动恢复后仍应检查会话及实际文件，再决定继续。

工具审批会显示具体命令与说明，可以选择“仅批准这一次”或拒绝；结果仍由服务核实。补充问题支持选项、允许的自由回答及明确取消。取消回答会把取消结果交给模型，模型仍可继续；结束整个执行应使用“停止任务”。计划面板显示正文与步骤，支持 Accept Edits/Auto 批准、修改要求及取消；正文缺失或超过显示上限时不能批准。扩展或验证交互仍显示限制，用户可取消。高级恢复尚未交付。

点击顶栏“文件变更”打开右侧副层，展开文件操作可阅读成功文件工具保存的差异或写入内容。关闭或 Esc 返回顶栏按钮，切换会话自动关闭；窄窗口副层覆盖部分阅读区，输入仍可用。这不是当前工作区 Git diff，也不覆盖 Shell/MCP 等工具未报告的逐文件修改。输出可能截断，空列表不代表磁盘没有变化。在设置中可选择 VS Code、Zed 或 TextEdit 打开当前项目内仍存在的文件；同一选择也用于消息中的路径链接和读取文件路径，默认 VS Code，在当前进程保留。打开的是当前磁盘内容，编辑器需已安装。本机 macOS 已确认 VS Code 实际打开对应文件；TextEdit 仅确认启动分发，Zed 未安装验证。

已有会话加载时显示进度，长历史分批读取后完整展示；每个空间的目录独立分页，可继续加载更早会话，一个空间失败不清空其他空间。点击其他空间的会话直接阅读，不停止原任务；只有实际向其他项目发送时才切换执行项目，有活动任务会先确认停止。本地目录不存在时，空间名称变浅，仍可打开会话，不常驻提示目录关联情况。同一执行项目下继续会话不额外做目录预检，能否执行由服务的实际条件决定；需要切换或重新准备执行项目时仍核对目录与授权。自动重接恢复所选会话和进程内草稿，不重发任务。

点击左栏“模型与 Provider 设置”或输入区模型名称可保存 OpenAI、DeepSeek、OpenAI-compatible 或 Ollama 配置。API key 随本机用户 kite-code.jsonc 保存，输入在提交后清空；保存会替换同一 Provider 的配置。模型名称留空时查询模型列表，手动填写时直接保存，是否可执行仍需实际任务验证。保存后点击模型，即使它已选中，也会刷新后续执行使用的配置。提交结果未知时应检查最新配置，不自动重试。

本机 macOS 已完成配置、问题/计划、项目与会话草稿、修改与测试、结果阅读、VS Code 跳转和重启后继续的原生验收；真实外部 Provider 的服务执行另行验证。另已验证长会话阅读、与 TUI 的同会话写入保护、服务制品损坏提示，以及手动替换应用后的会话和数据保留。桌面端仍是开发版本；正式签名、公证、下载分发与签名包升级、其他平台尚未完成资格验证。包内 Service 已验证自身 MCP OAuth 凭据的原生保存和重启恢复；从其他程序导入已有凭据的系统授权行为未完成验收，不承诺无提示迁移。

本次两栏界面通过真实服务回归、DOM 交互测试与浏览器布局检查；系统中文输入法和新版 Tauri 窗口仍需单独验收。验证范围见[两栏会话界面](../../../../apps/kite-desktop/docs/conversation-ui.md)。

设置中的 MCP 分类显示配置来源、连接与认证状态，可展开连接详情；按实际状态开始／取消认证或重新连接。操作完成后查看最新状态，浏览器认证完成后点击刷新；结果未知时不自动重试。Skills 分类展示当前项目可发现的名称、描述、来源与可用状态，没有安装入口。此功能不改变 Web 的只读权限。

页面完整刷新后，若原项目服务仍在运行，应用自动接回服务、恢复原会话并继续读取任务状态，无需重新添加项目或确认清理，也不停止原任务。普通界面热更新保留客户端连接；完整刷新不保证保留未发送草稿。应用或服务真正退出后的恢复不自动重放已停止的任务。

客户端启动以 300ms 内完成本地连接和首屏目录为优化目标；目录无需先恢复所有历史或准备模型。当前本机原生服务至目录的分段测量已低于该预算，完整系统启动至 Tauri 窗口绘制的端到端资格尚未确认，测量条件与负载限制见[启动说明](../../../../apps/kite-desktop/docs/history-and-recovery.md#启动预算与验证边界)。
