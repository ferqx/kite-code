# 阅读会话内容

History 展示用户消息、模型回答及可展示的工具生命周期。会话页面与桌面端共用布局与阅读交互，数据仍以 Web 接口允许的内容为准。助手回答支持统一排版的 Markdown 标题、段落、列表、代码、引用和表格，正文不增加内边距或独立限宽，与消息阅读列同宽；工具详情按需展开，普通用户与助手正文不重复显示角色标签。相对文件路径只展示文字，Web 不启动本地编辑器。

[完整工具消息结构与状态](../../../../plans/kite-client-experience.md#会话消息与工具渲染)为已确认设计，尚未完整实现；Web 继续只读，不因共享设计获得未提供的数据或执行操作。

## 工具状态

同一次工具调用从等待、开始到终态应更新同一个展示项。完成后不能残留另一张 loading 卡。终态没有再次提供名称时，沿用此前已知的真实工具名称，不凭空补一个执行结果。

执行前 `rejected` 以拒绝提示说明原因，不显示不存在的退出码或 `No output`。执行后 `failed` 与拒绝不同，可能需要核实部分副作用。取消也不能被当成成功。

Ctrl+A／Cmd+A 只全选当前会话的可见消息内容，不跨到页面其他区域。消息正文可选中复制；侧栏、标题、按钮等其他展示文字不可选中。段落与列表项的选区限制在内容范围。消息区独立滚动，首次进入显示最新内容；向上阅读时不被新增消息拉回底部，可点击“回到最新消息”。在当前页面内切换会话后返回，恢复阅读位置和展开项；重新加载或离开页面后不承诺保留。

## 历史与更新

查看运行中会话时，内容可能按[更新规则](updates-and-connection.md)继续增加。终态会话不会因为页面停留就不断刷新所有诊断。

历史展示受当前接口允许的字段和内容范围约束，不包含全部内部数据。模型思考的瞬时展示不保证能在 Web 重现；不要用 Web 与 TUI 画面不同判断会话数据丢失。

需要诊断事件时进入[日志](logs.md)，需要某次模型实际输入时进入[上下文检查](model-context.md)。
