# 查看 Runtime logs

通用 Agent V1.3 的[新开发观察入口](../../../../../apps/web/README.md#按需-runtime-logs)现提供所选会话的按需 Runtime logs、固定上界分页和准确 Model 输入导航。正式旧 Web 的启动入口尚未切换，分层真实资格见[实施进度](../../../../plans/unified-agent-refactor-v1-progress.md)。

先选择会话，再切换到 Runtime logs。日志按需读取，使用显式刷新取得后续内容，不与 History 共用自动更新承诺。

日志展示事件类型、顺序、时间、类别、状态、摘要及允许的详情字段。展开条目查看键值说明；它不是原始数据库事件转储，也不是无限分页的全部日志备份。

## 如何排查

先根据会话状态找对应时间和顺序，再展开错误或模型调用相关条目。工具拒绝与执行失败分别判断，不只看是否出现错误颜色。

`model.invocation_prepared` 的可用条目可以进入该次模型上下文检查。普通日志摘要不能代替完整模型输入；详见[Model Context](model-context.md)。

刷新失败时保留已读内容并处理连接问题。当前没有日志编辑、删除、重放执行或从日志直接发起审批的操作。对外分享前仍需检查内容是否包含敏感项目资料。

新开发面板刷新失败时保留已经读取的同会话内容，并同时显示 stale 和错误。时间或状态未记录时明确显示未知，不用当前状态补历史。超过实际保留边界会显示 cursor_expired，不自动换起点；切换、隐藏、关闭或取消读取会释放所属 GET，不取消会话执行。

## 开发入口的观察范围

打开或刷新读取首个最多 200 条页面，Load more 明确读取后续同一上界。面板最多保存 1000 条、2MiB UTF-8 metadata；达到上限显示未读完，不冒充完整日志备份。显式刷新重新读取当前首页面，成功替换旧观察，失败仍保留旧完整内容。事件 payload、原请求、配置、凭据和内部 owner 不进入日志详情。

仅实际原 Model 绑定仍可核实的条目提供输入导航；打开后仍需确认才读取敏感原文。普通 Tool、旧 metadata 或绑定漂移的条目不获得 Model 链接，读取日志不会发起审批、恢复、模型调用或业务重放。源码层、公共 HTTP/SDK/Cookie 和 DOM 分别验证，不把本机证据外推正式 launcher 或其他平台。
