# 运行与继续任务

## 新任务

使用 `run --task "任务"`，也可提供位置任务文字。未指定 `--thread` 时，新运行产生新会话标识；需要后续继续时保存事件中的标识。

`--workspace` 明确工作区。没有信任时，先进入 TUI 确认，或在已理解范围的前提下使用 `--trust-workspace`。权限模式可选择 `--ask`、`--auto`、`--full` 之一，不能同时提供多个。

## 输出和交互

CLI 输出运行事件。审批、问题、方案审核或其他交互可能要求从 stdin 回答；非交互环境不能假定默认回答已经提交。

读取最终状态，区分完成、失败、取消、阻塞和未知。事件输出或进程结束不应被脚本一概当成任务成功。强行结束客户端也不等于回滚工具的副作用。

## 继续

```sh
bun run agent resume --thread <会话标识> --workspace . --task "根据上次结果继续检查"
```

resume 必须有任务文字，不能只提供会话标识期待自动重放。它基于已有会话开始下一次执行，不恢复代码到旧节点。

已有 JSONL trace 可使用 `trace` 读取，不因此启动新任务。参数详见[参考](commands.md)。

## 当前未知结果的退出限制

当前 CLI 在收到未知结果或 recovery_required 后，可能已经输出诊断却继续等待。没有退出不一定表示任务仍在执行，也不能据此重复提交任务。先保留会话标识和最后的恢复提示，核实外部结果；这项退出行为尚未修复。
