# 客户端设计规范

适用范围：kite 桌面与 Web 的共享视觉语言，以及对应 Figma 设计。布局继续采用[已确认方案](../../../docs/plans/kite-client-experience.md)；图像生成的探索稿不替代当前 Figma，不作为实施依据。Web 的只读权限、桌面的执行权限仍由端侧决定，本规范不增加功能或授权。

本文维护视觉规则；共享组件和 Figma 主组件负责承载规则。下列数值是设计基准，不代表当前代码已经全部符合。当前实现与验证见[共享 UI 入口](../README.md)和[桌面会话界面](../../../apps/kite-desktop/docs/conversation-ui.md)。发现偏差时修正所属组件，不用页面覆盖样式重新定义一套规则。

## 信息层级

- Agent 正文是主内容。导航、工具过程、进度和资料副层保持次级，不用密集卡片、分支线或大面积状态色争夺注意力。
- 同一事实只展示一次。运行状态不在标题、正文、进度条和输入框重复堆叠；子 Agent 的消息归属及交接状态沿产品方案处理。
- 优先用间距、排版与对齐建立层级，其次使用浅底色；框线只用于必要边界。消息正文不逐条套卡片。
- 选中、悬停、键盘焦点和运行是不同状态。会话选中使用浅底纹，不增加左侧竖线；运行状态不能冒充键盘焦点。

## 间距与布局

Figma 使用现有 `Kite Layout` 变量。通用间距仅使用 `0、4、8、12、16、24、32、48 px`；会话输入区距场景底部统一为 `24 px`。不得为单页新增近似值。

| 关系 | 基准 |
| --- | --- |
| 工作台双行条目的标题与元信息 | 4 px；两行共享同一左边缘 |
| 图标与文字、相邻紧凑操作 | 8 px |
| 控件组之间、标题与说明 | 12 px |
| 正文块、消息内内容组 | 16 px |
| 不同内容段或主要区域 | 24 px；更大的阅读留白使用 32／48 px |
| 标准操作按钮、图标按钮 | 本体高 32 px；图标按钮宽 32 px |
| 新会话建议卡片 | 保留 112 px 高内容入口、16 px 内边距；它属于卡片式入口，不按单行操作按钮压缩 |
| 空间／会话行 | 单行标题，最小高 32 px；运行 Spinner 或“待用户输入”Badge 位于会话行最右，其他状态和时间放入延迟详情浮层 |
| 空间行与所属会话列表 | 4 px；由会话列表滚动容器的顶部内边距提供，不再叠加外边距 |
| 客户端外壳 | 左栏／中栏／按需右栏为全高同级 Resizable 面板；每栏标题区高 52 px |
| 左侧导航栏 | 默认采用 200 px 最小宽度，可调整至 420 px；窗口缩放时保持当前像素宽度，由中栏及已展开的右栏适应剩余空间；用户拖拽后的宽度在本机保存 |
| 中间页面栏 | 占据剩余空间，最小宽 360 px |
| 最右侧通用栏 | 默认宽 380 px，可调整至 300–640 px |
| 会话环境信息卡 | 宽窗口以 300 CSS px 宽度固定（2 倍显示比例的截图约 600 像素）在会话右上角；卡片展开时消息阅读列与 Composer 最大宽度从默认 844 px 收敛为 720 px，并保留 344 px 右侧安全区，但会话滚动容器继续占满中栏，使滚动条保持在最右侧；卡片隐藏后恢复默认阅读宽度。并排所需宽度按 `720 px 阅读列 + 344 px 卡片安全区 + 28 px 左侧内边距 = 1092 px` 计算，会话可用宽度低于 1092 px 时自动收起，内容过高时卡片内部滚动 |
| 账户区 | 用户按钮高 36 px，头像 20 px，内边距 4 px，图文间距 6 px；按钮与区域上下左右均保留 8 px 间距，侧栏本身不再叠加底部留白；区域顶部用横跨侧栏整宽的 1 px 边框与空间列表分隔；用户按钮只保留单行“个人工作区”文案 |
| Composer | 单行草稿最小高 112 px，textarea 基础高 52 px；采用纵向 Flex，底部操作栏用剩余空间推至底边；内边距为上 10 px、左右 12 px、下 4 px；模型与权限选择器高 26 px、内边距 2×6 px、图文间距 4 px。发送／停止按钮为 26×26 px 圆形按钮并与两者共用垂直基线；两种动作共用一个主控位且互斥，运行中无草稿或正在停止时显示停止按钮，输入运行中引导后切换为发送按钮 |
| 未缓存会话加载 | 保持消息区原尺寸，中央显示 48 px 无底色、低对比度风筝图标，以透明度和阴影做轻微闪光且支持 reduced motion；不显示加载文字或欢迎区，完成后直接渲染正文 |

Composer 发送图标使用带竖杆的向上箭头；消息准备与提交期间，同一圆形主控显示 loading 图标并禁用重复提交，服务确认后按运行状态切换。发送失败或结果待确认时停止旋转；减少动态效果偏好下保留静态忙碌图标。

Composer 整张卡片的非交互空白都属于提示词输入的聚焦区域，包括模型与权限选择器所在底栏的空白；点击选择器或发送／停止按钮本身时保留各自操作，不将焦点强制转给 textarea。

Composer 底栏在当前会话已观测到提示缓存 token 时，以辅助文字显示整数缓存命中率，按 `cacheHitTokens / (cacheHitTokens + cacheMissTokens)` 计算；没有样本或样本总数为 0 时不显示，不伪造 `0%`。切换会话时只展示目标会话指标，历史重读从已保存的 `model.cache` 事件重建累计值。

账户入口默认使用透明背景，与侧栏形成同一表面；悬停时再使用侧栏浅底纹反馈，不常驻白色卡片。

全局“新对话”与“工作台”属于同一组主导航行：使用相同高度、内边距、图文间距和悬停反馈，图标与文字均左对齐；客户端界面图标统一使用 Hugeicons，不维护页面专用 SVG asset，16 px 导航图标使用约 1.5 px 的轻量描边，避免单个入口显得更重；不把“新对话”单独绘制成居中的强调按钮。品牌图形、内容图片及纯 CSS 状态标记不属于界面图标。

有关联的子项必须由 Auto Layout／Flex／Grid 管理。单行文字按钮随标签加宽；图标按钮保持正方形。禁止用固定宽度文字层填满按钮，也禁止靠空格、换行、负坐标或逐页位移补对齐。

空间名称与右侧新对话按钮共用一个列表项容器，悬停背景覆盖整行及两者之间的间距；内部按钮不再绘制分开的悬停底色。空间展开时使用打开文件夹图标，收起时使用关闭文件夹图标；展开与新对话仍是独立的点击和键盘焦点目标。列表默认只保留名称；详情浮层首次悬停 500 ms 后显示，快速连续移入其他项时立即切换，延迟复用规则见共享 UI owner。

会话消息列表和侧栏列表分别承担滚动，内容增多不能挤走 Composer 或账户入口。所有列表型滚动区域（包括会话消息列表）统一使用 shadcn ScrollArea 及同一滚动条样式，不由页面各自设置原生滚动条；单条消息内部的代码、表格、命令输出和 diff 内容溢出不属于列表滚动，但其原生滚动条复用相同颜色 token。只有工具消息内可滚动的输出和文件差异使用 shadcn `scroll-fade` 渐隐提示；会话消息视口与普通消息内容不使用。浅色主题 Thumb 为 `#B8B8B8`、Hover 为 `#999999`，深色主题为 `#62665B`／`#7A7F72`，轨道透明。Figma 中滚动内容可超出滚动视口；按钮、文字列和非滚动容器不得无意越界。标题与说明组随内容增高，不用固定高度裁切行高。

页面级辅助内容统一进入与左栏、中栏同级且全客户端高度的最右侧通用栏，不各自创建浮层外壳。三栏由 shadcn Resizable 分隔，相邻宽度可拖拽；普通内容使用标题栏，会话详情使用 shadcn Tabs；标签只对应已有产品事实，不为未来能力预留空标签。关闭按钮始终位于标题栏右侧，内容区独立滚动。桌面端左侧导航和最右侧通用栏收起、展开时，面板实际宽度和相邻拖拽分隔线使用 180 ms ease-out 过渡；面板持续挂载，以便重新展开时恢复用户最近拖拽的宽度，折叠期间不可聚焦或操作。减少动态效果偏好下立即切换。会话环境信息卡由顶栏右侧图标按钮显隐，默认展开，并明确区分关闭、停靠展开与浮层展开三态。停靠卡随会话实际可用宽度低于 1092 px 自动收起，恢复宽度后保持关闭，不自动重开；宽度不足时用户仍可点击按钮，以不占右侧安全区的右上角浮层临时查看，浮层打开期间宽度恢复则转为停靠展开。停靠展开时消息正文和 Composer 通过右侧安全区避让卡片，但会话 ScrollArea 本身保持全宽，滚动条仍贴中栏最右侧。手动或自动收起均使用 160–180 ms 的淡出、向右轻微缩合及安全区释放过渡，展开时反向执行；减少动态效果偏好下立即切换。除用户主动打开的窄宽浮层外，卡片不得遮挡消息、工具输出、交互控件或 Composer，也不得把主滚动条移到卡片左侧。

侧栏宽度动画期间，内部内容保持该侧栏的最小展开宽度并由外层裁切，不随动画中的瞬时宽度换行或重排。中间会话栏则相反：从 Resizable 内容面板、会话视图、ScrollArea viewport 及其内部包装层到消息阅读列都必须允许 `min-width: 0` 并占满当前可用宽度，使消息正文随左右栏动画实时重新排版，不保留旧容器宽度或产生横向溢出。环境信息卡的显示偏好属于会话页面实例而不是单个会话，切换会话时保持同一显示或隐藏状态。

安排任务编辑器参考紧凑侧栏表单：标题使用无边框的大号输入，任务说明使用单独的圆角文本区，项目／运行环境和频率分别进入带边框的纵向分组行；正文独立滚动，操作栏固定在面板底部。只映射 Kite 已有字段，不复制参考产品的通知、设备或新聊天语义。右栏使用卡片背景覆盖全高，拖拽命中区通过分隔线伪元素扩展，不用透明 padding 留出可见空白。

新会话的工作区、环境和分支处于同一上下文栏：三项高 32 px、垂直居中、项间距 12 px、图文间距 8 px。栏宽比 Composer 两侧各缩进 16 px，贴合输入框上沿；这一组合内部允许 8 px 的衔接重叠，不把负间距用作普通对齐手段。工作区与分支默认透明，无下拉箭头或常驻独立灰块。菜单锚定各自触发按钮，名称变化后仍保持左对齐。

## 排版与对齐

界面控件继续使用现有中文／系统字体与 Inter fallback；Agent Markdown 正文和标题使用 Geist Variable，代码使用 Geist Mono Variable，由两端 Tailwind 入口加载同一 shadcn/typeset preset。一个控件内的标签使用同一字体与字重，不能用不同字体的字符拼出图标。

| 用途 | 字号／行高 | 字重与约束 |
| --- | --- | --- |
| 元信息、辅助说明 | 12／18 px | Regular；不可再缩小来容纳长文本 |
| 工作台条目标题、紧凑标签 | 12／18 px | Medium；与元信息左对齐 |
| 空间、会话列表项 | 14／20 px | Regular；空间与会话使用相同默认字重 |
| 主导航、按钮、上下文控件 | 14／20 px | Regular 或 Medium，按同一组件统一 |
| 会话环境信息卡 | 14／20 px | 与左侧导航统一；卡片标题、分组标题、执行项和空状态不得另设更大字号，卡片内文案使用 Regular 字重，以辅助文字色区分层级 |
| 消息正文 | 14／约 22 px | Geist Regular；Typeset `1.6` 行高，段落自然换行；不增加 padding 或独立限宽，与阅读列同宽 |
| Composer 输入 | 14 px／字体正常行高 | Regular；多行输入按内容增高；原生 textarea 不设固定 24 px 行高，避免空白行光标变高 |
| 区域标题 | 18／28 px | Medium |
| 页面标题 | 24／32 px | Medium |
| 新会话欢迎标题 | 28／40 px | Regular；不得扩展成营销式大标题 |
| 代码与行号 | 13／22 px | 等宽字体；代码与行号使用相同行高 |

普通业务文字必须设置显式行高，不使用 `AUTO`。同一阅读列的标题、段落、文件链接、过程摘要与 Composer 共享布局基准；消息角色的差别不能靠随意横移正文表达。横排的同类文字按基线对齐，图文按钮按行盒垂直居中；不能逐个用 `top: 1px` 修补。

紧凑导航、文件名与元信息单行省略，保留完整名称供详情、复制或可访问名称使用；正文和待审批命令自然换行。不可通过压低字号、压缩行高或裁掉末行消除溢出。长名称必须连同相邻图标、状态与按钮一起验收。

## 会话消息结构

工具种类、数据归属与状态语义见[完整工具消息设计](../../../docs/plans/kite-client-experience.md#会话消息与工具渲染)。下列规则只定义呈现，不让 UI 根据工具名称重新决定执行权限或展示分类。

具有准确 `turnId` 的 Agent 消息组成一轮：轮次状态行位于过程顶部；运行时过程默认展开，轮次完成、失败、取消或中断时过程切换为默认折叠，已确认的最终回复始终在折叠块外。中断前已有但未确认完成的正文保留在过程内，不以最后一段正文推测结论。直接回复无过程可展开时仍有静态状态行；可靠终态耗时显示“用时 …”，缺少可靠时间时显示“已完成”。可展开状态行由常规字重的状态或可靠耗时和始终可见、紧邻文字的箭头组成，使用工具消息标题的 32 px 高度，悬停背景保持透明，不使用前置状态图标，也不展示工具异常汇总或折叠操作文案；具体异常留在工具消息内。过程包含阶段说明和工具活动；结束后用户可手动重新展开，工具进度不改变主动选择。失败、取消、等待和需要恢复显示各自状态，无正文的取消也保留状态行。同一精确 Turn 的两端之间若夹有无身份的非用户消息，过程保持原顺序和单一折叠入口；用户消息阻断该合并。轮次从空状态进入首条可见消息时保留折叠按钮 DOM 焦点。没有准确轮次身份的 Web History 继续按原顺序平铺，不用相邻顺序推断一轮。原始 reasoning 正文不渲染为消息；活动思考且没有正在执行的工具时，轮次状态行显示“正在思考”，并附可靠的已处理时长。一般运行态显示“已处理 …”，成功结束后显示“用时 …”，时长跨越分、小时、天时切换单位；只有可靠 Turn 事件时间才展示耗时。

- 主 Agent 正文保持完整阅读列。主会话中的子 Agent 只展示工具消息；父 task 展开后显示所属工具步骤，不常驻子 Agent 的过程正文或结果段落。独立子会话下钻仍属后续设计，不借本次渲染调整开放。
- 会话顶部留白 24 px；普通消息间距 16 px，用户消息／助手最终回复后保留 32 px（容纳 20 px 悬浮复制按钮）。助手非最终正文后保留 8 px，与后续工具衔接；最终性使用 Runtime 的 `finalReply`，不以 `settled` 推断。工具上下外距仍为 8 px；工具记录到非最终正文为 8 px，到最终回复为 16 px；状态分隔线到下方首条可见消息均留 16 px（展开时为过程消息，折叠时为最终回复）；过程底部仅在同轮有已确认最终回复时绘制分隔线；轮次过程与最终回复的间距由外层统一承担，不展示思考内容。工具摘要与聚合子项统一为 24 px 行高、上下各 4 px 内距，避免不同工具的基线和行距跳动；输出／diff 与摘要间隔 4 px、底部间隔 8 px。
- 工具与正文共享 `--conversation-text-size`（常规 14 px、窄窗口 15.75 px），命令和文件名不另缩字号，工具图标为 1em；子 Agent 使用 Bot 图标。工具消息上下外距各 8 px，图标与文字间隔 8 px，单行最小高 32 px。读取／搜索保留 Runtime 明确分组；展开子项图标与标题图标左对齐，组内不额外缩进或叠加标题间距。
- 工具摘要与子 Agent 下的工具步骤使用共享 Marker 的图标和内容槽；上下文压缩使用 Marker 的 separator 变体。工具聚合默认折叠，执行中把当前工具动作与目标写在摘要行，只有实际 `running` 的工具计入“正在执行”数量，摘要标题变化使用礼貌播报；进度和终态不自动更改展开状态。工具行始终占一行；长命令、路径与失败摘要在可用宽度内省略，完整失败摘要保留在悬停提示中，展开的输出和差异仍按内容展示。
- 工具详情使用共享 Collapsible 展开和收起，用户在当前会话中主动操作时内容只做短暂高度过渡；切换会话后恢复已展开状态时直接呈现最终高度，不重播展开动画。系统要求减少动态效果时所有展开与收起都直接切换。
- 已取消工具直接显示“已停止”状态，不把事件的固定英文取消摘要重复当作结果预览；Shell 展开后仍保留实际收到的输出。
- 工具文字和图标默认使用辅助文本色（浅色为 #666）；hover 整行一起高亮，无背景色；工具与 Ask 标题展开后持续使用同一主文字色高亮，收起后恢复辅助文本色。文件 diff 展开时标题及箭头同步高亮。只有实际可打开的文件名在自身 hover／键盘焦点时显示下划线和点击反馈，其他区域不伪装文件链接。读取文件不展开内容，失败仅在同一行显示状态，不额外输出原始错误段落；审批原因仍保留。修改通过独立箭头展开工具报告的 diff，文件名仍交给宿主打开。
- Shell 摘要为终端图标、“运行”及真实命令，点击摘要展开输出，包括聚合内部的 Shell；其展开状态独立保留，收起聚合后再打开不丢失。只有一个浅底、8 px 圆角容器，无额外标题栏或嵌套输出框；总高最多 320 px，日志区最多 256 px，顶部与左右内距 16 px、底部预留 48 px，结果以 12／18 px 绝对定位在底部左侧。内部滚动只跟随仍在底部的读者，手动上滚后提供“回到最新输出”。空输出、失败、取消与未执行按真实回执区分；停止后保留已收到的输出及批准来源。
- Shell 结果前的小圆点按真实工具状态着色：成功为绿色、运行中为提示色、失败或拒绝为错误色；取消、等待及未知结果保持中性色。状态文字与退出码仍直接说明结果，颜色不单独承担含义。
- 运行中工具文字使用 2.8 秒扫光，不改变布局；系统要求减少动态效果时恢复静态文本。等待人工审批使用中性色，审批原因只展示服务端提供的一段文本，不由 UI 编造建议。
- 人工审批复用分体按钮：主按钮“仅批准这一次”，右侧箭头的菜单只含“批准本次及本会话相同命令”，选择即提交；只有宿主明确提供 same_command 时显示此入口。左侧按钮为“拒绝”，无额外授权范围说明。控件在提交期间沿用宿主 disabled 状态，不模拟授权结果。
- 活动 Ask 和审批位于原底部操作区，处理完移除活动控件；Ask 回执按轻量工具行展开已记录的问题／回答。上下文压缩用细分隔线和居中文字呈现进行中、完成或失败，失败原因在下方显示，不另套卡片。
- 普通结果自然换行，代码、命令输出和差异保留等宽排版及内部滚动；源内容限制与用户折叠分别说明。通用工具沿用已提供的安全标题、状态和结果，不新增参数 JSON 面板，也不从缺失字段推测执行事实。

验收同时包含整轮会话组合、各工具的展开结果、终态与非终态、空结果、长路径、长代码和不支持预览的内容。工具消息的完整性不能由一个通用 JSON 文本框或一张正常状态图证明。

## 图标与操作状态

Desktop 与 Web 的控件优先使用共享 shadcn 组件，并优先通过已有 variant、组合结构和语义颜色完成设计；共享样式让所有可操作的按钮显示手型指针，禁用按钮不显示手型；不得以页面私有 CSS 或原生控件复制公共 Button、表单、菜单、弹窗、标签页、提示、滚动与分栏能力。确需专用业务组件时也必须组合共享 primitive，并把跨端可复用部分留在 `kite-client-ui`。组件选择、接入例外和验证门槛见[共享 UI 基础控件规范](../README.md#基础控件)。

使用 HugeIcons 图标及 shadcn 组件；从 Figma 导出的专用图形继续使用随设计交付的本地 SVG。图标视口统一为 16×16 px；停止符号为视口内约 12×12 px 的实心方形。侧栏运行会话使用 16×16 px 旋转图形；需要回答或审批时改用高亮圆角 Badge 文案“待用户输入”，不同时显示运行图形。更多、发送、停止、展开、完成等图形不得使用 `•••`、`■`、`▶`、`✓` 等文字字符替代。状态说明和命令文本仍正常使用文字。

输入区的模型触发按钮只显示当前模型名称，不附带 Provider；菜单仍按 Provider 分组，并用完整 Provider 与模型名称标记当前项；当前模型暂不在目录时仍显示其名称。权限触发按钮使用共享 `Button` 的 `ghost` 变体，常态背景透明，悬停和键盘聚焦时与模型按钮共用辅助背景色；并显示当前模式图标和名称；上弹菜单先说明本次选择的作用，再以图标、标题和一句审批行为描述排列 Ask、Auto、Full；Full 前用共享分隔线提示风险级别变化，文案按系统语言显示中文或英文。共享下拉菜单的单选与多选标记统一使用消息复制成功时的 `Tick02Icon`；模型、权限、项目和分支的当前项标记位于选项右侧。Full 选项图标与文字、已选 Full 的触发按钮图标与文字、共享 `AlertDialog` 标题均使用警示色，确认按钮使用共享危险操作变体，公共按钮明确移除浏览器默认边框，危险操作色与页面警示色共用变量；每次从其他权限切换到 Full 前，使用共享 `AlertDialog` 以正文说明无需逐项征得同意及当前环境允许的命令、文件和联网操作，再用单一警示区提示文件被覆盖或删除、敏感数据传输等后果；补充可切回其他审批方式及系统限制，取消不提交，明确确认后才切换；点击当前已选中的 Full 不重复弹窗或提交。权限提交期间立即显示所选模式并保留静态下拉箭头，不显示旋转 loading，禁用触发按钮并保持布局和不透明度稳定；切换会话的短暂加载期间同样保持权限按钮不透明，加载完成后才更新目标模式；失败时恢复服务端确认的模式。

Composer 右侧只有一个会话级主控，所有状态占据同一个 32×32 px 位置：

| 会话状态 | 图形与可用性 | 可访问名称／反馈 |
| --- | --- | --- |
| 空闲、草稿为空 | 向上箭头，Disabled | 发送消息；不能提交 |
| 空闲、有可发送草稿 | 向上箭头，可用 | 发送消息 |
| 执行中 | 实心方形，可用 | 停止任务；允许先编辑补充草稿 |
| 等待局部审批或回答 | 实心方形，可用 | 停止任务；审批／回答仍在对应消息中处理 |
| 已请求停止、等待终态 | 等待图形，Disabled | 正在停止；防止重复请求，不提前显示已停止 |
| 已取得停止终态 | 回到向上箭头，按草稿决定是否可用 | 已停止在消息或状态位置说明 |
| 连接不可用／提交结果未知 | 禁止不合法操作，控件位置不跳动 | 在状态位置解释原因和恢复入口 |

发送和停止使用图标按钮，不在按钮中直接写“发送”或“停止”，不在旁边再放重复按钮。图标按钮必须有准确的可访问名称；悬停／键盘焦点可显示同义提示。无可访问名称的纯图标不是完成态。

Default、Hover、Focused、Disabled 使用所属基础组件的状态，尺寸、内边距和图标位置不得变化。键盘焦点独立使用清晰的主题 focus ring；不能把永久粗边框当焦点。关闭菜单、面板或详情后焦点返回触发入口。触屏与系统窗口控件的点击区域需单独适配，不把桌面 32 px 本体尺寸当作所有平台的触控结论。

## 验收与变更归属

每次视觉迭代至少核对主会话、资料副层打开后的窄阅读列、新会话空输入、运行中四种实际画面。控件状态变更还须覆盖可用、禁用、焦点与等待回执，不用一张组件截图代替业务验收。

1. 以 100% 比例检查文本基线、图标中心、按钮边界、组间距与最后一行；全页缩略图只能检查总体布局。
2. 结构检查同时覆盖子节点与父容器，不能只检查画板顶层。区分有意滚动／菜单浮层与无意越界。
3. 检查长名称、多行输入、长回复及打开面板时的重新布局；消息滚动不得带走输入框。
4. 检查发送／停止图形、资格、服务终态、焦点返回，以及中文输入法组合期间的 Enter；图形改变不能改变业务语义。
5. 检查主组件变更是否被实例覆盖阻断；不得只修改组件源就宣称所有业务画面已同步。
6. 图像生成样例只帮助讨论风格；Figma 尺寸／结构与真实客户端渲染、键盘、滚动证据分别验收。

Figma 验收不能替代实际应用验证；文档检查不能证明视觉正确。新增例外必须说明场景和所属组件，优先复用现有 token／组件，不建立页面专属的近似规范。

Ask 历史保留唯一可展开工具记录：单题标题展示“询问用户”和问题，内容为“回答：”及答案；多题标题展示“询问用户 · 已回答 N 项”，明细带有序前缀，每项按“问题：回答”展示。取消后内容只显示“已取消”。内容与标题文字对齐，换行对齐前缀后的正文，每项最多 5 行，超出截断，连续字符自动换行。仍按 toolCallId 去除重复工具记录，不展示结果 JSON。

Shell 终态 totalLines 大于 stdout/stderr 实际展示行数时，底部状态追加“输出已截断”，不将截断误认为执行失败；工具 exhausted 限制提示独立保留。仅在自动审批仍处于 reviewing、工具已取消且没有执行进度或回执时说明“任务在自动审批期间停止，命令未开始执行”，底部显示“未执行”；执行后的取消保留实际输出与停止状态。

可展开工具消息的箭头紧贴标题内容（6 px），位于状态文字之前；收起时仅悬停图标与文字组成的紧凑标题区或键盘聚焦时显示，展开后持续显示。文件修改的文件名与 diff 按钮保持独立操作；不可展开的读取不显示箭头。轮次过程使用独立折叠入口，思考正文不提供展开入口。

会话折叠箭头统一复用同一个向下图标，通过旋转从收起的 -90° 过渡至展开的 0°；轮次过程、Ask、聚合、文件 diff、Shell 和子 Agent 均使用 120 ms ease，与现有上下文入口箭头速率一致。轮次过程与工具详情复用动画折叠内容组件，展开为 300 ms，收起为 240 ms；减少动态效果偏好下关闭过渡与内容动画，不更改展开状态。

活动 Turn 的轮次标题可显示“正在思考”；思考结束后恢复轮次状态标题。当前共享组件不显示思考正文或分段计时，也不根据客户端接收时间推断整轮耗时。由宿主传入持久起点时，活动轮次可显示递增耗时；起点和终点都有持久事件时间时，完成态固定显示本轮耗时，缺失或倒序时隐藏。

暗色三栏背景：左侧导航使用 `#242424`，会话主区（含顶栏）和最右侧详情栏使用 `#191919`。页面背景由 `--page-background` 管理，卡片、输入框及浮层继续使用独立的 `--card`，亮色背景保持原值。

暗色普通边框与分隔线使用白色 8% 透明度，header 下边框与左右栏分隔线遵循同一颜色；输入控件边界使用白色 18% 透明度。透明度只作用于边框颜色，与所在表面自然混合，不降低整个组件或文字的不透明度。亮色边框及错误、危险状态边界保持原规则。
