# Additional input Store owner

Closed public command kinds are `input.steer` and `input.follow_up`. Steer requires text or valid image/file attachments, exact targetRunId and current contextSelectionId. Follow-up requires text or valid image/file attachments, exact afterRunId (null only without a current Run), current contextSelectionId and optional modelId/reasoningEffort. Inputs belong to the public root Session; original subject is checked from the actual Session creator and steer Run command. Child public input is rejected rather than granting a second group authority. Bodies reject unexpected keys; each nonblank content is bounded at 1 MiB and never silently truncated. There is no old eight-input queue threshold.

Admission preserves command ID, request digest and server sequence. Steer inherits its original Run rootWorkCommandId/seq and cannot drift to a newer Run. The public follow-up remains the immutable input command and creates its own ordinary Run; local cancellation of the preceding Run does not expand to that new intent, while root full stop covers its accepted sequence. expectedStoreId precedes idempotency. Exact contextSelection is checked both at admission and application, and never replaced with the current branch during a late retry.

公共输入保留原文与有效 `images/files` 元数据；纯附件也可构成普通输入。附件名称、路径和正文只作为低信任资料，不能产生停止、批准或权限。模型历史按准确图片引用读取原字节，文件引用只追加低权限资料说明，不改写持久正文。首条命名沿普通业务生命周期保存原文兜底，与输入分类无关。[图片回归](../../../../test/isolated/artifacts/input-images.test.ts)核原请求、实际 Model 输入及附件名称不施控。

follow-up 保存可信宿主的完整 Run configuration，与 root `startRun` 一致，不对配置副本单独施加 1 MiB 上限；公开输入正文与 Worker 队列背压仍遵守各自限制。重复应用已 applied 的原 Command 返回同一回执和 Run，不覆盖原配置。非 Workflow SQLite 测试覆盖超过 1 MiB 的配置、准确尾部和冷重开读取。

`applyInput` is an owner-only short transaction, not a Loop. Steer appends one user message to its original active Run, preserves sourceIds/originCommandId/inputKind/contextSelectionId, and saves an applied receipt. It closes only still-planned undispatched model/tool decisions with cancelled/superseded_by_user_input facts. Tool closure also writes its original callId result message so persisted assistant.toolCalls remain paired for a real Provider. Related approval/plan cards become historical cancelled; already dispatched calls and their immutable requests remain untouched. A waiting Run returns to running only when no other unresolved Interaction remains. Return supersededExecutionIds is bounded at 4096.

Follow-up application waits for its exact predecessor to become inactive and for the Session to have no foreground Run. It atomically creates exactly one new Run, message and original Command receipt; retries return the same history. Applied steer retries likewise return the original Run/message even after that Run finished, without copying input into a later Run. startRun only accepts run.start and cannot bypass follow-up conditions or overtake an earlier queued follow-up. Earlier noncancelled inputs apply in server order.

`markDispatching` and completed `finishRun` reject input_pending when an accepted steer still targets that Run. The Core checkpoint must apply/reject such inputs, discard superseded decisions, reread messages and decide again; it must not replay an old model/tool or mark a cancelled old execution failed. Admission after completed finish rejects the original target and preserves the client's opportunity to keep its draft. The Store does not claim that message application means a Model incorporated it; actual Model execution source IDs prove that fact.

Runtime 的统一接收检查点同时汇合本轮用户输入和 Agent 邮箱。用户输入保留原入口、顺序及未派发决定失效语义；普通 Agent 消息和最终结果只作为低信任资料接收，不能获得用户引导或审批权限。最终派发和完成门禁共用邮箱 pending 判定，核本轮可接收的 typed result；未来轮的用户排队输入不阻止本轮读取子结果。完整事务与旧协议兼容归[统一消息接收](../../README.md#统一消息接收)。

Cancelling an accepted input rejects it as cancelled_before_apply and produces zero messages/Run. Cancelling the exact original Run also closes its registered steer inputs without cancelling independent follow-up work. Application rejects stopped targets, changed context, wrong Store/subject/generation and cancelled commands; Core explicitly rejects stale accepted commands so they cannot spin pending. Pure listPendingInputs uses a consistent snapshot and bounded lossless sequence keyset; it does not consume or rewrite state.

Real SQLite tests in test/isolated/storage/inputs.test.ts cover twelve steer commands, ordering/pagination, pairing and untouched dispatched requests, live question preservation, cancel-before-apply, finish/admission races and no target drift, two queued follow-ups/foreground uniqueness and no startRun bypass, original context/subject/Store/owner/child scope, actual message transaction faults, new-Run rollback, INT64 sequence exhaustion and readonly >2^53 keysets. No user profiles, compatibility migration, workflow tables or model calls are introduced by this leaf.

Private Agent input admission is a separate owner-only finite path. The actual dispatched sender Tool, namespace, subject, original Store and exact direct-child carrier are derived from stored facts. `acceptAgentInput` seals sender/carrier columns for steer; public child acceptCommand remains root-only. `ensureAgentFollowUp` reuses the original child Session without changing its creation command, creates a new carrier and new input.follow_up command, and binds exact predecessor Run/context/configuration/source. Activation applies that input in the same transaction only after the predecessor is terminal and the Session has no active Run. Final cancellation/owner/source checks remain authoritative; cold reads never start work. A carrier ending before activation settles its accepted child command instead of leaving an invisible pending input.

Public Runtime `listPendingInputs` checks the expected Store and rejects child Sessions with group_root_required. The trusted child Loop reads Store pending inputs directly and only sees sealed Agent-origin commands. The internal child read needed for safe checkpoints does not expand the public additional-input surface; child execution/history projections remain independently readable.

活动显式结果选入复用同一输入 checkpoint：`result.include` 封准确原 Run/selection/result revision，owner-only `applyInput(kind=result_include)` 按 steer 顺序保存一条明确选入意图和低信任来源引用。列表的 steer 过滤同时观察这些定向意图；公共 child 输入仍拒绝。pending 引用不形成新的选入或接纳；应用、planned Tool 配对终态、审批收束和回执同事务。复用已有来源也须经过该检查点，并证明原来源仍在当前所选范围；应用消息的发布序号决定新的显式读取资格，不修改原来源和自动接纳事实。精确 Run 取消覆盖它，未应用的单独取消不产生来源，已应用选入保留为历史，不触碰原 Tool/Job。


Public root run.start and input.follow_up accept the optional string enum reasoningEffort: none|minimal|low|medium|high|xhigh|max. It remains part of the original immutable Command request and canonical digest. Steer rejects both model and effort choices; it never changes the original Run configuration. Core validates this closed intent without knowing Provider support; Service freezes supported effective settings before a new Run. [Actual HTTP selection tests](../../../../../../apps/service/test/isolated/run-model-selection.test.ts) verify original Command, wire and recovery configuration.

## 真实输入与工作选择

普通输入直接沿原 `run.start/input.steer/input.follow_up` → 普通 Run/Message → Model/Tool 执行链。Runtime 不生成 `human.input`、`human.input.decision` 或无工具解释轮，也不按正文做 pause/stop/continue/replace 的预处理。引导使用原活动 Run，排队输入等前驱终态后单独应用；相同正文的新 Command 不去重，单个 Command 重试只返回原回执。[真实 Runtime 回归](../../../../test/isolated/business/task/human-work-runtime.test.ts)核请求次数、SQL 记录、输入顺序、队列撤回与冷读取。

rootWork ID/seq 是准确执行因果，不作为普通会话新消息的自然语言归属。当前授权父 Tool 可管理已有直接 child；child 的 queued 引导仍绑定该 child 原 carrier 的因果，而源 Tool 保准确当前父执行。新轮次采用当前显式模型配置，旧 Run、旧工具和未知效果不因正文“继续”而恢复。

`agent_completion` 进入同一父 Session 的当前活动 Run 时保原 carrier rootWork、result revision 和 Source；目标 Run 可以属于后续普通输入。Source/consume/ack 的准确目标和同 Store/selection 证明必须全部成立。idle 接收者不能抢先于已经受理的普通输入；活动接收不被排队用户消息阻塞。[报告事务回归](../../../../test/isolated/business/task/collaboration-report-transactions.test.ts)核 SQL 故障、丢响应与队列优先。

历史 `human.input/decision` 及私有决定操作保留用于旧审计、已发业务回执和取消绑定；普通 Runtime 不再调用它们。旧 pending/unresolved、旧 selected-work 选择不阻止普通新执行；准确旧 pause/stop/replace、取消、Rewind、Store 身份及未知效果限制仍有效。历史 processing queued 准入、旧 processing Run 的恢复与最终派发均拒绝，不能重新调用分类模型。普通 Run 当前已验证 Model checkpoint 若仍是旧 in-band 输入解释，也在恢复配置与写入恢复回执前拒绝为 `input_processing_removed`；更早解释记录不阻止已经进入普通业务 checkpoint 的恢复。合成旧记录的[真实 SIGKILL 回归](../../../../test/isolated/recovery/human-input-processing-crash.test.ts)核冷读不变、queued 拒绝、running/succeeded in-band 恢复零 Provider/配置加载及较早解释记录不阻塞普通恢复。

普通 Message 的历史 `humanInput` 只读证明仍由 [human-input-display.ts](../human-input-display.ts)核完整 public/raw/processing/decision/business 链，忽略 source JSON 自报；只有准确已应用替代 Message/Run 存在才标记副本。业务已应用后取消原公共输入仍保留展示证明和封存 Fork 的准确替代关系；取消前未应用、未决或证明不完整时不隐藏原消息。新输入本身只有一个用户消息；旧记录不因移除分类而重写、删行或按文本猜测合并。原分页和 Fork 范围保持，呈现证明不授执行权。[历史 SQL 回归](../../../../test/isolated/storage/human-work-control.test.ts)核损坏证明、独立同文和封存 Fork。
