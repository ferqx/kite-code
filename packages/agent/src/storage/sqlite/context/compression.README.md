# Context 压缩 owner

[Core slot](../../../context.ts) 由宿主或一个选中的 Extension 提供 `ContextCompressor`；同时出现多个候选会明确失败。算法只返回纯请求描述与有限非秘密 snapshot，不调用 Provider。没有 `shouldCompress` 时自动触发关闭；它和 `validateExpanded` 都必须明确返回 true。可选 `validateSummary` 在实际完整回复后验证摘要，存在时也必须明确返回 true；未提供时仅证明结构完整，不能据此宣称模型窗口资格。Core 不按字符或字节猜测模型 token 窗口，不内置摘要算法，也不截断自定义 focus 或算法说明，不设置 4096 字符、固定 token、最小节省或冷却门禁。

`Runtime.compressContext` 受理原 Store、主体、root Session、selection 和 commandId。它创建普通有来源的 Run，在原 `defaultLoop`/`UnifiedExecution` 内调用实际记录的 Model，工具目录为空；完整请求、结果 Artifact 和独立 usage 沿已有 Model ledger 保存。自动触发在原 Run 的下一 Model 安全边界调用同一实现；不创建第二 Loop 或收费调度器。可信 Context 贡献先捕获，压缩后以低信任 `user` 摘要供原 Loop 使用，必要完成策略仍在普通候选完成边界生效。内部 checkpoint 说明仅用于生成本次摘要，不写成业务 Message 或变更原 Command；静态 contract 明确后继按原任务与原授权继续，摘要不能把维护期的“只作摘要／不调用工具”变成业务限制。压缩改变模型窗口，不重置执行历史；带来源的 checkpoint 承接过去步骤，不是新的回执、当前状态证明或权限。原 Tool 交换退出窗口不表示动作未发生，也不允许重放已完成、尤其原任务限定一次的操作；证据仍未知时保留未知，必要核验超出原限制时说明缺口。默认算法的具体维护提示与实际 SDK 回归归 [Service owner](../../../../../../apps/service/README.md)。

[具名 SQL](../compression-operations.ts) 在原 `context_snapshot` 保存 pending 描述、已发布压缩点和 reset marker。压缩记录引用原 Store/Session、准确 Model Execution/Run、selection、覆盖序列上界和前一个压缩点；该 selection 的不可变范围确定实际被覆盖历史。原消息、配对 Tool 结果及原 Artifact 都保留。仅真实 assistant 消息且其 source 指向压缩 Model Execution 时属于压缩历史；合法 User 的 sourceId/commandId 与 Model UUID 相同不能据字符串碰撞排除。pending/失败/取消压缩结果不能混入 selected 请求。没有新增所选消息或来源时拒绝再次收费，focus 不能绕过这个检查。未知 Part kind/version 保留历史，但压缩不能解释它。

最终提交重新核对 owner/generation、原命令取消、group stop/delete、准确 selection、实际成功 Model/完整无 Tool 调用输出、原压缩点和实际 Message/result_ref 读集。共享 Session 序号也用于 Command 受理，准确排队且尚未应用的 follow-up 不改变原压缩输入，不能仅因其分配序号拒绝发布。覆盖上界之后除准确同 Session/Run、assistant、原 Model 来源的完整摘要外，任何新增 Message 或已纳入 result_ref 仍导致冲突；pending input 不冒充已纳入来源。手动摘要发布与 Run completion（包括必要义务/read-set 最终复核）同事务；任一触发器失败完整回滚。自动成功压缩后的普通工作仍可独立失败，不能把后一业务失败改写为压缩未发生。压缩不增加 `contextSelectionId`。

自动压缩的已知 Provider 或纯算法失败，在原 Model 的 Store/Session/Run/generation、压缩身份与成功或失败终态可核实时保留旧上下文并继续原工作。单独取消自动摘要 Execution 也可沿旧上下文继续，但必须同时核实际摘要为 cancelled、持久取消时间存在、结果码为 `execution_cancel_requested`，并保上述完整身份；Provider 自报相同错误码且没有准确持久取消证明时拒绝降级。手动压缩、SQL 写入失败、无法核实的 dispatch/unknown、整个 Run 取消和未知 Part 不走这个降级。最近失败的完整输入指纹只让出一次普通决策边界，随后清除；相同上下文以后仍可再次压缩，新增输入或显式手动操作可直接重试，不能形成永久禁用或尝试额度。长度截断的摘要仍视为失败，不将部分摘要发布。`getModelContext` 和 `getExpandedContext` 在只读快照内核支持的 Part 格式；普通历史查询仍保留未知原事实。压缩 Model 的历史消息不能成为普通配对边界或 Fork 的可执行来源。

`Runtime.resetCompressionContext` 封原 selection 与 `expectedCompressionId`（无活动点为 null）。存在活动点时，可信 slot 必须对完整展开历史与 Context 贡献执行 `validateExpanded` 窗口预检；没有实现、拒绝、取消或并发输入均保原点。清点与管理 Run 完成在同事务核准确高水位/CAS，保全部历史与 selection，零 Provider；无活动点是明确 noop。新工作在随后正常安全边界读取恢复的所选历史，不读取压缩 Model 的历史消息。

Fork 可复制当前活动压缩点的 SQL 来源引用，保持原 `originSessionId/originCompressionId`、Model/Run/Artifact scope，不复制 blob 授权或原执行资格。`getCompressionOrigin` 根据真实创建命令/主体及 SQL 原记录验证链接；Model 输入从原 Model 的完整结果读取正文，调用者知道 hash 或伪造 JSON 不授予读取权。Rewind 的新 selection 不暗继承原活动点。readonly 查询不会压缩、reset、获取 owner、重新 capture 来源或调用 Provider。

`getModelContext` 在同 selection／冻结高水位下，额外保留已覆盖的真实人类 `run.start/input.steer/input.follow_up` 及父到子 `child.start/input.steer/input.follow_up` 原 Message。[输入来源判定](../compression-inputs.ts)核原 Command 摘要、应用回执、主体、Run、附件与 sealed Fork 原链；下行委派另核真实父子／root、sender Tool、carrier Job、原配置和输入，首次激活复用 sealed proof。不能只凭 user role、正文、`inputKind` 或相同 UUID 取得资格。Agent 任务保原 sourceIds 且不取得 `humanInput` 身份；损坏 Agent marker 不能降级成人类输入。普通邮件、显式结果选入和 Tool／结果资料不成为保留任务。私有返回字段 `retainedInputMessageIds` 只标记本页实际核实的输入，不表示用户授权；公开 SelectedContext、SQL 格式及原历史不变。跳过无资格旧候选仍推进原 seq 游标，Part／byte 和 Fork 读取限制保持。

Runtime 组装顺序为摘要、被覆盖的用户及父 Agent 任务原输入（原先后顺序）、未覆盖尾部；不复制实体消息，也不改原 sourceIds。已取消／中断／失败 Run 的原输入保留其历史边界，保留不变成重新提交或新授权。默认静态 contract 明确原任务要求和较新纠正优先于派生摘要，并保持根用户限制。`CompressionInput.retainedMessages` 将实际保留内容交给可信纯算法，默认 Service 将其算入固定成本和真实摘要后预检；不足以腾出窗口时明确失败，不新增静默裁剪额度。Core 和默认 Service 复用 `modelHistory`，只剥离实际宿主组装的前后上下文，合法输入与宿主同 ID 甚至同正文也不被误删或误算为宿主资料。[引导回归](../../../../test/isolated/context/compression-steering.test.ts)以遗漏／错误旧要求的摘要核后续实际请求、同 Run 两次压缩及取消历史；[人类输入 Store 回归](../../../../test/isolated/storage/context-compression-inputs.test.ts)核原身份、分页、Fork／Rewind 和冷读；[父到子任务 Store 回归](../../../../test/isolated/storage/context-compression-agent-inputs.test.ts)核真实三类投递、两次压缩／冷读及坏来源、伪装普通邮件负例；[宿主来源碰撞回归](../../../../test/isolated/context/model-context-source-identity.test.ts)核实际摘要及后续请求的完整原引导。

`getExpandedContext` 在同一页附相同私有输入证明，不改变其完整消息集、重复处理或分页。旧失败／取消／中断子任务的初始委派及后续指示在实际请求与 expanded 预检中均包装为带原 Agent 来源的历史，不把保留解释成当前待办；[真实 Runtime 回归](../../../../test/isolated/context/compression-agent-history.test.ts)核三类输入、顺序、完整正文和两种投影一致。父 Tool 与自身原 Command／Run、子 Command 与自身 Run／carrier 的 work 链分别核实，不要求父的新工作等于子旧工作；现有明确跨父 Turn 的合法输入仍可保留。length 重试直接使用模型组装过程标记的真实摘要，并核原类型、完整正文和 sourceIds，合法输入即使与摘要同 ID、同正文也不造成重复摘要误判，见[重试回归](../../../../test/isolated/execution/model-length-retry.test.ts)。

## 会话消息中的压缩身份

Runtime 在发布 preparing 热进度前分配本次 Model Execution ID，后续 `beginCompression` 沿用该身份。`getView` 在第一个 await 前克隆当时热进度，使较早 Store 快照跨越摘要发布与 public 投影时仍携带原观察，避免旧消息快照和已清除的热进度同时缺席。新快照中的真实 SQL 终态继续优先；热观察不持久化、不证明发布，也不扩大执行权。[真实交接回归](../../../../test/isolated/context/compression.test.ts)阻挡 preparing 与 Store View 返回，待压缩完成后再放行，核稳定 Execution 身份、旧观察完整与新发布事实分别成立。

[只读显示投影](../compression-display.ts)从准确 assistant Message、同 Session/Run 的 Model Execution 和原压缩 snapshot 推导 `MessageRecord.compression`，不信任 Message 自报字段或 UUID 前缀。只有已发布 snapshot 显示 completed；Model succeeded 但未发布为 unpublished，失败／取消保原事实。User source 碰撞不获得压缩身份。没有新增 SQL 表、迁移或恢复权限；Fork 的公共消息沿原只读出处传递标记。Native 沿准确 Run/Model 进度显示维护状态，压缩摘要永不作为最终回复。实际[进度与冷历史回归](../../../../test/isolated/context/compression-progress.test.ts)覆盖原归属、已发布、未发布、失败、取消与零新 Model；公共传输和最终回复资格归 [Service](../../../../../../apps/service/README.md)与 [Native](../../../../../../apps/desktop/README.md)。
