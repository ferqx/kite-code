# SQLite engine assets

The public `@kite-ai/agent/sqlite-engine` leaf imports only Node filesystem/path/crypto/module APIs. Import, manifest parsing and `verifySqliteEngineAsset` do not open a database. Bun SQLite is required only by initialization or actual measurement. This leaf supplies integrity and exact runtime identity; it does not approve a publisher, minimum version, upstream fix or backport.

The compiled package's fixed `storage/engine/` directory contains closed `engine-selection.json` (`{version:1,manifestSha256}`), `engine-manifest.json`, and, for a dynamic selection, the named library. Dynamic manifests retain the closed library/size/SHA shape. Builtin manifests instead contain `linkage:'builtin'` and no library fields. Both pin target, driver and exact SQLite version/source ID. Any present engine directory with missing or invalid metadata fails; only complete absence permits `development_no_selection`.

`initializeDefaultSqliteEngine()` runs before public Store profile access, preflight or Worker creation. An explicitly initialized source host revalidates its original selection rather than relabeling an unselected development engine. Dynamic initialization is macOS-only and calls `Database.setCustomSQLite` exactly once, before the first DB. Missing assets, late initialization and mismatched identity reject without retry or builtin fallback. A failed initialization also blocks later default initialization in that module.

Bun's chosen native library is shared across Workers in the same OS process. The private Worker open message contains only the actual parent's selection (or null for unqualified development). A Worker validates those assets and measures its existing engine; it does not repeat the setter. Builtin initialization measures the embedded engine without changing it: it does not pretend to detect whether another caller previously opened a DB. Linux/Windows builtin support can use the same metadata contract, but actual platform and fixed-source release evidence remains separate.

Maintenance's raw source/normalization/UI-validation connections use the same host initializer. No Store schema, SQL business record, HTTP request, JSONC field or Model engine-selection authority is added. Node/Electron `node:sqlite` remains a separate embedded engine; this Bun selection is not its qualification.

Focused qualification uses an owned copy of the existing macOS 3.51.3 library, relocation, exact source measurement, a shared Worker, two public Store Workers with concurrent WAL writes, backup/restore and cold readonly lookup. Compiled malformed-sidecar probes reject before any profile creation. Builtin observation is tested against the actual current engine and explicitly does not claim a release fix. These tests do not replace a complete release producer, platform CI or the Native embedded-engine proof. Asset validation and a noncooperating external edit are not an atomic OS operation; formal runtime integrity and use leases belong to the enclosing verified bundle.
