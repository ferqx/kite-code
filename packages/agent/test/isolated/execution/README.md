# Unified execution integration tests

[lifecycle.test.ts](lifecycle.test.ts) verifies the [Runtime lifecycle leaf](../../../src/lifecycle.README.md) through disposable SQLite Workers and exact barriers: submission's first Store await, owner acquisition, terminal binding disposal, duplicate shutdown completion, idle observations and final host callback, callback failure, detached/unconfirmed Jobs and failed disposal. Two Runtime instances on one profile cancel only their own live groups; a durable submission whose response is held on the closing observer still completes under the surviving original owner. Read/control calls protect resource lifetime; no time limit is widened to make shutdown pass. Assertions await Worker-dependent rejection before inspecting it, avoiding Bun's nested asynchronous rejection assertion wait.

The existing Fork and Session-management unknown-Job fixtures preserve all business assertions and now explicitly expect `shutdown_cleanup_unconfirmed`, `drain_failed` and a still-readable Store. Their in-memory adapters have no external process; only explicit fixture teardown closes that original Store. This replaces their former successful-close assumption without inventing a confirmed stop.

requirements.test.ts exercises actual Core, SQLite Worker and fixed Model requests without injecting requirement rows: ordinary Tool registration strengthens the next dispatch/completion boundary; missing and unsatisfied evaluators cannot produce a completed Run; exact waiver evidence remains a durable business record rather than passed validation; namespace, caller Run claims and a previous Run's real Execution cannot register new scope. Trusted per-Run initialization receives immutable actual command/Run/Session before the first Model and missing record/implementation produces zero adapter requests. Background ordinary Jobs preserve their frozen refs, original conditions and permission binding across a newer Run, retaining the binding lease until terminal and disposing it once. Fixtures use temporary profiles, harmless counters and explicit gates, and always close Runtime/Store. Tests do not invoke paid models, mutate production code or access old user profiles.

condition-context.test.ts verifies generic host context seams through actual Core and temporary SQLite profiles. Trusted initialization creates immutable actual-Run metadata before the first Model gate; unselected namespace, invalid schema/prefix and replacement fail with zero Model calls, while retained access closes after the first Execution. A still-dispatched ordinary Tool changes a related record between a Job evaluator's scoped read and its final dispatch transaction: even an evaluator that omits recordReads cannot start the Job with stale facts, whereas an unrelated write remains safe. Evaluators receive actual planned identities and exact-ref read scopes. Run completion has a null Execution; Job completion carries the actual still-running Job identity before its terminal transaction. Question and plan-review receipts match accepted revisions, original request/answer and actual execution provenance; another Session's interaction is unavailable and information approval cannot grant a separately denied Tool permission. Gates, harmless counters and finally cleanup make these checks deterministic without SQL-fabricated qualification or production edits.
