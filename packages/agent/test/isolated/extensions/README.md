# Run binding verification owner

`run-bindings.test.ts` verifies host-resolved RunConfiguration extensions/sources/dispose through actual Core, default Loop and disposable SQLite profiles. It changes no production implementation and imports no legacy engine.

The v1 Model request is held by an explicit gate while a separate Session admits v2. Tests compare each actual Model tool schema with the immutable Run manifest and executed handler/version. Mutating the caller's original schema, description, handler/version and Workspace serial resource key must preserve v1; resource acquisition delegates to real native Workspace locks and verifies the sealed original key. No elapsed-time assumption controls version changes.

Unknown/duplicate selected tool IDs fail admission before any Model call and dispose their acquired binding exactly once. A public JSON start request cannot inject host definitions or tool selections: only the trusted configuration manifest reaches the fixed Model, and the unregistered call has a persisted failure with zero adapter effects.

A permission gate permits a precise source change between the Model decision and original Tool dispatch. Actual Model messages use the per-Run source, the global fallback remains unused, and changed freshness produces a durable failure before Tool effects. The next Model sees refreshed selected source content without rewriting the original decision evidence.

Ordinary detached Jobs use different explicit operation keys for distinct business intentions. Each Job starts before its parent Tool returns; parent Run completion leaves the binding lease alive. A terminal event releases the first Job/Run binding exactly once; Runtime close stops the remaining actual handle and drains its terminal/disposer before the Store closes. New v2 bindings do not replace a v1 background Job. Adapters use finite fixed events and explicit gates, not a process or remote provider.

`context-contributions.test.ts` verifies scoped pure extension context hooks through actual Core and temporary SQLite. Business records are read only from the selected extension namespace and contributions reach Model as user data even when the hook asks for system placement; trusted project instructions retain their default system role. A writer in one Model decision changes the record before the later Tool, producing zero later effects and a next Model request with the new source. Public original Execution proofs contain only stable source IDs/digests and remain unchanged by record updates or edits to returned objects. Query and Session-view reads invoke no capture, Model or durable writes; other Session execution proofs are denied. Per-Run hook versions, namespace collisions, malformed local source content, per-hook/aggregate count and body budgets are tested before any Model or effect. Fixtures use fixed models, harmless counters and finally cleanup, with no production edits or business-extension imports.

`step-bindings.test.ts` exercises the optional pure `readStepCapabilities` hook in one real Run. Initial manifest v1 stays historical while a later successful Model seals v2 schemas, namespace/version bindings and non-secret capability snapshot; the actual v2 Tool then writes its own record namespace. Catalogue changes during approval or resource waiting produce zero old Tool effects and a new Model catalogue. A change at Model admission preserves the failed old intent and rebuilds the actual retry request before Provider invocation. An already-dispatched ordinary Job keeps its v1 implementation and the Run lease through later v2 steps, disposing once at terminal. Duplicate registrations and oversized snapshots fail before any Model or Tool; Query and history/view reads neither refresh the hook nor write. Existing Run-binding fixtures cover Runs without the optional hook. All profiles are temporary, models fixed, adapters harmless, barriers explicit and cleanup guaranteed; no production or SQL qualification rows are fabricated.
# Operation 输出分页

[operation-output.test.ts](operation-output.test.ts) 使用实际普通 Job、SQLite Worker 与固定 Model，核实原 Store/namespace/Session/command/execution 身份、冻结 upper cursor 的连续页及完整正文 SHA-256；错范围、游标超前和未知 options 不写事件或停止目标。关闭重开后的明确只读 Tool 只读取旧输出，原 Job starts 保持一次；此证据不把新用户显式 read Run 的 Model 调用当成隐式 Job 重放。

[detached-tool.test.ts](detached-tool.test.ts) 验证普通 Tool operation 的原 cancellation 从真实 Command 经 StandaloneScope 到 planExecution 保持一致，不只为 Job 保存。实际父 execution.cancel 停止 attached Tool，但 detached sibling 保留原独立边；原 Run Command 不被误取消。重复原 ensure/cancel 无新派发/事件，释放 gate 后 detached Tool 仅一次效果，历史读取零新增效果。与 operation-output、cancellation、run-bindings 四文件组合 12 tests/149 assertions 通过；新实际用例 1/26，Agent typecheck exit0。

[fork-lifecycle.test.ts](fork-lifecycle.test.ts) 使用实际 Core/SQLite 的普通 Tool records API 和纯生命周期规则。copy 保原 origin/raw 内容但不能登记原 executable obligation 或启动旧 plan；rebuild 按所选消息边界产生新来源记录。原 ID 重试不再 prepare，caller 更改注册/schema 不改已捕获规则，源 CAS 竞态和 SQL 触发器会回滚新 Session 与全量 copy。未来记录保 raw 并明确 omit/reject，原 ≥17MiB 模型 Artifact 不改 scope；cold 读不调用 Provider。
