# 验证选择与证据复用

根据本次已确认目标与实际 diff 选择验证，围绕受影响的用户行为和必要失败边界；收尾与重新打开条件遵循[根 AGENTS](../../../../AGENTS.md)，不因进入该 Skill 就执行全部检查。

- 文档变化运行 `check:docs` 和对应作用域的 `check:docs-impact`。
- TypeScript 变化运行受影响测试和 typecheck。
- 技术边界变化运行对应边界检查。
- 发布证据或其检查器变化运行 `check:plan-evidence`。

任务或适用门禁已明确要求全量、真实模型、平台或发布验收时，仍按原要求完成；定向回归、受控结果和本机结果不代替对应资格。不能为达到收尾条件缩小已确认范围、删除必要断言或放宽安全约束。

复用已有实际执行记录，核对原命令、代码版本、环境、结果及未覆盖范围。确认相关文件、依赖、配置和生成输入未变，原范围覆盖当前断言，且没有新失败、有依据的新风险或环境变化使结果失效；在本次交付回复中说明适用依据即可，不新建复用记录。

相关变更或新失败出现时，沿实际依赖核对哪些结论失效，只补受影响的必要验证。证据不明确时先核影响范围，再补能解决该不确定性的验证；不凭会话、阶段或提交变化重复全部检查，也不为同一结论新设固定重跑次数。已有合同和强制门禁明确要求的范围与次数保持。

旧失败、unknown、inconclusive 与尚未执行的资格保留原事实，不以其他范围的通过或旧成功记录覆盖。不能确认与本次交付安全无关的问题仍须核实，不能仅标记 limitation 后收尾。

现有 hook 和 CI 独立运行。不使用跳过参数，不新建持久验证缓存或同步台账。
