# Agent Note: 同源 Skill 目录与局部可用性

Status: implemented

## Problem

终端需要发现实际配置的 Skill；仅从配置名称拼接候选无法证明文件、版本与依赖是否可用。当前 Service 的 Run 装配又会因任意配置项读取失败而拒绝全部任务，与 [V1.3 §15.2](../../../../docs/plans/unified-agent-refactor-v1.md#152-skills-决定可加载知识和流程) 的局部错误约束冲突。新的知识选择字段不包含旧 Workflow 的 activation、inline/fork、output 与 verification 语义，因此目录接通不能作为 Workflow 迁移完成的证据。

## Decision

Service 的只读目录和实际 Run 装配共用 Skill 发现与状态解析。目录绑定真实 Store、Workspace、配置和内容版本，只返回配置 ID、名称、摘要、版本、启用状态与有限错误/缺能力列表，不返回路径、正文或凭据。分页绑定完整目录 revision；变化时拒绝继续拼页，由调用者明确重新读取。可用仅表示知识可以按需读取，不授予执行权限。

每次发现重新核全部启用位置和当前内容版本；独立文件 I/O 每批最多四项并发，按原配置顺序汇总后发布绑定。完成顺序不决定重复物理位置的首配置 ID，首项 digest 错误也不改变重复判断。分页继续完整重读，不引入版本缓存或目录截断。

禁用项不读取文件；坏项局部标记。缺省选择保留可用项，显式选择坏项或 child 继承的原项失效必须拒绝，不能静默扩大或缩小准确选择。查询不启动 Run、Provider、Shell、MCP 或凭据解析。TUI `/skills` 只读目录，刷新、关闭、会话切换有独立取消域和代次，目录成功不能清除 SSE unknown。

Skill leaf 默认移除项目数、正文与引用数的任意额度，仍支持宿主明确的正安全整数 limits，并保留路径、UTF-8 和常规文件校验。配置文件既有字节与结构校验继续有效，命名数组不再另加 512/4096 项计数限制；传输分页不裁掉总目录。

## Alternatives considered

- 在 TUI 直接扫描目录：会复制宿主可信 root 与配置规则，并绕过公共 Client，故使用同源 Service 目录。
- 用 `selectedSkills` 接旧 `/<Skill 名称>`：旧入口有真实 Workflow 准入与执行帧，知识选择不足以保留语义；本轮只交付发现，动态 Workflow 继续按完整方案迁移。
- 继续在任意坏项上整体失败：会阻止未选择该 Skill 的普通任务；改为局部状态，并保留显式选择与继承的严格失败。
- 每页逐项串行读取：保留了版本检查，但完整大目录反复读取时等待累加。改为有界独立 I/O 并发并按配置顺序归并，保留全部安全检查和重复归属；不延长原验收预算。
- 默默截断目录或替换为另一固定总数：无法完整发现有效配置；使用完整 revision 的显式分页，超出既有配置字节或传输单项边界时明确失败。

## Consequences

真实文件目录与 Run 装配共用可用性，不再由未选坏项阻断普通任务。明确选择和原继承仍严格；非 Skill 配置继续先执行原凭据/形状检查，避免局部容错改变其他能力的错误优先级。公开 requested 仍最多256项，默认实际 resolvedIds 不使用这个单请求额度。

定向验证包括301项真实 HTTP 目录、默认根 Run 与一个 worker 的301项准确继承、304项真实配对/共享终端跨页与迟到隔离、5001项配置合并、超过1MiB正文和资源完整读取。Client 每页前后复核原宿主，不能以同 Store 的新实例替换已准入来源。完整结果、首次失败与未覆盖范围见[实施进度](../../../../docs/plans/unified-agent-refactor-v1-progress.md)。

## Risks

目录读取版本不是以后执行的授权或版本预订；现有 CLI `--skill` 仍在实际 Run 准备时解析当前选择。Workflow、动态命令和精确已显示版本的激活仍未由本目录实现。读取依赖 OS 文件状态，revision 只能防止不同读取结果被拼成同一目录，不承诺与外部写者的文件系统事务。
