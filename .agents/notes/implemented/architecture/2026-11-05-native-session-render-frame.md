# Agent Note: Native 会话切换的渲染帧与读取资格

Status: implemented

## Problem

首次切换时，选择意图、已显示数据和读取资格共用状态。RPC 分批返回使输入区先换页、再换模型和草稿，瞬间空草稿甚至把发送误换为停止；控件还会在普通读取时反复变暗。先前按控件缓存启用外观只能补偿部分组合，不能保证新 scope 的首帧一致。本篇部分替代[视觉与资源生命周期修正](../bug-fix/2026-10-19-conversation-cache-visual-resources.md)的 Composer 外观缓存和审核标签缓存；原正文 KeepAlive、资源预算、取消和来源隔离继续适用。

## Decision

- Native 的已提交帧统一持有 NativeState、草稿、模型准备结果和准备页归属。导航意图独立撤销旧操作；冷目标先取得模型及首次保存草稿，再提交同一帧。暖目标使用自己的已知草稿／目录展示，再按当前读取核实；迟到请求按原 generation、Store 与 view intent 拒绝。新对话返回相同已选会话也执行接管，不以身份相同跳过。
- 已观察事实与当前读取资格独立。相同会话普通读取中保留已知权限事实，真实失败清除；派生 selection 和动作门禁仍撤销旧资格。公共 ReadGate 可嵌套且只收紧交互；Button 使用原生 disabled，Lexical 使用不可编辑状态，业务禁用独立决定视觉。Composer 不再保存控件外观历史或逐控件覆盖 disabled 样式；表单、Enter、文件与权限回调也核门禁。
- 正文目标身份仍先更新，准确的有界 DOM 缓存可立即恢复；未缓存正文沿原加载／历史流程。没有等待历史读尽、可选指标或工具目录才开放整个页面。指标采用明确读取态及固有宽度，环境未知／读取中不冒充已确认空闲。

## Alternatives considered

1. 继续按控件缓存外观并加覆盖样式：冷 scope 没有先前样本，新增异步组合还会泄漏中间状态，不能建立统一提交边界，移除。
2. 在整个切换中隐藏页面或重挂载输入区：会丢输入节点、阅读位置和缓存优势，拒绝。
3. 等待全部历史、指标与后台目录完成才提交：长历史和慢可选读取会拖延独立操作；只准备输入区首帧必需事实，其余沿各自明确读取状态与资格继续。
4. 读取期间让按钮实际可操作、只依赖最终写入校验：仍可能启动过期弹层或附件准备。保留原生禁用、回调核对及真实写入准入，不从保留的展示事实取得权限。

## Consequences

冷目标接管需等待原模型与首次草稿读取，等待期间保留暂停的已提交输入区；失败结束准备并沿原错误与恢复机制显示，不猜默认模型或借其他会话事实。已提交帧不承诺所有可选区域同时完成，也不改变消息、权限或工具协议。当前实现和验证归 [Native owner](../../../../apps/desktop/README.md#会话消息渲染验证)与 [UI owner](../../../../packages/ui/README.md)。
