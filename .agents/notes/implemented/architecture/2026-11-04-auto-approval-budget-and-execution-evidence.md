# Agent Note: Auto 审核预算、等价操作复用与执行证据恢复

Status: implemented

## Problem

长任务中的 Shell Tool 和它创建的 Job 分别调用语义审核，同一操作重复等待并重复传入历史。审核没有独立等待预算，合法只读查询和有条件的中间暂存仍有真实误拒。压缩后原始任务虽然保留，步骤进度和修改依据却可能离开模型窗口；持久记录存在不代表模型能找回。另有空转控制轮询反复读取全部活动句柄。

## Decision

本记录的默认任务授权材料及 recordedReads 选择已被[Shell 风险事实与审批策略分工](2026-11-04-shell-risk-review-facts.md)部分替代：新默认可信 Shell 仅评动作风险，其他可信内置能力跳过该项语义审核；下文最小授权材料继续适用于旧 Run／自定义合同。独立预算、超时策略、准确派发证明、压缩恢复与未知效果的理由继续适用。新合同缓存身份与材料复用以新记录和当前权限 owner 为准。

用户确认 Kite Agent 没有运行阶段定义，Planning 仅表示计划模式。保留准确原 Run 的计划批准要求、版本和成功 receipt，不再投影 planning/building 阶段；可变 progress 不混入稳定计划批准来源。

Auto 语义审核默认总预算 10000ms，可由 autoApproval.timeoutMs 配置。预算覆盖审核准备、共享 Model 排队及实际调用。超时与审核决定竞争同一持久终态，晚到输出不能改写已定结果。超时依据独立于模型批准，不进入批准缓存；非超时技术错误仍返回准确原结果。独立人工要求不由超时替代，真实超时后仍可进入原人工决定。

用户进一步明确：超时默认放行语义审核，交给工具原有执行策略兜底，不增加超时专属收窄。Shell 文件和网络范围使用本次 workspace_write/full_access、none/internet 请求与原父子、宿主硬边界的交集；省略请求仍是 workspace_write/none，显式请求可按原策略执行外部写入及联网。实际范围进入派发证明和公开日志，保护资源、硬拒绝、取消、独立人工及未知效果边界保持。默认放行不伪造模型批准，也不承诺纯语义业务要求由沙箱强制保证。

后续确认将审核输入与业务模型窗口分离。默认 host 明确启用最小授权材料合同，Core 从原任务、实际祖先委派和已生效纠正构造带来源的材料，压缩不会抹掉纠正；角色指导、计划正文、准确拒绝与同一操作的有限效果事实保留。助手自定步骤、普通邮件和大段历史输出不形成授权。完整原 payload、模型输入及来源绑定仍封存，旧 sealed / legacy 原文不改写；不新增另一个模型总结授权，也不以材料列表宣称全任务效果等价保证。

真实自然样本进一步显示，移除整窗时一并丢掉用户显式引用的登记文件，会让合法入口、暂存和外部核对失去判断依据。增加有限 recordedReads：只选当前 Session／当前任务、真实内置文件工具已经返回、且路径被原任务或当前操作字面引用的文本选段；保最新已读 baseline 和实际页，不从正文递归扩候选。大正文沿原 Artifact 校验和 request body 封存处理，旧 compact 无该字段时不重写或重发。已完成读取按首次封存时的事实选择，不用意图创建次序替代完成次序；内置 Shell 的冻结实际工作区根用于同一相对路径映射。原 check 的读取和先前效果观察保持 sealed 快照，后续观察不重启该次审核；授权原文、角色、拒绝及现行权限仍严格匹配。它仍是低信任历史数据，不是当前磁盘、当前 Model 接收或新授权；Shell stdout、无 baseline 外部读取和不兼容附件不自动恢复。

审核 reason 要求一句、最多30词。支持参数的普通模型接口创建独立审核 adapter，输出上限为原设置与256的较小值；业务、摘要和标题保持原设置。当前登录渠道明确不支持该参数，不偷偷发送或宣称硬限；保留短理由与原总期限。真实 length 结束明确保存 authorization_check_output_limit，即使正文已有批准 JSON 也不授予执行，不将截断冒充超时。

使用既有 Command 保存 authorization.policy 依据。等价操作在同一任务、主体、适用会话和当前权限下可复用准确原批准；内置 Shell Tool 与真实子 Job 共用一次语义审核依据，分别保留原执行身份和最终事务核验。同操作在途审核合并等待。参数、范围、任务纠正、拒绝或任务内相关效果变化使原复用依据失效；未观察的外部脚本/远端变化不据此获得永久不变保证。

Shell ensure 对已存在 key 的原请求冲突在建立新 Command／Job 前拒绝，因此只在这一步把 operation_conflict 返回为已知 failed 并指导读取原 key；实际启动后异常和其他未知保持原保护，不能靠放宽未知规则恢复任务。

压缩不新建任务或 Run，用户要求的改动清单与验证覆盖原任务全部 checkpoint；摘要继承原 Run 已完成路径和准确回执引用，缺本次结论必要的原证据时先读取，不能把窗口移除当作未执行或只交付当前窗口。摘要仍是有归属的历史，不变成新回执。

压缩指导保留原目标、准确路径、归属、receipt、验证和未知；进度不可见时通过 read_plan 恢复。新增只读 read_execution_evidence 从当前任务的已有 Execution、原 Shell 及可绑定 checkpoint 读取证据，固定真实分页，不新建改动台账。Shell 未捕获的逐文件变化仍未知，累计 diff 不作为独占归因。

控制轮询复用持久 Changes，仅在新增句柄、相关控制变化、游标失效或输出积压时读取原准确取消标志。读取失败不推进游标，保留原检查节拍、本地取消和跨进程兜底。项目来源只在同次 checkpoint 去重组装，不删除旧来源或放宽 freshness。

## Alternatives considered

- 删除 Job 权限核验以减少审核：会丢失真实子调用范围与最终派发约束，采用准确父依据复用并保留 Job 核验。
- 超时伪造 approve_once 或继续返回普通技术失败：前者虚构模型决定，后者违背用户确认的继续策略，采用独立持久策略事实。
- 超时一律收窄到 workspace_write/none：用户明确采用默认放行语义审核、工具策略兜底，保留本次显式文件和网络请求与原硬上限交集，不另设超时专属收窄。
- 按命令名称扩充只读白名单或新增角色 OS 模式：不能解决实际任务语义和复合命令误拒，本次优化提示词与原机制，不新增角色沙盒。
- 将 progress 直接注入稳定 planSource：会使同批后继工具和历史成功 receipt 的依据失效，采用已有进度读取与独立执行证据查询。
- 另建工作记忆/改动台账或每次自动回灌全部历史：复制事实并继续增大窗口，采用准确范围的现有证据按需读取。
- 增加审核专用 Model 池或改变子任务期限：没有当前收益证据，本次保留共享资源和已有期限。
- 当时未采用完全移除用户任务的风险审核：考虑到同命令在不同任务中的授权差异，先采用最小有来源材料；后续用户确认风险审核只管高危效果，任务约束交业务指导与原执行边界，故新默认合同改用上述独立风险方案。旧合同保留原材料以维持恢复身份。
- 在不支持输出参数的渠道传入上限或本地字符截断冒充 token 上限：前者直接失败，后者不能证明 token 数或正常完成，保留真实渠道限制与完整结束校验。

## Consequences

Auto 超时继续由实际执行机制兜底，并不保证所有业务语义；当前只读角色仍是任务指导，普通工作区沙盒不能冒充 OS 禁写保证。准确原调用的拒绝终态不能由迟到结果或该次超时覆盖，独立人工和硬边界继续核验。未新增跨工具业务效果等价的硬拒绝索引；新调用的超时继续不提供任务级语义拒绝不可绕过的技术保证，模型仍须遵守原拒绝。没有适用继续机制的工具返回明确 timeout 和未执行事实。已知未知效果不因读取证据或 Run completed 变为成功，也不能自动重放。

审核实际设置进入配置身份。支持接口的旧活动 Run 在原审核未设上限或大于256时，按既有恢复合同报 run_configuration_mismatch，旧记录不改写、不重发；原上限不大于256、当前登录渠道与自定义审核器不因此改变身份。减少输入和输出预算不等于已证明时延必然降低或任意模型均不误判，真实结果仍由验收入口保留。

当前实现归[权限 owner](../../../../packages/agent/src/permissions/README.md)、[执行证据 owner](../../../../packages/agent/src/business/execution-evidence/README.md)、[压缩 owner](../../../../packages/agent/src/storage/sqlite/context/compression.README.md)及[授权合同](../../../../docs/active/authorization.md)。工具及协议版本不升级。真实模型、原生平台和客户端范围分别由现有验收入口记录，不以隔离回归外推任意长任务保证。
