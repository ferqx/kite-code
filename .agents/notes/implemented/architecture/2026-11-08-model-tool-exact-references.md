# Agent Note: 模型工具使用准确引用

Status: implemented

## Problem

文件完整基线、计划摘要与修订、连接代次和操作意图曾由模型反复组装。字段组合错误既增加失败，也混淆工作身份；无限默认观察会让已经没有活动目标的会话仍停在等待。放松一致性检查或自动重投会扩大权限、覆盖并发变化或重复未知效果。

## Decision

按用户确认的参数对照收敛公开表面，当前合同归[模型工具 owner](../../../../packages/agent/src/model-tools.README.md)。文件、正文、计划和MCP引用定位原成功派发回执，并核实际owner、Store、Session、原Run、对象和修订。进度另绑定当前Run；父子Session不互借。Worktree和子工作引用定位原扩展意图／OperationRef，原Store读者继续核范围。Browser页面／元素引用封装准确页面、原代次和快照位置，原controller核本任务、控制权和新鲜度；人工继续的原结果另提供新代次引用。

引用只是定位信息，不能携带批准、放宽当前模式、选择最新对象或重放原操作。公开Schema拒绝旧模型字段，不新增旧数据读取或迁移。仍在使用的内部Browser步骤保显式key/代次输入；模型声明可提供独立纯Schema，由现有表面投影和原Core输入校验分别核验，不另设执行前处理平台。

真实 Luna medium 暴露了将完整 binding／OperationRef 编码成长串仍会抄错的问题。子工作引用改为准确 carrier ID 的短表示，由 Host 从原 Command 和 Store Operation 记录取回完整 OperationRef；MCP 引用只带原执行与 descriptor 序号，准入从原成功回执读取 server，完整配置／代次与 descriptor 也从原回执取回。当前 UUID 对应的子工作／MCP连接引用26字符，资源／prompt31字符，不建额外引用表或进行 ID 前缀匹配。Shell／Evidence 的执行 ID 同样无损缩短，Shell 自动句柄也从原调用ID派生为26字符，不再要求复制70字符摘要。无效子工作引用在受理前的只读核验中明确未执行，实际受理后未知语义不变。

通用观察游标只编码完整scope的SHA-256摘要与原位置，避免200项过滤使返回游标超过自身4096字符入口。摘要不授予权限，原读者继续核范围和位置。

动态 Tool 归属核原已完成 Model 的冻结 toolBindings，不能只看初始 Run 的静态目录，也不以当前目录证明历史；原 Model 的 Store／Session／Run／Step／root work 与 Tool 必须准确一致。

## Alternatives considered

- 只增加提示说明：不能消除模型手抄一致性字段的负担，也不能静态表达互斥组合。
- 自动补齐最新版本或修正身份：可能把原计划批准、文件基线或子工作切换到另一对象，拒绝。
- 每次生成新的操作键来恢复失败：会丢失原意图及未知结果边界，拒绝；宿主键只随已持久Tool身份生成。
- 按命令全文合并所有Shell调用：会把用户明确授权的新执行合并掉，也不能替代目录、范围和未知效果核验，拒绝。只保证同一已持久Tool身份重入复用原操作；观察沿原句柄进行。
- 全部引用限制在当前Run：会无谓拒绝同一Session后续对话使用仍有效的文件回执。原Run身份继续核验，进度和Browser任务保持各自更窄边界。
- 删除统一Browser仍用的内部参数：会破坏当前内部步骤。保内部闭合合同，公开模型入口单独拒绝这些字段。
- 把完整binding／OperationRef直接编码为长引用：真实模型仍会改动其中字段或漏抄尾部，改为只定位原回执；完整身份留在宿主。另建引用注册表会增加写入、接纳不确定性与恢复边界，本次没有采用。

## Consequences

参数校验、准确回执与原授权共同约束执行，错误引用不被猜测或自动重投；无活动目标的默认观察立即返回。Worktree观察只读原意图及Job，即使原结果正文缺失或未知也不重新派发。引用呈现不再额外重验损坏记录，保原失败分类。计划实施仍在各模式下等待人答，批准计划与批准后续工具独立。

2026-11-08，macOS arm64／Bun1.4.4：Luna medium最新完整基线Full／Auto各10组通过，请求批准9/10，另有一次Auto切换场景主动重执行；失败原报告保留。收紧输出目录用途及前后台观察指引后，三模式子Agent／运行中权限切换6/6通过，52次业务及1次审核请求、40个Tool全部成功，每个切换场景的原效果一次、3次切换及固定cwd均确认。短引用中断／MCP续作及三模式Worktree创建观察删除另有定向成功证据。主检出8 workspace构建、6607文件类型检查，Shell93项／685断言及最终反馈52项／473断言通过；隔离Electron计划窗口1项／313断言的未变审批、拒绝及取消路径复用实际过程证据。准确入口与原失败归[模型测试 owner](../../../../tests/e2e/live/model/README.md#全工具真实模型)。

特殊Plan／Output文件适配器与Service描述按同一新模型合同接线，完整正文／Artifact和原机器回执保留。没有旧字段别名、旧数据迁移或版本升级，Store和审核回执仍为1，API仍为/v1；当前内部Job合同不因此删除。原失败和有限验证范围保持，不据后续成功把旧报告改绿，也不宣称所有真实场景或生产99.99%已经取得。
