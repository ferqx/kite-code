# Agent Note: 可见工作区差异持续同步

Status: implemented

## Problem

用户要求打开变更标签后，外部编辑器、Shell 或 Agent 继续改代码时，文件树与选中差异同步。原窗口聚焦和消息触发会遗漏无消息的修改；直接高频重复列表又会反复运行Git、复制索引并撤下正文，打断阅读。

## Decision

仅可见标签持有Main列表lease及文件／Git元数据监听，事件绑定原读取ID和完整scope，不传路径或内容。事件合并后只通知失效，renderer串行取得一个新观察，最多保留一个后继请求；同路径沿原节点更新已确认正文，失败明确保留旧结果，不能当作干净仓库。隐藏窗口、切页、关闭或换scope释放监听与读取。此决定仅取代[单次操作与工作区分离](2026-11-09-native-operation-and-workspace-diffs.md)的刷新范围；历史操作、预算、安全过滤器检查与只读边界不改变。

## Alternatives considered

- 仅靠会话消息：无法覆盖外部编辑与持续Shell写入，不满足需求。
- 每次文件事件都扫描Git：列表本身包含多次子进程与索引复制，连续写入会放大成本；采用批处理、频率上限和单后继。
- 所有平台强制递归监听：Linux Node实现可能逐目录展开巨大依赖树，因此Linux使用浅层通知与仅可见时低频后备；支持递归的平台无健康空闲轮询。
- 刷新卸载整个视图：会丢阅读位置和折叠，采用同身份保留上次结果并核新结果；真正换scope不保留。

## Consequences

同步不是每个写入的事务快照，也不承诺即时延迟；持续写入会批量展示最近读取，后备模式有约10秒加读取耗时的延迟。Git忽略目录的事件未逐项过滤，仍受合并和频率上限约束。当前值与上次结果的读取失败状态必须分清。具体源码、测试和平台限制归[Desktop owner](../../../../apps/desktop/README.md#原文件变更面板与编辑器)，历史文件Artifact不随工作区更新。
