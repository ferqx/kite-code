# Agent Note: Desktop 会话按可见轮次读取

Status: implemented

2026-11-14，分页与占位由[连续历史](2026-11-14-desktop-continuous-history.md)替代。轻量快照、按需详情、阅读锚点与缓存的取舍继续适用。

## Problem

Windows 上已有会话能在运行结束并保存历史后仍显示空白。Shell 采集已截断，但持久回执的正文与详情仍占较大空间，Main 又在选中状态和执行观察中重复发送同一回执。旧窗口策略还会在首次读取时传输全部历史，并在累积挂载后持续增长。

## Decision

会话选择只读取有界的运行与操作事实。近期消息可先展示，早期历史使用固定水位下的轮次位置索引。视口触及占位时按原消息身份读取，正文接管后保持该身份和屏幕偏移。折叠工具和超大正文沿原身份按需读取，区分观察恢复与业务写入。

## Alternatives considered

- 继续缩短 Shell 采集会改变已保存证据的边界，且无法覆盖非 Shell 正文和旧会话。
- 分页按钮可以限制单次读取，但用户选择保持连续滚动，并要求在轮次进入视口时才读取。
- 仅保留最新的 DOM 窗口可以减少节点，但无法消除选择快照和首屏历史的传输成本。

## Consequences

轮次索引与正文独立读取。跟随尾部时按索引提交后的内容范围选择挂载窗口。断线后的新基线保留已读轮次，进视口时重新核对原正文，继续用原历史身份恢复阅读偏移。

原会话和隔离长历史的 Windows 实机切换、重开、占位接管和本机事件流恢复证据见 [Desktop owner](../../../../apps/desktop/README.md#执行观察与操作准入)。旧的[按消息加载](2026-10-26-desktop-progressive-history.md)仍提供折叠详情、身份锚点、滚动和缓存生命周期的依据，并记录旧服务兼容路径的取舍。
