# Agent Note: Desktop 连续历史与后台恢复

Status: implemented

## Problem

按可见轮次读取增加了索引、消息正文和当前观察之间的交接。索引失败只提供手动重试，轮次失败后退出可见读取，运行中的会话也可能显示覆盖阅读区域的同步提示。用户要求撤下分页、占位及会话读取失败提示。

## Decision

Native 沿轻量快照的固定水位分批读取完整历史，然后按持久游标合并变更。会话呈现为连续时间线。读取中断由已有观察恢复机制自动重试，保留已显示的版本，成功到达覆盖界限后恢复相关操作。过期游标立即撤销旧观察，交由新的会话视图建立基线。

首次构建长会话时使用可被后续选择打断的 React 更新。整段已读消息保留在同一 DOM，浏览器推迟离屏布局，便于直接滚动、原生全选与恢复阅读锚点。轮次产物查询单独按接近阅读区的原轮次启动，从而避免为首次显示发起整段历史的文件查询。

## Alternatives considered

- 保留轮次索引并为失败占位自动重试：仍依赖两个读取路径交接，且与用户明确撤下分页的要求冲突。
- 把失败提示移到输入区：仍把后台恢复交给用户，本次移除其界面入口。
- 一次请求传输全部正文：会使长历史重新碰到传输和 IPC 预算，所以保留有界批次、原记录身份和超大正文的独立读取。

## Consequences

连续历史首次读取与渲染随正文规模增长。轻量快照、超大旧正文预览、详情延迟构造、阅读锚点和缓存边界继续适用。分页版本的设计取舍与实机证据见[可见轮次记录](2026-11-14-desktop-viewport-history.md)及[原消息窗口记录](2026-10-26-desktop-progressive-history.md)，现行读取与验证归[Desktop owner](../../../../apps/desktop/README.md#执行观察与操作准入)。
