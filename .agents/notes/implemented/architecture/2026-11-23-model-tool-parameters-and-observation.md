# Agent Note: 模型工具参数与原执行证据

Status: implemented

## Problem

真实模型调研发现，模型需要逐轮保存并复述一部分宿主引用，技能已经完整可见时也可能重发正文。浏览器代码把观察与多次输入混在同一次调用里，使过期引用和部分执行的原因难以定位。

## Decision

协作者用稳定目标投递，轮次继续用独立派发身份归属结果。Shell 用整数会话号继续原命令。覆盖和编辑由宿主从当前封存请求选用实际读取过的版本。只有相同完整技能正文仍然可见时，重复加载返回简短状态。浏览器按操作提供结构化入口，复用严格的原页控制、动作派发和未知结果处理。

结构化浏览器通过同一页面 Job 取得控制与资源，只有执行脚本时才创建代码 Job 和独立进程槽。沿用同一页面状态、原回执与取消边界，避免读取页面也依赖脚本资产。协作者标识由同一目录血缘的首个锚点查询，目录摘要继续提供任务与状态。

当前参数和实际语义归[模型工具 owner](../../../../packages/agent/src/model-tools.README.md)，完整执行与复验归[已确认方案](../../../../docs/plans/kite-agent-real-model-test-plan.md#模型工具入口调整与复验)。

## Alternatives considered

- 继续让模型回填基线、协作轮次和 Shell 输出游标。宿主仍需核对这些身份，模型拼写错误和重复读取会增加回合。计划与 MCP 的独立业务引用继续适用[原准确引用决定](2026-11-08-model-tool-exact-references.md)。
- 将 Shell 改成交互终端。当前受管 Job 使用关闭的 stdin，交互终端需要独立输入和清理边界，现有命令与续读接口即可满足本次场景。
- 以读技能时的内存标记去重。模型上下文压缩后可能缺少正文，因此使用本次封存请求证明正文仍然可见。
- 继续只让模型执行浏览器脚本。结构化输入可以在派发前核目标，并用原执行记录交代批量表单中实际完成的字段。

## Verification

官方 OpenAI Responses `gpt-6-luna`／medium 复验确认协作续派、Shell 区分两个原 Job、文件身份变化拒写、PDF 选页、技能正文只进入请求一次、旧元素零派发及网站回执丢失后只入账一次。大规模协作观测到 32 条实际活动流，原 64 KiB 联合检查点未命中。Native 选区有成功和早期未触发原 Run 的证据，按[验证方案](../../../../docs/plans/kite-agent-real-model-test-plan.md#模型工具入口调整与复验)区分记录。

## Consequences

模型窗口缺少原文件基线时需要重读。错误或取消仍要区分已知未派发和效果未知。标签页控制的续接依赖已确认清理和原页面身份。同一页不同原生元素的动作须分别核实。
