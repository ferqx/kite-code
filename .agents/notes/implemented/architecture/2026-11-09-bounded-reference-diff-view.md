# Agent Note: 参考图差异阅读与有限渲染预算

Status: implemented

## Problem

用户认可参考图中的紧凑编辑器、双栏对齐、右侧目录树、行号与增删色，并要求在Kite落实且注意性能。此前可靠的操作diff与Git读取已经接通，但简单逐行文本和展开卡片不满足本次明确的阅读设计。图片中的完整编辑器能力不能直接视为当前数据或授权；有界预览不包含整份文件，也不能凭截断部分声称完整统计。

## Decision

保留[原来源与取消边界](2026-11-09-native-operation-and-workspace-diffs.md)，只在共享只读模型中解释原操作预览和标准Git patch。双栏和统一视图复用同一有限模型，已保留上下文可折叠；缺失上下文、未知旧行号和未读取的增删统计不补造。一个ScrollArea拥有两侧滚动，轻量同步词法标记受总token预算约束，超限回退纯文本。预算归[UI owner](../../../../packages/ui/README.md#文件差异的按需与有界显示)。

工作区沿原变更标签显示单个选中正文和右侧目录树，树节点固定分页，最多2048个目录与1000个文件，超限保留剩余相对路径和全部已准入文件；路径与深度仅在展示侧有界处理，Main仍只接收原不透明观察ID。同视图只保留一个选择意图、筛选值与布局偏好；刷新重新核准观察，切scope、过滤排除与关闭释放旧reader，不维护全文件正文缓存。原可拖动分栏首次准备较宽阅读区域，之后不覆盖用户尺寸；窄布局仍可访问文件列表。

## Alternatives considered

- 把参考HTML直接当客户端实现：参考数据和行为是模拟，会绕开原Main身份、错误与取消边界；只迁入视觉规则。
- 嵌入完整编辑器并拉取所有前后全文：会扩大依赖、读取与内存，当前只需有限只读差异；保留既有组件和宿主事实。
- 为全部文件计算总增删或同时渲染双栏正文：会将选中按需读取变为全仓工作，截断也不足以得出准确总数；树只展示实际状态，计数标记为预览。
- 无限追加文件节点与对每行异步语法着色：持续交互可累积DOM和缓存；选择固定页面、单正文和同步总token预算。
- 为折叠行重新请求完整文件：会混淆历史和当前内容且突破预览预算；只有模型中实际保留的上下文可展开。

## Consequences

预览可以解释改动而不成为编辑器；超限、二进制、冲突、未知格式和错误仍有真实提示。目录分页、未知行号留空、部分上下文不可展开是有界读取的明确代价。参考图的图标、统计或菜单不构成未经实现能力。实际验证与浏览器／Native窗口限制归[Desktop owner](../../../../apps/desktop/README.md#原文件变更面板与编辑器)，DOM或构建通过不能替代视觉与完整原生旅程。

共享右栏有宿主变更内容时采用240px／85%的边界，因此切到浏览器或子页后仍允许保留阅读宽度；仅变更页首次打开准备62%，不会为了普通页主动扩栏。没有宿主变更内容时继续沿用300px／640px。
