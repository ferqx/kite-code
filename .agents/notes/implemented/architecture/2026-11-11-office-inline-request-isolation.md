# Agent Note: Office 局部修改请求隔离

Status: implemented

## Problem

用户要求选中办公内容后在原位置输入修改要求，按 Enter 直接发给 Agent，而非只将选区加入聊天草稿。Office 转换页面不是可信应用页面，不能读取或篡改用户输入；已有聊天草稿也不能被局部发送误消费。

## Decision

选区仍在预览的独立 world 冻结。Main 用原文件身份、SHA、位置描述和有界矩形建立单独的可信 sandbox 输入 View，不向 Office DOM 放入提示文字或桥。Enter 产生一次请求，复用原 InputFile 工作副本与 caller journal；Main 核对独立提交材料与注册输出引用，跳过普通 composer 草稿的匹配／消费，而非改写或暂存后还原草稿。请求未知时不自动重发，仍保原命令的核实与准入边界。

连续区域、预览页和工作表请求沿同一边界，不把页内脚本、DOM 属性或真实点击当授权。宿主白名单复制描述并核实际文件类型，原 target／SHA 始终来自受控快照。每个浮动范围用冻结 serial 贯穿输入寿命；排版失效仅撤原 serial，投递前再读并核 owner，关闭按原 serial 精确释放，防迟到结果误关后继输入。

Word 采用实际 HTML 排版 settled 代次与完整正文源块映射，不用章节或滚动位置伪装原生 Word 页码；标题明示预览页正文，页眉／页脚、页码、水印和背景不在该范围。不完整正文页保预览与文本选择但拒页级请求。Excel 整表与单元格矩形使用不同 scope，范围必须完整且有界。旧稀疏范围仅作为待重选草稿数据恢复，仍保普通文字、附件及原 CAS；新提交保持严格，不剥掉范围后静默改成整文件请求。

Excel 名称框与只读值／公式栏仅展示文档已经拥有的选区材料，保留定位、展开和复制的实际用途，不增加地址编辑或单元格写入。用户输入修改要求仍在独立可信 View；不能为了模仿公式编辑栏，把提示文字放回文档 DOM 或增加无用的确认／取消编辑按钮。整体选区覆盖与表头默认网格修复也不改作者单元格样式或扩大范围授权。 冻结纸面与作者边框仅以有界、非交互绘制层修正固定转换器的透明／collapsed 绘制缺陷，不重写表格布局；选框覆盖外围共享边而保内部作者边，取消交还原样。复杂映射拒绝而非推断缺格，保持文档描述不可信的原边界。
原字节／适配／交互的同源对照确认强制字体改变了部分行高，亦确认原转换器自身已有网格缺陷。因此离线层去掉全局字体覆盖而保本地资源，Excel 只读栏移至可信宿主、在 native viewport 外让位；选框留在文档内的独立 ShadowRoot 纯绘制层，保受控定位 serial 与必要网格兼容。此处样式隔离不能替代原文件身份和请求授权，作者字体缺失仍按系统回退；新版可见与联合验证状态以 owner 和当前计划为准。
## Alternatives considered

- 在 Office HTML 中直接加入 textarea：转换器脚本共享 DOM，可观察或改变提示文字，不采用。
- 只在主 React 页面画输入框：原生 WebContentsView 覆盖主 renderer，无法可靠显示在所选对象附近，不采用。
- 全屏透明 WebContentsView 承载选框再转发点击：当前 Electron 没有已证实的每 View 点击穿透，CSS pointer-events 不能证明跨 View 输入穿透；转发合成事件也改变可信输入边界，不采用。仅把可放在预览区域外的只读栏移到宿主。
- 只将选区加入聊天草稿：不符合用户明确的局部 Enter 发送交互。
- 暂时覆盖普通 composer 草稿再发送和还原：会与正在输入、附件和私有草稿 CAS 并发，可能丢失或误发内容，因此使用独立材料。

## Consequences

新增输入 View 遵循全局 overlay 层级，没有 preload、Node、Native bridge、网络或导航能力。已有预览和不可变历史 reader 的安全边界不放宽；不恢复本地插入或写入 RPC。局部发送的 accepted 表示请求已接收，文档修改仍由 Agent 执行。当前实现与实机验证范围归 [Desktop owner](../../../../apps/desktop/README.md#办公输出文件)。
