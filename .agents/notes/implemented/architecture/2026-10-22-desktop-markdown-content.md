# Agent Note: 桌面 Markdown 的图表与扩展内容展示

Status: implemented

## Problem

用户要求桌面消息支持 graph 等丰富内容，同时保持透明底、细线和表格统一边框。原 GFM 把图表和公式作为文本，脚注虽然生成却无法跳转。把消息直接变成带脚本、外部资源或自定义样式的HTML会越过现有展示边界；流式未完成源码也不应持续报错或覆盖当前阅读。

## Decision

扩展由[共享桌面 renderer](../../../../packages/ui/src/desktop/MessageContent.tsx)负责，纯固定parser同时加入公式供Native Worker复用。高亮、提示块、公式排版与图表都是派生展示，不改写原正文、完整读取证明或复制来源。独立Web／TUI和输入草稿的可视化范围保持各自契约。

2026-10-25用户调整视觉要求：细线过多，各类元素需要自身样式，表格保留原样。初版的通用透明底／细线要求因此只继续约束表格、普通引用与绘图；行内代码和代码块改用轻底色，提示块改用按类型区分的底色、图标和标题，链接默认用颜色、交互时显示下划线。采用已有组件和共享主题变量，不变更解析、源文、复制、权限或图表安全范围；代码和编辑器的具体样式由[UI owner](../../../../packages/ui/README.md#markdown-提示词编辑)维护。

Mermaid首批只接受流程、时序、类、状态和ER图的非交互语法，围栏闭合后懒加载本地库。禁止配置指令、frontmatter、HTML、自定义样式、点击与图片／图标语法，使用strict模式和纯文字标签。客户端主题去掉填充和阴影；按用户后续反馈，边框和箭头采用蓝色、生命线等辅助线采用青色，并分别适配深浅主题，避免把透明底误解为全黑白。以SVG image显示结果，不挂载生成的SVG DOM或事件绑定。源码长度、边数和生成图大小设限，错误／不支持／超限均保留完整源码；原CSP不放宽。图表按自然尺寸显示，超出阅读列时内部滚动。

Mermaid的初始化与绘图共享全局状态，所以在同一串行队列运行；AbortSignal使尚未开始的任务退出，并阻止正在计算的迟到结果发布。已开始的同步布局不能被中途抢占，输入上限不等于固定CPU时限。图表随现有会话Activity停止观察和新计算，已显示图计入原缓存资源预算；窗口隐藏释放，恢复重绘。源码展开状态保留在原组件，不恢复旧操作资格。

标题和脚注ID按消息实例隔离。fragment仅解析当前消息已有目标，点击后在该消息内滚动并移动焦点，不依赖页面全局hash或文件打开回调。

## Alternatives considered

- 继续只显示源码：无法满足已确认的图表、公式与高亮需求。
- 直接插入可交互SVG：可提供节点点击和HTML标签，但扩大消息的DOM、事件及样式能力；首批阅读需求不需要这些能力。
- sandbox iframe：可进一步分离文档，但现有CSP禁止frame，布局测量和主题／生命周期交接也增加独立运行面；本次采用受限输入、strict渲染及SVG image，不增加frame权限。
- 用远程服务生成图表：会外传正文并引入网络依赖，因此未采用。
- 每个流式片段立即解析：会反复解析未完成语法，增加错误闪现和主线程工作；等待围栏闭合，当前源码保持可读。

## Consequences

新增依赖与图表模块增加静态制品体积，Mermaid按需加载。代码高亮与公式排版在renderer运行，Worker仍只负责纯语法解析。图表不承诺完整Mermaid配置、交互或任意大小；公式采用KaTeX支持的语法。背景、尺寸限制和错误回退以[UI owner](../../../../packages/ui/README.md#markdown-消息内容)为准，操作及客户端范围归[桌面手册](../../../../docs/handbook/clients/desktop/README.md#提示词与附件)，实际浏览器、Worker与平台证据归[Desktop owner](../../../../apps/desktop/README.md#markdown-与附件输入)。
