# Agent Note: 会话文件复用文件工具与不可变历史

Status: implemented

## Problem

2026-10-23 用户确认：上传附件在源文件删除后仍须可读，重开会话仍能看到历史图片；Agent 输出与 Plan 方案必须真实落盘并能在后续对话修改。实施前图片已保存原件，但普通文件仅有路径引用。输出若只有不可变 Artifact，无法直接维护当前工作文件；若所有消息只指向可变路径，修改会改变历史交付。

用户进一步要求不设计面向附件缓存的专用工具，Agent 通过文件工具读取。当前 Profile 受保护且 Blob 不可变，直接给普通文件工具放开整个目录会泄露不相关私有内容，并破坏存储完整性。Plan 文件写入也不能绕过原 Run／版本批准。

## Decision

复用 Artifact 保存上传原件、交付快照和历史工具正文；会话独立输出与当前方案存为持久可编辑工作文件；PDF 提取文本与页图使用可清理的派生缓存。统一通过现有文件工具表面访问，宿主按准确 Store／Session／subject、来源引用及用途解析登记路径，不新增缓存工具，也不全局放宽私有目录保护。

原件已是物理 Blob，不默认增加第二份永久 inputs 副本。读取 Blob 必须反查实际引用和完整内容；可写文件不能用硬链接或目录联接与 Blob 共用对象。历史消息引用交付快照，后续修改使用当前工作文件。普通工作区源码继续沿已有 Files／检查点合同。

方案文件是可编辑草稿，原 Planning 记录继续拥有步骤、封存版本和批准。审阅从实际文件封存准确内容；普通文件写入与既有计划工具通过同一协调路径，修改后旧批准不能继续派发新版工作。Plan 只开放准确方案目标，不把通用写工具伪装为只读工具。

PDF 解析和缓存留在宿主文件读取内部；UTF-8 正文复用既有完整交接，页图必须补真实视觉结果到模型输入的协议，不能以 PNG 路径代替图像。缓存不承担历史权威，已交给模型的结果持久保存。

当前行为和数据交接归 [Files](../../../../packages/agent/src/tools/files/README.md)、[Planning](../../../../packages/agent/src/business/planning/README.md)、[维护](../../../../packages/agent/src/maintenance/README.md#会话工作文件与-manifest-v20)和[桌面手册](../../../../docs/handbook/clients/desktop/README.md#提示词与附件)。本决定已完成 Windows 开发交付范围；[Desktop](../../../../apps/desktop/README.md)与[Terminal](../../../../apps/cli/docs/terminal-release.md)分别保存客户端过程、正式候选证据和未取得的安装／平台资格。

## Alternatives considered

- 普通附件继续只传原路径：实施前路径引用不满足删源后的历史读取，因此新上传需要持久原件；旧历史引用不静默迁移。
- 新增 `read_attachment/search_attachment`：前期讨论过，用户明确选择文件工具统一读取；格式解析和缓存由工具内部承担。
- 全部内容放在自动过期缓存：会丢失已发送附件和未交付修改；必须区分持久资产与可重建内容。
- 每轮传入所有附件全文或 PDF 页图：读取及上下文成本较高；文本／PDF 按范围读取，当前直接图片输入保留。
- 只保不可变 Artifact：适合原件和历史，缺少可编辑当前文件，因此增加会话工作文件。
- 只保一个可变输出路径：旧消息随新编辑改变，交付时须另封存快照。
- 再永久复制全部原件到 inputs：Blob 已保存字节，默认双份增加磁盘与清理成本；仅具体消费者需要时生成受控副本。
- 放开整个 Profile 给 Files 或 Shell：扩大数据库、凭据和其他会话访问，拒绝；仅适配准确登记目标。

## Consequences

已验证上传原件与删源重开、文本／PDF 读取、输出连续修改与历史版本、Plan 准确文件和批准、缓存重建、Fork 隔离、备份包含最新工作文件及未知回执查询。Native 隔离页面和真实 IPC／Service 分别观察准备、取消、提交占位接管、故障与重开；TUI 原生过程及全新正式候选沿原预算验证，未将受控页面等同于完整 Electron 安装版。具体命令、环境和断言范围留在上述 owner，不由本 Note 推定其他平台资格。

文本和页图复用同一文件工具表面，减少专用协议，但模型是否能理解视觉内容仍取决于实际端点。两协议 wire 与真实模型扫描页／柱图结果分别保留；单个正确样本不保证任意字体、复杂排版或识别准确率，不支持视觉的端点明确失败。

文件系统与 SQL／消息发布没有跨介质原子性，保留原身份、pending 与 unknown，不以盲重试补齐。输出发布后半段失败仍阻断后继工作；Plan 未完成发布或文件漂移不能沿旧批准执行。文件登记、Plan 协调和维护 manifest 使用准确版本，v20 保存实际当前工作文件，旧备份格式与新 Store 独立授权不放宽。

PDF 解析器、Canvas、字体与 CMap 增加打包和平台成本。固定解析器的已识别字体失败明确拒绝，不发布静默替代结果；实际输出预算、取消调度和缺失资源恢复已有有限验证。Worker 不构成 OS 沙箱，物理线程退出、机器 OOM／硬内存隔离及完整安装资格不能由这些测试推定。缓存命中不能绕过授权和完整性；完整源校验仍扫描原件，不承诺低成本随机 IO。
