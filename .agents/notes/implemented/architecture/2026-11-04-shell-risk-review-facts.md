# Agent Note: Shell 风险事实与审批策略分工

Status: implemented

## Problem

自动审核同时解释 Shell、判断风险和核任务授权，真实模型会把能力上限误当实际效果，也会在相同 argv 下随脚本内容改变调用关系判断。仅追加提示词例外出现回归：危险预处理脚本被误判为不执行而获批。已测语法子集补入中立调用事实后，12 个定向样本的决定和关键理由符合期待，但不证明通用解析或稳定正确。

## Decision

[默认 Shell 风险审核超时停止](2026-11-14-shell-risk-review-timeout-stops.md)替代了默认 Shell 审核的输出上限和超时放行。原时间预算、审核材料与执行证据继续适用。

默认可信内置 Shell 使用独立风险合同；Shell owner 提供可核实 argv、参数消费关系和允许读取的直接入口快照，模型只输出 ordinary/high/critical 与短理由，Core 按冻结合同映射为原 approve_once/ask_user/reject，并分别保留原风险输出和派生决定。新合同不读取或发送任务、计划、委派、历史输出，也不因材料不全回完整业务窗口。其他可信内置能力跳过这项语义审核，仍核原硬准入与独立人工要求；自定义能力不因同名取得该标记。

只读任务由业务指导、原工具集合和已有硬边界表达，必要临时探索不授权修改业务文件；不新增角色 OS 禁写、命令白名单或 Agent 运行阶段。事实不包含风险答案，不识别的语法或程序身份明确标注缺项。缺少未知程序正文本身不升级高危；已知删除或外发的关键目标／载荷未知才形成具体风险不确定性。

复用现有审批、缓存、最终派发和 Tool→Job 证明。Auto 的复用身份加入审核合同及材料 fingerprint；动态程序及依赖不完整的材料不扩大跨独立调用复用。准确自身 Job 复用模型／人工材料依据；有效 Auto 相同命令人工 grant 沿当前授权校验继承，不宣称当前脚本材料已被重新审核，也不改变手动分层授权。Shell 在有材料批准标记时于启动前复核已封存入口；timeout 不取得该标记。直接快照只读工作区内受保护路径规则允许的普通 UTF-8 文件，最多64KiB，不递归扫描依赖。

超时仍默认通过本次语义审核并保原请求范围，不伪造批准、不缓存超时；材料准备的实际异步工作保留配置租约直到结束，不拖住已超时调用。已知准备失败不能因后续持久化等待跨过期限而变成超时放行；非超时技术失败和独立人工要求保持。新 Run 冻结合同标记与完整提示词／固定映射摘要，旧 Run 与自定义审核器恢复原合同，旧封存输入不改写、不重发，残缺或不匹配标记在模型装配前拒绝恢复。

本决定部分替代[原审核输入设计](2026-11-04-auto-approval-budget-and-execution-evidence.md)中的默认任务授权材料方案；其超时、执行证据、压缩和未知效果理由继续适用。原任务授权材料与 recordedReads 只继续服务旧 Run／自定义审核合同。

## Alternatives considered

- 继续扩充提示词的命令例外：真实样本出现修复一类语法后另一类高危误放，不能独自承担可确定的参数解释。
- 让事实解析器直接批准 Shell：语法事实不代表代码安全，不能代替效果判断。
- 所有未知程序或不支持语法都转人工：把材料缺失当高危会重复误拦。
- 构造通用 CLI 解释器、递归扫描依赖或增加文件系统监听：超出当前有证据的最小修复，不提供相应保证。
- 全局替换自定义审核和历史输入：会改变已冻结合同，采用新默认合同显式选择。

## Consequences

有限语法事实和直接入口快照不覆盖任意动态依赖、配置或所有外部进程修改竞态。原生文件快照内部存在同步读取，预算控制不提供卡住的 OS 文件系统读取可被毫秒级中断的保证。未知正文默认 ordinary 是已确认的风险判别政策，不认证未知程序安全；风险模型仍可误判，原权限及沙箱不保证所有语义高危必被阻止。只读和精确交付要求仍须业务 Agent 遵守，不能由风险审核代做任务授权。工具定义及协议版本不变，不更新 HTML。

当前合同、实现与回归归[权限 owner](../../../../packages/agent/src/permissions/README.md)、[Shell owner](../../../../packages/agent/src/tools/shell.README.md)、[授权合同](../../../../docs/active/authorization.md)及[真实模型入口](../../../../tests/e2e/live/model/README.md)。

2026-11-04 macOS arm64／Bun1.4.2 实测：冻结生产提示词、解析与映射后，42份合成风险输入全部分类、决定和关键理由符合预期，原模型为 gpt-6-luna／low。再用真实 Service 默认策略、原生 Shell 和测试注入的同模型 adapter 跑三模式与主／可写子／只读子9格，共129次真实请求；15次 Auto 风险判断及15个自身 Job 的父依据复用、24个失败 Tool 到准确下一模型的完整回执均独立核对通过。业务目标仅4格完整通过，手动只读格完成查询但范围漂移，其余4格失败，原机械5过4败不改写。这些结果及失败归测试 owner，不扩大为所有任务可完成的资格。语义测试与自然流程分别放宽审核预算以检查正确性，不证明生产3秒期限、默认 SDK transport、完整客户端窗口或长期稳定性。
