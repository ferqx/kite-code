# Agent Note: 单项审批拒绝与整轮停止的回执

Status: implemented

## Problem

同一模型回复可以包含多个独立授权的工具。拒绝一项审批曾取消同批未开始的工具，并打断已经运行的工具。用户也可能在模型调用已保存、对应工具还未登记时停止整轮，造成后续模型输入保留调用却缺少配对结果。

## Decision

- 人工拒绝只结算提请审批的调用。同批其他工具各自完成排队、权限复核和派发。模型请求中的调用和工具结果都按模型给出的顺序排列，工具可以按实际完成顺序落库。
- 用户停止的来源和准确 Run 范围与取消命令一起保存。异步上下文准备在最终派发检查前完成，适配器在入口核对取消信号。正常结算和冷恢复从原持久模型回复补齐未登记或未派发且缺少回执的调用。已执行的结果、未知副作用和恢复边界沿实际证据处理。
- SQLite Store 在同一 Profile 内序列化同 ID 的命令写入，预先查无持久记录才发本地停止信号。实时停止可在 SQLite 写锁解除前生效，相同 ID 的重放或冲突沿持久事务判定。
- SDK 以 Provider 的调用索引为顺序依据。冷恢复先识别已停的模型批次，以原输出和工具身份为未执行调用配对，普通恢复仍核原输入。审批拒绝以原 `interaction.answer` 的应用回执为准，已生效的拒绝优先于后来的停止。

## Alternatives considered

- 保持拒绝时取消整个工具批次。这样会中断已授权的独立工作，用户无法只拒绝本项。
- 停止后只提供一条整轮说明。模型历史中的原调用仍需要按调用 ID 配对。
- 丢弃停前已保存的调用。这样会丢失模型已经请求执行的事实，部分结算的工具批次也会变得不完整。

## Consequences

同一轮后续请求可以同时看到人工拒绝和独立工具的真实结果。停止尚在结算时可提交下一条消息。即使进程在保存停止后、结束 Run 前退出，下一次请求也能配对原调用，包含原参数无法解析的未派发工具。未知效果仍约束本批后续派发及恢复。

本决定部分替代[工具结果保留 Agent Loop 的解释能力](2026-10-29-tool-results-preserve-agent-loop.md)中的人工拒绝联动取消。原决策关于工具结果入历史、结果未知和存储完整性的理由继续适用。范围与证据见[权限边界](../../../../docs/active/authorization.md)、[恢复手册](../../../../docs/handbook/features/recovery.md)和 [Responses 请求测试](../../../../apps/service/test/isolated/responses-loop.test.ts)。
