# Agent Note: 以准确工具反馈和任务证据改善 Agent 行为

Status: implemented

## Problem

2026-10-23 的父子会话暴露了三类相连的问题：模型看不到预设的实际能力限制，给只读子 Agent 分配了需要派发进程的步骤；不存在的 Shell 引用抛错后被当作未知效果，连带中断正常读取；内容搜索只接受目录、遇非法编码整体失败，模型反复换路径重试。另一条子任务读取了旧实现，以同名符号和文件存在代替当前入口可达性的证据，父任务没有核实决定结论的连接。

原结果实际完成了单次投递和父任务续报，不能将本次问题归因为重复消息或结果未接纳。`Run.completed` 只说明执行轮按运行时条件结束，不能证明自然语言任务的全部结论正确。改善需要同时覆盖工具可用性、模型实际可见的能力、证据使用及收束；只改展示或继续叠加运行状态无法解决这些问题。

同日后续真实会话在新版合同与工具已加载时仍产生 83 次搜索，其中一个子任务 54 次搜索、17 次零命中，最终混接旧装配和当前实现。2026-10-24 的隔离真实模型复核进一步暴露了有限字面搜索被解释为全局无引用、子报告原文误读被父级沿用的问题。这些实际失败重新打开本决定的检索收束与结果采用范围，不能归为客户端未重启。

## Decision

在负责模块能确定事实的位置处理失败。[Shell](../../../../packages/agent/src/tools/shell.ts)仅把本地引用缺失或记录类型不符的预查转成带纠正信息的 failed；该查询没有启动或停止目标 Job。Store 异常、已取得引用但无法核实的结果及真实派发后的未知效果继续保守结算，不全面捕获异常，也不从普通返回字段推导权限或派发事实。

[Files](../../../../packages/agent/src/tools/files/README.md)的最初 `files.search@3` 接受单文件和目录；模型默认每页 100 条、每行 2000 个字符预览，明确续页和截断。复用已锁定的 ignore matcher，所有实际读取继续走原 native 路径、FD 和身份检查。根目录默认解释范围内的 `.gitignore`；显式文件与非根目录保留明确范围优先级。二进制与非法编码作为当前页未检查项返回，权限和 I/O 错误不伪装成跳过。低层未指定上限时保留完整匹配和长行能力。新增参数继续沿原模型名称投影，同步准确只读定义版本白名单及 bundle 依赖声明。

[Task](../../../../packages/agent/src/extensions/task/README.md)从实际注册目录生成默认角色和开放预设说明；私有预设不泄漏，说明不增加父子能力或审批权限。保留六个协作工具、普通 child 异步受理、稳定身份、完整结果 Source 和真实接纳机制。模型按必需步骤选择角色，父任务核实会改变结论的关键依据。

[共用行为合同](../../../../packages/agent/src/model-context.ts)先定义任务推进和直接交付，再集中保留授权、协作、证据及连续性规则。证据要求约束模型如何判断，不是固定回答模板；委派只传达结果和必要约束，不把约束扩展成逐字符、完整元数据等额外报告任务。合并多处重复的描述和证明要求，而非持续增加输出禁令。可纠正失败按具体反馈改变方法，代码研究从当前入口追踪到实际效果；保留原输入和后续纠正优先、压缩不重放、一次性限制、真实 unknown、计划只读与独立权限边界。子报告与独立观察分开，快照一致只证明观察时内容一致，不能据此推断历史没有写入。

沿原测试设施补充真实任务验证，分别保存原 Model 输入/输出、工具、结果及代码证据。机器断言负责可核对的调用、原文、来源和状态，全文中的推断、覆盖范围及表达比例须结合完整轨迹判断。二者不合并成一个“模型已正确完成所有任务”的结论。

后续实现把取证观察放回实际数据路径：[Files](../../../../packages/agent/src/tools/files/README.md)返回准确 query、实际扫描统计、命中文件 baseline，以及 lookup／inspection observation。读取附当前窗口的有界原文片段，明确完整性；搜索在零命中、分页、跳过及字面模式符号时给具体范围解释。字面扫描完整不等于调用链完整，更不证明全局不存在其他实现。

[通用观察 leaf](../../../../packages/agent/src/tool-observations.ts)不识别具体文件工具 ID。子取证预览只取成功、配对且属于准确 Run／Session／Store 的原回执观察；大正文与观察元数据分别交接，不把选定历史外或已压缩工作当作未发生。没有搜索／读取累计额度，也没有按次数注入的默认收束提醒。

成功 child 的原结果保正文，在 `details.evidence` 携带宿主核原执行身份后的有界取证预览，包含读取窗口、版本与原文。父级能直接对照总结与实际片段，再独立核决定结论的入口连接；不要求复做全部子工作。预览明确 selected-history 边界和遗漏，完整原回执仍持久保留；后续 child Run 不混入旧证据。预览不能作为语义真值、权限或新完成条件。将取证数据与结论放在同一原结果 Source 中，避免为取得这些基本依据额外轮询或要求子任务重复发报告。

该决定延续[模型工具表达](2026-10-18-model-tool-presentation.md)的内部身份与公开名称分离，以及[普通循环检查点](../bug-fix/2026-10-17-normal-loop-checkpoints.md)的原派发事实、精确重复失败与原轮次归属；不替代这些仍有效的安全和恢复理由。

2026-10-24 后续核对发现，模型原输入重复携带 query、observation 和读取 excerpt，多个 complete 表示不同范围；child 原文证据位于报告之后的嵌套字段。这些是呈现负担，不能直接归因为模型能力不足。按用户确认，增加 owner 同步纯 formatter，将工作区读取／搜索和成功 child Source 的关键事实、范围及原文集中呈现，原取证数据与完整 Artifact 仍持久保留。转换位于 Runtime 的模型历史组装阶段，预算、压缩、重试与封存输入共同使用实际文本；旧快照只读原呈现。未识别结构和异常 formatter 保留原结果，真实正文读取失败继续拒绝。

效果沿原真实任务设施做固定模型、系统合同、任务、配对文件字节与路径的 8 次对照。原始呈现仅由隔离测试实例覆盖模型呈现方法恢复，生产没有调试开关；实际 HTTP 正文、原 Store 和封存模型输入分别核验。检索次数、输入量、决定性证据齐备后的操作与全文结论分别记录，不以缩短返回或少搜索推导核验正确。结果与局限归真实模型 owner。

2026-10-24 的下一轮决定先修工具合同：读取声明明确 `next_line → start_line`，搜索升级到 `files.search@4`，明确 `next_cursor → cursor`，而非要求模型猜原内部字段。搜索以 `files` 定位命中文件、`content` 返回匹配行；默认前者能避免同一长文件的大量行命中淹没文件集合。它仍搜索实际字面正文，不静默排除归档、文档或旧实现；游标绑定原模式、查询、范围和过滤条件，实际扫描与返回数量分开。

本轮对工具集合的整理以真实动作和独立用途为边界。普通宿主在合格 Shell 上提供20项，无 Shell 时15项；计划／验证、Skill、Workflow、MCP仍按原显式配置选用。保留路径查找、正文搜索、读取、修改和进程／协作生命周期的实际职责；不因内部旧定义对模型隐藏就删除可信消费者。实际默认及条件目录归[模型工具 owner](../../../../packages/agent/src/model-tools.README.md#工具选择与职责)。

早期实验曾增加研究工作状态工具，把模型填写的问题、来源引用及子报告处置经 CAS 再存入 records/context。首轮双 checkout 实测反驳了将其作为默认改进的预期：A合计41个Model请求、92次工具、14次搜索、285229输入tokens，B为52／104／11／445086。B仅一项委派在结束前保存一次21745字符状态，且经历两次真实引用错误；状态没有纠正profile误读，也保留了有限搜索推全局无引用的判断。原93份请求三方身份／全文核验通过，只证明输入、执行与记录真实。全部八次与负结果保留在[真实模型owner](../../../../tests/e2e/live/model/README.md#工具合同与研究状态的双-checkout-对照)。

按后续需求全部撤回这一未提交实验，而非保留显式启用入口：删除工具、导出、记录和上下文投影、权限例外、宿主选择、桌面标签及测试注入；也删除 Files 为其增加的模型引用 UUID。原成功 ToolResult、Source、Artifact 仍负责观察事实；模型写入的来源索引或“采用”状态不能成为第二份事实权威。原计划和验证工具有已有批准、版本及实际执行用途，不与这次研究记录混同。

工具设计核对采用[官方工具工程原则](https://www.anthropic.com/research/writing-tools-for-agents)、[官方工具参考](https://code.claude.com/docs/en/tools-reference)和固定版本的[公开执行工具声明](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/core/src/tools/handlers/shell_spec.rs)、[公开计划工具声明](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/core/src/tools/handlers/plan_spec.rs)。采用职责清晰的原语、默认按命中文件定位、显式按行取内容、准确续页参数和可操作的失败结果；计划只记录步骤，不能证明自然语言结论。其他产品按平台选择进程检索或专用读取工具，不构成本项目删除只读角色 Files 的依据。仅公开的工具参考与 SDK 合同可用于未公开完整核心实现的部分，不把示例仓库冒称完整内核源码。

现有 `list_agents` 能从原持久结果核身份并重新返回最近终态的完整子报告，`wait_agent_events` 只给事件摘要，无需另建结果工具。旧 Source 经过压缩不代表原全文仍在每次输入；重读最近报告可重新取得正文，但不保证任选更早轮次。当前活动轮与最近旧终态仍须区分，全文可读不能替代本轮结果接纳或主张核验。

最终比较继续采用 `a10b781e2` 与候选两个独立 checkout 的真实生产路径。固定系统合同、模型、任务与配对物理工作区；工具声明和搜索粒度是明确处理变量，不覆盖生产 formatter。生产、harness、原 Store 输入与 wire 身份均冻结核对，全部八次固定样本与失败保留。第二轮不覆盖首轮负结果，不以目录缩小或少检索宣称子结果语义可靠。

## Alternatives considered

- 在 Core 对 attempted 后的异常统一当作普通失败：会把真实未知效果降格，允许不安全继续。采用工具本地可证明的失败分支，保留其余保守处理。
- 仅补提示或搜索错误文案：无法使只读角色执行进程，也无法让目录专用搜索支持文件。先修实际工具和能力合同，再补行为指导。
- 只在密集证据规则之后追加“简短回答”：真实轨迹中父任务仍主动要求额外报告，冗长继续向子任务传播。采用精简重复规则、明确其用途并前置交付原则；同任务对比只用于观察改善，不把小样本差异当成唯一因果证明。
- 新增输入分类模型、通用完成评审器、业务完成表或第二个调度循环：增加延迟和多份权威，仍不能把开放自然语言目标变成可靠真值。继续使用唯一 Loop、原持久结果和已有 required 条件。
- 按宽泛错误次数自动取消或强制切换工具：不同路径上的已知失败可能仍在解决新问题，无法可靠判断停滞。本次保留原同工具同参数重复失败保护，通过准确反馈与真实任务观察改善纠错。
- 用输出长度、关键词、固定调用顺序或单次成功作为质量门槛：容易奖励形式而掩盖错误推断。只机器核验能准确证明的事实，并保留失败样本与全文人工核验结论。
- 把全部 child Tool 数据再次内联聚合：独立回执合法而聚合超过传输边界时，会使本可成功的任务结算失败。只增加有界、显式省略的取证预览，原正文和原执行记录不裁剪。
- 自动证明代码可达性或用另一模型对所有回答打分：开放仓库与自然语言结论不能靠通用结构化字段获得可靠真值。提供可对照的原取证、限定研究范围并验证实际样本，不宣称自动语义证明。
- 按三次连续搜索或六次读取注入收束提醒：隔离 r1–r3 实验证明消息能送达，部分样本后续检索减少，但仍出现局部错误采纳；次数不代表任务进展，不能证明这项额外上下文值得成为默认机制。经复核撤回，删除对应注入和计数测试，保留原始实验结果，不把送达或少搜索改称语义核验通过。

- 继续在全局行为合同加入检索步骤、强制收束话术或按次数提醒：工具续页声明错误和粒度不合适是实际接口问题，不能让额外文字代替修复。直接修复原工具合同，不在全局系统合同新增一层提示。
- 用模型填写的“已核验”状态批准整个 child 报告：会把自报判断升级成假证明。原始工具和完整子报告保留可重读来源，实际判断仍需核实，不能宣称支持来源必然蕴含结论。
- 在 Core 加研究完成表或第二个循环：会把任务材料变成新的完成权威，并影响原取消、恢复和必要条件。撤回研究状态实验，保持唯一 Loop、原持久结果及已有完成资格。

## Consequences

改动适用于使用默认工具、角色和行为合同的主、子 Agent，没有新增普通聊天确认、诊断界面、强制计划或审批层。忽略和分页提升搜索可用性，也使未检查范围成为回答必须尊重的事实；关闭普通 ignore 不能绕过保护路径或权限。

确定性回归覆盖缺失引用后的下一 Model 与同批正常读取、真实 unknown、单文件/混合编码搜索、分页/预览/忽略、安全边界、实际角色声明、原结果接纳及压缩/引导。真实模型任务独立检查当前代码链、能力选择、单次写入与父实际读回；证据和适用范围见[真实模型 owner](../../../../tests/e2e/live/model/README.md#工具反馈与任务质量)。

行为指导已经实施，但不能保证模型的每个推断或表达都正确。真实样本仍观察到报告偏长、快照被过度解释以及搜索范围陈述不准，必须与核心执行成功分开记录；不据机械断言通过宣称这些质量问题全部消失。本机隔离任务不替代默认 Service 权限、客户端全过程、跨平台安装制品或长期运行资格。

简洁呈现的八次固定配对实测中，相同 Files 回执字节数减少约 50.9%，整任务输入 tokens 合计减少约 20.5%；搜索合计反而从 10 到 14，子报告局部误读与父笼统背书仍出现。保留本次减少重复信息和前置来源的实现，但不将其视为已经解决检索收敛或语义核验；真实模型 owner 保留完整配对、检查器修正与人工结论，未追加样本筛选结果。

删减后的第二轮固定八次生产路径比较中，A为40请求／92工具／8搜索／257631输入tokens，B为55／110／13／410855。95份父子请求及完整来源交付均核实，工具错误0，但两侧仍出现全局无引用的过度概括和父级认可子报告profile误读；B全部13次搜索均显式content，不能证明files默认粒度的实际收益。保留明确续页和单位合同修复，不把它们宣称为检索收束或语义核验已经改善；完整结果与限制仍归真实模型owner。
