# Agent Note: 全局确认使用专用原生浮层与统一应用 UI

Status: implemented

## Problem

网页由 Main 的 WebContentsView 绘制在 Root 上方，Root DOM 的 z-index 无法盖住它。通用菜单、选择器或全局弹层触发网页撤下，会让仍应可见的网页变成应用空底；aria-hidden 与 inert 还会把无相交的选择器误判为视觉隐藏。用户明确要求移除这一策略，并确认全局对话框应采用同一主窗口内、原生层级高于网页的应用自绘浮层，保持各平台 UI 一致。

用户另明确要求失败反馈不弹“操作未完成”对话框，改用能理解原因的临时 message。该提示不能批准权限、重试未知执行、改变原任务结果或替代原命令核对。

## Decision

正常主窗口中的完全权限与移除空间确认，共用一个 Main 所属的专用 WebContentsView。2026-11-06用户要求明确退出无条件立即关闭可见界面，并在5秒内结束进程，采用4秒清理截止；已移除退出确认及失败通知；Overlay不接受退出kind。完整层序为 Root ＜ Page ＜ 浏览器受控输入屏障 ＜ 应用全局浮层。所有 Page 与 shield 插入都经过保留浮层最高位置的入口；shield 不因浮层在最上而反复排序，也不把焦点抢回 Root。

普通固定客户端的浮层只加载构建产物中的 global-dialog.html、专用 preload 和同一套共享 AlertDialog、CSS 与字体；显式开发入口沿原 Main 从同一受限 Vite renderer 地址派生 global-dialog.html，专用 preload 与原隔离配置保持。背景透明，遮罩覆盖完整内容区，原网页保持真实可见，不导航、刷新、复制截图或调整网页 bounds。主题跟随 Main 的实际主题；自绘确认按钮、布局和风险文案由共享组件维护。目录／文件选择器保留系统行为；启动致命失败或主窗口已不存在时，原无法依附应用浮层的系统路径仍保留。

Root IPC 仍只提交准确请求 ID 与固定语言的 Full 确认。Main 校验准确 Root、主 frame、URL、父窗口和在途 owner；专用 Renderer 只能接收有限 kind 的状态并返回同一 requestId 的决定，没有 Service、浏览器、文件或通用 HTML 执行桥。空间名称按文本呈现，不能成为 HTML。自绘确认共用一个 modal owner；退出请求先退休旧自绘确认，再立即隐藏界面并进入原后台清理，旧肯定结果不能落到继任者。

Root 的准确应用节点在 modal 期间 inert，Main 只拦截 Root 的 before-input／before-mouse 事件。Page 的这些事件也接收授权 CDP 输入，不能统一 preventDefault；人工鼠标由最高原生 Overlay 命中，人工键盘由浮层焦点与 DOM 模态约束，Page 授权输入继续沿原 lease／控制门禁。显式焦点操作仅在父窗口仍 focused 时执行，后台取消不重新激活客户端；重新激活时当前浮层接回焦点，隐藏浮层不再参与 Root 的焦点目标选择。关闭后仅在父窗仍 focused 时恢复仍属于同一主窗口、仍可见、文档未替换的原 WebContents；隐藏、最小化、Root 导航／崩溃／销毁、overlay 崩溃或请求取消都退休当前决定。崩溃的 overlay 可以在下一次请求重新创建。Host在创建时保存准确contentView与Root WebContents，用同一引用注册及解绑；closed回调不重新读取已销毁BaseWindow的原生访问器。该清理修正针对实际退出时的Object has been destroyed／原生错误框留存，不改变document reload、确认或输入门。当前取消不等待首帧，肯定决定仍需presented；初始化或提交失败不构成确认；明确退出不再依赖窗口、状态查询或对话框；准确资源释放仍沿原停止owner进行，超过4秒的未完成清理不再阻止进程结束，也不据强退补写成功。

预热 view 平时隐藏；发起确认时，冷启动与预热未 ready 的 view 都立即以完整尺寸、最高原生层级显示透明背景并承接人工输入，再等待共享 Dialog 提交后的 presented 通知，避免加载空档和依赖隐藏 Chromium view 的 rAF。Dialog DOM 尚未加载时没有取消按钮或 Esc 处理器；当前 false 不等待 presented，只说明已有决定的准入，不承诺整个加载阶段物理 Esc 可立即处理。通知用于当前 dialog 的决策准入，不是 WindowServer 像素回执，也不恢复被删除的浏览器 ACK／witness 或截图交接。网页绘制与 UI 实际过程仍分别核证据。

Full 的有效确认继续交给原 Composer／权限控制器，新对话只修改本地待创建偏好；空间移除仍在确认后核新鲜空间身份并沿原 journal／命令提交；退出沿原 ownsQuit 与服务清理控制器。Overlay 自身不执行这些业务动作，不改变工具、服务协议或依赖版本。

2026-11-13，提供商删除接入同一个 modal owner。原设置页内的 AlertDialog 只能遮住设置区，窗口级浮层覆盖应用自绘菜单并接管输入。Main 从准确观察中提取名称和模型数量，弹层只回传决定。确认后 Main 复核观察与引用，配置写入继续走原 journal，保证结果未知时仍能核对同一次删除。常规页移除默认模型摘要后撤销专用读取端口，引用保护仍在删除路径执行。实现及 Windows 观察见[Desktop owner](../../../../apps/desktop/README.md#native-provider-与下一次模型选择)。

旧“操作未完成”AlertDialog 已移除。现有展示范围内的失败按用户2026-11-06确认改为临时 Toast，由 Root Renderer 通过 Portal 挂到 `document.body`，脱离聊天区域的 DOM 与滚动布局；位置与最大宽度沿会话区域的 CSS anchor，避免跨入右侧原生网页，并避开标题栏。打开设置时移入当前设置Dialog，避免模态范围外的提示不可访问；保留剩余计时，脱离旧挂载点的hover／focus不继续暂停。仍约六秒、hover／focus暂停、可以手动关闭；每次 occurrence 有独立身份，旧计时器、旧按钮及未提交的 React 渲染不能清除新消息。错误只映射为普通客户端独立业务实际能触发的项目记录不存在、本地数据存储异常与Service处理异常三种说明，其他普通业务使用中性兜底。诊断开关不再开启全局Toast；无来源、仅枚举、只有测试展示或其他局部owner的别名删除。普通异常及GET失败不推断业务结果未知；已知回执后的刷新失败沿原读取恢复。真正回执未知要求先核原操作，不诱导重复提交。普通、迟到或退出中的读取仍沿原归属门禁，不因此新增提示；设置表单自己的错误继续局部呈现，全局错误不复制到设置行内。

2026-11-16，用户进一步明确：“除了表单校验异常，其他的所有错误提示只能走 toast 组件，toast 组件只能反馈错误状态，不允许反馈进行中状态。进行中状态通常有所在的操作按钮或者界面内进行反馈”。该规则已归入[根工程约束](../../../../AGENTS.md#工程约束)，替代上文把表单自己的所有错误都保留局部呈现的宽泛表述；例外仅为表单校验，业务提交错误仍通过 Toast。真实业务／工具结果和待批卡不是临时操作提示，不据此删除持久事实。本轮审批展示落实该规则：不采用会话内常驻异常行，也不把正常等待搬进 Toast；真正无法核实的原答复只提供同一 command 的只读核对。临时提示会消失，因此后台核对与持久原答复不随提示退役，返回原会话仍可再次核对未知结果；不新增常驻恢复栏或重复审批入口。多错误串行显示，避免重叠与刷新刷屏。实现、回归与适用范围归 [Desktop owner](../../../../apps/desktop/README.md#原审批面板与授权观察)。

同日后续确认，表单校验与右侧文件预览等有对应内容区的失败在所属界面反馈。会话消息区的异常以会话执行循环为依据。发送失败与回执待确认在按钮结束加载时通过同一 Toast 宿主反馈。首条失败的提示随原提交接管到目标会话，离开该呈现后退役。会话文件卡与环境信息的「参考」栏都以已输出文件为内容。「参考」栏只提供文件链接和分页。此决定更新上文的局部反馈例外，保留审批回执只读核对和原工具结果的展示理由。现行规则及发送归属见[客户端状态反馈规范](../../../../docs/development/subsystems/clients.md#状态反馈规范)和[桌面输入意图](../../../../apps/desktop/src/input.README.md)。

2026-11-16，图片预览沿用户要求复用同一透明原生模态底座，而不是在 Root 中提高 z-index 或隐藏右侧网页。共享底座只负责尺寸、主题关联、原生置顶、输入围栏、焦点与窗口生命周期；确认保留原固定 DTO、准确 requestId 及 presented-before-true 规则。图片层位于普通内容／输入屏障上方、正式确认下方；两者的受限 preload 与事件类型相互独立。图片源仍由 Root 的原有读取 owner 核验，独立图片 Renderer 仅取得当前选中的有限字节与组内展示信息，不取得文件路径、Service 或通用应用桥。图片层关闭不能解除仍在进行的确认输入围栏，确认关闭也不能解除仍在显示的图片层。

2026-11-21，桌面空间会话搜索沿用户要求加入同一透明原生模态层序，不复用确认的决定协议。最初在 Root 提升层级并临时撤下网页的候选方案，在真实 Electron 的一次受控点击中使已按下的鼠标无法完成松开：撤回浏览器视图会更新画面凭据，原坐标保护正确拒绝已过期的截图。搜索因此使用专用视图和独立受限 IPC，沿用底座的窗口层序与焦点机制，不更改 Browser／Office 的可见性、几何或授权。搜索在图片预览和权限确认之下；打开搜索结果仍由 Root 核对当前目录并导航，不从搜索浮层执行其他业务操作。实现与验证范围归 [Desktop owner](../../../../apps/desktop/README.md#侧栏会话搜索)。

2026-11-21，桌面设置采用同一原生模态底座。原全页设置使用 `covered` 撤下 Browser 和 Office，不适用于保留原工作现场的浮窗。新设置视图以独立、受限的设置端口转发到当前 Root 已有的设置校验与提交；不复制 Service 所有者或完整 Root 桥。主题、最近提交和当前 Store 只按表单所需投影。正式权限确认仍有最高层序，外部 OAuth 失焦不等于关闭设置。产品行为和测试边界见 [Desktop owner](../../../../apps/desktop/README.md#设置浮窗)。

## 与既有决定的关系

本决定部分替代[固定 Renderer Note](2026-11-02-browser-fixed-renderer-layout.md)的通用弹层撤页方案。其 Root／Page 单一 owner、准确原页身份、受控输入屏障、首文档绘制准入、取消与页面保留继续适用。本 view 仅承载应用确认，未恢复旧浏览器 Chrome Renderer、工具栏副本或浏览器布局交接。

## Alternatives considered

- 仅提高 Root DOM z-index：无法跨原生子视图排序，不能覆盖网页。
- 弹框时撤下网页或用截图替代：不满足用户保留真实网页的要求，且扩大截图身份、期限与恢复语义。
- 主窗口所属系统 message box：070／071 曾沿该方向准备与验证，能位于网页上，但用户随后明确选择应用自绘以统一各平台样式，已撤销该 Full 路径；失败材料保留。
- 为每个确认另开窗口：会引入窗口激活、位置与独立焦点管理；用户选择同主窗口的专用浮层，采用原生子视图排序。
- 把所有临时反馈也变成模态确认：违反用户对失败 message 的明确要求，也会无故打断阅读和操作。

## Consequences

普通固定客户端构建增加专用 HTML、Renderer 和 preload，Root 原 index.html／renderer.js 不变。2026-11-03 实机核对确认开发 Main 已从 Vite 加载两页，因此 development 仅构建 Main、preload 和 helper，不再生产构建未使用的静态 overlay；Vite 预热两页与 NativeDesktop，确认组件改经公开窄入口避开会话解析依赖。普通完整 app manifest 继续收录并校验全部静态资源，不升级工具或 bundle 格式版本。

源码、聚焦回归、实机动作与画面分别提供不同资格。073 已核 Full 三轮、真实遮罩输入阻断、焦点与原页保持；074在run前因退出竞态退役，075用最终制品补核空间长说明与真实取消；审看限连续前六秒及稳定尾，不扩称整片。随后补提前取消、Root-only输入拦截、冷启动透明覆盖和前台焦点约束，并让 Root 排除隐藏焦点目标；这些行为用定向回归及076c实际Electron输入补核：旧Host吞掉已返回ACK的Page CDP鼠标，修复后键鼠到达而Overlay维持native focus；物理mask点击在Overlay＋1、Root／Page为0，取消和准确原页状态保持。load前仅核原生visible／全bounds／top，未扩大为空DOM物理输入或整体像素资格；精确范围仍归Desktop owner。退出改回原生后删除 Overlay 的退出分支；Full／空间的文案、DOM 与 CSS保持，复用075正常开关画面，不称所有UI资产逐字未变。各平台实际窗口、活动工作退出的真实展示及临时消息自然失败路径的资格，只以[Desktop owner](../../../../apps/desktop/README.md#固定-renderer-布局收敛2026-11-02)记录为准，不由共享代码或最终截图推导。旧 resize、收展及重开反例继续保留，本决定不构成整个浏览器视觉收敛完成。
