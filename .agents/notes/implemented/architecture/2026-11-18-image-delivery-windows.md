# Agent Note: 保存原工具语义并按已确认序位交付本地图

Status: implemented

## Problem

单次看图工具可以合法成功，多个结果的累计字节仍能让历史展开失败。重复把全部像素附在后续请求会扩大请求、费用与断连后的不确定性；简单删除早期图片又无法证明它们曾送达，以及新问题能否重看原图。

## Decision

保留[严格解码和不可变原件](2026-11-04-strict-local-image-reading.md)。以工具执行、原序位、哈希、大小及当前选定身份确认交付，不按像素哈希合并来源。一次普通工具回执绝不拆成多个伪调用；需要分片时由同 Run 的无工具观察执行接收原像素。只有完整成功的实际执行结算覆盖。笔记是带出处的低信任资料，不证明同帧比较，也不代替有权限的源定位。后续精确问题可显式按原序位再读归档，不重新执行原文件读取。

## Alternatives considered

- 只保留路径、裁剪或缩略图：无法在原路径消失后保证可追溯交付；失去的细节也不能由模型笔记补回。
- 全部请求固定重传，或在未知断开后自动重试：不能区分已交付与未交付，可能反复传同一大批。
- 把本地 32 MiB 或一次供应商 413 推为通用单图阈值：序列化的工具和上下文也占空间；保留本地硬限，只在获得明确拒绝后调整分组，并给仍可容纳的成员一次紧凑单图投递机会。
- 让主业务模型执行多个伪造的工具回执：会丢失调用配对或重复副作用，且无法解释哪些原序位已确认。

## Consequences

额外只读观察会增加模型用量。费用和回复时延随提供方、源图片、后续任务及重看次数变化；合成测试不是稳定成本或视觉准确率保证。不同帧的图像不是同帧比较。对本地可事务验证的状态关门不等于能够撤回已传给外部的字节。对应执行、恢复和原件复看见[正文 owner](../../../../packages/agent/src/model-body/README.md#工具视觉结果)。
