# Agent Note: 上下文显示估算的有限分块

Status: implemented

适用范围：本 Note 继续规定缺失服务端输入统计时的本地回退计数。2026-10-16 已按[用量记录决定](2026-10-16-provider-token-accounting.md)优先显示同原请求的实际输入数；该变化不替代下述有限分块、完整字符和资源取舍。

## Problem

TUI 在读取准确原 Model 请求后同步计算上下文显示估算。现有真实 Host 和导出 PTY 会读取含 9 MiB 连续中文的完整 Files 结果；`gpt-tokenizer` 的 cl100k BPE 对没有切分点的长段表现出病态增长，阻塞 TUI 主线程。Model 与 Run 已在 Service 持久完成，终端却保留 Working，无法绘制原完成结果或响应后续按键。本机独立诊断中，连续 3,000 个“中”计数约 38 ms，30,000 个约 3.4 s；这不是模型执行未完成或等待文案变化。

## Decision

[上下文估算](../../../../packages/agent/src/context-estimate.ts)仍完整计算每条消息正文、Tool calls、toolCallId 和工具 Schema，framing 与预算公式保持。每个字符串按最多 1024 个 UTF-16 code unit 分块，遇高位 surrogate 把边界向前移动，不拆有效 Unicode scalar。每块沿同一 cl100k tokenizer 计数；每次估算至多缓存 128 块的结果，超出逐项淘汰，函数结束释放，避免长驻保留请求正文。

短文本沿原完整字符串计数。长文本各块分别计数，块之间的 token 合并可能不同，因此只作为明确的显示估算；不用于 Provider 计费、请求变换、执行准入或精确容量承诺。当前完整实现与入口归 [Agent owner](../../../../packages/agent/README.md)。

## Alternatives considered

- 继续对完整长字符串同步 BPE：保留一次性 tokenizer 结果，但已实际阻塞 TUI，原 10 秒及 30 秒业务步骤无法完成。
- 截断正文或按固定字符比例估算：可以降低计算量，但会丢失尾部信息或放弃当前 cl100k 计数基础，不符合完整显示估算的边界。
- 只分块、不缓存：能限制单次 BPE 输入，但重复大段仍反复计算相同块。局部有界缓存复用相同字节计数，不跳过任何字符，也不扩大长期文本保留。
- 1024 code unit 分块并局部缓存：限制病态单段的输入，在保持短文本原精度和全部字符参与的同时，只接受长文本块边界的显示近似差异，因此采用。

## Consequences

显示估算的长文本值可能与一次性全串 BPE 有小幅差异，仍明确标为估算。没有增加模型输入额度、截断实际历史、改变活动 Run 或放宽权限／清理门禁。回归保原短字符串精确断言，增加完整 3,145,728 字中文及尾部计数，以及 surrogate 跨块边界；真实 Host 和正式候选导出仍按原完整业务文件、原正文和原步骤预算验证。
