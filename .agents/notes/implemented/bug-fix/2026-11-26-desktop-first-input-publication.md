# Agent Note: 桌面首条输入与会话发布

Status: implemented

## Problem

桌面发送首条消息需要先取得会话身份以准备权限、附件和草稿。原流程在这一阶段就向会话目录发布记录。首次提交明确失败会留下空会话。已应用的本机输入记录也长期占用发送待处理额度，满额时阻止新输入。

## Decision

[Service](../../../../apps/service/README.md) 在创建记录中保存首条输入的既定命令身份。会话目录从原 Store 读取该命令的应用事实。确认失败后，桌面保持准备页和草稿。输入受理回执沿原请求立即返回，应用状态随后只读核对。

[桌面发送日志](../../../../apps/desktop/README.md#native-项目会话目录)没有累计发送额度。已应用的普通输入保留原记录，可按命令身份查询。界面只附带近期已应用记录。后续发送退出已确认的旧内存状态，未知请求继续沿原身份恢复。

## Alternatives considered

- 发送失败后删除已发布会话。删除会使空会话先出现在侧栏，也要处理进程退出、删除失败和并发写入造成的竞态。
- 新发送时远程逐条核对并清理已应用记录。历史核对的延迟和失败会传到当前发送回执。

## Consequences

准备记录可供权限、附件和原回执读取，普通会话目录只发布首条输入已经应用的会话。确认失败后可重新提交新请求，结果未知时继续查询原命令。已有真实消息和后续执行失败保留在已发布会话。

Main 在会话准备期间串行处理首次提交。受理后同一草稿修订继续归原命令，既有会话的不同命令仍按各自作用域保存、派发和核对。只读核对保留未派发请求的原派发资格。切换会话时，只有仍持本地首次派发权的申请可以按未发送结束。
