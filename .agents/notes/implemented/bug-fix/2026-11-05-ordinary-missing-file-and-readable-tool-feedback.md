# Agent Note: 普通文件缺失观察与可理解的工具反馈

Status: implemented

## Problem

普通文件探索在确认目标不存在时仍返回工具失败，界面使用失败颜色，模型容易把正常的文件发现过程理解成执行、权限或恢复异常。另一方面，模型预先收到的 Files 说明同时含有“外部没有基线”和“Full 外部有基线”等不一致信息；失败后才解释入口范围，不能解决工具选择前的混淆。部分工具还只返回机器码或内部执行术语，不能直接说明用户能够理解的原因。

用户确认调整普通缺失、模型反馈与最终 Files 说明。本决定记录已实施的反馈机制与边界；固定回归、实际窗口和真实模型证据分别说明其资格，模型任务稳定性没有因此取得。

审查另发现：已有工具观察和 Shell 回执的失败子 Agent，原持久 `details.evidence` 完整，但新增失败英文呈现只保终止原因，遮住原本交给父模型的工具证据。自然矩阵结束并保存代码前后摘要后，复用严格子结果 formatter 支持准确可信失败结果，保原观察、输出及遗漏说明，同时将终止原因解释为英文；未知证据结构仍回退原完整 Source。此分支以修后回归和真实模型定向结果核验，未借用修前自然矩阵取得资格。

## Decision

- 普通工作区及外部 `read_file` 在本次实际读取中确认目标缺失时，返回正常观察：`outcome:succeeded`、`File does not exist: "<path>".` 和 `details:{path,exists:false}`。缺失不产生空文件正文、行窗口、Artifact 或编辑基线，界面按正常结果展示，不使用失败红色；已存在的空文件保持真实空正文，是否有编辑基线继续由原读取范围决定。
- 只在目标读取边界识别确定缺失，不吞掉 Artifact 发布、权限或保护路径、损坏的私有附件／计划／输出引用、取消与未知效果。外部缺失的能力描述仍先核请求路径、实际祖先和保护范围；缺失不是解除读取权限的理由。
- 本轮统一的 Files 工具说明、工具拥有的已知公开错误原因及必要后续指导使用简洁英文，不以内部 Run／Session／Job／carrier／dispatch 术语或裸机器码代替原因。原命令 stdout／stderr、MCP 结构化业务数据和其他原始业务正文保真，不做全局翻译或删除；原错误码、身份、审批、取消、输出和恢复事实继续归原持久回执所有。未知原因仍为通用解释，不公开任意 Error 正文，不从原因表推断效果或授予重试。
- 在 [Service 最终 Files 装配](../../../../apps/service/src/file-checkpoint-configuration.ts)生成一致的工具与 path 说明：工作区读写、三模式普通外部读取、普通外部修改 Full-only、Full 可编辑基线条件，以及准确附件／计划／输出引用各自的范围。保留现有参数和版本，不增加 Files 的 `filesystem`／`network` 申请字段。非 Full 的入口不支持不等于用户拒绝整个业务任务；只有原任务与当前工具、角色、审批仍允许，且没有真实拒绝或未知效果时，才可向 Shell 等支持工具提交独立请求。
- 继续沿原 Loop、普通工具批次、父子权限交集、取消及未知恢复路径处理，不新增 Agent 阶段、审批系统或完成闸门。
- 失败子 Agent 已安全读取的历史证据沿原结果继续交给父模型；复用严格子结果呈现的来源、版本、原结果及证据结构校验，不把失败呈现成成功，不回流整段内部 JSON，也不从失败推断此前没有效果。未知或不能识别的结构仍保原结果，不因简化丢掉新限定。
- Store 原身份与 Artifact 正文读取位于纯展示异常回退之外，包括压缩后按原引用恢复的证据正文。未知展示形状仍保完整原结果，有 Artifact 时同时保完整已验证正文，不能仅取 `content` 丢掉未知 evidence 限定或外部业务字段；真实缺失或损坏沿原模型准备失败路径处理。通用错误表不凭同名错误码断言未发布修改；只有实际拥有该事实的原生 Files 路径保留准确未发布说明。

当前接口及产品行为归[工具手册](../../../../docs/handbook/features/tools-and-approvals.md)与[共享边界](../../../../docs/active/unified-agent-boundary.md)。本记录只补充[此前 Files 范围与交付反馈决定](2026-11-05-files-scope-feedback-and-task-delivery.md)的普通缺失分类与模型呈现取舍，不改变该决定的父子协作、收尾及权限边界；[Full 外部修改决定](../architecture/2026-11-05-full-mode-external-file-mutations.md)继续适用。

## Alternatives considered

- 继续把普通缺失作为失败，只改文字或去掉红色：不能使成功观察与真实失败的状态一致，模型及其他结果消费者仍会收到失败事实，因此不采用。
- 将所有 `ENOENT` 都改成成功缺失：会混淆原始目标缺失、完整结果存储失败和私有引用损坏，可能掩盖恢复问题；只在准确读取边界处理，私有适配器显式保留原错误。
- 全局删掉 ID、机器码或非英文文字：会损坏命令输出、MCP 业务字段、用户正文及追溯依据；改成呈现层的已知原因解释，原业务数据与持久记录保持。
- 为消除 Files 与 Shell 的表面差异，直接允许非 Full 外部 Files 修改：会改变已确认的工具范围和最终证明要求，不属于这次反馈调整。保持 Full-only，并在模型选择工具前说明支持范围与独立审批义务。
- 继续叠加各适配器的说明：已有普通 reader、Full 与附件层文字会相互冲突；在最终装配统一说明，只调整文字，不改变 schema 语义。
- 对失败子任务只呈现原因、移除原证据：父模型会失去此前已发生的写入、观察和诊断，无法合理说明部分结果；严格复用现有子结果格式，并保未知结构回退，不新增证据系统或第二条执行路径。
- 把事实读取与纯格式转换放在同一宽泛异常回退中：会将旧证据正文的缺失或损坏变成成功 JSON，掩盖恢复失败；将 I/O 与完整性校验留在原 Runtime，只有纯展示可以降级，不增加异常包装或新的恢复管理器。

## Verification and limits

2026-11-05，macOS ARM64／Bun1.4.2，当前任务工作树：

- [原生 Files 缺失回归](../../../../packages/agent/test/isolated/files/missing-file.test.ts)覆盖普通工作区及外部缺失与空文件的区别、保护路径及别名、非法路径、取消、私有 factory，以及读取成功后 Artifact `ENOENT` 仍为失败。[Service 三模式回归](../../../../apps/service/test/isolated/full-external-files.test.ts)核实际下一模型及最终目录，请求批准与 Auto 的外部 Files 修改仍按原入口范围拒绝。
- [公开原因回归](../../../../packages/agent/test/isolated/execution/public-failure-causes.test.ts)经 Runtime 核 Ask、Skills、Planning、Web、取消、未知原因及非英文正文；[执行证据回归](../../../../packages/agent/test/isolated/execution/evidence-public-feedback.test.ts)核原 Shell Job／Tool 及两流字节、范围和 owner。[失败子任务回归](../../../../packages/agent/test/isolated/business/task/partial-child-failure.test.ts)核真实先写后读、Shell 失败、子模型失败后仍交父原证据且只发生一次效果；严格纯呈现和既有子证据测试同时通过。
- 隔离 Desktop 加真实 Service／Core 的普通缺失过程完成一次输入、读取、正常结束、展开和刷新重开；82次 DOM 变化无失败／红色，准确路径和灰色“文件不存在”保留，原读取不重执行。这是实际隔离浏览器过程，非完整 Electron 安装版或所有客户端资格，详细过程归[Desktop owner](../../../../apps/desktop/README.md#原工具过程与结果阅读)。
- 自然18例262次物理请求保留机械12过6败与3项实际业务失败；全部12份子结果成功，未覆盖失败子分支。修后边界16例245次物理请求另含两次无 HTTP 的受控失败，保留原机械13过3败及各项资格；已确认原证据送达、实际拒绝、生命周期和生产3秒超时规则。更正夹具换行比较后的 fresh 双样本中，Terra通过，Luna原效果、诊断和传输正确，但最终漏报后续子失败及公开原因未知，保留真实语义失败，不重跑筛选。完整数量、代码摘要与限定归[原真实测试记录](../../../../tests/e2e/live/model/README.md#审批策略与原生-shell-执行)，不同代码批次及离线复核不混为同批通过。
- 随后代码审查修复了宽泛展示回退与同名错误码效果推断。[证据读取回归](../../../../packages/agent/test/isolated/execution/evidence-public-feedback.test.ts)通过真实压缩验证完整正文恢复、准确旧正文被删除或损坏后阻止后继模型，以及未知子证据限定和外部业务字段完整保留，原操作与回执不变；[失败呈现回归](../../../../packages/agent/test/isolated/execution/tool-failure-presentation.test.ts)验证外部工具产生实际效果后抛同名错误仍为未知，不能被解释为未修改。本次修后不重新运行真实模型，先前原模型报告及失败保持，不据旧样本授予新代码整组真实模型资格。

## Consequences

缺失只描述本次读取时刻；外部程序之后可以创建该路径，不能作为长期不存在或后续新建成功的保证。所有模式仍须接受真实权限、保护范围及执行边界。

呈现规则只清理工具拥有的解释和摘要。原业务正文可能合法包含英文以外的语言、机器码或与内部身份相似的字符串，不能用关键词删减它们；失败前已有输出、部分效果和未知结果必须继续保留准确限制。

本轮没有更改工具定义或协议版本，也没有将新呈现回溯成历史批准。代码与 UI 已落盘不证明全客户端和平台资格，最终结果由原验证证据说明。
