# Agent Note: 子配置的默认知识交集与准确未受理回执

Status: implemented

## Problem

真实探索委派在创建子会话前因 `skill_capability_missing` 失败：父任务自动选入浏览器知识，分析子角色移除了浏览器工具，装配却把默认知识当作强制依赖。工具随后把准备失败统一解释为可能已受理，模型既不能继续委派，也得不到准确配置原因。当前目标是不扩大子角色权限，同时让回执区分明确未受理和无法确认。

## Decision

默认继承仍以父快照的准确配置 ID 为上限，只在子能力收窄、同 ID 被目录明确标记缺少能力时省略该默认知识。显式选择、禁用、未知 ID、坏文件与冻结配置恢复检查保持严格，不重新按名称匹配，也不通过给子角色增加工具满足知识依赖。该范围修正[单次选择决定](../architecture/2026-10-02-per-run-skill-selection.md)和[同源目录决定](../architecture/2026-10-02-scoped-skill-catalogue.md)中“所有继承均强制”的表述，准确父身份、配置来源和其他失败约束继续适用。

创建或明确续作的配置准备失败后，Host 排除取消与资源清理未确认，再按原操作身份重新核对持久回执。有准确原回执就复用，没有原回执才以内部标记证明本次未受理。Task 只识别这个可信标记，输出有限英文说明，不声称原协作者已经停止或不存在；同名异常、回执无法读取和受理后的异常不能据此变成未受理。没有新增工具参数、审批或执行身份系统。

## Alternatives considered

- 为分析子角色补开父浏览器工具：会把知识依赖变成扩权理由，违背现有角色边界。
- 忽略所有继承失败：会掩盖明确选择、坏配置和历史绑定变化，只省略目录已证明缺少能力的默认项。
- 只凭 `skill_capability_missing` 异常码报告未受理：相同异常也可能来自受理后的边界，不能证明零创建；改用 Host 的原身份核验结果。
- 所有准备失败继续报告受理未知：虽然阻止盲目重放，却丢失了可以证明的真实原因；保留不确定性只用于实际无法确认的情况。

## Consequences

默认分析委派可以在既有工具交集内启动；明确选择缺依赖仍失败。模型能分辨配置需要修正与原工作需要核验，但不得把错误说明当作另建身份重放未知效果的授权。完整当前契约归 [Service](../../../../apps/service/README.md#同源-skill-知识目录) 与 [Task owner](../../../../packages/agent/src/extensions/task/README.md)。[能力继承回归](../../../../apps/service/test/isolated/child-skill-capability-inheritance.test.ts)和[受理回执回归](../../../../packages/agent/test/isolated/business/task/preparation-failure.test.ts)分别核真实装配和下一模型输入；固定模型回归不证明真实模型能稳定完成所有委派。
