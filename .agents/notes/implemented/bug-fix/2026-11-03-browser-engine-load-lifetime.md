# Agent Note: 普通网页加载与首帧等待沿浏览器引擎生命周期

Status: implemented

## Problem

Windows用户再次看到网址及网页标题已更新、内容区却显示“网页显示尚未确认”。原展示路径在等待主文档与首个完整原生帧时分别设置12秒和2秒应用期限；期限经过即封为display failed，之后引擎正常完成也不能接管。真实Electron隔离慢页已复现这一过程。用户于2026-11-03明确要求不自行设计超时，由浏览器引擎处理。

## Decision

普通网页展示直接等待准确文档的引擎就绪及当前完整原生帧，不增加应用倒计时。较慢页面继续loading，真实引擎错误沿原浏览器失败页，实际进程或订阅故障仍保可读失败。导航、撤页、隐藏、Root／scope／几何变化及关闭继续取消准确等待和订阅，旧回调不能授后继页面显示；Windows临时节流策略在准备结束或退休时恢复。

加载停止与Agent控制通道分离均不构成网页失败证据。停止只退休当前读等待，同epoch已提交文档仍可由后续DOM-ready或隔离世界的实际readyState取得就绪；仍须通过准确文档及完整原生帧门禁。尚未提交的主动停止显示中性“已停止加载”。Agent detach按attachment与读者自身current核对退休Agent读，不取消普通展示等待；真实引擎失败则使文档失败，迟到就绪不能覆盖它。

本决定仅替代[固定Renderer结构决定](../architecture/2026-11-02-browser-fixed-renderer-layout.md)中普通展示的文档与首帧期限。完整原生帧、原网页／frame／文档／Root／scope／revision／几何检查、控制权、Agent操作期限、未知与截图证明保持。当前实现、命令、过程证据与资格范围归[Desktop owner](../../../../apps/desktop/README.md#浏览器加载失败页2026-11-03)。

## Alternatives considered

- 保留或延长12秒／2秒：仍可能在浏览器未失败时错误终止展示，与用户要求冲突。
- 直接把DOM-ready或URL当作已显示：会丢失完整原生帧及原页面检查，不能用取消期限代替正确准入。
- 超时后自动刷新／重建网页：可能丢失表单、重复导航或网站副作用，也没有解决原错误的判断来源。
- 把停止或控制通道分离当成整页失败：会使仍可完成的原文档无法接管；保留读者自身取消及原epoch就绪核验，避免刷新页面来掩盖错误分类。

## Consequences

慢页不会仅因应用固定秒数变为失败。未完成的引擎加载或绘制可继续等待，直到引擎结果或明确生命周期变化；取消和准确资源清理因此继续是必要条件。该决定不承诺OS跨surface原子绘制、安装制品或其他平台资格。
