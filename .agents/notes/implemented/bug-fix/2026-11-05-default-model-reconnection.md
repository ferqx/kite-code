# Agent Note: 模型请求失败默认进入有界重连

Status: implemented

## Problem

Windows开发客户端手动断网后，原轮约3.5秒结束；只读SQLite显示唯一首次Model执行以`model_failed`失败，没有重试前驱或连接失败细节。旧AI边界仅接受SDK的可重试标记及少量TypeError系统码，不能覆盖未识别的真实断网异常。旧记录已丢失原错误，不能反推出当次具体系统码。

用户于2026-11-05明确要求“如果非权限拒绝，默认重连”。当前产品行为归[恢复手册](../../../../docs/handbook/features/recovery.md)，实现归[AI owner](../../../../packages/ai/README.md)。

## Decision

模型请求与传输失败默认转换为有限的`ModelAttemptError`；明确HTTP401／403认证或权限拒绝除外，不根据远端文字推断拒绝。请求前的历史校验在Provider错误边界之外；用户取消、响应完整性校验、未知结果和原执行关闭证明继续保持原合同。Runtime仍负责退避、最多5次重连、准确前驱及取消；SDK不增加内部重试，不升级协议或工具版本。

已知系统码仅决定可读细节，未知错误也有重连资格。公开异常不保留原message、cause、URL、body或凭据。

## Alternatives considered

- 只补网络断开／不可达的系统码：能覆盖已知缺口，但无法满足用户要求的默认规则；新平台或无code异常仍会直接结束。
- 将所有失败都重连：不符合明确权限拒绝例外，也会误重试本地校验和用户取消。
- 在客户端按断网状态重发任务：会丢失后端关闭证明和原请求身份，可能重复工具效果；沿用Runtime原重连路径。

## Consequences

HTTP400／404／409／422等非权限错误也会消耗最多5次重连；确定性配置问题可能更晚结束，这是用户确认策略的代价。401／403立即失败；SDK每次仅一个Provider请求，不靠错误正文扩大权限。原故障事实和工具零重复效果边界保持。

原源码对新增定向回归28项中16项失败；修复后AI、Agent重连、Service Responses及Native轮次10文件152项／2291断言通过。只使用本机模拟Provider，直接公网断网及完整安装制品未取得新资格；实际窗口证据归Desktop owner。
