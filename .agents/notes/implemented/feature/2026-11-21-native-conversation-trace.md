# Agent Note: Native 思维链的等待状态与完成摘要

Status: implemented

## Problem

工具执行后再次思考时，混合思维链仍显示上一条工具。用户需要展开过程或查看卡片才能辨认何时需要回答与审批。完成摘要只留动词，合并了文件读取和图像查看，也把命令观察、目录操作及实际执行混在一起。

## Decision

思维链依据原模型阶段、当前 Interaction 与工具事实更新原标题和思考行。需要用户处理的等待优先于执行和思考，失去确认时撤下活动提示。结束摘要只使用明确允许的动作短语，沿原步骤顺序去重。前后台 Shell 共享实际执行结算的口径，MCP 只收录原远端工具调用。创建子 Agent 和计划审阅使用独立消息行，其余可见子 Agent 工具保留在链内供阅读。具体显示规则归[桌面手册](../../../../docs/handbook/clients/desktop/README.md)，实现与验证归[Desktop owner](../../../../apps/desktop/README.md#原工具过程与结果阅读)。

本决定替代[连续工具聚合](../bug-fix/2026-10-25-native-contiguous-tool-aggregation.md)中 Native 主会话 Trace 的默认汇总与状态规则。原稳定身份、读写范围、结果核验与开合交接继续适用。

## Alternatives considered

- 用当前 Run 的进行中状态代替准确思考或交互状态，会将工具间空档、自动审核和断线保留记录显示成需要用户处理的活动。
- 单独增加状态行会重复原工具、问答和轮次反馈，并使收展及接管期间的阅读位置发生变化。
- 按工具名称、命令文本或通用成功状态为所有工具生成摘要，会把后台受理当成命令执行，或把目录查询当成远端工具调用。

## Consequences

准确后台命令的冷读需要取得原关联 Job 的结算证据，读取失败时保留原受理行。[计划审阅与主输入](2026-11-21-native-plan-review-composer.md)更新了待审控件的位置和答复入口，计划正文继续沿原消息阅读。每个打开的历史审阅持有自己的只读句柄和原附件验证。已保存答复在原执行确认接收前显示待确认。摘要只使用已有事实，执行、权限与存储协议沿原合同。
