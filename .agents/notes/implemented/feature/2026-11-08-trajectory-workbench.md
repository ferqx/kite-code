# Agent Note: 右侧轨迹工作台与按需详情

Status: implemented

2026-11-09，[逻辑操作决定](2026-11-09-trajectory-semantic-operations.md)部分取代下述“四项组合过滤”和逐对象出行方式：顶部改为坐标及独立折叠开关，准确重连／后台工作归并；本页右侧标签入口、材料与历史、调宽及覆盖式详情的取舍继续适用。

## Problem

用户需要理解输入、模型、工具、子任务、审批和回复的因果关系。只显示树会丢失准确版本正文；按生命周期逐条展开又会淹没业务过程。递归 DFS 顺序不能表达并行调用的全局先后，单独的序号也不能代表耗时。预读全部材料来补列表摘要或全文搜索会扩大权限与成本。

初稿曾采用会话主区域的“对话／轨迹”切换。用户在实施时明确轨迹继续放在右侧栏，入口位于新标签页，因此本决定采用右侧独立 Tab，并通过实际容器宽度决定节点详情形态。[分型详情决定](2026-11-08-trajectory-node-details.md)负责各类节点内容；[原事实决定](../architecture/2026-11-08-trajectory-facts-and-trace-consumers.md)继续负责底层只读、原事务封存、权限与导出边界。

## Decision

### 入口与状态

“新标签页 → 工具 → 执行轨迹”打开右侧栏轨迹 Tab；重复打开选择已有 Tab，共享原八标签上限。只有激活且可见的轨迹 Tab 挂载 reader，隐藏、关闭或换会话会取消原 owner 的读取和回放，不执行工具、不发送消息、不接受审批。会话草稿和消息阅读仍归原 Session owner。

右侧栏沿现有分隔线调宽。日志行高 38px；轨迹容器达到 840px 后，选中节点的详情默认占约 40%，内部键盘和指针分隔线可调宽。小于该宽度时，详情覆盖整个轨迹 Tab 内容区，保留外层标签栏；关闭／Escape 回到原行。切换宽窄布局保留节点、Tab 和阅读位置，不能产生第二个 reader。

视觉沿用户确认的原型：紧凑图标筛选、右对齐搜索、四类命名泳道及时间刻度、彩色类型标签、局部层级细线、原轮次分组行、行尾观测时长与状态、蓝色选中底和左强调线；详情使用类型标签、轮次／来源序号、关闭图标、下划线 Tab 和独立正文层次。样例文案不成为生产摘要数据；没有合格公开 metadata 时使用真实类型／定义名称，不为填满原型的样例片段预读正文。后来确认的无生命周期、工具四 Tab 和右侧标签位置取代原型中对应的旧内容。

### 索引、顺序与关系

完整固定前缀派生轻量索引，保存闭合规范事件、公开 metadata 和准确 Evidence refs，不含正文或私有 binding。消息、模型、工具与子任务、自动压缩和审批默认可见；“显示全部事件”补入辅助行政原事件，不删除原事实。流式更新和终结归并到原实体，不重复成行；辅助行政行使用独立 `event:<eventId>` 选择身份，不能因共用 owner 而串选。

行按实体首次全局 Decimal64 sequence 排列，然后叠加真实 parent/depth。后代不要求连续相邻，不为让父子相邻重排并行事件。缩进可封顶但完整深度与原父身份保留；折叠隐藏后代显示，不丢索引或选择。缺失或范围外父级明确说明，不凭相邻、名称或层级补造。消息关联、carrier→child 及原 Store 证明沿原合同，出现子会话引用不扩大读取 scope。深链计算迭代执行。

### 四项组合过滤

时长、执行轮次、调用类别、子调用和元数据搜索按 AND；轮次与类别各自多选按 OR。轮次 `null` 表示不限，`[]` 是合法零匹配；类别空集同样保持零匹配。非默认条件可单独移除，也可全清。条件变化不 seek、不扩展 upper、不进入 live，不重置原选择、材料版本、Tab、阅读与折叠偏好。

时长使用同 Store、同历史前缀的已记录观测区间，明确包含计划／排队／审批等待等口径，不称 Provider 纯耗时。未终结但有同域后续观察时只能说明已观测跨度；单点、缺时、缺口、跨域或倒序时钟保持未知，不用当前时间延长历史。消息等非调用没有耗时／子调用匹配资格。主调用需要确证执行身份和无父关系证明，来源未知不能冒充主调用。

过滤结果保留真实祖先但淡显，祖先不计命中。活动条件临时展开命中路径，不覆盖用户折叠偏好。选中节点被过滤或折叠后，详情继续显示准确版本并说明原因；回到更早 cursor 而节点尚不存在时说明范围缺失，不自动改选祖先。搜索只覆盖名称、定义、类型、状态、原身份、轮次、序号和事件类型，不读取 Evidence、reasoning、transport 或本机 URI 生成全文索引。没有合格公开摘要时列表使用真实类型和名称，不自行从私有 JSON 猜正文。

### 时间轴、历史与材料 owner

概览支持观测时间和事件顺序坐标。各原 Store 时钟域分开；缺时或不能对齐的项进入未知域。事件顺序等距不代表耗时。点击或键盘选择标记定位同一实体，不改变 cursor 或 upper。列表采用可描述真实层级的时间顺序表格，键盘上下沿可见全局行，左右折叠或定位确证父级；大列表虚拟化保留正在聚焦的行。

四条业务泳道为输入／回复、模型、工具／子任务、压缩／审批。消息以原记录时间点定位，确证执行区间以条表示，并行区间分轨。缺时域只显示原序号刻度，辅助原事件另有定位区，不能被画成业务调用或虚构耗时；非调用的提示明确为已记录时间点或时间未记录，不混入“调用时长未知”。

首次在线打开固定为历史前缀；新增通知只提示。显式返回最新才扩展快照并跟随 live；阅读早处或打开详情会固定历史，流式状态仍沿同一实体归并。跳转输入在完整本地前缀验证成功前显示原已提交 cursor，失败保留原位置。断开／重连以连接 epoch 拒绝旧 wake，旧请求不能清掉断开错误或继续 probe。

仅当前详情 Tab 请求准确原材料；概述、过滤、搜索不预读全文。请求绑定原 Store／Session／scope、upper、event、sequence、ref 和 contentVersion。每次 source、cursor、owner、选择或可见性替换都先隐藏旧正文，取消原读取；A→B→A 的迟到 open 仍在原 source 关闭 lease。按原分块身份、hash、授权 epoch 校验到 EOF 后才呈现；图片只为已核实原栅格材料创建并回收 Blob URL。离线换包使用相同隔离，不能向 Runtime、Provider、网页或当前文件补历史。

筛选不裁剪导出：导出仍按固定来源 scope 保存完整规范记录及显式选择的材料。旧格式、缺材料、Fork 继承消息或未知来源不追补时间、身份或未来正文。新增 `tool_input` 不自动赋予旧 Trace grant 权限；新读端继续读取旧 V1，旧严格读端不据此获得透明向前兼容承诺。

## Alternatives considered

- 主区域独立页面：初稿有利于宽布局，但用户明确保留右侧栏；采用可调侧栏和按容器切换的覆盖式详情解决窄宽阅读。
- 全高树、完全删除详情：能简化展示，但无法检查原参数、结果、摘要与准确版本；仅移除生命周期界面，按需详情保留。
- DFS 顺序作为时间顺序：后代连续但会误排并行过程；使用首次全局 sequence 与真实深度、父级定位。
- Provider 纯耗时统一筛选：现有事实不能普遍证明；使用有依据的观测区间和未知状态，不叠加子调用冒充父耗时。
- 四个静态数字或互斥条件：不能组合过滤；使用独立条件、内部 OR、跨维度 AND，空集不自动放宽。
- 预读所有正文以支持 snippet／全文搜索：成本、权限和历史来源失效难以解释；限定 metadata 搜索和选中材料读取。
- 过滤后自动改选第一项或祖先：会打断审计原版本；保留原选择并明确筛选外状态。
- 生命周期／来源独立 Tab 或 Raw 输出内部 JSON：用户要求删除阶段展示；来源保留为 metadata，Raw 仅规范事件与受限公开材料。

## Consequences

索引随事件 metadata 和关系增长，不随所有正文增长。归并、排序、过滤与 UI 布局各有 owner：首次索引 O(E+V+links)，排序 O(V log V)，一次过滤 O(V+links)。完整安全事件索引增加固定前缀内存，但避免选行重扫或 renderer 接触私有源；时间未知与缺失材料是合法结果。
