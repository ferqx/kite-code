# Agent Note: Native 计划审阅与主输入

Status: implemented

[计划审阅与原任务用户消息](2026-11-21-plan-review-conversation-reply.md)更新了操作位置和文字答复的归属。当前待审面板占用原主输入框位置。本文保留原消息放置、精确版号和草稿回执的取舍。

## Problem

等待计划决定时，桌面客户端隐藏主输入框，并在原消息行使用独立的审批操作。用户希望在与补充问题相同的区域选择并提交，也希望从主输入直接发送修改意见。

## Decision

计划正文、步骤和附件读取留在原会话消息中。待审控件和补充问题共用输入框上方的交互区、单选项和提交锁。当前会话只有一份可答复的待审计划时，主输入发送的文字作为该版本的 `revise` 意见提交。审批与拒绝由面板明确选择，停止沿原任务操作。共享的答复入口接收已核实的计划正文和准确原 Interaction，主输入的来源信息留在 renderer。

## Alternatives considered

- 在消息区保留待审表单会让计划和问答的操作位置不同。把整份计划移到输入区又会挤占审阅和输入空间。正文沿原消息阅读，决定和提交沿共享交互区处理。
- 把主输入的文字排入后继任务会丢失对当前计划版本的绑定。从自然语言猜测是否批准也会使实施同意不明确。

## Consequences

附件读取证明失效时撤销两处提交入口。主输入保留原文，直到取得对应答复的准确回执，之后只清理本次提交且仍匹配的草稿。未知回执期间保留该草稿的原提交关系。此决定更新[思维链呈现](2026-11-21-native-conversation-trace.md)的待审卡位置与提交入口，原工具位置的只读历史与原执行接收证明继续适用。操作与验证见[Desktop owner](../../../../apps/desktop/README.md#native-计划入口与完整审核)。
