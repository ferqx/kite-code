# Agent Note: Windows 工作树归档前拒绝所有目录联接

Status: implemented

## Problem

隔离工作树复用主仓库依赖后，依赖图可以通过 workspace junction 返回主仓库源码。2026-10-19 的归档日志与合成仓库实测确认，本机 Git 工作树删除会沿该链删除模拟主仓库文件；归档快照成功和上层清理成功均不能证明主仓库保全。用户要求确认原因并防止再次误删。

## Decision

[根规则](../../../../AGENTS.md)禁止 Windows 工作树以联接共享其他 checkout 的依赖、源码和缓存，并要求归档／删除工作树及关联聊天前执行[只读检查](../../../../scripts/check-worktree-cleanup.ts)。检查不跟随联接，任何联接或读取失败都阻止批准；已核实的临时联接只允许先非递归移除入口，再复查。实际步骤、事故证据和范围归[开发文档](../../../../docs/development/worktree-safety.md)。

## Alternatives considered

- 继续共享依赖，仅凭工具承诺或快照完成判断安全：实际删除已越界且可能丢失未提交版本，不能采用。
- 只检查直接指向源码的联接：依赖入口与 workspace 包形成间接链，单一目标类别不足以判断安全。
- 只拒绝外部目标：内部联接可继续形成循环或经过其他入口到达外部；本地清理流程采用更简单的全部联接拒绝。
- 修改已安装 Codex／Git 或假定升级修复：本仓库不拥有这些实现，未经相同夹具实测不能宣布已修复。当前通过依赖隔离、入口断开及只读门禁落实防护。

## Consequences

增加独立依赖安装的磁盘和时间成本，清理前需要处理 Bun 自己创建的包联接。门禁是 Agent 操作规则，不能拦截应用 UI 自动清理；必须从一开始避免外部共享联接，并保持检查与归档之间无并发写入。检查失败保留工作树，不能改用其他递归删除器绕过。用户业务行为、授权和发布边界不变。
