# Agent Note: Use lifecycle based Agent Notes for durable decisions

Status: implemented

## Problem

迁移前的单一决策目录把已接受的方案、实际交付的决定、后来被取代的记录和仍待实施的设计放在一起。`accepted` 只表示设计被接受，却容易被读成能力已经交付；部分取代与历史归档又需要读者逐篇追踪文字说明。此前改进记录模板和维护规则，仍无法让目录直接表明记录的当前用途。

## Decision

仓库把原始记录的长期决策理由迁入 `.agents/notes/`，按 `proposed`、`implemented`、`rejected`、`archived` 生命周期及 `feature`、`bug-fix`、`simplification`、`architecture`、`process`、`testing` 类别组织，移除旧目录及其索引和模板。记录的状态与目录一致；已交付记录用当前事实陈述，无法从原文证实的备选或验证明确留缺口。当前产品行为、实现边界及验证范围仍分别由产品手册、active 与 workspace owner 文档和实际测试负责，Agent Note 保存选择该边界的理由与放弃的方案。

现有记录迁移时逐篇保留可核实的理由、取舍和限制，并修复跨记录与当前文档的链接。部分取代的决定保留适用范围与双向关联；仅曾实施且已结束的决定归档。新记录及状态移动遵循本目录的[维护规则](../../README.md)。

## Alternatives considered

- **继续保留旧目录并强化模板和状态字段**：此前已经在模板与文档维护规则中补充备选、后果及验证要求。这改善单篇内容，却仍让 `accepted` 同时覆盖设计和已交付能力，目录也不能区分提案、有效决定和冻结历史，因此不足以解决检索与当前依据混淆。
- **同时保留旧目录和 Agent Notes**：会让同一决定出现两个可编辑位置，引用、状态和校验可能相互矛盾；迁移后只保留一套决策记录。
- **只保留当前 owner 文档并从 Git 历史查理由**：当前文档适合说明行为和边界，Git 历史不提供稳定可检索的真实备选、放弃的能力及重新考虑条件，因此不能承担长期决策记忆。

## Consequences

迁移需要逐篇辨认交付状态、重排目录、修复入站与出站链接，并维护状态和格式检查。旧记录的日期或备选证据不完整时须如实留下缺口，不能为形式整齐而补造。目录检索可以直接区分提案、已交付决定和冻结历史；任何 Agent Note 仍不能单独证明现行产品承诺、代码行为或验证已经覆盖的范围。
