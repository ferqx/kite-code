# Agent Note: 显式限定来源与站点的浏览器 Cookie 导入

Status: proposed

## Problem

用户希望考虑现有浏览器Cookie导入，以便受管网页沿用指定站点状态。当前手动WebContentsView与Agent受管Chrome分属不同owner，前者是非持久Session，后者使用私有临时Profile。自动复制日常资料会扩大账户权限、混入无关站点，并可能使认证材料进入模型或日志。本轮只交付方案，未读取Cookie、密码或Profile；实际边界归[Desktop owner](../../../../apps/desktop/README.md#agent-浏览器观察与人工操作)。

## Proposal

后续先让用户明确选择来源、目标浏览器与站点／域范围。优先评估用户主动提供的站点导出文件，不默认扫描、解密或读取日常Chrome数据库；任何直接浏览器来源需要独立评估现有正式接口与OS权限，不在现有会话悄悄接入。

导入预览只列站点、Cookie名称、到期／Secure／HttpOnly／SameSite等属性及数量，不显示原值；在准确owner、原Session、站点范围、覆盖行为与有效期边界上取得一次明确确认。Cookie值只从受支持私有入口传给该owner，不能进入模型输入、提示词、注释、一般日志或源码补丁。需保留来源漂移、跨会话、目标关闭、覆盖冲突与未知导入的准确身份，unknown不重发。退出与清除只作用于原私有目标，不能删除来源浏览器资料。

目前没有核实agent-browser 0.39.4是否提供满足这些范围与unknown恢复要求的入口，也未确认手动标签的有限Main port如何承载同等契约；实施前须查明最小后端合同。如需Tool／公共协议升级，必须单独明确范围并取得用户确认。现阶段不显示可点击的导入菜单。

## Alternatives considered

- 整个Chrome Profile复制到测试／Agent目录：会包含无关登录、密码和运行锁，且不符合最小范围，未采用。
- 把Cookie作为提示词／注释或通用文件交给模型：会暴露秘密且无法约束实际使用，未采用。
- 用户主动选择站点导出材料并经私有owner注入：更容易限制范围，是后续优先评估路径；仍需解析、覆盖、生命周期及准确结果合同，不能凭上游CLI存在就宣称可用。

## Acceptance criteria

使用专用本地无凭据Cookie夹具核域／路径／Secure／HttpOnly／SameSite、到期和数量／字节上限；跨站点与跨owner拒绝；确认前零读取／注入；模型请求及普通日志无原值。未知请求只能核实原申请，不以换ID重发；清除和退出不影响来源。真实账户导入不在本轮授权内。

## Risks

Cookie可代表登录和账户权限。域范围、重定向、子域、同名覆盖和过期语义需精确，手动标签与Agent能力不能混称为同一浏览器。仅有名称预览不证明来源可信，临时Profile也不自动构成秘密保护通道。
