# 第二章 三层架构

## 2.1 架构总览

OpenPX 采用 **protocol → core → app** 三层分离架构，使 Agent 核心成为纯逻辑库（零 I/O），支持 TUI、Desktop、CLI 等多前端接入。

```
┌──────────────────────────────────────────────────────────────┐
│  src/app/            UI 渲染层                                │
│  ├─ cli/             CLI headless（NDJSON 输出）              │
│  ├─ tui/             React Ink TUI                           │
│  └─ (desktop/)       Electron/Tauri（未来扩展点）             │
├──────────────────────────────────────────────────────────────┤
│  src/protocol/       事件协议层                               │
│  ├─ events.ts        AgentEvent 23 种子类型                   │
│  ├─ actions.ts       UserAction 5 种动作 + InterruptPayload   │
│  └─ provider.ts      UserInputProvider 接口                   │
├──────────────────────────────────────────────────────────────┤
│  src/core/           Agent 核心库（纯逻辑，零 I/O）            │
│  ├─ harness/         图编排：graph / routes / tool-runner     │
│  ├─ model/           LLM 适配：context / factory / deepseek   │
│  ├─ tools/           工具实现：shell / file / apply-patch      │
│  ├─ subagent/        子 Agent：runner / task-tool / roles      │
│  ├─ mcp/             MCP 协议：manager / tool-adapter          │
│  ├─ skills/          Skills 系统：loader / skill-tool          │
│  ├─ sandbox/         沙箱执行器                                │
│  ├─ config/          配置读取与路径管理                        │
│  ├─ persistence/     SQLite checkpoint + 会话管理              │
│  └─ runner.ts        runAgent / resumeCodeAgent 单一入口       │
└──────────────────────────────────────────────────────────────┘
```

## 2.2 依赖约束

```
app ──→ protocol ──→ (无依赖)
  │
  └──→ core ──→ protocol
```

- `src/protocol/`：**零依赖**，不引用 core 或 app
- `src/core/`：只依赖 protocol，**不允许** `console.log`、`process.stdin`、`process.stdout` 或任何终端 I/O
- `src/app/`：只依赖 protocol 和 core，只做**渲染 + 输入采集**

## 2.3 数据流

```
用户输入 → App 层 → UserInputProvider.requestAction()
                         ↓
                    Core 层 runner
                         ↓
                   LangGraph 图执行
                         ↓
              AgentEvent ← provider.onEvent()
                         ↓
                   App 层 reducer → UI 更新
```

核心循环：App 层通过 `UserInputProvider` 接口与 Core 层交互。Core 层通过 `onEvent()` 推送事件，通过 `requestAction()` 请求用户输入（interrupt 时）。App 层的 reducer 消费事件更新 UI 状态。

## 2.4 设计收益

| 收益 | 说明 |
|------|------|
| 多前端复用 | 同一 core 层可被 TUI、CLI、Desktop 共享 |
| 可测试性 | core 层可独立测试，无需终端环境 |
| 事件标准化 | 所有前端消费同一事件协议，行为一致 |
| 渐进迁移 | 未来新增前端只需实现 UserInputProvider |
