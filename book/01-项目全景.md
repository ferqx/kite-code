# 第一章 项目全景

## 1.1 一句话定位

OpenPX 是一个**开源、多模型、跨平台的终端代码 Agent**——不绑定特定 AI provider，在 LangGraph 生态之上提供可审计的人机协作编程体验。

## 1.2 目标用户

| 用户画像 | 核心诉求 |
|----------|----------|
| 专业开发者 | 在终端中与 AI 协作完成代码任务 |
| 多模型用户 | 灵活切换 DeepSeek / OpenAI / Ollama 等 provider |
| 安全敏感团队 | 审批机制、工具策略、风险分类 |

## 1.4 技术栈

| 层面 | 技术选型 |
|------|----------|
| 运行时 | Bun |
| 语言 | TypeScript (ESM) |
| TUI 框架 | React Ink |
| Agent 框架 | @langchain/langgraph |
| 模型适配 | @langchain/deepseek、@langchain/openai、@langchain/ollama |
| 持久化 | SQLite (bun:sqlite) + LangGraph Checkpoint |
| 配置格式 | JSONC (jsonc-parser + Zod 校验) |

## 1.5 架构原则

1. **Provider 无关** — 核心逻辑不绑定特定 AI provider；provider 专有行为隔离在适配器层
2. **可审计** — 所有工具调用留下审批记录和 checkpoint；用户可以回溯任何决策
3. **渐进式自主** — agent 能力可逐级放权（default → shell 授权 → full_access），不强制二元开关
4. **事件驱动** — TUI 和 CLI 通过统一的标准化事件协议消费；新前端只需对接事件流
5. **跨平台优先** — 所有新功能必须在 Windows/Unix 双平台通过测试
6. **LangGraph 生态内** — 不做轮子，利用上游 checkpoint、stream、interrupt 机制

## 1.6 与竞品的差异

| 维度 | OpenPX | Claude Code | Open Code |
|------|--------|-------------|-----------|
| 模型绑定 | 无（多 provider） | 绑定 Claude | 无 |
| 前端形式 | TUI + CLI | TUI + IDE 插件 | IDE + TUI |
| 审批粒度 | 工具级 + 命令级 | 工具级 | 工具级 |
| 架构分层 | protocol/core/app 三层 | 单体 | — |
| 持久化 | SQLite checkpoint 链 | SQLite | — |
| MCP / Rewind / Skills | 已支持 | 已支持 | — |

## 1.7 明确不做

| 不做 | 理由 |
|------|------|
| IDE 插件 | TUI 是唯一前端交互通道 |
| 托管 SaaS | 仅本地运行 |
| 移动端 | 仅终端环境 |
| 代码审查 Bot | 不属于交互式 agent 职责 |
| Web 前端 | 不在当前规划中 |
