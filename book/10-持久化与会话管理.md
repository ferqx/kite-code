# 第十章 持久化与会话管理

## 10.1 SQLite Checkpoint

OpenPX 使用 LangGraph 的 `BunSqliteSaver` 作为 checkpoint 持久化后端。

### Checkpoint 存储内容

```
checkpoint = {
  channel_values: {
    messages: [...],           // 完整消息历史
    plan: AgentPlan | null,    // 计划状态
    workspaceAccess: string,   // 工作区访问模式
    authorization: object,     // 授权状态
  },
  config: { configurable: { thread_id, checkpoint_id } },
  metadata: { source, step, writes },
  parent_config: ...           // 父 checkpoint（形成链）
}
```

### Checkpoint 链

```
checkpoint_1 ← checkpoint_2 ← checkpoint_3 ← ... ← checkpoint_N
  (初始)        (step 1)        (step 2)              (最新)
```

每次图执行一步后保存新 checkpoint，形成可回溯的链式结构。

## 10.2 会话管理

### SessionManager

`SessionManager` 是 TUI 层的多会话管理器：

```
SessionManager
  ├─ createSession(workspace)     → 创建新会话
  ├─ switchSession(oldId, newId)  → 切换活跃会话
  ├─ registerSession(threadId)    → 注册历史会话
  ├─ removeRuntime(threadId)      → 移除会话运行时
  ├─ getRuntime(threadId)         → 获取 SessionRuntime
  └─ getSnapshot()                → 获取所有会话快照
```

### SessionRuntime

每个会话对应一个 `SessionRuntime` 实例：

```typescript
class SessionRuntime {
  id: string;                    // 会话 ID (threadId)
  name: string;                  // 会话名称
  workspace: string;             // 工作目录
  agentLoopActive: boolean;      // Agent 是否正在运行
  abortController: AbortController | null;
  conversationHistory: string[];
  pendingSkills: string[];
  thinkingLevel: string | null;
  eventBuffer: AgentEvent[];     // 后台事件缓冲
  dormant: boolean;              // 是否休眠

  runTask(task, deps): Promise<void>
  abort(): void
  setForeground(active: boolean): void
}
```

### 前台/后台模式

```
前台会话：provider.onEvent → dispatch 到 UI，实时显示
后台会话：provider.onEvent → 缓存到 eventBuffer，切换回前台时回放
```

## 10.3 多会话并发

### 独立 AbortController

每个会话拥有独立的 `AbortController`，会话间互不污染：

```
会话 A: AbortController_A → runAgent_A
会话 B: AbortController_B → runAgent_B

用户中断会话 A → AbortController_A.abort()
会话 B 不受影响
```

### 竞态保护

- `loadGenerationRef`：每次 `LOAD_SESSION_PENDING` 递增 generation counter，旧的异步加载结果被丢弃
- `agentLoopActiveRef`：防止重复启动 agent 循环

## 10.4 会话命名

首次用户消息后，自动生成智能会话名称：

```
用户输入 task → agent 完成
  → generateSessionName(task) → LLM 生成简短描述
  → persistSessionName() → 更新 SessionManager 和 UI
```

## 10.5 会话搜索

`/sessions <keyword>` 命令支持按关键词搜索历史会话。搜索范围包括会话名称和消息内容。

```
/sessions 认证
  → searchSessions(path, "认证")
  → 先匹配 session_name（SQL LIKE，快速）
  → 再加载命中的会话检查消息内容（较慢）
  → 返回匹配的会话列表
```

搜索在 SessionSelector 面板中以实时输入方式呈现，输入即搜索（debounce 300ms）。

## 10.6 会话导出

`/export` 命令将当前对话导出为 Markdown 文件，保存到 `~/.openpx/sessions/<timestamp>.md`。
