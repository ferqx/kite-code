# 第十二章 测试体系

## 12.1 测试分层

```
┌─────────────────────────────────────────────────────────────┐
│                    测试金字塔                                 │
├─────────────────────────────────────────────────────────────┤
│  P3: 真实模型端到端 (test:real)     ~5 tests  · 最慢 · 需配置 │
├─────────────────────────────────────────────────────────────┤
│  P2: TUI E2E (mock agent)          ~71 tests · 中等 · 快速   │
├─────────────────────────────────────────────────────────────┤
│  P1: 集成测试 (mock model)          ~30 tests · 较快          │
├─────────────────────────────────────────────────────────────┤
│  P0: 单元测试                       ~100 tests · 最快         │
└─────────────────────────────────────────────────────────────┘
```

## 12.2 测试命令映射

| 改动范围 | 验证命令 |
|---------|---------|
| 图路由、审批流 | `bun test tests/graph.test.ts` |
| 全图集成（mock 模型） | `bun test tests/integration.test.ts` |
| 工具实现或限制 | `bun test tests/tools.test.ts tests/tool-definitions.test.ts` |
| 工具安全策略 | `bun test tests/tool-policy.test.ts` |
| CLI | `bun test tests/cli.test.ts` |
| 上下文整理 | `bun test tests/context.test.ts` |
| 运行时编排 | `bun test tests/runner.test.ts` |
| checkpoint 持久化 | `bun test tests/checkpoint.test.ts tests/integration.test.ts` |
| TUI reducer 逻辑 | `bun test tests/tui-reducer.test.ts` |
| TUI 布局/渲染 | `bun test tests/tui-layout.test.tsx` |
| TUI e2e（mock agent） | `bun test tests/e2e/` |
| TUI 启动与输入链路 | `bun test tests/e2e/startup.test.tsx` |
| TUI 会话切换完整链路 | `bun test tests/tui-session-switch.test.tsx` |
| 跨模块/不确定 | `bun test` + `bun run typecheck` |
| 真实模型链路 | `bun run test:real` |

## 12.3 测试编写原则

1. **测试是为了发现程序问题，不是为了通过而通过**。如果测试断言与实际行为不符，应优先怀疑程序行为是否正确
2. 测试用例名称应描述验证的**行为**，而非实现细节
3. 生产代码中不允许 `as any` 或 `: any`（外部 API 约束除外，需注释说明）

## 12.4 TUI E2E 测试

### 测试架构

```
tests/e2e/
├── startup.test.tsx           # 启动与输入链路
├── tui-e2e-all.test.tsx       # 完整 E2E 套件
├── tui-session-switch.test.tsx # 会话切换链路
└── harness.ts                 # Mock Agent 响应分配器
```

### Mock Agent

E2E 测试使用 mock agent 替代真实模型，按顺序返回预定义响应：

```typescript
const responses = [
  { events: [{ type: "text", data: { text: "Hello!" } }] },
  { events: [
    { type: "tool_call", data: { name: "read_file", args: { path: "src/App.tsx" } } },
    { type: "tool_done", data: { name: "read_file", ok: true, summary: "45 lines" } },
    { type: "text", data: { text: "Done!" } },
  ]},
];
```

### E2E 断言类型

| 断言类型 | 说明 |
|----------|------|
| `rendered` | 组件成功渲染，无崩溃 |
| `output` | 输出区包含预期文本 |
| `status` | StatusBar 显示预期状态 |
| `interrupt` | 审批/输入块正确渲染 |
| `session` | 会话状态正确 |
| `keyboard` | 快捷键触发预期行为 |

## 12.5 真实模型测试

### 隔离策略

真实模型测试文件使用 `.real.ts` 后缀，不被 `bun test` 默认发现：

```bash
# 默认测试（不含真实模型）
bun test

# 真实模型测试（需配置 ~/.openpx/openpx.jsonc）
bun run test:real
```

### 覆盖范围

覆盖所有模型可见工具的端到端链路：`read_file`、`write_file`、`edit_file`、`shell_execute`、`update_plan`、`ask_user`。

## 12.6 TypeScript 类型检查

```bash
bun run typecheck
```

提交前必须运行，确保零错误。

## 12.7 平台兼容

| 维度 | 要求 |
|------|------|
| 测试用例 | Windows / Unix 双平台 |
| TUI | Windows / Unix 双平台 |
| Shell 工具 | Windows / Unix 双平台（bash 选择策略） |
| 文件工具 | 正确处理路径分隔符差异 |
| 测试覆盖 | 包含平台差异相关的边界情况 |

## 12.8 TUI 验证特殊性

- Ink 渲染管线在 `ink-testing-library` 和真实终端中行为不同
- TUI 布局/交互类改动仅靠单元测试无法验证正确性
- **测试全绿 ≠ 功能正确**，TUI 布局类改动必须在提交前 `bun run tui` 手动验证
