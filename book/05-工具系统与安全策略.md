# 第五章 核心层：工具系统与安全策略

## 5.1 内置工具集

OpenPX 的工具注册顺序由 `src/core/tools/definitions.ts` 中的 `builtinTools` 数组定义，所有工具按固定顺序排列：

### builtinTools（按注册顺序排列）

| # | 工具 | 用途 | 风险分级 | 条件 |
|---|------|------|----------|------|
| 1 | `read_file` | 读取文件内容 | `read`（直通） | 始终 |
| 2 | `edit_file` | 编辑文件（search/replace） | `write_file`（需审批） | 始终 |
| 3 | `write_file` | 创建/覆写文件 | `write_file`（需审批） | 始终 |
| 4 | `shell_execute` | 执行 shell 命令 | 按命令内容分级 | 始终 |
| 5 | `read_mcp_resource` | 读取 MCP 资源 | `read`（直通） | 始终 |
| 6 | `Skill` | 加载技能指令内容 | `read`（直通） | 有 skills 时 |
| 7 | `task` | 派发子 Agent | 直通 | 有 config + sink 时 |
| 8 | `update_plan` | 更新 Agent 计划 | `plan`（直通） | 始终 |
| 9 | `ask_user` | 向用户提问 | `read`（直通） | 始终 |
| 10 | `set_authorization_mode` | 切换授权模式 | 直通 | 始终 |

### 动态追加工具

| 工具 | 来源 | 追加位置 |
|------|------|----------|
| `mcp__<server>__<tool>` | MCP 服务器 | builtinTools 末尾 |

**前缀缓存稳定性**：builtinTools 顺序固定不变，MCP 工具只追加在末尾，保证模型前缀缓存命中率。

## 5.2 工具契约（ACI Contract）

每个工具描述遵循结构化 ACI 契约：

```typescript
{
  whenToUse: string;        // 何时使用此工具
  commonMistakes: string;   // 常见误用和纠正
  outputFormat: string;     // 输出格式说明
  failureHandling: string;  // 失败处理指南
}
```

契约定义在 `src/core/tools/tool-contracts.ts`，是工具行为的一等 UX 文档。

## 5.3 shell_execute：Command Action Envelope

`shell_execute` 不只是命令字符串，而是一个结构化的 action envelope：

```typescript
{
  command: string;                    // 必填：要执行的命令
  intent?: "inspect" | "verify" | "build" | "test" | "git" | "other";  // 意图声明
  objective?: string;                 // 目标说明
  justification?: string;             // 执行理由
  expected_observation?: string;      // 预期观察
  failure_strategy?: string;          // 失败策略
  prefix_rule?: string[];             // 建议放行模式
  grant_request?: string;             // 授权请求
}
```

### 命令分级

```
shell_execute 命令
  │
  ├─ 只读命令（cat, ls, grep, git status...）→ 直通
  │
  ├─ 普通执行（npm test, tsc...）→ 审批
  │
  ├─ 写入/VCS 变更（git commit, git push...）→ 审批
  │
  └─ 高危破坏性（rm -rf /...）→ 默认拒绝
```

## 5.4 工具安全策略

所有安全判断集中在 `src/core/harness/tool-policy.ts`：

### 策略评估流程

```
工具请求到达
  │
  ├─ 1. 工具是否在 read-only 访问的白名单中？
  │     └─ 是 → 直通（read_file, read_mcp_resource, Skill, update_plan, ask_user）
  │
  ├─ 2. 当前 authorization 是否为 full_access？
  │     └─ 是 → 直通（shell_execute, write_file, edit_file, mcp__*）
  │
  ├─ 3. 工具是否需要审批？
  │     ├─ shell_execute → 按命令内容分级
  │     ├─ write_file / edit_file → 需审批
  │     ├─ mcp__* → 默认需审批（config 中 risk:"read" 除外）
  │     └─ 其他 → 直通
  │
  └─ 4. 是否有 same_command 授权？
        └─ 是 → 直通
```

### 审批粒度

| 授权 | 效果 | 持久性 |
|------|------|--------|
| `approve_once` | 仅本次执行 | 不持久 |
| `same_command` | 同一命令直通 | 当前 thread + workspace |
| `full_access` | 所有写入工具直通 | 当前 thread（新 thread 不继承） |

## 5.5 审批交互

### 审批 payload

```typescript
interface ToolApprovalPayload {
  scope: "once";                   // 审批范围
  cwd: string;                     // 工作目录
  threadId: string;                // 会话 ID
  tool: string;                    // 工具名
  command: string;                 // 命令内容
  risk: string;                    // 风险等级
  approvalHash: string;            // 请求哈希
  summary: string;                 // 人类可读摘要
  reason: string;                  // 审批原因
  expectedEffects: string[];       // 预期效果
  grantOptions: string[];          // 可选授权粒度
  recommendedGrant: string;        // 推荐授权
  modelJustification?: string;     // 模型解释
  objective?: string;              // 目标
  expectedObservation?: string;    // 预期观察
  failureStrategy?: string;        // 失败策略
  suggestedPrefixRule?: string[];  // 建议放行模式
}
```

### 审批流程

```
Agent 调用受保护工具
  → tool-policy 评估风险
  → routes 决定进入 approval 节点
  → graph interrupt → need_approval 事件
  → TUI 渲染审批块
  → 用户选择 approve/deny
  → resume → tool-runner 执行（或跳过）
```

## 5.6 read-only vs write 访问

| 模式 | 可执行工具 | 需审批工具 | 被拒绝工具 |
|------|-----------|-----------|-----------|
| `read-only` | read_file, read_mcp_resource, Skill, update_plan, ask_user | — | edit_file, write_file, shell_execute(非只读) |
| `write` | 全部（直通或审批） | shell_execute, edit_file, write_file, mcp__* | — |

`planning` 阶段是独立执行边界——即使在 `write` 模式下，planning 阶段也只能执行只读工具和 `update_plan`。

## 5.7 MCP 工具策略

```
MCP 工具（mcp__*）
  ├─ config 中 risk: "read" → 直通
  ├─ full_access 模式 → 直通
  └─ 其他 → 触发审批
```

## 5.8 工具执行失败处理

- 失败原因和正确用法由工具结果自身返回
- 失败结果包含 `failure.reason` 和 `failure.guidance`
- 非零退出或异常转换为 `ok: false` 的 ToolMessage，不抛出到图执行层
